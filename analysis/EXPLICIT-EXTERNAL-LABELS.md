## 1. ВЕРДИКТ

[ФАКТ] По всем 69 .be найдено 47 надёжных литералов

(вид code) другой зоны при значении > 02000.
Это полный перечень, а не только зона 0137.

[ФАКТ] Ещё 275 литералов Xnnnnn помечены в исходнике
как CALL-OUT §4/§6. Их цель - внешний модуль,
но точная процедурная метка в индексе отсутствует.

[ФАКТ] Пример задачи BR0321 ЭКВ 50320 (Z0154:194 и
Z0554:223) НЕ разрешается: страница 24 не привязана
в ZONE-BASE-MAP.md, владелец неизвестен.

[ФАКТ] Сколько можно превратить без нарушения
принятой верификации:
  сценарий 0-0 rebuild : 0 (любая замена меняет
                         слово в referring модуле);
  сценарий re-dispak/link: 47 при известной цели,
                         из них 4 проверены на копии.
Остальные блокируются: §8.

## 2. ДАННЫЕ И МЕТОД

Файлы /tmp отсутствовали, данные созданы заново:
  tools/v78_label_index.py --format json
  tools/v78_offset_resolve.py --labels ... \
      --format json --summary
Итог: 2428 меток, 69 файлов, 59546 записей,
разрешено 51204. Области: local 4308,
interzone 45010, external 10228.

Парсер .be: 18315 определений ЭКВ, 7455 токенов.
Критерий "литерал на процедуру":
  1. VALUE в кавычках, восьмеричное;
  2. значение > 02000;
  3. resolver даёт target_label A##### вида code
     в зоне, отличной от зоны файла;
  4. имя в операнде ПБ/ПВ/ПИО/ПИНО/ПЕ/ПО/НТЖ/
     ЦИКЛ вне своей строки ЭКВ.
Все 47 прошли пункт 4. Малые значения окна 0147
(база 00000) отброшены как ложные.

Коллизии: зоны 0151 и 0153 имеют базу 74000,
0152 и 0157 имеют базу 76000. Адрес 0o77322 это
A01322/0152, хотя комментарий .be говорит "0157".
Адрес сам по себе владельца не доказывает.

## 5. ЯВНАЯ ФОРМА ПРЕОБРАЗОВАНИЯ

Tier A, ссылающийся модуль:

Модуль-владелец: сразу после строки, где <symbol>
уже определена как метка, добавить:
  +         ВХОДН <symbol>

ВАЖНО: писать "NAME ВХОДН NAME" в шапке модуля
нельзя. Это создаёт метку по адресу 02000 и даёт
дубликат с поздним определением: ошибка 0002.
Проверено на копии, зоны 0154 и 0170.

Tier B, владелец - начальная метка модуля:
  + X316B ВНЕШН Z0157.Z0157A
  + Z0157A ЭКВ Z0157

Семантика (EXTERNAL-CALL-FORMAT.md §0, §1):
  CALL_word = бит перемещаемости | X | D

ВНЕШН на саму процедуру точнее, чем ВНЕШН на
начало модуля: сохраняется смещение D.

Точные слова (gold -> silver, 15-битное поле адреса):
  0137:0564  адрес 25522 -> 20000, op 151 -> 141
  0137:1403  адрес 25522 -> 20000, op 151 -> 141
  0137:1620  адрес 25522 -> 20000, op 151 -> 141
  0137:1630  адрес 77322 -> 00000, op 170 -> 143
  0145:1176  адрес  3212 -> 60000, op 026 -> 002
  0165:1571  адрес  3636 -> 60000, op 026 -> 002
Три слова 0137 отвечают трём вызовам P75522,
слово 1630 - P76122, 0145 - BR3212, 0165 - BR3636.

Причина: ЭКВ подставляет число без бита
перемещаемости. ВНЕШН порождает слово с битом 21
(0o4000 в 12-битном поле) и номером символа;
линкер подставляет база(X) + D. Поле адреса
стало 00000 или 60000 вместо литерального
absolute, а opcode изменился на код внешней
связи. В сценарии re-dispak это допустимо по
решению пользователя; в 0-0 - нет.

Побочный факт: добавление "A01212 ВХОДН A01212"
в шапке даёт OШИБKИ=0001 и слово +0002+*****.
Правильная форма - голое "ВХОДН <метка>" после
существующего определения метки.
