## 0. ГЛАВНЫЙ РЕЗУЛЬТАТ

[ФАКТ] В колоде работают ДВА разных распознавателя:

1. АРАП-разборщик карт. Он строит 6-байтовое слово
   карты и сравнивает его с эталонами 076336-076436
   командами `aex` (побитовый xor) + `uza`.
   Это РАСПОЗНАВАНИЕ КЛАССА карты, то есть лексика.
2. Макроредактор (проход 1, зона 0154) и макромашина
   (проход 2, зона 0170). Они работают с текстом
   `МАСRО ... МЕND`, `∧`-параметрами, `GВLА/SЕТА/АIF`.

[ФАКТ] Разделение исходной строки на поля
`МЕТКА / ОПЕРАЦИЯ / ОПЕРАНД / КОММЕНТАРИЙ`
прямо НЕ НАЙДЕНО: в исходниках нет процедуры,
которая бы это делала. Шапка 0176.1743-1763 есть
ФОРМАТ ЛИСТИНГА, а не доказательство парсера.

[НЕ ИЗВЕСТНО] Именованной процедуры синтаксического
разбора ни для одного из трёх проходов не найдено.
Известен НОМЕР ПРОХОДА и наблюдаемые эффекты.
Оригиналов макроредактора, макромашины и АРАП
на дисках нет (PASSES-STATIC-FLOW.md:42-44).

## 1. ЧТЕНИЕ КАРТ И РАСПОЗНАВАНИЕ УПРАВЛЯЮЩИХ КАРТ

### 1.1 Где читается карта (ФАКТ)

Цикл в странице ОП 06, адреса `014145-014415`
(ARAP-CARD-PARSER.md:14-30, 146-205).
Трасса B-explore.err: `75647: vjm 14145(15)`,
далее подготовка регистров и уход на `14355`.

Слово карты строится по байтам:

    014346: aox -1(11)   acc += байт
    014346: atx -1(11)   mem[r[11]-1] = acc

r[11] = 53437, запись идёт по `r[11]-1` = 053436.
Счётчик r[5]: 00050 -> 00040 -> ... -> 00000,
по 010 на знак, всего 6 знаков
(ARAP-CARD-COMPARE.md:26-34, 79-100).
Пример ЗОНМОД: `1162705513027044` = GOST «ЗОНМОД».

[ФАКТ] Цикл `014325-014341` НЕ сравнивает слово с
эталоном. В нём нет команды сравнения acc с ячейкой
таблицы. Это управление циклами через r[1], r[4], r[5]
(ARAP-CARD-COMPARE.md:17-24, 102-132, 170-179).

### 1.2 Дескриптор 077143 и диспетч (ФАКТ)

Дескриптор 077143-077150 пишет подпрограмма
`074520-074527`, читает `074530-074537`
(DESCRIPTOR-WRITER.md:15-24, 34-65).
Переход делается ТОЛЬКО по слову 077144:

    074532: xta 77144 / ati 12
    075651: uj (12)     PC = r[12]

Слово 077144 есть r[12], адрес возврата `vjm`,
а не «ключ карты» (ARAP-DESCRIPTOR-077143.md:15-35).
Это ОДИН 6-словный буфер, перезаписываемый перед
каждым переходом, а не таблица «карта -> PC».

Три входа распознавателя (CARD-074021.md:15-25,
142-178; DESCRIPTOR-WRITER.md:156-209):

    r[12]    класс              карты
    074021   карты-рамки        ВВД, ТРН, ЕКОНЕЦ
    075654   карты-действия     0-0, 1-1, БЛМАК,
                                БТМАЛФ, ЗОНМОД,
                                ЗОНГП, ЗПКОМП,
                                ЧТКОМП, КНЦ
    074770   строки исходника   (не карты)

Для 074770 флаг 074544 = 0000000100000000
(ставит 074765), поэтому `u1a (12)` переходит
сразу на 074771 (DESCRIPTOR-WRITER.md:188-192).

[ФАКТ] КВЧ обработан ВНЕ разборщика карт АРАП
(конец вычислений МАКРО-БЕМШ) и не даёт эха
(CARD-074021.md:169-172). Эталон 076425 (КВЧ)
стоит в пути СТРОК, по адресу 074777, а не в
диспетче карт (CARD-074021.md:69-90).

### 1.3 Буферы 076xxx и регистры (ФАКТ)

Слово карты M[076505] строится блоком
`074463-074465` из таблицы `076713+R15`:

    t := M[076713 + R15]
    M[076522 + R15] := (K + t) mod 2↑48
    K = 076406 xor 076407 = 60 60 60 60 60 60

(ARAP-CODES-40-01.md:125-157; CARD-074021.md:109-113).
Таблица 076700+ в gold нулевая, заполняется из
ячеек 00607+ при загрузке архива с ленты 42.

Регистры, прямо названные в трассе:
- r[5]   счётчик знаков, 00050 -> 00000;
- r[11]  указатель таблицы 053436 (=53437);
- r[12]  PC из 077144;
- r[1], r[4]  индексы цикла 014325-014341;
- r[13], r[14]  указатели словаря 074251;
- r[10]=01345, r[11]=03015  поля дескр. (074530);
- r[16]  смещение пула 072000;
- r[17]  адрес таблицы 053401 (074526).

[НЕ ИЗВЕСТНО] Смысл r[10]=01345, r[11]=03015 и
флага 074544, кроме выбора ветви `u1a (12)`
(DESCRIPTOR-WRITER.md:216-225).

### 1.4 Выбор конкретной карты (ФАКТ + ГИПОТЕЗА)

После `uj (12)` оба класса сходятся на подпрограмме
поиска `074251`, которая работает с r[13]/r[14]
как с указателями словаря
(ARAP-DESCRIPTOR-077143.md:196-201).

[ФАКТ] Непосредственно перед обработчиками исполняется
блок `077421-077432`: он читает таблицу по 06452
и делает `u1a (16)`. Цель: 03031 для ЧТКОМП,
07056 для ЗОНМОД (ARAP-CARD-COMPARE.md:265-293).

[ГИПОТЕЗА] Таблица 06452 содержит пары
(код карты, адрес обработчика). Точный формат
записей и правило индексации не восстановлены.

## 2. ЭТАЛОНЫ 076336-076436 И КОНСТАНТА K

### 2.1 Что такое K (ФАКТ)

    076406 = 40 40 40 40 40 40  (пробел 0x40)
    076407 = 20 20 20 20 20 20  (код источника)
    A xor B = 60 60 60 60 60 60 = K

(CARD-ETALONS.md:60-65; FILLER-44-40.md:53-60).
Прямое преобразование 074463-465 прибавляет K
к слову каталога; обратное: `t = (E - K) mod 2↑48`.
Проверка: t = `43 4f 43 54 41 42` (COCTAB) даёт
`a3 af a3 b4 a1 a2` (СОСТАВ)
(ARAP-CODES-40-01.md:140-153).

[ФАКТ] 0x40 это пробел 7-битного внутреннего кода
БЕМШ, 0x44 это знак `$`, заполнитель поля справа
до 6 знаков (FILLER-44-40.md:9-22, 85-100).
Буквы лежат в 0xa0..0xdf, знаки в 0x40..0x5f.

### 2.2 Алгоритм сравнения с эталоном (ФАКТ)

`aex` есть побитовый xor (dispak/dispak/arith.c:
131-136: acc.l xor enreg.l). `uza` ветвит при
нулевом acc. Значит пара `aex E / uza L`
реализует `if (word == E) goto L`.

Точные адреса трёх наборов (CARD-ETALONS.md:121-140;
CARD-074021.md:46-108):

    карты-рамки, вход 074022:
    074024 xta 076505 / aax 076337  маска ACC
    074025 aex 076340 / uza 074105  АРХ(?)
    074026 xta 076505 / aex 076341  ТРНПФК
    074027 uza 074020 / xta 076506
    074030 aex 076342 / uza 074117  заполнитель
    074031 xta 076351 / aex 076336  счётчик
    074033 xta 076352 / aex 076336 / uza 076012

    строки исходника, вход 074770:
    075035 xta 076505 / aex 076433  БПК
    075037 aex 076434 / 075040 aex 076435
    075042 aex 076436 / uj (12)
    074774 aex 076346  КНЦ
    074776 aex 076345  END
    074777 aex 076425  КВЧ

    карты-действия, вход 075655:
    075033 xta 076505 / aax 076431  маска низа
    075034 aex 076432 / u1a 2(12)   хвост

### 2.3 Ответ на вопрос 3 (ФАКТ + ГИПОТЕЗА)

[ФАКТ] Механизм сравнения слова карты с эталоном
есть. Это `aex`/`uza` над словами в том же
преобразованном коде, что и M[076505].

[ГИПОТЕЗА] Называть это ЛЕКСИЧЕСКИМ АНАЛИЗОМ
корректно по аналогии: распознаётся 6-байтовое
ключевое слово карты или класса строки.
Это НЕ разбор текста исходной программы на
лексемы и НЕ разбор полей строки.

[ФАКТ] Прямого декодирования эталона в имя карты
в трассе НЕТ (CARD-074021.md:109-113). Чтения
076340 как АРХ, 076433-436 как БПК/ЛОФ/ЛОН/ПКА
суть ГИПОТЕЗА (CARD-ETALONS.md:104-119, 199-205).
076341 содержит байты `b4 b0 a8` = «ТРН», это
совпадает с дампом M[076505] для карты ТРН
(CARD-ETALONS.md:157-165) и есть наиболее
надёжное прочтение.

## 3. СИНТАКСИЧЕСКИЙ РАЗБОР МАКРООПРЕДЕЛЕНИЯ

### 3.1 Проход 1, макроредактор 0154 (ФАКТ по тексту)

Читает исходник колоды, ищет пары
`МАСRО ... МЕND` до `ФИНИШ`, строит таблицу
определений: имя, список формальных `∧А ... ∧Р`,
тело (PROGRAM2-LOGIC.md:73-98; ARCH:299-303;
Z0154.md:125-138).

[ФАКТ] Зона 0154 загружена по 02000₈ (страница 01),
1024/1024 точных слов; breakpoint 02000 показал
`xta 6065` = первую команду зоны
(PROGRAM2-LOGIC.md:79-85; Z0154.md:13-20).
Первые слова: `START сч '6065'`, `Э50 '103'`,
`пб '2757'` (dis/MBE-Z0154-L1.asm:7-9).

[ФАКТ] Счётчик `-КОЛИЧ ЯЧ ГС` живёт по адресу
0154.1450-1451 (dis/MBE-Z0154-L1.asm:694-695).
Одно простое определение даёт ровно 2 ячейки ГС,
макрос с `LСLА/SЕТА/.МЕТКА/АIF` даёт 4
(ARCH:236-252; PROGRAM2-LOGIC.md:192-208).
Делитель: факт регистрации макроса, не число
параметров и не длина тела.

[ФАКТ] Порядок штампов в листинге: редактор
(строка 11), счётчик ГС (строка 12), макромашина
(строка 14) (PASSES-DYN-FLOW.md:33-67).

### 3.2 Формальные параметры и переменные (ФАКТ)

[ФАКТ] Переводчиком принят ASCII `&` как префикс
параметра (в OCR `macros.be` заменён на `∧`);
обязателен ведущий пробел перед `macro`
(ARCH:153-157; PROGRAM2-LOGIC.md:37-45).

[ФАКТ] Байт `∧` = 0x4D в зонах 0147-0177 НЕ
встречается, поэтому ∧-параметры не лежат там
GOST-текстом (Z0154.md:136-138).

[ФАКТ по тексту] `GВLА/GВLВ/LСLА` суть объявления
переменных, разбираемые при регистрации макроса
(Z0154.md:133-135). Исполнение `SЕТА/SЕТВ`, `АIF`,
`ЭКВ/ЭКВИВ`, ветвления по `∧ВS` делает проход 2
(ARCH:317-322; PROGRAM2-LOGIC.md:100-109).
`АIF + SЕТА + .МЕТКА` единственный механизм
условной генерации и циклов (ARCH:177-190).

### 3.3 Где именно код разбора (ЧЕСТНО)

[ФАКТ] Базовый листинг `-a0 -e0` зоны 0154
трассирует только 2 слова; 0 целей вызовов
(ANNOT-MACRO.md:32-52; Z0154.md:28-46).
Атрибуция кода зоне 0154 сделана ПО ШТАМПУ
0154.0751 (dis/MBE-Z0154-L1.asm:377).

[ГИПОТЕЗА] Внутренний алгоритм поиска пар
МАСRО/МЕND и разбора списка ∧-параметров
не восстановлен. Нет адреса процедуры,
которую можно было бы назвать «синтаксический
разборщик макроса». Есть только проход 0154
и его измеримые эффекты.

[НЕ ИЗВЕСТНО] Физический адрес и длина таблицы
ГС в ОП; биты самих ячеек не наблюдались
(Z0154.md:155-156; PASSES-STATIC-FLOW.md:155-156).

### 3.4 Свидетельство пула (ФАКТ)

В опытах P0/P1/P2/PF в пул по 072000 попадают
ВСЕ строки исходника, включая шапку, тело,
`mend` и `finish` (TEXT-POOL-06445.md:61-136;
POOL-DESCRIPTOR-FIELDS.md:58-91).
Пример из дампа (TEXT-POOL-06445.md:102-112):

    72001  «юяц»
    72004  «&m юяц»
    72007  «ууууу»

[ФАКТ] Это наблюдаемое представление строки,
но НЕ разбиение на поля. Текст хранится
6 байтами во внутреннем 8-битном коде со
старшим битом 0x80 (TEXT-POOL-06445.md:114-117).

## 4. РАЗДЕЛЕНИЕ СТРОКИ НА ПОЛЯ И ПУЛ 072000

### 4.1 Разделение на поля (НЕ ИЗВЕСТНО)

[ФАКТ] Шапка листинга 0176.1743-1763 содержит
колонки `МЕТКА, ОПЕРАЦИЯ, ОПЕРАНД, КОММЕНТАРИЙ`
(ARCH:362-364; BE-LISTING-MODULES.md:60-85).
Это ФОРМАТ ВЫВОДА, интерфейс между проходами
2 и 3, а не текст процедуры разбора.

[ФАКТ] Источники значений колонок частично
известны (BE-LISTING-MODULES.md:122-136):
- МЕТКА   таблица `*МЕТ*`;
- ОПЕРАЦИЯ  KOI-7 таблица 0137;
- ОПЕРАНД   поле команды (гипотеза);
- КОММЕНТ.  текст исходника (гипотеза).

[ФАКТ] C-код dispak НЕ содержит строковых
форматов `АДРЕС`, `МЕТКА`, `ОПЕРАЦИЯ`: это
данные гостевой программы (BE-LISTING-SOURCE.md:
6-11, 17-33). Значит разбор делает транслятор,
но КАКАЯ процедура, не установлено.

[НЕ ИЗВЕСТНО] Печатная процедура для всех колонок
(BE-LISTING-MODULES.md:115-119).

### 4.2 Ближайший наблюдаемый механизм (ФАКТ)

Слово распознавателя строк 074770/075035 с
эталонами 076433-076436 и 076345/076346/076425
относит строку к КЛАССУ: БПК, ЛОФ, ЛОН, ПКА,
END, КНЦ, КВЧ (CARD-074021.md:69-90).
Это классификация строки, НЕ разбиение на поля
МЕТКА/ОПЕРАЦИЯ/ОПЕРАНД/КОММЕНТАРИЙ.

### 4.3 Кто пишет в пул 072000 (ФАКТ)

Запись идёт одной командой зоны 0156
(страница ОП 03, база 06000):

    06057: xta 6402     указатель пула
    06057: aax 6165     маска 0o1777
    06060: ati 16       r[16] = смещение
    06060: xta 6404     дескриптор
    06061: atx 72000(16)  mem[072000+r[16]] = acc

(TEXT-POOL-06445.md:81-100;
 POOL-DESCRIPTOR-FIELDS.md:111-117).
Пул занимает одну страницу 072000-073777₈,
проверка границы в 06046-06050.

Шаблон дескриптора строится в зоне 0154
блоками 01640-01662: `01661: aox 1762`, где
01762 = 0000000000052000
(POOL-DESCRIPTOR-FIELDS.md:93-104;
 dis/MBE-Z0154-L1.asm:814, 831).
Флаг 2010 ставится позже, подпрограммами
04747/05130/04502/05237/03501 через
`aox 6126` = 0010000000000000.
В базовом листинге 0154 эти слова суть `конд`
(dis/MBE-Z0154-L1.asm:759, 814, 831).

Формат дескриптора (POOL-DESCRIPTOR-FIELDS.md:
7-21, 40-46):

    [ 2010 | N | 0005 | 200K ] (восьм.)
    N  номер исходной строки
    K  число 48-битных слов записи
    K = 1 + ceil(длина/6) + 1

### 4.4 Кто читает пул (НЕ ИЗВЕСТНО)

В опытах P0-P2 макрос НЕ вызывался, поэтому
читатель записей пула при развёртке не найден
(TEXT-POOL-06445.md:180-187).
Смысл константы 0o1200000 и различие
2010 против 2000 тоже не доказаны
(POOL-DESCRIPTOR-FIELDS.md:159-173).

## 6. СВОДКА СТАТУСОВ

ФАКТ:
- карта читается циклом 014145-014415, слово
  строится в 053436 по 6 знаков;
- дескриптор 077143-077150 есть 6-словный буфер,
  PC берётся из 077144 через `uj (12)`;
- M[076505] строится в 074463-465 с K=0x60...;
- `aex` есть xor, `aex E / uza L` есть равенство;
- эталоны 076336-076436 сравниваются в трёх
  распознавателях 074022, 075035, 075033;

- запись в пул идёт 06061 `atx 72000(16)`;
- дескриптор пула = [2010|N|0005|200K].

ГИПОТЕЗА:
