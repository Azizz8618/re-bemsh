# Динамический порядок проходов: редактор -> машина -> АРАП

Дата: 22.11.2026. Задача: зафиксировать live-трассировкой
порядок проходов МАКРОРЕДАКТОР -> МАКРОМАШИНА -> АРАП и
передачу управления между ними. Затронут только этот файл;
коммитов нет.

## 2. Live-точки останова: переход редактор -> машина

Задание: копия минимального листинга
`/tmp/.private/azizz/memory-map2/MEMMAP2-listing.b6`.
Команды отладчика по образцу `run*.cmds` из memory-map2.

### Run A (`DYN-A.cmds` / `DYN-A.out`, без трассы)

Точки: `b 02000`, `b 01314`, `b 01322`, `b 03450`.

Порядок остановов и печати (номера строк `DYN-A.out`):

| Строка | Событие |
|---|---|
| 2-5 | установлены 4 breakpoint |
| 6-23 | 01322 `ita`, перемешано с печатью заголовка |
| 24 | `BPEMЯ CЧETA: 00.00.00 0` |
| 25 | `02000: 00 010 6065 xta` (вход редактора) |
| 27 | `MAKPOPEДAKTOP OT  20.06.78` |
| 29 | `001330-KOЛИЧ ЯЧ ГC` |
| 31 | `01314: 00 30 02000 uj` (переход) |
| 32 | `02000: 00 037 0003 ntr` (вход машины) |
| 33 | `MAKPOMAШИHA OT 1.11.78` |
| 35-49 | `03450: 00 30 02452 uj`, 37 срабатываний |

Все четыре точки сработали. Ключевой факт: адрес 02000
остановил дважды с РАЗНЫМ содержимым слова: `00 010 6065`
(xta) и `00 037 0003` (ntr). Между ними был один переход
`01314: uj 2000`.

### Run B (`DYN-B.err`, трасса уровня 3)

Те же точки, трасса включена после первого останова.
490508 строк трассы. Свидетельства (номера строк):

```
30428:02000: xta 6065   (=0000000000002002)
30429:02000: *50 103    (=0042000100000731)
138310:01314: uj  2000  (=0037000303002214)
138311:02000: ntr 3     (=0010063200500105)
138312:02000: uj  2214  (=0010541500400017)
405107:03450: uj  2452  (=7400000075107777)
```

`01314: uj 2000` встречается в трассе ровно один раз
(строка 138310). Контекст 138265-138325 показывает: перед
ним редактор работает по 03430-03444, затем идёт диспетчер
01322 -> 01331 -> 01344 -> 01212 -> 01213 -> 01311 ->
01313, и только потом `01314: uj 2000` -> `02000: ntr 3` ->
02214.

Пара вступительных слов совпадает с таблицей
`docs/ANNOT-MACRO.md` §3: у зоны 0154 это
`START сч '6065'`, `Э50 '103'`, `пб '2757'`; у зоны 0170
это `START ржа '3'`, `пб '2214'`. То есть два прохода
загружаются по одному адресу 02000 в разное время
(оверлей страницы 01). Это наблюдение, а не карта
дисковых зон.

Точка `03450` сработала поздно (первый раз на строке
405107, уже после штампа машины), 37 раз. Её атрибуция
к ячейке редактора ERR_CNT из
`analysis/MEMORY-MAP-PC2-NOTES.md` §1 (0154:1450) в этом
прогоне напрямую не подтверждается.

Runs A/B прерваны командой `q` на повторяющемся 03450:
`КОНЕЦ ЗАДАЧИ` в их stdout нет. Для поиска третьего
прохода они не пригодны.

## 5. Что осталось НЕДОКАЗАННЫМ

1. Исполнение прохода АРАП ни разу не перехвачено. Нет ни
   runtime-штампа в листинге, ни своего пограничного
   breakpoint. Порядок АРАП после машины опирается на
   docs/ANCHORS.md §2 и docs/ANNOT-MACRO.md §2, а не на
   этот эксперимент.
2. Не найден адрес перехода машина -> АРАП. Точки 074000
   и 076000 сработали до проходов и не являются входом.
3. Не прослежен механизм смены содержимого страницы 01
   между двумя остановами 02000: какой экстракод читает
   новую зону и какую зону диска. Дамп ОП в этот момент
   не снимался.
4. Роль 01322 в переключении проходов не установлена: он
   срабатывает при печати заголовка и при выводе листинга,
   то есть это общий диспетчер, а не переключатель.
5. Принадлежность кода машины зоне 0170 здесь не доказана.
   Совпадают только вступительные слова из ANNOT-MACRO §3;
   адрес исполнения совпадает с адресом редактора.
6. Роль 03450 неоднозначна: в PC2 это ERR_CNT редактора,
   здесь он исполняется после штампа машины 37 раз.
   Возможна общая подпрограмма или повторная загрузка
   страницы, но это только гипотеза.
7. Runs A/B прерваны до `КОНЕЦ ЗАДАЧИ`; Run C/D не имели
   трассы, поэтому полной картины всех переходов нет.
