[ФАКТ] Задания: job2-chtomp, job2-zonmod, job2-knc
и job-B-sostav-orig (копии из desc-77143).

[ФАКТ] Точки останова: 074520 (до записи) и
074530 (после записи). В каждой точке снимались
r[10]-r[15] и дампы `77140 b` / `77150 b`.

[ФАКТ] Формат дампа: 6 октальных байт по 3 цифры.
`000 000 000 000 170 021` = байты 00 00 00 00 70 11
= 0x7811 = 074021.

[ФАКТ] Первые 4 останова job2-chtomp:

## 4. Три лишних значения 077144

[ФАКТ] Частоты в полной трассе B (совпадают с
ARAP-DESCRIPTOR-077143.md §1.1):

    word   uj(12)  число  источник r[12]
    074021  074516   2   ret из 074020 vjm 74456(12)
    074022  075651   2   ret из 074021 vjm 75641(12)
    074770  074516 103   ret из 074767 vjm 74456(12)
    075654  074516   4   ret из 075653 vjm 74456(12)
    075655  075651   4   ret из 075654 vjm 75641(12)

[ФАКТ] Все три "лишних" значения суть АДРЕС ВОЗВРАТА
команды `vjm 74456(12)` (семантика cu.c:139):
r[12] = PC+1. Запись 074522 просто копирует его
в 077144. Специального константного поля нет.

[ФАКТ] Цепочка заглушки (трасса 1041894+, 1395574+):

    074516: uj (12)      PC = r[12] = 074770
    074770: utc
    074770: vjm 75641(12)  r[12] = 074771
    075641: xta 74544      acc = word[074544]
    075641: u1a (12)       PC = r[12], если acc != 0
    074771: vjm 75035(12)  -> распознаватель 075035

[ФАКТ] Для 074021 и 075654 word[074544] = 0,
поэтому u1a (12) НЕ переходит, а исполняется
075642 -> 075643 -> writer снова. Второй writer
пишет уже 074022 / 075655. Затем 074530 читает
их, и 075651 uj (12) идёт прямо в распознаватель.

[ФАКТ] Для 074770 word[074544] =
0000000100000000. Его ставит 074765:
    074763: arx 76343 / asn 50
    074765: atx 74544
Поэтому u1a (12) переходит сразу на 074771.

[ФАКТ] Итоговая карта PC:

    074021 -> (перезапись) -> 074022 ->
             074022: xta 76336 / arx 74040 ...
             сравнение с 076336-076342
    074770 -> 074771 -> 075035 ->
             075035: aex 76433 / 76434 / 76435 / 76436
             075043: uj (12) -> 074772 -> 074774 ->
             076571 -> 074326
    075654 -> (перезапись) -> 075655 ->
             075655: vjm 75033(12) ->
             075033: aax 76431 / aex 76432

[ФАКТ] 075650-путь НЕ проходит через заглушки:
074530 грузит 074022 или 075655 прямо в r[12],
и 075651 uj (12) идёт сразу в распознаватель.

[ГИПОТЕЗА] Три заглушки суть "вход в диспетчер" для
макро-расширения: 074770 помечает активный режим
(флаг 074544), а 074021/075654 дают обычный вход,
который требует повторной записи дескриптора.
