# Поиск режима: метка первого поля равна зонному индексу

Дата: 23.11.2026. Write-set: только этот новый отчёт.
Коммитов, пушей и правок .be в репозитории нет.

## 0. Вердикт

ФАКТ: отрицательный результат. Ни один из 21 проверенных
вариантов не дал поля адреса 00012 при настоящей метке
первого поля на слове 00012 (восьмеричном) и прямой
ссылке `ПВ <метка>(М16)` без `-З` и без `ЭКВ`.

ФАКТ: значение настоящей метки первого поля всегда равно
HAM + индекс слова. При HAM=10000 метка слова 00012
имеет значение 10012. При HAM=00001 оно равно 00013.
Эталон зоны 0137 хранит индекс без базы (например 01036),
поэтому прямое попадание невозможно без HAM=0.

ФАКТ: HAM=0 транслятор не выдаёт. `СТАРТ '0'` и
`СТАРТ 0` дают ошибку `НОЛЬ ЗАПР0Щ1` и HAM=00001.

## 1. Методика

Рабочий каталог: `/tmp/.private/azizz/label-mode/`.
Образы 2048, 2053, 2099, 2248 скопированы из
`/usr/local/share/besm6` (только чтение). dispak всегда
вызывался с `BESM6_PATH=/tmp/.private/azizz/label-mode`.

md5 эталонных образов до и после всех прогонов:
  2048  4b94cc188969c110dcc78d1958b80fe0
  2053  4c6abfc5068a94f8766fc38e360acabd
  2099  90971c339b8744a545c8719a5d134650
  2248  c11067b35e2b85a51433e7d7b5efdd19
Копии после прогонов совпадают с источниками.

Задание собрано встроенным Python-сниппетом из
`tools/rebuild-zone.sh:105-119` (карточки `шифр 419999↑`
... `0-0↑` ... `_$ЕКОНЕЦ`), режим `0-0`, только листинг.

Минимальный модуль (20 команд = 10 слов, метка на слове
00012o, ссылка на слове 00013o):

    TSTMOD СТАРТ '10000'
           Е
           М
           ЗП  , cmd 00 ... cmd 19
    I12    ЗП  , LABEL WORD index 00012o
           ПВ I12(М16) , REF
           ЗП  , tail 1
           ЗП  , tail 2
           ФИНИШ

Выборка из листинга варианта a (строки листинга):

    L43: ADDR=[10012] 00 000 0000 I12  ЗП
    L44:              16 31 10012     ПВ I12(М16)
    L54: ... I12 10012 ... (таблица *МЕТ*)

Индекс 00012o выбран потому, что цель задания сформулирована
как поле адреса 00012. Две команды БЕМШ упаковываются в одно
48-разрядное слово, поэтому 20 команд = 10 слов индекса.

## 3. Проверка на реальной зоне 0137 (только копия)

Копия `bemsh/MBE-Z0137.be` положена в
`/tmp/.private/azizz/label-mode/realzone/bemsh/`,
`gold` и `tools` подключены символьными ссылками.
Сверка через `tools/rebuild-zone.sh 0137 B`.

База (файл репозитория без правок):
  HAM=10000, ДЛИHA ПPOГ=02000
  WORDS: всего=1024 совпало=1024 различий=0
  RESULT: PASS

Проба: замена в копии `ПВ I1036-З(М16)` на
`ПВ I1036(М16)` (убрано вычитание базы):
  HAM=10000, ДЛИHA ПPOГ=02000
  WORDS: всего=1024 совпало=1023 различий=1
  RESULT: FAIL

ФАКТ: расхождение в слове 0436.
  gold   090000ec821e  (поле 01036)
  silver 0900000c921e  (поле 11036)
Листинг, строка 934:
  `00 31 11036  ПВ I1036(M16)`
Строка 1461 (метка): `I1036 11036`.
Строка 2494 (*МЕТ*): `I1036 11036`.

Это прямое подтверждение механики из раздела 0: метка
первого поля на слове 1036 несёт значение база+1036,
то есть 11036, а эталону нужно 01036.

## 4. Разделение выводов

ФАКТ:
  - Значение метки первого поля = HAM + индекс слова.
    Подтверждено строками *МЕТ* во всех вариантах.
  - HAM=10000 или 00001 у рабочих вариантов;
    77777 появляется только с ошибкой переполнения.
    Нулевой HAM отвергается: `НОЛЬ ЗAПP0Щ1`.
  - `ВХОДН`, `ВНЕШН`, `росп`, `ЗОНМОД`, карточки `0-0`,
    `КОНК` и `БЛМАК` это правило не меняют.
  - `ЭКВ '12'` даёт нужное поле, но не является меткой
    первого поля; `ВНЕШН` добавляет бит релокации.
  - Режим `1-1` портит копию 2248 и не печатает код.

ГИПОТЕЗА:
  - Поведение вытекает из трёхпроходной схемы
    (МАКРОРЕДАКТОР -> МАКРОМАШИНА -> АРАП): symbol
    разрешается АРАПом как абсолютный адрес, а не как
    смещение. Прямых исходников транслятора нет.
  - Не исключено, что в другой версии МАКРО-БЕМШ
    (ВАР.12/77, зоны 0540-0577) есть директива сдвига
    базы для меток. Здесь она не проверялась.

НЕ ИЗВЕСТНО:
  - Нет полного списка управляющих карточек АРАПа;
    проверены только встречающиеся в репозитории.
  - Не проверялись директивы `ОПРЕ`, `DК`, `НОП`,
    `GВLА` и макросы `ЕВНЕШ`/`ВХОДБ` как способ
    изменить значение метки: они не описаны как
    адресные и в задании не встречаются.
  - Не установлено, существует ли неописанная card,
    задающая нулевую базу без ошибки.

## 5. Практический вывод

Рабочего рецепта без `-З` и без `ЭКВ` не найдено.
Для зоны 0137 остаются два проверенных способа:
  1) метка первого поля + вычитание базы `I1036-З`;
  2) `ЭКВ`-имя с литеральным индексом.
Оба дают 0 отличий с эталоном; первый уже внесён в
`bemsh/MBE-Z0137.be` (см. analysis/REAL-LABELS-0137.md).
