### Правила, найденные при замене

1. Базовая метка `З ЭКВ Z<зона>` должна стоять **после** строки
   `Z<зона> СТАРТ`, иначе `НЕОП MET`.
2. Для зон с HAM (0147, 0547) требуется компенсация `+1`
   после `-З`: `A00011-З+1`.
3. Число в операнде десятичное, номер метки восьмеричный:
   29₁₀ = 035₈.

### Переименование внешнего литерала (ФАКТ)

Для единственного надёжного внешнего кодового адреса зоны 0137
`X77322 = '77322'` (цель A01322 зоны 0576, по global_xref.tsv)
проведено переименование ЭКВ в `P76122` с сохранением значения:

```
X77322 ЭКВ '77322'  ->  P76122 ЭКВ '77322'
все вхождения X77322 -> P76122
```

`rebuild-zone 0137` → ✓ 2000 слов, 0 отличий. Имя теперь несёт
адрес цели (076122), оставаясь обычным ЭКВ, то есть байты не
меняются. Остальные внешние цели требуют такого же разрешения,
но для большинства из них цель помечена [Г] в global_xref.tsv.

## 7. Ограничение, требующее решения пользователя

Полная ликвидация внешних литералов непосредственно НЕ выполнима при
инварианте «0 отличий от gold». Возможные пути:
1. переименовать технические ЭКВ в procedure-подобные имена
   (байты не меняются) плюс каталог;
2. снять инвариант и принять биты релокации `ВНЕШН`.

Пункт 1 может быть выполнен без дополнительного решения;
пункт 2 требует явного разрешения.

## 8. Свои сценарии по образцу re-dispak (24.11)

Добавлен инструмент `tools/v78_link_verify.py` (10 тестов OK) с
тремя стадиями: compile (1-1, ЗОНМОД в ПЕРСО), link (свой rvs-style
задание), verify (посекторное сравнение, как verify.pl). Он НЕ
копирует модули re-dispak: все 33 модуля берутся из наших `.be`.

Проверено на 33 зонах B:

```
compile: 33 зоны, все rc=0
link:    rc=0, ЗОНГП=430137 ... (линкер работает)
```

Найдены и исправлены три ошибки сценария: нужен заголовок
`к 00 070 1003` из rvs.pl, имя модуля ровно 6 знаков без
разделителя, комментарии `*...` должны отфильтровываться.
После исправления компиляция даёт `МОДУЛЬ Z0141 ЗАПИСАН В
ЗОНЫ С 434000 ПО 434001`, `ОШИБОК=0000`.

Оставшееся препятствие: **205 неразрешённых внешних ссылок**
в линкере. Большинство имён испорчены техническими ЭКВ
(`JJJJJJ`, `‾‾‾‾‾‾` и т.п.) — это макро-генерируемые `ВНЕШН`,
чьи owner/symbol в реконструкции не соответствуют реальным
модулям. Статическая фильтрация строк `ВНЕШН` с не-Z владельцем
не помогает: имена появляются при развёртке макросов `ЕВНЕШ`.

Это и есть конкретный остаток работы по «внешние метки в явном
виде»: нужно привести 205 сгенерированных внешних имён к видам
`Z<зона>.<символ>` и добавить соответствующие `ВХОДН` в целевых
модулях. До этого посекторная сверкаlinked зон с gold показывает
отличия и не является доказательством.

## 10. Проверка фикса шага 2 (24.11)

Фикс `SRC_BASE + 2*i` устранил испорченные имена: в 33-модульном
линке больше нет `НЕТ МДЛ`, но-linker ушёл в известный цикл
`НЕВЕРНЫЙ АДРЕС В КОР КОМ` (адрес слова 42122, ИКОП 12,
адрес 52724). Это совпадает с поведением РВС 01/78 из
re-siprod: линковщик не останавливается на неисправимой ссылке
и повторяет попытку бесконечно.

Команда (30 с таймаута):

```
timeout 30 env BESM6_PATH=... dispak -s link.b6 < /dev/null
  ЗОНГП=430137 ...
  НЕВЕРНЫЙ АДРЕС В КОР КОМ АДРЕС СЛОВА 42122 ИКОП 12 АДРЕС 52724
  rc=124
```

То есть посекторная верификация пока НЕ пройдена: мешает не
формат задания и не имена, а неисправимая адресная ссылка в
реконструированном объекте. Для её снятия нужно разобрать
конкретное слово 42122/52724 и найти соответствующий ЭКВ,
что является отдельной задачей.

## 11. Деталь неисправимого адреса (24.11)

Трасса линковщика с -tt и BESM6_WATCH=72504 показала,
откуда берётся 052724:

```
72247: uj  72257  acc=0037777777752724
72257: atx 72504  store 0037777777752724
72261: xta 72504
72262: aax 72445  (=0000000000077777) acc=...52724
72262: wtc 72503  acc=0000000000052724
72361: xta 72504  (=0000000000052724)
72362: aux 72470  acc=5272400000000000
НЕВЕРНЫЙ АДРЕС В КОР КОМ АДРЕС СЛОВА 42122 ИКОП 12 АДРЕС 52724
```

То есть 052724 лежит в таблице внешних символов линковщика
по 72504 и извлекается маской 077777, а затем не помещается
в 12-битное поле адреса команды. Попытка взять core dump
по PC 72364 не дала файла при доступном BESM6_DD_DEBUG=1,
поэтому владельца символа по дампу установить не удалось.

Дополнительно исправлены базы загрузки в link-задании:
вместо START='10000' для всех модулей теперь используются
измеренные базы из label index, с HAM 000001 для зон с базой 0.
Это убрало `ОШИБКА НАЗ`, но не `НЕВЕРНЫЙ АДРЕС`.

Вывод: для точного снятия блокера нужен доступ к внутренней
таблице символов линковщика РВС 01/78 (исходника нет) либо
дальнейшая дизассемблировщика его кода по PC 72200-72470.
Это выходит за пределы «нормализации ЭКВ» и является отдельной
задачей по реконструкции линковщика.

ЭКВ требует восстановления формата записи таблицы (имя, база,
смещение, признаки), чего в исходниках 01/78 нет.

отдельная задача реконструкции линковщика, а не проблема
нормализации ЭКВ или внешних объявлений.
