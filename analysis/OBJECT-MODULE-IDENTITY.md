# Идентичность объектного модуля зоны 0147

Дата: 21.11.2026. Все прогоны только на копиях в
/tmp/.private/azizz/obj-ident/ (AGENTS.md §0). Ни `.be`,
`gold/`, `dis/`, образ или инструмент не изменён.

[Д] факт из источника с file:line; [Г] наш вывод/гипотеза.

## 1. Что такое объектный модуль (формат)

[Д re-siprod/notes/linker.md:26-31] задание `1-1` + `БТМАЛФ`
+ `ЗОНМОД43<зона>` пишет объект на ленту 43 (ПЕРСО).
[Д linker.md:191-194] слово 1 объекта — имя модуля, 6 байт,
код знака `0x60+ASCII` (пример: `ba5051545740` = `Z0147 `).
[Д docs/DIS2BE.md:121-126] режим `1-1` вставляет пары слов
перемещений `00000fffff00 <TYPE|ADDR>`; в `0-0` их нет.
[Д re-siprod/notes/loader.md:19] sym-элемент
`(0o4000+X)<<24 | C<<12 | D` — внешние связи живут в sym.
[Г] Значит объектный модуль = шапка + код + записи
перемещений + таблица символов, а НЕ готовый код.

## 2. Опыт: сборка варианта ВНЕШН в режиме 1-1

Ход: копия 2248/2048/2053/2099 в /tmp; задание из
`/tmp/.private/azizz/vneshn-probe/variants/B-obj-Z0147.be`
(`Z0154 ВНЕШН Z0154.ENT154` + 4x `ПБ Z0154`), `1-1`,
`ЗОНМОД433100 0001`. dispak: 0 ошибок транслятора,
`ЧУЖОЙ CИMBOЛ` (владелец вне задания), `ДЛИHA ПPOГ=02000`,
`BXOДH=1 BHEШH=1`, запись `ЗOHЫ 433100 ПО 433101`. [Д]

Дамп `besmtool dump 2248 --start=03100 --length=2`: [Д]
* 12288 байт = 2 зоны; md5 `98db4dcc...`
* слово 0 = 1, слово 1 = `Z0147 `, слова 2-14 = шапка
  (слово 8 = `000001000001`: счётчики ВНЕШН/ВХОДН);
* 26 пар перемещений `00000fffff00` на словах 0026, 0042,
  0056, ... 0502; вторая слово пары — `...0001`, `...000b`;
* таблица символов/имен в хвосте (слово 3776).

Контроль: `.be` без ВНЕШН в `1-1` даёт тоже 12288 байт,
md5 `2538b40cfc117b43ecfba361026d8e9e`, те же 26 пар
перемещений. [Д] То есть перемещения вставляет САМ режим
`1-1`, а не директива ВНЕШН (ср. DIS2BE.md:121-126).

8 байт ВНЕШН в `0-0`: слова 1236, 1276, 1310, 1314,

analysis/VNESHN-BYTE-EXPERIMENT.md:54-57). [Д]
В gold маркеров `00000fffff00` — 0 (связанная зона). [Д]

## 4. Поиск эталонного объектного модуля на ленте 43

Сканер сырых зон (8256 байт/зона, 8 служебных слов + 1024
слова) по заголовку «слово 0 = 1, слово 1 = имя»: [Д]
* том 2248: 8 модулей (CONSUL, Z0147 — наш запуск, и др.);
* том 2222: 110 модулей (CONSUL, DRAKON, gp1, ДИСКИ,
  ДИСП70 и др. — это модули ДИСПАК/СИПРОД).
Модулей с именем `MBE*`, `Z0147`, `ENT154`, `*BEMSH*` или
модулей транслятора 06/78 НЕТ ни на 2248, ни на 2222. [Д]
Зоны 0137-0177 на 2348/2248 — связанная программа, не
объектные модули (analysis/reloc.md:30-40). [Д]

## 5. Вердикт

[Г] НЕТ. Правильно оформленная внешняя ссылка `ВНЕШН` не
даёт идентичности ни с одним эталоном в наших данных:
* (a) с gold-зоной 0147 — НЕТ: объектный модуль 12288 против
  6144 байт, 4692 отличия уже в первой зоне; даже в `0-0`
  ВНЕШН меняет 8 байт. Причина: gold это связанная зона без
  перемещений, а объект их содержит (DIS2BE.md:121-126).
* (b) с объектным модулем на ленте 43 — НЕТ эталона для
  сравнения: модуля транслятора 06/78 на 2222/2248 нет.

[Г] Адаптация проверки невозможна без самого объектного
модуля: чтобы требовать идентичность с объектным модулем,
нужно сначала получить исходный объект из архива (его нет в
наших образах). Текущая проверка `0-0` + linked-gold —
единственная доступная, она даёт PASS для всех 69 зон с
базовыми `.be`. Для объектной идентичности нужна полная
сборка РВС со всеми модулями 0137-0177, которой у нас нет.

[Г] Семантически `ВНЕШН` корректен: `0c04..` (адрес 02000 в
gold) и `0180..` + CA в объекте — одна и та же ссылка после
разрешения линковщиком (VNESHN-BYTE-EXPERIMENT.md:54-57).
Но это эквивалентность ПОСЛЕ линковки, а не побайтовая
идентичность самих файлов.
