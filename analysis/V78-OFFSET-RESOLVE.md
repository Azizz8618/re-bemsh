# V78-OFFSET-RESOLVE: разрешение адресных смещений

Дата: 24.11.2026. WRITE-SET: только этот НОВЫЙ отчёт и два
новых файла (`tools/v78_offset_resolve.py`,
`tools/tests/test_v78_offset_resolve.py`). Коммитов и push
нет. Эталоны, `.be`, `gold/`, `dis-forced/` не менялись.
Адреса восьмеричные. Степень ↑. Строки <=60 колонок.

## 0. ОПЕРАТОРСКАЯ ДЕФИНИЦИЯ

«Смещение» включает литералы, указывающие на ПРОЦЕДУРНЫЕ
МЕТКИ того же или внешнего модуля, а не только числовые
сдвиги. Поэтому инструмент извлекает все адресные
выражения из поля операнда и сопоставляет их с индексом
меток, а не только вычисляет число.

## 1. НАЗНАЧЕНИЕ И ВХОДЫ

Инструмент `tools/v78_offset_resolve.py` read-only,
детерминированный, стандартная библиотека Python 3.

Входы (только чтение):

| источник | роль |
|---|---|
| `bemsh/MBE-Z*.be` | 33 зоны B |
| `bemsh/MBE2-Z*.be` | 32 зоны B2 |
| `bemsh/ASM-Z*.be` | 4 зоны ASM |
| `analysis/ZONE-BASE-MAP.md` | базы 69 зон, Приложение A |
| `dis-forced/Z*.asm` | дополнительно, флаг `--asm` |
| `--labels FILE` | индекс меток параллельного инструмента |

Индекс меток принимает три формы: список записей,
`{"labels": [...]}` и словарь `{зона: [записи]}`. Ключи
записи: `name`/`label`/`symbol`, `zone`, `absolute`/
`address`/`addr`/`offset`, `status`. Если база зоны
неизмерена, адрес восстанавливается из зоны и смещения
по карте баз.

## 2. ИСПОЛЬЗОВАНИЕ

    python3 tools/v78_offset_resolve.py --help
    python3 tools/v78_offset_resolve.py --summary
    python3 tools/v78_offset_resolve.py --labels idx.json \
        --format json --check > /var/tmp/v78-offsets/r.json
    python3 tools/v78_offset_resolve.py FILE.be \
        --scope local --format text
    python3 tools/v78_offset_resolve.py \
        --asm dis-forced/Z0137.asm --format json

Флаги: `--root DIR`, `--labels JSON`, `--base-map MD`,
`--asm [ASM ...]`, `--scope local|interzone|external`,
`--format json|text`, `--check`, `--summary`.

Коды выхода: 0 = успех, 1 = нарушение `--check`,
2 = ошибка ввода/CLI.

## 3. СХЕМА ЗАПИСИ

Каждая запись имеет ровно 12 полей:

| поле | тип | смысл |
|---|---|---|
| `file` | str | путь к исходнику |
| `line` | int | номер строки, 1-based |
| `mnemonic` | str | мнемоника операции |
| `operand_raw` | str | поле операнда как в исходнике |
| `base_symbol` | str/null | база выражения |
| `offset_value` | int/null | числовое смещение |
| `offset_radix` | str | `octal`/`decimal`/`none` |
| `absolute` | int/null | адрес 0..0177777 |
| `target_label` | str/null | имя метки из индекса |
| `scope` | str | `local`/`interzone`/`external` |
| `target_zone` | str/null | зона цели |
| `status` | str | `Ф`/`Г`/`Н` |

`absolute` отсутствует для 48-битных кавычных слов и
отрицательных смещений: они не являются адресами.

## 4. ПРАВИЛА РАДИКСА (ФАКТ)

Проверено в `analysis/OPERAND-CATALOG.md §4` и
`analysis/OPERAND-FORMS-INVENTORY.md §3`:

1. Голое число в выражении `.be` ДЕСЯТИЧНОЕ:
   `64`, `64-6` = 58, `64+16` = 80.
2. Кавычное значение ЭКВ ВОСЬМЕРИЧНОЕ: `'76267'` =
   0o76267.
3. `D00100+40` = 0100₈ + 40₁₀ = 0150₈ (104₁₀).
   Подтверждено байтом `dis-forced/Z0137.asm:381,265`.
4. `-З` вычитает базу наложения без численной оценки;
   в записи сохраняется маркер `D00003-З`.
5. Внешний адрес = страница × 02000₈ + смещение:
   `37*02000+1234`. Страница восьмеричная, смещение
   десятичное (правило 1).

Извлекаемые формы: `Dnnnnn`, `Annnn`, `Innnn`,
`Gnnnnn`, `Xnnnnn`, кавычные `'nnnn'`, голые числа,
`+N`/`-N`, `-З`, `name.NN`, `страница×02000+смещение`.
Регистры `(Мn)`, `(М1,1)` снимаются, но не несут адреса.

## 5. КЛАССИФИКАЦИЯ ОБЛАСТИ

1. `target_label` ищется в индексе по адресу, имени
   или паре (зона, смещение).
2. `target_zone` берётся из метки, иначе из окна базы
   `[база, база+01777₈]` по `ZONE-BASE-MAP.md §4`.
3. Совпадение со зоной файла даёт `local`.
4. Другая зона B или B2 даёт `interzone`.
5. Нет зоны в карте даёт `external`, статус `Ф`/`Г`/`Н`.

Статус метки приводится: ФАКТ/ПОДТВЕРЖДЕНО → Ф,
ГИПОТЕЗА → Г, НЕ ИЗВЕСТНО → Н. Для внешней связи с
фактом статус понижается до Г без прямого измерения.

## 6. ПРОВЕРКА `--check`

Проверяются инварианты: восьмеричная форма кавычных и
`X`-меток, десятичная форма голых чисел, диапазон
`0..0177777`, отсутствие `target_label` без `absolute`,
не менее 1000 разрешённых записей на корпусе.
На текущем корпусе: 0 нарушений, код выхода 0.

## 9. ГИПОТЕЗЫ И НЕИЗВЕСТНОЕ

- [ФАКТ] Правила радикса 1-5 и базы карты зон.
- [ФАКТ] Инструмент не изменяет входные файлы;
  проверено сравнением mtime и размера в тесте 44.
- [ГИПОТЕЗА] Приписывание адреса маленьких ЭКВ-литералов
  зоне 0147 (окно 00000-01777) по одной карте баз.
  Метка индекса уточняет выбор, но без неё возможна
  ложная классификация `interzone`.
- [ГИПОТЕЗА] Снижение статуса внешней связи с Ф до Г
  без прямого динамического входа.
- [НЕ ИЗВЕСТНО] Физическая база зон 0137, 0140-0146,
  B2: в карте стоит `-`. Поэтому локальные адреса этих
  зон не привязываются к окну без метки из индекса.
- [НЕ ИЗВЕСТНО] Число истинных процедурных меток без
  индекса параллельного инструмента: 776 совпадений на
  синтетическом индексе не являются оценкой полноты.
