# Именованные переменные транслятора БЕМШ — ГИПОТЕЗА

Дата: 19.11.2026. Файл: `sym/MBE.named.tab` (76 записей).

**ВНИМАНИЕ.** Это таблица *аннотации*, а не ground truth.
Все 76 имён — **ГИПОТЕЗЫ**, выведенные из частоты обращений
и контекста дизассемблирования. Ни одно имя не подтверждено
исходником транслятора (его нет). Таблица не меняет ни одного
байта эталонных образов и не заменяет `sym/MBE.tab`.

## 1. Источник адресов

Разбирались только `dis/MBE-*.asm` и `dis/MBE2-*.asm`
(дизассембль `-a0 -e0`, 0-based координата `disbesm6`).
Извлекались операнды команд: `'NNN'(Мn)`, `NNN(Мn)`,
метки `D#####` / `A#####` и блоки `пам <N>`.

По `docs/ANCHORS.md` логические адреса листингов `mbe60_*`
(**тест ДКС**, а не транслятор) физическими якорями не являются:
0 совпадений характерных слов со всеми зонами. Поэтому символы
`*МЕТ*` / `*EXECUTE` в таблицу **не переносились**.

Адреса вида `02000`, `04000`, `06000`, `010000`, `012000`,
`014000` имеют шаг ровно `02000₈` = 1024 слова. Гипотеза:
шесть рабочих областей/таблиц по 1K слов в памяти задачи.
**Не отождествлять эти числа с номерами зон диска** без
доказательства (загрузочная база транслятора неизвестна).

## 3. Правила именования

| Признак | Имя | Основание |
|---|---|---|
| уиа/слиа `<адр>`(Мn) | TAB0..TAB5, PTR… | загрузка базы в индекс |
| счи Мn после уиа | CNT0..CNT6 | счётчик/инкремент |
| зп `<адр>` | ERRCELL*, OUTBUF | ячейка-приёмник |
| сч `<адр>` | LIMIT* | граница/лимит |
| пв `<адр>`(М15) | SUB* | вход процедуры, VJM |
| по/пе `<адр>` | ERRJMP, ERREXIT | общий выход |
| сда 64+N | — | константа, не имя |
| конд п'ГОСТ' | ERRCELL* | текст `ОШ.СПР.НА БЕМШ1` |
| D##### | CNT*, FLAG* | метка данных зоны |
| пам N>=16 | ZEROBUF, OUTBUF | буфер/заполнение |

Ключевые контексты:

* Зона 0147, адреса 12–37: цикл
  `уиа '<база>'(М16); счи М16; сда 64-20; зп D006xx;
  слц D006xx; зп D006xx` — шесть баз с шагом 02000₈
  и шесть счётчиков. Отсюда `TAB0..TAB5`, `CNT0..CNT6`.
* Зона 0173, адрес 01522 и далее: повторяется пара
  `рег '<код ошибки>'; зп '4154'` / `зп '4231'`, а рядом
  текст `ОШ.СПР.НА БЕМШ1` (docs/TEXT-CONSTANTS.md §5,
  зона 0173.0655). Отсюда `ERRCELL1/2`,
  `ERRCELL3..5`, `ERRPTR0..4`.
* Зона 0157: 12 раз `по/пе '76027'` подряд → общий
  выход/обработчик `ERREXIT`.
* Зоны 0146/0160/…: `по '66666'(М15)` → возврат
  через M15 (`RETM15`), по шаблону `CALL → ВЖМ + ПБ (М15)`.
* Зона 0137, адреса 0060–0121: 7-битный текст мнемоник
  `ЗП СЧ СЛ ВЧ … УИА ПО ПЕ ПБ ПВ ЦИКЛ` → `MNEMTAB`.
  Таблица в KOI-7 подтверждена docs/TEXT-CONSTANTS.md §6.1
  (0137.0060–0120); имя ячейки — гипотеза.

## 5. Демонстрация

```
disbesm6 -a0 -e0 -nsym/MBE.named.tab \
  gold/MBE-Z0137-L1.bin > /tmp/.private/azizz/named-demo.asm
```

Выход: `exit=0`, stderr пуст. Фрагмент
`/tmp/.private/azizz/named-demo.asm`:

```
    1 00 000 0000 		зп	MBEENTRY
      00 100 0000 		зп	SYSCALL
      00 000 0003 		зп	INITCELL
```

Было (в `dis/MBE-Z0137-L1.asm`):

```
      00 100 0000 		зп	'70000'
      00 000 0003 		зп	D00003
    1 00 000 0000 		зп	START
```

Три строки, где числовой адрес стал именем:

1. `'70000'` → `SYSCALL` (ячейка приёма в зоне 0137);
2. `D00003` (= адрес 3) → `INITCELL`;
3. адрес 0 (авто-метка `START`) → `MBEENTRY`.

Зона 0137 с `-a0 -e0` содержит всего 5 слов кода
(далее `пб (М3)` обрывает трассировку), поэтому других
подстановок в ней нет. По всем 65 зонам переименовано
9112 строк аннотации (максимум 2048 в зоне 0175 —
нулевая зона, где все `зп START` стали `зп MBEENTRY`).
Ни один байт образа при этом не изменился.

## 6. Неопределённости

1. Все имена — ГИПОТЕЗА. Исходного текста транслятора на
   диске нет; подтвердить роль ячейки можно только трассой
   на эмуляторе с Known good input (задача следующей фазы).
2. Имена `SUB*` даны по шаблону `пв <адр>(М15)`, а не по
   тексту: роль процедуры не установлена.
3. `рег '<число>'` и `Э50…Э77` — немедленные константы.
   `disbesm6` (`praddr`, `offset_as_number`) подавляет для
   них подстановку символов: `CONST3554` в листинге не
   появится, оставлен для полноты.
4. Окно `fuzz=64` даёт ложные `TAB3+1`, `TAB0-1` в зоне
   0147 — это артефакт печати, не реальные ссылки.
5. Имя для адреса 0 убирает маркер `next insn used as data`
   и добавляет строку `ноп` в начале зоны 0137.
6. Метки `D#####` zone-local: имя `CNT4` (адрес 00632)
   подставляется во всех зонах, где встречается адрес 00632.
   Это аннотация, не утверждение о глобальности ячейки.
7. Таблица построена для B (`ВЕР.06/78`, зоны 0137–0177).
   B2 (`ВАР.12/77`) имеет сдвиг `+0400₈`; отдельная таблица
   не строилась, но совпадающие адреса подставляются и там.
