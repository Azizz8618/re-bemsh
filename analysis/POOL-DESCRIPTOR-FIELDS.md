## 0. Результат кратко

[ФАКТ] Дескриптор строки это 48-битное слово, которое
читается как ЧЕТЫРЕ 12-битных поля (по 4 восьм. цифры):

    [ 2010 | N | 0005 | 200K ](8)

N - номер исходной строки (восьм.).
K - число 48-битных слов в записи этой строки.

[ФАКТ] Поле 0005 постоянно во всех опытах. Поле 200K
меняется как 2002/2003/2004/2005 и равно 0o2000 плюс
число слов записи. Поле 2010 получается из базы 2000
через OR с битом 0o0010000000000000.

## 1. Статика: разбор 48-битного слова

[ФАКТ] Значение из трассы P2:
`2010000100052003`(8) = 0x408001005403.

Байты (старший первый), восьм. / hex:
    100 200 001 000 124 003 / 40 80 01 00 54 03

Полукоманды (24 бита каждая) по dispak/optab.c:
    LHS 0o20100001: IR=2 CODE=01 ADDR=00001
    RHS 0o052003:   IR=0 CODE=00 ADDR=52003

[ФАКТ] Разбор на полукоманды НЕ даёт осмысленных мнемоник.
CODE=01 это stx, CODE=00 это atx, но адреса 00001 и
052003 не несут смысла адреса. Аналогично разбору префиксов
в GS-CONSTANTS.md §1, где 002... даёт сбр+зп. Поля следует
читать как структуру данных, а не как команду.

[ФАКТ] Структура из четырёх 12-битных полей однозначна:

    биты 47..36 = 2010   флаг/тип
    биты 35..24 = N      номер строки
    биты 23..12 = 0005   константа шаблона
    биты 11..0  = 200K   база + число слов

## 3. Откуда берутся поля (трасса PF)

[ФАКТ] Шаблон строится в ячейке 076505 подпрограммой
01640-01662 зоны 0154. Исходное слово 2000000300000002.
Команда 01661: aox 1762 OR-ит константу ячейки 01762:

    01762 = 0000000000052000

Результат: 2000000300052002. Отсюда поле 0005 и
старшая часть поля 200K суть части ФИКСИРОВАННОЙ маски.
Младшая цифра K вычисляется из разности указателей
(01642-01646, ячейки 01751/01752): 06402 AND 0o1777.

[ФАКТ] Флаг 2010 ставится позже, писательской подпрограммой
04747/05130/04502/05237/03501:

    aox 6126 (=0010000000000000)

[ФАКТ] Запись в пул идёт одной командой зоны 0156:

    06057: xta 6402
    06057: aax 6165    маска 0o1777
    06060: ati 16      r[16] = смещение
    06060: xta 6404    дескриптор
    06061: atx 72000(16)

## 4. Верхняя граница пула

[ФАКТ] Индекс r[16] это младшие 11 бит ячейки 06402
(маска 0o1777). Смещение меняется в 0..0o1777, то есть
пул занимает одну страницу 072000-073777₈ (1024 слова).

[ФАКТ] Перед записью идёт проверка перехода страницы:

    06046: xta 6402
    06046: atx 6426
    06047: aex 6424    acc -= база 0o1200000
    06047: aax 6272    acc &= 0o7776000
    06050: uza 6057    если 0, писать сразу

Маска 0o7776000 = биты 10..20. Она ненулева, когда
смещение достигло 0o2000 = 1024 слова. Тогда исполняются
06051-06056 перед записью. Это проверка границы страницы.

[ФАКТ] Наблюдённый максимум во всех пяти трассах -
r[16] = 0o31, последняя запись 072031, четырёхсловная
запись кончается на 072034₈. До границы 073777 далеко.
Переполнения и захода в 074000+ в опытах НЕТ.

[ФАКТ] Выше страницы пула, по 074000₈, лежит таблица
префиксов текстовых ячеек 247... (GS-CONSTANTS.md §3.1).
Пересечения с пулом в трассах не наблюдалось.

## 5. ФАКТ / ГИПОТЕЗА / НЕ ИЗВЕСТНО

ФАКТ:
  дескриптор = 4 поля [2010|N|0005|200K] в восьм.;
  N - номер исходной строки, K - число слов записи;
  K совпадает с шагом указателя r[16];
  поле 0005 и префикс 2000 идут из маски 01762;
  флаг 2010 есть OR с 0010000000000000;
  запись идёт 06061 atx 72000(16);
  указатель - 11 бит, пул = страница 072000-073777₈;
  проверка границы стоит в 06047-06050;
  максимум опытов - 072034₈, переполнения нет.

ГИПОТЕЗА:
  2010 против 2000 различает строки внутри макроса и
    строки после MEND (в дампе 72023/72026 база 2000);
  0005 это код типа "исходная текстовая строка",
    по аналогии с тегами 002 (макрос) и 247 (текст);
  0o2000 в полях связан с базой счётчика 06445;

НЕ ИЗВЕСТНО:
  точный смысл константы 0005 и префикса 2000;
  что делает обработчик 06051-06056 при переходе
    страницы (возврат на 072000 или новая страница);
  причина, по которой флаг 2010 ставится не для всех
    дескрипторов, видимых в дампе;
  кто читает дескрипторы при развёртке макроса;
  поведение пула при реальном заполнении 1024 слов.
