# Нормализация внешних символов: корень и метод

Дата: 24.11.2026. Write set: только этот файл.
Черновик и опыты: /var/tmp/ext-normalize/.
Ни один .be, образ или gold не менялся. Коммитов и push НЕТ.
Все адреса восьмеричные, степень ↑.

## 1. ВЕРДИКТ

[ФАКТ] 205 строк НЕТ МДЛ вызваны НЕ макросом ЕВНЕШ,
НЕ ошибкой кодировки имён и НЕ техническими ЭКВ.
Имена в .be объявлениях корректны.

[ФАКТ] Причина: сценарий tools/v78_link_verify.py кладёт
объектные модули в ПЕРСО с шагом в одну зону
(SRC_BASE + i, строка 183). Каждый объект занимает
ДВЕ зоны. Вторая зона содержит таблицу внешних имён.
Следующий модуль перезаписывает её своей первой зоной.
Линкер читает вместо имён мусор, чаще всего забел
AA/55, отсюда JJJJJJ.555555.

[ФАКТ] Лечение: шаг две зоны. Проверено: при шаге 2 и
при шаге 4 число НЕТ МДЛ равно 0, связано 33 модуля.
Правки .be не нужны и вредны для побайтовой сверки.

## 2. КАК ЧИТАТЬ МУСОРНЫЕ ИМЕНА

Линкер печатает байты памяти через таблицу знаков.
Три шаблона объясняют почти все строки лога:

  байты AA AA AA AA AA AA  -> JJJJJJ
  байты 55 55 55 55 55 55  -> 555555
  байты 00 00 00 00 00 00  -> ‾‾‾‾‾‾

[ФАКТ] Слово `aaaaaaaaaaaa` даёт JJJJJJ, слово
`555555555555` даёт 555555. Слово из нулей даёт ‾‾‾‾‾‾.
Смешанные строки вроде ‾‾‾‾D‾.‾‾‾‾‾‾ это те же байты
кода соседнего модуля, прочитанные как имя.

## 5. ПРЕДЛОЖЕНИЕ ПО НОРМАЛИЗАЦИИ

Выбран путь (b): правка генератора заданий.
Путь (a), правка .be, отвергнут: объявления уже
корректны, а любая правка меняет объект и ломает
побайтовую сверку с gold.

Точная правка, tools/v78_link_verify.py, строка 183:

    # Every object occupies two zones; a one-zone
    # stride overwrites the previous name table.
    src = SRC_BASE + i * 2

  БЫЛО: src = SRC_BASE + i

Других правок не нужно. link_job() (строки 119-130)
берёт зоны из manifest.json, поэтому подхватит новые
значения src автоматически. Команда ЗОНМОД в
compile_job() (строка 112) оставляет `0001`:
транслятор всё равно пишет две зоны, проверено в
листинге.

Альтернатива, если нужна привязка к фактической длине:
читать из листинга `ЗАПИCAH B ЗOHЫ C x ПO y` и
использовать шаг y-x+1. Для всех 33 зон он равен 2,
поэтому простой шаг 2 эквивалентен и проверен.
