## 2. ИЗМЕРЕННЫЕ ФАКТЫ ЭТОГО ПРОГОНА

Все числа получены одним потоковым проходом по трассе.

| Что | Значение | Пример строки |
|---|---:|---|
| строк трассы | 5141914 | 1 |
| исполненных команд | 4554097 | 1 |
| строк store | 587817 | 5 |
| строк DD pc= | 0 | нет |
| страница 014 (12dec) | 12680 команд | 271258 |
| vjm на 01322 | 31 | 1035549 |
| PC 64077, atx | 22296 | 900 |
| из них с операндом 076xxx-077xxx | 22269 | 900 |
| store в 070000-071777 | 2573 | 1035626 |

Страница 014 исполняется, но mct.page_info(12)
возвращает zones=None. Ни одна карта баз не относит
030000-031777 к загруженной зоне. Это совпадает с
MODULE-CALLS-DYN §3 и PROC-LABEL-SCOPE-DYN §2.

Переход vjm 1322(16) находит цель 01322 по литералу,
регистр 16 есть LINK. Примеры: строки 1035549,
1454321, 4850537. Все 31 событий дают одну цель.

Константы статического кода: 070000 (SYSCALL,
Z0137 §3.1), '70707' (выпр, analysis/xref.txt:8),
'36436' (мода, analysis/xref.txt:520). В трассе эти
цифры встречаются как данные в словах монитора:
70707 в строках 45013-45021, 36436 в 140686-140690.
Они НЕ являются PC зоны 0137. Store по адресам
070000-071777 идут на страницу 034 (зона 0150),
а не в зону 0137.

PC 64077 это цикл копирования мониторной страницы 032.
Команды atx несут адреса 076xxx-077xxx в операнде,
а печатаемые адреса store лежат в нижнем ОП
(00400, 02747, 041327) из-за 15-битного переноса.
Поэтому называть их "записью в верхнее ОП" неверно.
Принадлежность цикла какой-либо зоне не доказана.

Граница после загрузки: строка 1454316 даёт
02000: xta 6065, вход в 0154 по RESIDENT-ZONES §3.
Строка 1948452 даёт 02000: ntr 3, поздняя фаза 0170.
Само имя зоны в трассе отсутствует, DD pc= нет.
Смена 0154 ↑ 0170 измерена в других dispak-прогонах
с точками останова, здесь она только гипотеза.

## 3. ЧЕСТНЫЕ ОТРИЦАНИЯ

* У 0137 нет измеренной физической базы. PC сам по
  себе зону не называет: страница 01 содержит
  0154/0170/0172, страница 014 не имеет зоны вовсе.
* Строка 1 трассы, 00010: ntr 7, встречается ровно
  один раз. Это страница 00, зона 0147, НЕ 0137.
  Использовать её как сигнал инициализации 0137
  нельзя. Это прямая проверка заданного допущения.
* Команд по PC 00000-00004 нет. Нет и команд на
  странице 010 (010000-011777, условие трансляции
  из RESIDENT-ZONES §5.2). База 0137 неизвестна,
  поэтому это не опровержение загрузки.
* Набор из 32 страниц x 12 адресов (384 пробы,
  RESIDENT-ZONES §4.1) не сработал в прогонах со
  снимками ОП. Это НЕ свойство данной трассы: в ней
  есть команды с PC 02000, то есть со смещением 0.
  Утверждать "в трассе probes не сработали" поэтому
  нельзя. Тест проверяет только арифметику решётки.
* Отсутствие исполненного кода 0137 в этом прогоне
  не означает, что загрузчик никогда не работает.
  Вывод ограничен одним заданием и одной трассой.
* Тесты НЕ доказывают, что 64077 грузит именно 0137.
  Это наблюдаемый мониторный цикл, не атрибуция зоны.

## 4. ЧТО ОСТАЁТСЯ НЕ ИЗВЕСТНО

1. Момент загрузки зон 0137-0143.
2. Физическая база 0137 (10000 это условие
   трансляции, не измеренный адрес).
3. Правки адресных полей при загрузке (relocation).
4. Какая зона реально лежит на странице 014.
5. Исполняемый ли код блок 0137.0040-0117
   (Z0137 §7, гипотеза).
6. Связь цикла 64077 с конкретной загружаемой зоной.
7. Точный момент смены оверлея 0154 ↑ 0170
   внутри этого прогона.
