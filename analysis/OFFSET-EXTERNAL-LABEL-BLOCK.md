# Проверка: можно ли заменить внешний литерал на явную метку без изменения байтов

Дата: 24.11.2026. Опыт на копии репозитория
/var/tmp/ext-label-exp/, эталоны не менялись.

## 1. Постановка

В MBE-Z0137.be есть технический ЭКВ `X76662 = '76662'`
(строка 460), используемый как `ПБ X76662(М7)` (строка 2002).
Комментарий указывает: адрес за зоной, зона 0157, страница 37.
Хочется заменить его на явную внешнюю метку.

## 2. Опыт 1: ВНЕШН вместо ЭКВ

Было:
```
X76662 ЭКВ '76662' ,зона 0157 (стр.37); CALL-OUT §6
```
Стало:
```
X76662 ВНЕШН Z0157.Z0157A ,зона 0157 (стр.37); CALL-OUT §6
```

`bash tools/rebuild-zone.sh 0137` на копии дал:

```
Первое различие: байт 4369 → зона 0000, слово 1330
  Эталон:   7db209000080
  Проверка: 800009000080
Различия:
  0000.1330:  256 → 241
  0000.1330:  257 → 310
  0000.1330:  406 → 00
```

То есть **ВНЕШН добавляет бит релокации и меняет байты**.
Это совпадает с прежним выводом: `LABEL-MODE-EXPERIMENT.md`,
`REAL-LABELS-0137.md`, где ВНЕШН был отклонён для 0137.

## 3. Опыт 2: объявить внешнюю метку, не используя её

Добавлена строка `X76662E ВНЕШН Z0157.Z0157A` без изменения
операнда. Результат: `ЧИCЛO OШИБOK=0001`, транслятор
отверг объявление.

## 4. Вывод

При инварианте «0 байтовых отличий от gold» **нельзя**
сделать внешнюю метку семантически явной через `ВНЕШН`:
директива меняет код. Это конфликт двух требований:
- пользователь просит «сделать внешние и входные метки
  в явном виде, ликвидировать литералы, указывающие на
  процедуры»;
- ранее установленный инвариант требует байтовой
  идентичности образа.

Возможные пути без нарушения инварианта:
1. Переименовать технические ЭКВ в осмысленные имена,
   несущие имя целевой процедуры (ЭКВ не меняет байты).
2. Завести каталог «литерал → процедурная метка → модуль»
   и аннотировать `.be` комментариями.
3. Для меток ВНУТРИ модуля использовать уже доказанную
   форму `A#####-З±N`, она байты не меняет (2197 меток
   восстановлены).

Для принятия решения между (1)+(2) и изменением инварианта
нужна позиция пользователя.
