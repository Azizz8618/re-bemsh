# Формула GOST-8 → байт имени в ГС VALUE

Дата: 22.11.2026. Write set: только настоящий файл.
Образы, листинги и существующие файлы не изменялись.
Коммитов и push не делалось.

## 0. Результат

[ФАКТ] Формула найдена. Это НЕ арифметика и не поворот
битов, а табличная подстановка из 64 байт в зоне
0147 макроредактора:

    byte = TAB[GOST8 & 0x3f]

TAB лежит по адресу зона 0147, слово 0o0561
(файл `gold/MBE-Z0147-L1.bin`, сдвиг 2214).
Код макроредактора
в `dis/MBE-Z0147-L1.asm:759-612` читает её командой
`сч A00557+2(М14)` при `счмр 64` (индекс по модулю 64).

[ФАКТ] Все 16 измеренных пар буква → байт совпадают с TAB
побайтово, 16/16. Гипотезы `or 0x80`, `+ 0x80`, `xor 0x80`,
поворот и affine опровергнуты (раздел 5).

## 3. Где живёт формула

[ФАКТ] В зоне 0147 (загрузчик/АРАП по
`docs/TEXT-CONSTANTS.md` §4, слово 0147.1315 =
штамп "ИПМ МАКРО-БЕМШ") лежит 64-байтовая таблица:

  индекс  байты (hex)
  00-07   50 51 52 53 54 55 56 57
  08-0f   58 59 4b 4d 4f 4c 4e 40
  10-17   71 a0 48 49 6f 5d 5b bb
  18-1f   bd 4a 47 47 6d 5c 5e 5a
  20-27   a1 c2 a2 c7 c4 a5 d6 da
  28-2f   c9 ca ab cc ad a8 af d0
  30-37   b0 a3 b4 b9 c6 b8 c3 de
  38-3f   db dd d9 d8 dc c0 d1 a4

[ФАКТ] Точнее: таблица начинается со слова 0o0561, байт 0,
и занимает 64 байта (слова 0o0561..0o0573). Индекс =
код GOST (0..63). Не все 64 Value уникальны: 0x47
встречается дважды (индексы 0x1a и 0x1b), поэтому
обратная таблица неоднозначна. Прямая подстановка
однозначна.

[ФАКТ] Код-потребитель в `dis/MBE-Z0147-L1.asm`:

  610: сч D00711 / уи М14   вычисление индекса
  611: счмр 64               индекс по модулю 64
  612: сч A00557+2(М14)      чтение TAB[индекс]

Адрес `A00557+2` в восьмеричной нотации равен 0o00561.

## 4. Формула (python)

    # GOST-8 (0x20..0x3e) -> байт ГС VALUE
    TAB = bytes([
        0x50,0x51,0x52,0x53,0x54,0x55,0x56,0x57,
        0x58,0x59,0x4b,0x4d,0x4f,0x4c,0x4e,0x40,
        0x71,0xa0,0x48,0x49,0x6f,0x5d,0x5b,0xbb,
        0xbd,0x4a,0x47,0x47,0x6d,0x5c,0x5e,0x5a,
        0xa1,0xc2,0xa2,0xc7,0xc4,0xa5,0xd6,0xda,
        0xc9,0xca,0xab,0xcc,0xad,0xa8,0xaf,0xd0,
        0xb0,0xa3,0xb4,0xb9,0xc6,0xb8,0xc3,0xde,
        0xdb,0xdd,0xd9,0xd8,0xdc,0xc0,0xd1,0xa4,
    ])

    def gost8_to_value_byte(gost8):
        return TAB[gost8 & 0x3f]

    # проверка: gost8_to_value_byte(0x2f) == 0xd0 (П)

[ФАКТ] Индекс маскируется на 0x3f, старшие биты кода
игнорируются. Для букв это избыточно (коды уже 6-битные),
но совпадает с аппаратным `счмр 64`.

## 5. Опровергнутые гипотезы

Все проверены на 16 парах из раздела 1.

  гипотеза                   результат
  byte = gost | 0x80          совпало 3/16
  byte = gost + 0x80          совпало 3/16 (gost < 0x80)
  byte = gost xor 0x80        совпало 3/16 (gost < 0x80)
  byte = rot(gost,n) | 0x80   0/16 ни при одном n=0..7
  byte = rev6(gost) | 0x80    0/16
  byte = (a*gost+c) mod 256   0/16 ни при a,c
  6-битная перестановка      0/16 ни при одной перестановке

[ФАКТ] Причина расхождений: таблица не является
линейной функцией кода. Примеры:

  GOST 0x22 (В) → 0xa2 = 0x22 | 0x80   (совпало)
  GOST 0x23 (Г) → 0xc7 ≠ 0x23 | 0x80   ("> 0x80 + 0x44")
  GOST 0x2f (П) → 0xd0 ≠ 0x2f | 0x80   (доп. биты 0x50)

Именно эти "дополнительные биты" первого байта
(`GS-CELLS-DIRECT.md` §5) и есть результат
нелинейной подстановки TAB, а не поле длины или типа.

## 6. "Дополнительные биты" первого байта

[ФАКТ] `GS-WORD-FIELDS.md` §0 опроверг гипотезу о поле
длины/параметров в первом байте. Первый байт это первая
буква имени, закодированная той же TAB.

[ФАКТ] Разница между "обычным" `gost | 0x80` и TAB:
  для 6 букв (а в е м о р) TAB = gost | 0x80 или +1;
  для остальных TAB добавляет биты 0x40 и/или меняет
  младшие разряды.
Пример: П = 0x2f → 0xd0 (старший бит 1 + бит 6 = 1 +
младшие 0x50 вместо 0x2f).

[ГИПОТЕЗА] TAB это таблица перехода из GOST-10859 во
внутренний 8-битный код МАКРО-БЕМШ (аналог кодировки
"ASCII с подменой строчных латинских кириллицей").
Прямого доказательства происхождения таблицы нет.

## 8. ФАКТ / ГИПОТЕЗА / НЕ ИЗВЕСТНО (сводка)

ФАКТ:
  формула byte = TAB[GOST & 0x3f];
  TAB в зоне 0147, слово 0o0561, 64 байта;
  код читает её `сч A00557+2(М14)` при `счмр 64`;
  16/16 измеренных букв совпали;
  простые формулы or/+, xor, поворот, affine опровергнуты;
  предыдущая гипотеза о поле длины в первом байте ложна;
  регистр исходной буквы не влияет (unicode_to_gost).

ГИПОТЕЗА:
  TAB это переход в "внутренний" 8-битный код МБЕ;
  биты 0x40-0x5f в таблице кодируют строчные.

НЕ ИЗВЕСТНО:
  происхождение конкретных значений TAB;
  почему 0x47 дублируется (индексы 0x1a, 0x1b);
  судьба байт 7-8 длинного имени N8;
  смысл поля 2041 в теге (за пределами этой задачи).
