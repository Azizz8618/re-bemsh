Дата: 23.11.2026. WRITE-SET: только новый файл
`analysis/V78-TOKEN-BREAKPOINTS.md`. Коммитов, push и
правок существующих файлов НЕТ. Скретч:
`/var/tmp/v78-syntax/breakpoints/`.

Статусы: [ФАКТ] прочитано напрямую из трассы или
отладчика, [ГИПОТЕЗА] смысловая привязка,
[НЕ ИЗВЕСТНО] ответа нет. Адреса восьмеричные.
↑ вместо каретки. Тире не пишем. Ширина <=60 колонок.

## 0. ПРЕДУПРЕЖДЕНИЕ О ЗОНАХ

ВНИМАНИЕ. DD `z=` задаёт ЗОНУ ДИСКА, а не код зоны
0144. В инвентаре записи `0147.0637R` и `0152.0371R`
первое число есть номер дисковой зоны, а не адрес ОП.
Привязка к ОП идёт отдельно, по `MEMORY-MAP.md` §5:
зона 0147 → база 00000, зоны 0154/0170 → база 02000,
зона 0155 → база 04000. Не путать `z=` в DD с кодом.

## 1. МЕТОД И КОНТРОЛИ

[ФАКТ] Образы 2048, 2053, 2099, 2248 скопированы из
`/var/tmp/source-parser-exp` в скретч. `guard.sh`
отвергает `/usr/local/share/besm6` (exit 3).
md5 до и после сводки совпадают:
`4b94cc18...` (2048), `4c6abfc5...` (2053),
`90971c33...` (2099), `c11067b3...` (2248).
Прогон меняет образ 2248, поэтому перед КАЖДЫМ
запуском образы восстановлены из `pristine/`.
Финальный `md5.restored` равен `md5.before`.

[ФАКТ] Отладчик dispak (`-b -v`):
`b PC` ставит точку, `g` пуск, `v` даёт полный дамп
15 регистров, `PC-` дамп 8 слов. Точка останова
срабатывает только на ЛЕВОЙ половине слова.
`dispak -tt` печатает PC, мнемонику, 48-битное слово
по исполнительному адресу, аккумулятор и `r[reg]`.

[ФАКТ] `BESM6_CORE_ON_PC` в этом build не работает:
дампа нет даже на всеми подтверждённом PC 06061.
Поэтому для правых половин применён только `-tt`.

## 2. КОЛОДЫ С ГРАНИЦЕЙ ТОКЕНА

База взята из `S1.job.b6` (5 исходных строк).
Изменена ровно одна строка, остальные 30 байт в байт.

| Колода | Отличие от D0 | Строка |
|---|---|---|
| D0 | база | `ZLBL1 ZOPC1 ZOPR1 ; ZCMT1` |
| D1 | нет ведущего пробела | `МАСRО` вместо ` МАСRО` |
| D2 | `;` заменён на `,` | `ZLBL1 ZOPC1 ZOPR1 , ZCMT1` |
| D3 | нет пробела после `;` | `ZLBL1 ZOPC1 ZOPR1 ;ZCMT1` |

[ФАКТ] D1 семантически отличается: листинг даёт
`ОПЕРАЦИИ НЕТ` и `ТЕРМ НЕ ОПР`. Ведущая колонка в
06/78 есть поле метки, поэтому её удаление меняет
не границу, а смысл строки. D2 и D3 суть чистые
тесты границы разделителя.

## 5. ПРЯМОЙ ПОИСК БАЙТОВ ГРАНИЦЫ

[ФАКТ] Проверен КАЖДЫЙ 48-битный операнд и каждое
значение аккумулятора на всех 7 кандидатах в D0-D3.
Байты 0x40 (пробел), 0x5a (`:`), 0x4c (`,`),
0x5b (`;`), 0x4a (`*`) НЕ встретились ни разу.
Операнды суть маски (`001774...`), дескрипторы
(`20100001...`) и указатели (`7317...`).

[ФАКТ] При этом текст с разделителями в пуле ЕСТЬ.
Дамп 072000 (`S1.pool.out`) даёт:
```
 72014 TEXT 133 001 272 243 255 264 [; ...]
 72025 TEXT 112 253 257 250 245 303 [*КОНЕЦ]
```
0o133 = 0x5b (`;`), 0o112 = 0x4a (`*`).
То есть граница токена записана в пул, но ни один
из кандидатов её не держит в аккумуляторе.

## 6. ДВА НЕОБЪЯСНЁННЫХ СТАТХИТА И БУФЕР КАРТЫ

[ФАКТ] `0147.0637R сбр 072002(М3)` и
`0152.0371R сбр 007417` в `-tt` НЕ исполняются:
ни одного `0637:` или `0371:` в D0-D3 нет.
`b 637`, `b 371` дают 0 попаданий.
Правые половины точкой останова не ловятся,
поэтому сделан вывод только по `-tt`.

[ФАКТ] Карта `053436`: `b 53436` даёт 0 попаданий.
`BESM6_CORE_ON_PC=53436`, `=637`, `=371` дампа не
создают (проверено на рабочем PC 06061 тоже).
Карта есть данные, а не исполняемый код.

ведущего пробела меняет смысл строки, растёт число

исполняются чаще. Прямого чтения символа границы
на кандидатах нет.

ОПЕРАНД / КОММЕНТАРИЙ. Фаза 2C этого не установила.

ОТВЕРГНУТОЙ и этим прямым опытом.
