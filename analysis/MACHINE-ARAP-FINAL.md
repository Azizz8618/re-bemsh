## 2. ФАКТ: где лежат зоны 0151/0152 в ОП

[ФАКТ] `dispak/extra.c:3467`:
    addr = (uil.i_addr & 03700) << 4;
Для `uil=10/0/3700`: `03700 << 4 = 076000`.

[ФАКТ] DD-трасса (`/tmp/.private/azizz/
page6-zone/dd-trace2.err`):

    DD pc=01222L u=30 z=0151 RD
       uil=10/0/3600  -> база 074000
    DD pc=01223L u=30 z=0152 RD
       uil=10/0/3700  -> база 076000

[ФАКТ] Дамп свежего прогона (`dump76.out`,
точка `01735`) по `076000` побайтово совпал со
словом 0 `gold/MBE-Z0152-L1.bin`:

Тождество зоны 0152 и адресов `076xxx`
установлено.

## 4. ФАКТ: прямой переход найден

[ФАКТ] Переходы на `076000` (481 всего):

    1454294: 76557: uj  76000
    1481459: 04057: vjm 76000(16)   (75 раз)
    1490791: 77232: vjm 76000(16)   (270 раз)
    1869814: 77125: vjm 76000(16)   (последний)

[ФАКТ] Вызов из кода `04057` (страница 02) - это
обычный подпрограммный `vjm` с возвратом через
`r[16]=04057`. Тело на `076000` сохраняет регистры
в ячейки `06512-06516` (обменная страница):

    76000: atx 6520(12) -> 06513: store 0
    76002: atx 6512(12) -> 06512: store ...4057
    76004: atx 6515(12) -> 06515: store ...4060

[ФАКТ] Свежий прогон с `b 76000` останавливается
на `76000: 00 23 01211 wtc`. Переход подтверждён
независимо от полной трассы.

[ФАКТ] Первый переход (`76557: uj 76000`, строка
1454294) стоит непосредственно перед входом
редактора (`1454315: 01236: uj 2000`). Цепочка:

    01735: uj 76556
    76556: xta 76630 / atx 1174
    76557: uj 76000
    76000: wtc 1211 / uj 1237
    01230-01235: *70 1133-1141

То есть `076000` работает шлюзом в редактор.

[ФАКТ] Все 481 переход на `076000` лежат в
диапазоне строк `1454294-1869814`. Вход машины:
`1948451: 01314: uj 2000`. Переходов в АРАП

[ФАКТ] В `PASSES-ARAP-TRANSFER.md` §3 было
"второго/третьего входа нет" для REG-listing.
В задании B входов три:

    1454315: 01236: uj 2000  -> редактор
    1948451: 01314: uj 2000  -> машина

[ФАКТ] Третий вход (`01276`) не проход: по

АБСОЛЮТНАЯ"). К АРАП он отношения не имеет.

## 7. ГИПОТЕЗА

1. [ГИПОТЕЗА] "Три прохода" - статическая модель
   (`PASSES-STATIC-FLOW.md`). Фактически в B:
   редактор (`0154`) → машина (`0170`), плюс
   резидентная подсистема архива в старшей ОП
   (`074000-077777`), включающая зоны 0151,
   0152 и код `076xxx`. Она вызывается из
   редактора/настройки до входа машины.
2. [ГИПОТЕЗА] Зона 0152 совмещает роль кода
   (`076000` - шлюз, `076600+` - рабочий код) и
   пула диагностических текстов (`0152.0151+`).
   Парсер карт в page 6 (`014216-014236`) читает
   тексты, а вызов `vjm 76000(16)` запускает
   архивную обработку. Это и есть "активация
   АРАП картами", только до фазы машины.
3. [ГИПОТЕЗА] Штамп "АРАП ВАР.04/78" в строке 2
   листинга - метка входного потока, а не
   runtime-штамп прохода. Runtime-штампы есть
   только у редактора и машины.

## 8. НЕ ИЗВЕСТНО

1. Почему вызовы архива (`04057`, `77232`) идут
   до входа машины, если статическая схема
   ставит АРАП third после машины.
2. Что именно делает рабочий код `076600-077777`
   (13-14K исполнений): точная семантика не
   восстановлена.
3. Где находится dispatch control-карт (`06452`): в полной
   трассе `PC 06452` не встретился ни разу.
4. Почему `0151` (каталог) молчит в задании B,
   хотя загружена в ОП.
5. Привязка `vjm 76000(16)` из `77232` к
   конкретной карте (ЧТКОМП/БТМАЛФ/ЗОНМОД).
