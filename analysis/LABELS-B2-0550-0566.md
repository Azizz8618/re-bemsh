# Восстановление меток dis-forced в B2 (0550-0566)

Дата: 23.11.2026.
Write-set: 11 файлов `bemsh/MBE2-Z<зона>.be` и этот отчёт.
Коммитов и пушей нет.
Резерв: `*.bak.20261123_230811` рядом с .be.

[Д] = факт из файла, листинга или rebuild; [Г] = наш вывод.

## 1. Задача и правило оператора

Каждая метка `A#####`/`D#####` из `dis-forced/Z<зона>.asm`
обязана стоять в первом поле соответствующего `.be`.
Зоны: 0550, 0551, 0552, 0553, 0554, 0555, 0557,
0561, 0562, 0565, 0566. Всего 11 зон.

## 2. Методика [Д]

1. Из dis-forced извлечены пары (адрес слова, метка).
   Колонка 1 = адрес+полуслова, колонка 2 = метка.
   Адрес восьмеричный; формат `NNNN:MM` распознан тоже.
2. Для каждой зоны выполнен rebuild-zone.sh MBE2,
   из листинга взята колонка N ИСХ (поз. 55-58).
3. Слово dis с адресом N (СТАРТ '0') соответствует
   слову .be по адресу 010000+N (СТАРТ '10000').
   N ИСХ переведён в физическую строку .be счётом
   некомментарных строк. Получена точная карта
   слово -> строка .be без догадок об индексах.
4. Метка вставлена в первое поле (8 пробелов заменены).
   Байты и мнемоники не тронуты.
5. После каждой зоны rebuilding давал RESULT: PASS
   и `✓ Файлы идентичны (2000 слов)`.

## 3. Почему не старый инструмент [Д]

`tools/restore_dis_labels.py` ставит метку на индекс
`N-1`, что верно только для `.be` с `СТАРТ 1`.
Здесь у всех зон `СТАРТ '10000'`, поэтому верен индекс N.
Проверка на 0551 показала: 8 меток, вставленных ранее
группой 2, стояли на одно слово раньше (например,
D01507 на слове 1506 вместо 1507). Они сдвинуты на
правильные слова. Rebuild остался побайтовым.

## 4. Техника ссылок [Д]

Согласно `analysis/Z0137-LABEL-TECHNIQUE.md`:

- метка первого поля принимается только с вычитанием
  базы: `ИМЯ-З` или `ИМЯ-З±N`;
- прямая ссылка без `-З` даёт 1 отличие;
- `ВНЕШН` и `ВХОДН` дают релокацию и ломают байты;
- голые числа в выражениях ДЕСЯТИЧНЫЕ, кавычные
  значения ЭКВ ВОСЬМЕРИЧНЫЕ.

В этих 11 зонах новые имена меток не использовались
ни в одном операнде .be (проверено по всем файлам),
поэтому массовой перекодировки ссылок не потребовалось:
достаточно самого определения метки, байты не меняются.

## 5. Конфликт и его решение [Д]

В 0551 на слове 1172 стояла метка `PTR173` с тремя
ссылками вида `PTR173-З+1`. dis-forced требует там
`D01172`. Проведено переименование `PTR173` ->
`D01172` в определении и во всех 3 ссылках.
Смещение `+1` сохранено: `D01172-З+1` даёт то же слово.
Rebuild 0551: 0 отличий. Иных конфликтов нет:
совпадений имён меток с ЭКВ в 11 зонах не найдено.
