# ЧТО ДЕЛАЕТ ФЛАГ D01167 ОТРИЦАТЕЛЬНЫМ ИЛИ НЕНУЛЕВЫМ (B2)

Дата: 22.11.2026.
Write set: только analysis/D01167-NEGATIVE.md.
Коммитов и push нет. Эталонные образы не менялись.
Адреса восьмеричные. Разделитель карт в тексте: ↑.
Статусы: [ФАКТ], [ГИПОТЕЗА], [НЕ ИЗВЕСТНО].
Моноширинный шрифт, ширина строки <=60 колонок, степень ↑.

## 0. КРАТКИЙ ОТВЕТ

[ФАКТ] Ни один writer в dispak НЕ может сделать D01167
  отрицательным:
  - статический writer 0551.1674R кончает `asn 136`, это
    логический сдвиг вправо на 42 разряда; он обнуляет
    старшую половину слова, результат всегда >= 0;
  - мониторный writer 0401.1120 копирует D01165, который
    получается из `счи`; `счи` тоже обнуляет старшую
    половину acc (cu.c:610), результат тоже >= 0;
  - начальное значение ячейки 01167 в образе равно нулю.

[ФАКТ] Принудительный вызов writer через таблицу
  диспетчеризации даёт D01167 = +420070₈. Это НЕНУЛЕВОЕ, но
  ПОЛОЖИТЕЛЬНОЕ значение. Ветка 0565/0566 не выбирается.

[ФАКТ] Принудительная установка отрицательного D01167
  в отладчике подтверждает причину: загружаются 0565/0566
  (штамп «МАКРОКОМПИЛЯТОР ОТ 12.2.76», DD z=1765/1766).

[НЕ ИЗВЕСТНО] Ни в одной из 145 доступных колод нет карты,
  которая естественно выбирает handler 75673 (D01167).
  Каким реальным заданием или дескриптором он выбирается,
  в доступных материалах не установлено.

## 1. СТАТИКА: ПОЛНЫЙ РАЗБОР WRITER

### 1.1. Контекст 0551.1660-1773

[ФАКТ] `зп D01167` не отдельная подпрограмма, а звено
  большого блока 0551.1660-1773, который копирует набор
  системных флагов D011xx в страницу 00. Фрагмент
  (dis-forced/Z0551.asm:1875-1888):

    1670 пб '75653'       вызов общего блока
    1671 счи / зп D01112  флаг из ввода
    1672 пб '75653'
    1673 сч '76476'       M[076476] в ACC
         сбр '76357'      PACK по маске M[076357]
    1674 сда 64+30        сдвиг (в dispak: asn 136)
         зп D01167        <-- ЗАПИСЬ ФЛАГА
    1675 пб '75653'
    1676 сч '76476'       тот же расчёт
         сбр '76357'
    1677 сда 64+30
         зп D01101        <-- соседний флаг

[ФАКТ] Слова 1703-1715 повторяют ту же пару с масками
  076354/076357 и пишут D01107, D01115, D01110, D01120.
  Слово 1757 пишет D01165 из `счи`, слово 1764 пишет
  D01171 из M[076476]. Это «сброс состояния» дескриптора.

### 1.2. Что такое 076476 и 076357

[ФАКТ] 076357 это константа-маска PACK:

    076357 = 0160340701603407₈
    биты маски: 0-2, 8-10, 16-18, 24-26, 32-34, 40-42
    всего 18 битов, по 3 в каждом из 6 байтов.

  PACK (besm6_pack, simh/BESM6/besm6_arith.c:474) сжимает
  эти 18 битов в младшие разряды результата. Старший бит
  результата берётся из бита 42 входного слова.

[ФАКТ] 076476 это ячейка верхней памяти, куда подпрограмма
  074326 сохраняет регистр R2
  (analysis/LOOP-76600-BRANCHES.md, разд. 1).
  В прогоне B2-2048-6600 в момент
  writer там лежало слово 2505112024053520₈. PACK дал
  4200700000000000₈, то есть слово с битом 47 = 1.

### 1.3. Ключевой факт: сдвиг УБИВАЕТ знак

[ФАКТ] В dispak opcode 036 (`сда`/asn) реализован функцией
  `asx()` (dispak/arith.c:532-583). Это ЧИСТО логический
  сдвиг: `acc.l >>= i`, при i >= 24 ставится `acc.l = 0`.
  Для `asn 136` счётчик enreg = 136₈ = 94₁₀, вычитаем 64₁₀,
  получаем сдвиг вправо на 42 разряда. Старшая половина
  acc обнуляется.

[ФАКТ] То же поведение в SIMH BESM-6: `besm6_shift(i)` при
  i > 0 делает `ACC >>= i` без знакового расширения
  (simh/BESM6/besm6_arith.c:525-539). Оба эмулятора дают
  неотрицательный результат.

[ФАКТ] Следствие: PACK может дать отрицательное слово
  (4200700000000000₈, бит 47 = 1), но `asn 136` превращает
  его в 0000000000420070₈. Знак теряется. Значит статический
  writer НЕ может поставить D01167 в отрицательное значение
  ни при каких входных данных.

[ФАКТ] Запись в 0547.1304 читает D01167 и ветвит `по A01213`
  при ACC >= 0. Положительное 420070₈ даёт тот же переход,
  что и ноль: грузится пара 0570/0571.

## 2. ТАБЛИЦА ДИСПЕТЧЕРИЗАЦИИ

### 2.1. Почему writer не исполняется

[ФАКТ] Блок 1660-1773 вызывается через computes-goto.
  В слове 1666 (PC 75666) стоит `wtc 1(14)` + `uj` с
  нулевым адресом.
  `wtc` (cu.c:729) берёт из M[R14+1] адрес в MODREG, после
  чего `uj` переходит по нему. В прогоне B2-2048-6600
  (B2-2048-6600.tt.err:25116) R14 = 77063, откуда берётся
  адрес 75676. Управление ПЕРЕПРЫГИВАЕТ слово 1674.

[ФАКТ] Поиск в таблице идёт циклом 074251-074253:
  `сч (М14)` / `нтж 77144` / `слиа 2(М14)` /
  `цикл 74251(М13)`. Ключ в M[77144], ищется в таблице
  пар ключ/адрес.

### 2.2. Содержимое таблицы 077020-077077

[ФАКТ] Дамп-table через отладчик dispak (брейкпоинт 75666,
  команды `77020 -`, `77030 -`, ...). Пары ключ (чётный
  адрес) → адрес (нечётный). Значимые записи:

    ключ 077020 -> 077021 = 75134
    ключ 077022 -> 077023 = 74602
    ключ 077024 -> 077025 = 74607
    ключ 077030 -> 077031 = 75714
    ключ 077032 -> 077033 = 75711  (D01110)
    ключ 077034 -> 077035 = 75671
    ключ 077036 -> 077037 = 75752
    ключ 077040 -> 077041 = 75754
    ключ 077042 -> 077043 = 75757
    ключ 077044 -> 077045 = 75667
    ключ 077046 -> 077047 = 75717
    ключ 077050 -> 077051 = 75722
    ключ 077052 -> 077053 = 75761
    ключ 077054 -> 077055 = 75764
    ключ 077056 -> 077057 = 76525
    ключ 077060 -> 077061 = 75703
    ключ 077062 -> 077063 = 75673  <-- D01167
    ключ 077064 -> 077065 = 75676  <-- D01101
    ключ 077066 -> 077067 = 75701

[ФАКТ] transition 75673 начинается со слов 1673/1674 и
  потому ведёт к `зп D01167`. transition 75676 ведёт к
  `зп D01101`. Обе записи присутствуют в таблице.

[ФАКТ] Во всех доступных -tt трассах ни один `wtc` не
  загрузил 75673, и PC 75673 ни разу не исполнялся.
  Зато 75676 исполнялся (B2-2048-6600.tt.err:25118-25121).

[ФАКТ] Ключ 077061 (для 75673) прочитан как
  GOST-слово `6655 0253 5372 6720`; ключ 077065 (для 75676)
  равен `5032 1664 5412 0500`. Расшифровка этих 6-байтовых
  ключей в читаемый текст не установлена.

## 6. МОНИТОРНЫЙ ПУТЬ

[ФАКТ] `счи` (I_ITA, cu.c:610) ставит `acc.l = 0`, беря
  только младшую половину из регистра. Поэтому D01165,

  отрицательными в dispak.

[ФАКТ] В base.txt найден вызов `0407.1043/1044: пб 1117(7)`

## 7. СВОДКА СТАТУСОВ

ФАКТ:
  единственный статический writer: 0551.1674R;
  он кончается логическим сдвигом asn 136, знак стирается;
  принудительный вызов даёт +420070₈, не отрицательное;
  запись 077062 таблицы содержит handler 75673, но ни одна
  трасса его не выбирает;
  7 вариантов карт не изменили флаг (всегда 0);
  принудительный отрицательный флаг включает 0565/0566;
  мониторный writer тоже обнуляет знак через счи;
  страница 04 в трассах отсутствует.

ГИПОТЕЗА:
  D01167 задумывался как копия D01165 (монитор) или как
  признак «старого» макрокомпилятора 12.2.76;
  ключ 077061 это GOST-имя дескриптора архива АРАП,
  чтение которого порождает переход на 75673.

НЕ ИЗВЕСТНО:
  какое реальное задание или архивный дескриптор выбирает
  ключ 077061 и handler 75673;
  расшифровка 6-байтовых ключей таблицы 077020-077077;
  исполнялась ли ветка 0565/0566 когда-либо на реальном
  архиве 1970-х годов.

## 9. ОГОВОРКИ

1. /tmp заполнен, поэтому каталог d01167-neg это symlink на
   /var/tmp/d01167-neg-work; образы подключены symlink на
   копии из /tmp/.private/azizz/d01167/.
2. Задание с режимом 1-1 записало модуль на ленту 43,
   поэтому md5 копии 2248 изменился. Эталон не тронут.
3. D01167 в 4 проверенных заданиях = 0; версия « writer
   исполнялся, но дал ноль» не подтвердилась: writer
   вообще не вызывался, пока его не вызвали вручную.
4. Вывод «не может быть отрицательным» справедлив для
   dispak и SIMH. Для другой реализации БЭСМ-6 с
   арифметическим (со знаком) сдвигом он может не
   выполняться; такой реализации под рукой нет.
