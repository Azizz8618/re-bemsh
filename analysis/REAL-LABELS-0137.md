# Настоящие метки первого поля в MBE-Z0137.be

Дата: 23.11.2026. Write-set: только `bemsh/MBE-Z0137.be` и этот отчёт.
Коммитов и пушей нет. Эталонные образы и прочие файлы не изменялись.

## 0. Короткий ответ

Для двух внутренних целей инвентаря (`SUB_I_1036`, `INIT_I_3`)
НАСТОЯЩИЕ метки первого поля возможны и дают 0 отличий.
Референция должна вычитать базу модуля: `I1036-З`, `I3-З+1`,
где `З ЭКВ Z0137` равно предписанной базе `010000`.
Прямая ссылка без вычитания (как `пе G10012` в ДИСПАК) невозможна:
эталон зоны 0137 хранит зонно-относительные адреса без базы.
Остальные 40 внешних целей инвентаря не могут иметь метку первого
поля принципиально: их адреса вне диапазона адресов этого модуля.
Они оставлены как `ЭКВ`-имена `E#####`.

## 1. Механика СТАРТ/HAM и значений меток

Факты из исходников и листингов:

* `re-dispak/apunkt.be:1`: `АПУНКТ СТАРТ '10000'`.
* `apunkt.be:23`: `G10012 сч` (метка первого поля), `apunkt.be.lst:39`:
  адрес слова `10012 = 010000 + 012`.
* `apunkt.be.lst:374`: в таблице символов `G10012 10012`.
* `apunkt.be:17` / `lst:32`: `пе G10012`, поле адреса `10012`.
  То есть в ДИСПАК значение метки равно база+индекс и ровно это
  значение попадает в поле адреса.
* В зоне 0137 эталонное слово `asm:1089` (индекс 1036) и CALL
  `asm:587` содержат поле адреса `01036`, то есть только индекс.
* База `010000` предписана оператором (`RESIDENT-ZONES.md:280-288`).
  СТАРТ распознаётся как шапка только первой некомментарной строкой
  (`docs/SEMANTIC/B-START-TOP-1.md`).
* Нулевая база недостижима: `СТАРТ '0'` даёт ошибку
  `НОЛЬ ЗАПР0Щ1` и `HAM=00001` (`START-SPECIAL-FIX.md:56-62`).

Следствие: при базе `010000` метка на слове 1036 имеет значение
`011036`, а эталону нужно `01036`. Разница ровно `010000`, то есть
база `З`. Вычитание базы в поле адреса есть перенос соглашения
ДИСПАК в соглашение этого эталона, а не подмена метки `ЭКВ`.

## 4. Граница применимости

При базе `010000` метка первого поля принимает значения
`010000..011777`. При базе `1` значения `00001..02000`.
Из 40 внешних целей ни одна не попадает ни в один диапазон,
например `04231`, `014342`, `022415`, `034562`, `070000`.
Поэтому настоящая метка первого поля не может обозначать эти
адреса без явной лжи или без директивы `ВНЕШН`, которая добавляет
перемещение и ломает байты. Эти 40 целей остаются `ЭКВ`-именами.
Утверждение operatorа "EQU-based solutions rejected" выполнено
для обеих внутренних целей, где метка первого поля действительно
возможна. Полное понимание всех внутренних правил БЕМШ не
утверждается: выводы ограничены наблюдёнными листингами, ошибками
транслятора и побайтовыми сверками.
