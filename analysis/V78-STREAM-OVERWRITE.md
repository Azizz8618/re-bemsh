## 0. ВЕРДИКТ

### Вопрос 1: почему 01675 затирает вывод 01413

ФАКТ. 012000 есть ОБЩИЙ буфер двух разных каналов.
Ниже мнемоника трассы (`-tt`), динамическое
подтверждение; статика дана в §2.2:

    01412 xta N(5)   R5=076642  RLE-ВЫХОД
    01413 atx N(11)  R11=012000  ранняя запись
    01674 xta 76511(4)           RLE-ВХОД 076505+
    01675 atx ...                поздняя запись

ФАКТ. Разница только в ЗАГОЛОВКЕ. Текстовые слова совпадают:

    01413: 2000000100000003  (база)
    01675: 2000000100052003  (база | 00052000)

Статика `dis-forced/Z0152.asm:791-820` показывает RLE-цикл
076600-076623: вход 076517/076505, выход 076642.
По `analysis/DESCRIPTOR-0005.md` §2, шаблон дескриптора
собирается в 076505 шагами 01640-01662, где

    01661 aox 1762   маска 0000000000052000
    01662 atx 76505  -> 2000000100052003

ГИПОТЕЗА (наиболее вероятная). Это НЕ авария и НЕ
перезагрузка машины, а ДВУХСТАДИЙНЫЙ конвейер одной
задачи: сначала 01413 кладёт в 012000 сырые слова
RLE-выхода, затем 01661/01675 добавляет поля дескриптора
0005 и 2000 и перекладывает тот же текст в 012000 в
окончательном виде. Последняя сброска (35765) оказывается
перед загрузкой пула (61620), поэтому в 072000 попадает
именно вариант 01675.

НЕ ИЗВЕСТНО. Точная ветка/триггер, включающая 01675 вместо
01413. Статического кода для PC 01640-01676 в gold НЕТ
(низкая память, вне зон 0137-0177).

### Вопрос 2: код 0200 в потоке ГОСТ

ФАКТ. 0200 (0x80) есть УПРАВЛЯЮЩИЙ код "установка позиции"
печати, НЕ пробел и НЕ метка данных. Он поглощает СЛЕДУЮЩИЙ
байт и ставит колонку `pos = c % 128`.

Доказательство: `dispak/dispak/extra.c:1383-1387`

    case GOST_SET_POSITION:
    case 0200: /* set position */
            c = getbyte(&bp);
            pos = c % 128;
            break;

Там же `:1308-1312` дубль в print_text_debug().
Пробел в ГОСТ есть 0017 (`gost10859.h:29`), новая страница
есть 0201 (`extra.c:1359`), повтор знака есть 0174
(`extra.c:1388`). Печатный поток идёт из буфера 06432
вызовом Э64 (`analysis/V78-LISTING-COLUMNS.md` §2).

## 2. ЧТО ДЕЛАЕТ КАНАЛ 01675

### 2.1 Динамический портрет

ФАКТ. По `analysis/RLE-CONSUMER.md` §5:

    5072764355120642 в 012000+, но берёт его
    из 076505+ (xta 76511(4)).

То есть источник 01675 есть область RLE-ВХОДА, а не
RLE-ВЫХОДА 076643+, который читает 01412.

ФАКТ. Атрибуция 174 store в 012000

### 2.2 Статический контекст 076505

ФАКТ. Зона 0152 грузится по базе 076000. Поэтому смещение
06505 файла gold/MBE-Z0152-L1.bin есть адрес 076505.

ФАКТ. Форсированный листинг RLE-цикла:

    Z0152.asm:791  604 сч 76517(М6)   входное слово
    Z0152.asm:793  605 зп 76502
    Z0152.asm:795  606 цикл 76611(М2)
    Z0152.asm:800  611 нтж 76317      тест 0x40
    Z0152.asm:802  612 сч 77173       замена 0x01
    Z0152.asm:812  617 зп 76642(М5)   выход
    Z0152.asm:816  621 сч 76503
    Z0152.asm:818  622 зп 76642(М5)
    Z0152.asm:820  623 пб 76603
    Z0152.asm:826  626 вчаб 6505      указатель входа
    Z0152.asm:836  633 вчаб 6505      указатель входа

Следствие. 076505+ есть ИСТОЧНИК цикла 076600. После
выборки слова входная область уже не является живым
входом и может использоваться повторно. Именно там
(076505) собирается дескриптор по `DESCRIPTOR-0005.md` §2.

### 2.3 Сборка дескриптора перед копированием

ФАКТ. `analysis/DESCRIPTOR-0005.md` §2, трасса PF:

    01640 xta 76505   (=2000000100000003) база
    01641 aax 1755    (=0000000000076000)
    01642-01647       вычисление K
    01660 xta 76505
    01661 aox 1762    (=0000000000052000)
    01662 atx 76505   -> 2000000100052003

Ячейка 01762 = 0000000000052000. OR добавляет два поля:
0005 (тип) и 2000 (префикс пула). Это в точности объясняет
разницу между заголовками 01413 и 01675.

ФАКТ. Итоговые 6 заголовков в 072000 (`DESCRIPTOR-0005.md`):

    2010000100052003
    2010000200052003
    2010000300052002
    2010000400052003
    2010000500052005
    2010000600052003

Флаг 2010 ставится отдельно (`aox 6126`), см. там же.

## 3. ПРИЧИНА ЗАТИРАНИЯ

### 3.1 Тайминг (номера строк -tt)

ФАКТ. Сводка по `V78-RLE-DRUM-BRIDGE.md` §3, §5:

    звено                       первая  последняя
    01413 → 012000                9019      197057
    WR 012000 → (12,0)           21252      197096
    01675 → 012000              33800      177324
    WR 012000 → (12,0)           35765      179577
    RD (12,0) → 072000          61620      149162

ФАКТ. Между WR@35765 и RD@61620 НЕТ ни одного WR на
тракт (12,0). Данные 01675 доходят до пула без помех.

ФАКТ. Сброс WR@21252 нёс 84 слова 01413 (строки 9019+).
Сброс WR@35765 нёс 24 слова 01675 (строки 33817..35655).
Первая загрузка 072000 только в 61620.

### 3.2 Что именно перезаписано

ФАКТ. Сравнение 24 слов (`V78-RLE-DRUM-BRIDGE.md` §6):
012000 перед WR@35765 против 072000 после RD@61620
совпало 24/24 позиции. Примеры:

    0032664150731257  совпало
    1620000100000000  совпало
    2152640156526641  совпало

ФАКТ. Заголовки при этом НЕ совпадают с ранними:

    012000@9019   2000000100000003
    012000@33800  2000000100052003
    072000@61637  2010000100052003

То есть текст один, а служебное поле наращено.

### 3.3 Ответ на вопрос "что это было"

ФАКТ. НЕ авария. Прогон продолжается до печати листинга
и второго RD 072000 (строка 149162).

ФАКТ. НЕ перезагрузка машины. Барабан (12,0) сохраняет
запись между 35765 и 61620; RD читает её успешно.

ФАКТ. НЕ случайное попадание. 01675 исполняет ту же
схему atx в 012000, что и 01413, с осмысленным
заголовком дескриптора.

ГИПОТЕЗА. Это плановая смена ФОРМЫ записи в одном буфере:
сырая форма (01413) -> форма дескриптора (01675).
Буфер 012000 используется дважды как промежуточный
склад, и последний сброс перед загрузкой пула имеет
решающее значение. Точный триггер переключения каналов
установить не удалось.

НЕ ИЗВЕСТНО. Почему ранний сброс WR@21252 делается
вообще, если его данные всё равно заменяются. Возможные
ответы (другой получатель, контекст иной строки,
страховка) трассой не различаются.

## 4. КОД 0200 В ПОТОКЕ ГОСТ

### 4.1 Чем этот байт НЕ является

ФАКТ. Пробел в ГОСТ-10859 есть 0017 (0x0F):
    gost10859.h:29   #define GOST_SPACE 0017
В коде БЕМШ пробел есть 0x40 (V78-BYTE-ENCODING.md §0).
В TEXT-6 пробел есть 0x00. Восьм. 0200 ни в одной из
этих таблиц пробелом НЕ является.

ФАКТ. Печатные коды ГОСТ-10859 лежат в 0000-0137.
Байт 0200 (0x80) лежит ВНЕ печатного диапазона, то есть
не может быть данными-символами.

ФАКТ. В текстовых каталогах 06/78
(analysis/V78-TEXT-LITERALS-A/B/C/D.md) байт 0200 как
символ НЕ встречается. Упоминания "0200" там суть
номера слов зон, не байты. docs/TEXT-CONSTANTS.md §2
явно относит байты >= 0x4E к непечатным (`в'...'`).

### 4.2 Что он есть

ФАКТ. dispak печатает ГОСТ-поток в print_gost():

    extra.c:1380  case 0143 / 0341: нулевая ширина
    extra.c:1383  case GOST_SET_POSITION:
    extra.c:1384  case 0200: /* set position */
    extra.c:1385      c = getbyte(&bp);
    extra.c:1386      pos = c % 128;

То же в отладочной печати: extra.c:1308-1312.

ФАКТ. Соседние управляющие кода:
    0173 GOST_SET_POSITION  gost10859.h:112
    0200 set position       extra.c:1384
    0201 new page           extra.c:1359
    0174 / 0265 повтор      extra.c:1388-1389
    0172 конец информации   gost10859.h:111
    0377 GOST_EOF           gost10859.h:117

Следствие. 0200 и 0173 однотипны: оба задают колонку.
0201 задаёт новую страницу.

### 4.3 Ответ на открытый пункт

Открытый пункт (`V78-LISTING-COLUMNS.md` §6.1):
 "позиция или признак новой страницы".

ФАКТ. ОТВЕТ: позиция. Код 0200 есть установка позиции
печати со следующим байтом-аргументом. Признак новой
страницы есть код 0201, а не 0200.

ФАКТ. На разбор колонок листинга это не влияет: PC 04206
уже раскладывает поля по r[2], а 0200 лишь расставляет
пробелы при выводе (`V78-LISTING-COLUMNS.md` §2).

## 5. СВОДКА СТАТУСОВ

ФАКТ:
  012000 пишут 01413 (076642+) и 01675 (076505+);
  заголовки отличаются ровно на маску 01762 = 00052000;
  текст 24/24 слов доходит до 072000;
  последний WR перед RD пула есть 35765;
  это не авария и не перезагрузка машины;
  0200 есть управляющий код "установка позиции";
  новая страница есть 0201; пробел ГОСТ есть 0017.

ГИПОТЕЗА:
  затирание есть плановая замена сырой формы записи
  на форму дескриптора в том же буфере;
  012000 есть многоразовый промежуточный склад пула.

НЕ ИЗВЕСТНО:
  ветка/триггер выбора 01675 вместо 01413;
  статический код PC 01640-01676 (вне gold-зон);
  смысл раннего WR@21252, данные которого заменены;
  исходник формата дескриптора 1978 года.
