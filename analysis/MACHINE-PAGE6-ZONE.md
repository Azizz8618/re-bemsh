# Машинная страница 06: какая дисковая зона?

Дата: 22.11.2026. Write set: только этот файл.
Коммитов и push нет. Образы и gold/ не изменялись.
Опыт на КОПИЯХ томов в `/tmp/.private/azizz/page6-zone/`.

Статусы:
- [ФАКТ] прочитано в исходнике, трассе или дампе.
- [ГИПОТЕЗА] догадка без прямого свидетельства.
- [НЕ ИЗВЕСТНО] ответа в полученных данных нет.

Восьмеричные адреса пишем как `014145`. Степень: `↑`.

## 0. Главный результат

[ФАКТ] Единственная загрузка Э70 в машинную страницу 06
(база `014000`) за весь прогон задания B это чтение зоны
`0072` с ЛУН 42 (том 2099, смещение 0). Команда Э70
исполняется по PC `03041` и относится к ЧТКОМП, а НЕ к
загрузчику парсера.

[ФАКТ] Парсер карт АРАП (`014145-014415`) в страницу 06
НЕ загружается ни одной Э70-загрузкой. Его код приходит
из входного буфера задачи через Э60 (начальный загрузчик).
Поэтому вопрос «какая зона тома 2048 соответствует
странице 06 с парсером» НЕ имеет ответа в виде номера
дисковой зоны.

[НЕ ИЗВЕСТНО] Нет прямого свидетельства о зоне, из которой
был бы прочитан именно код парсера. Такой зоны нет ни на
одном из 14 доступных образов (см. §4).

## 1. ФАКТ: Э70-отображение страницы 06

Прогон: копия `job-B-sostav-orig.b6`, локальная сборка
`dispak/build/dispak/dispak`, `BESM6_DD_DEBUG=1`.
Поток stderr, 250 строк `DD pc=`. Строка для страницы 06:

    DD pc=03041L r016=06601 u=42 z=0072 RD
       uil=10/0/600 uir=42/0/72

Разбор по `dispak/extra.c`:

* `:3160` `addr = (uil.i_addr & 03700) << 4`.
  `0600 & 03700 = 0600`, `0600 << 4 = 014000`.
  Это база страницы 06.
* `:3172` `zone = uir.i_addr & 07777` = `0072`.
* `:3161` `u = uir.i_opcode & 077` = 42 (ЛУН 42).
* `:3651` `(zone + dd->offset) & mask` = физическая зона.
  В колоде `лен 42(2099)` смещения нет, `offset = 0`,
  значит физическая зона = `0072` тома 2099.

Итого отображение: `ЛУН 42, зона 0072 -> база 014000`.

[ФАКТ] Это ровно аналог случая page 01 из
`PASSES-OVERLAY-MECH.md` §2, только ЛУН 42 и зона 0072.
Там: `uil=10/0/100, uir=30/0/1770`,
физическая зона `(1770+6200)&07777 = 0170`, база 02000.

[ФАКТ] Всего в трассе две загрузки в диапазон
`014000-017777`: зона `0072 -> 014000` и зона
`0073 -> 016000`. Обе от PC `03041`.

## 2. ФАКТ: это НЕ загрузка парсера

[ФАКТ] Команда, исполнившая Э70, это `03040: *70 6601`
в обработчике ЧТКОМП (`ARAP-CARD-PARSER.md` §4.1).
В полной трассе `B-explore.err`:

* строка 1037087: первый вход в парсер `14145: its 16`;
* строка 1478923: `*70 6601` с дескриптором зоны 0072.

Парсер исполняется ЗАДОЛГО до чтения зоны 0072.
Поэтому зона 0072 не содержит код парсера.

[ФАКТ] Проверка брейкпойнтом. Команды `b 14145`, `g`,
дамп страницы (`14000 b` ... `15770 b`). Оба бинаря
(`/usr/local/bin/dispak` и локальный build) дают
`14145: 00 043 0016 its`. Слово по `014145` =
`002 060 016 011 200 072` (6 октальных байт).

## 3. ФАКТ: откуда берётся код парсера

[ФАКТ] При останове до первой команды (`dispak -b`,
точка `00010`) страница 06 целиком нулевая: все 1024
слова дампа `000 000 000 000 000 000`. Код появляется
позже, в ранней фазе.

[ФАКТ] Первые записи в страницу 06 идут из кода загрузчика
по PC `064063-064100` (это как раз диапазон `060000-067777`,
страница 30). Фрагмент полной трассы:

    64065: xta 17        r=014000  (база page 06)
    64066: aax 1714(15)  r[15]=64000
    64067: ati 2
    64070: utc 60(15)
    64076: utc (4)       r[4]=76001
    64077: atx 76001(2)  r[2]=15777
       14000: store 0000000000000000

`atx 76001(2)` с `r[2]=15777` даёт адрес
`(76001+15777)&077777 = 014000`. То есть загрузчик
копирует данные в страницу 06.

[ФАКТ] `utc` это opcode 022 (`optab.c:88`, `I_UTC`), не Э70.
Прямых `DD pc=` событий для этой фазы нет: Э70 не участвует.
Механика чтения входного потока описана в
`dispak/input.c:110-156` (`e60()`, `case 060` в
`cu.c:876-877`). Данные приходят из файла входного буфера
`~/.besm6/input_queue/NNN`, а не с диска.

[ФАКТ] Супервизор грузится отдельно: `dispak.c:468-487`,
таблица `sv_disk[]` (`dispak.c:82-86`) читает том 2099,
зоны `0100-0105` в адреса `0100000-0112777`. Страница 06
в пользовательской адресации туда не входит.

## 4. ФАКТ: отрицательный поиск по образам

Искались 6 байт слова с `014145`
(`02 30 0e 09 80 3a`) и ещё 15 слов областей
`014140-014167` во всех доступных образах:

    2048, 2048.2448, 2048.bak, 2053, 2063, 2086,
    2099, 2113, 2148, 2153, 2222, 2248, 2348, 4001

Результат: 0 попаданий во всех 14 файлах.
Поиск по `gold/*-L1.bin` (70 файлов) также дал 0 точных
попаданий для ключевого слова `014145`. Лучшая побайтовая
сверка дампа страницы 06 с зоной - 584/1024, что
соответствует низкоэнтропной таблице (`0175`), а не коду.

[ФАКТ] Это согласуется с `RAM-SNAPSHOT-EXTRA.md` §4, где
зоны `0140-0146` помечены NON-RESIDENT (max 4/1024).

## 5. ГИПОТЕЗА

Парсер АРАП это код резидентного супервизора/
начального загрузчика, поставляемый во входном буфере
задачи. Он занимает страницу 06 с ранней фазы и не имеет
дисковой зоны-источника. Дисковая зона 0072 тома 2099
попадает в ту же страницу позже как оверлей данных ЧТКОМП.
