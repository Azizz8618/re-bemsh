## 3. Побайтовые доказательства (ключевые)

Шаг 1 (адрес). CW 05752 готовит acc, 05755 исполняет
*70 6612. В extra.c:3577 страница вычисляется как
(uil.i_addr & 03700) << 4. Подстановка: 03500 даёт
072000, диапазон 072000-072377 (1024 слова). DD-
строка pc=05756L u=12 z=0000 RD uil=10/0/3500.
WATCH=072001 RW=1: 0 попаданий, значит пишет Э70,
минуя STORE. Поле z= есть тракт барабана, не память.

Шаг 6-11 (RLE). 76604 сбр 76332(М2) выделяет байт
из 076505+. 76611 нтж 76317 тестирует маску 0x40
в старшем байте. При байте 0x40 acc=0, ветка 76612
сч 77173 подставляет 0x01 в 76503. При знаке (0x5a
двоеточие) ветка 76615 цикл 76621(М4). 76613/76614
считают серию 0x40: N пробелов дают байт 0x01..0x05.

выдаёт его в RLE-выход. 76623 пб 76603 замыкает цикл.

Шаг 12 (потребитель). 01412 сч N(5) читает M[076642+N],
01413 зп N(11) пишет M[012000+N]. R5=076642, R11=
012000+16*k. 6 блоков по 16 слов: 12000, 12016,

064063; семантика ПФ; смысл кода 0200 в потоке ГОСТ

ГАП 3 (Г). Интерпретация r[2] у 04206 как «номер поля»

## 5. Центральный вопрос: есть ли парсер 4 полей

КРИТЕРИЙ §0 (V78-SYNTAX-FINAL-VERDICT.md §1). PC
считается парсером, если он:
(a) читает байт исходной строки;
(b) по-разному решает для одного знака в разных полях;
(c) меняет адрес назначения или структуру записи.

| Кандидат                | (a)| (b)| (c)| Вердикт        |
|-------------------------+----+----+----+----------------|
| сбр/рзб 076600         | да | нет| час| не парсер      |
| диспетчер 076031       | да | НЕТ| адр| не парсер      |
| упаковщик 077421       | да | нет| да | не разметка    |
| цикл 075344-075401     | да | нет| нет| не парсер      |
| маркеры 075353-357     | да | нет| вет| не парсер      |
| METKA 075377/075357    | да | нет| нет| не парсер      |
| слоты 04201            | НЕТ| нет| да | не парсер      |
| writer 04206           | да | нет| да | не парсер      |

ВЕРДИКТ: НЕТ. Механизм выделения четырёх полей не
найден. Это уже не «не нашли»: найдены ВСЕ механизмы,
которые могли бы его образовать, и ни один не принимает
на вход номер поля. Диспетчер 076031 классифицирует
байт по ЗНАЧЕНИЮ через XOR-константы и маску 0xC0.
В матрице 8x4 ветвь не зависит от поля для 7 из 8
знаков; исключение запятой объясняется признаком
первой 6-байтовой группы r[5], не номером поля.

Найдены вместо парсера: побайтовая нормализация
0x40 → 0x01 и RLE; классификация байта по значению;
проверка маркеров конца строки и подчёркивания;
решение о наличии метки; механический слотовый writer;
регистрация пар ЗНАЧЕНИЕ/ТЕГ макроопределений.

ГИПОТЕЗА. «Поле» в 1978-й может быть не операцией
разбора строки, а соглашением о том, в каком 6-байтовом
слове оказался текст. Полностью проверить нельзя: нет
исходников 1978 года.
