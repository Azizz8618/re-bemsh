# Механика листинга БЕМШ в dispak: что делает C-код

Дата: 23.11.2026. Write-set: только этот файл.
Коммитов и правок других файлов нет.

## 0. ВЕРДИКТ

C-код dispak НЕ является транслятором БЕМШ. Он печатает
то, что выдала гостевая программа ИПМ МАКРО-БЕМШ ВЕР.06/78,
через экстракод е64. Строковых форматов "АДРЕС", "МЕТКА",
"ОПЕРАЦИЯ" в C нет: это данные транслятора.

Метка первого поля всегда имеет значение база + индекс.
Для слова 1036 при базе 010000 это 011036, не 01036.
Адрес 01036 даёт только ЭКВ-литерал, но это не метка слова.

## 1. ФАКТ: где живёт печать листинга

Цепочка (порядок вызовов):

1. vsinput.c:1-3 кодирует карты задания в input queue.
2. dispak.c:362 вызывает vsinput(), dispak.c:370 input().
3. input.c:25-100 читает паспорт; e60() подаёт карты
   в память гостя (input.c:100).
4. Транслятор БЭСМ-6 читает карты и печатает е64.
5. extra.c:1751 print() исполняет е64 не-нативный путь.
6. cu.c:1197-1198 вызывает dpout_decode() для xnative.
7. dpout.c:58 dump() декодирует RLE-буфер АЦПУ и пишет
   в stdout через gost_write() (dpout.c:31-56).

Ни в одном из этих файлов нет printf("...АДРЕС...").
Шапка "ОШИБКИ ... КОММЕНТАРИЙ" берётся из памяти гостя
как текст ГОСТ (формат 0 в extra.c:1744, 1802-1808).

## 2. ФАКТ: код C, который формирует строку листинга

Формат слова е64 описан в extra.c:1721-1749:

    ffff bbbbbbbb dddddddddddd
    esss wwwwwwww rrrrrrrrrrrr

f=0 текст ГОСТ, f=1 команда, f=2 восьмеричное,
f=3 вещественное, f=4 текст ITM (extra.c:1743-1748).

Разбор полей слова: extra.c:1786-1791
(format, offset, digits, final, width, repeat).

Функции печати (точные строки):

| что                    | файл:строка                |
|------------------------|----------------------------|
| строка в stdout        | extra.c:1229 lflush()      |
| текст ГОСТ             | extra.c:1334 print_gost()  |
| текст ITM              | extra.c:1440 print_itm()   |
| символ                 | extra.c:1496 print_char()  |
| восьмеричное (АДРЕС)   | extra.c:1511 print_octal() |
| команда (КОМАНДА)      | extra.c:1554 print_command1|
| две половинки слова    | extra.c:1583 print_command |
| вещественное           | extra.c:1656 print_real()  |
| диспетчер е64          | extra.c:1751 print()       |
| нативный буфер         | dpout.c:58 dump()          |

print_octal() (extra.c:1511-1542) сдвигает слово влево
на 64 - 3*digits бит и печатает digits октальных цифр.
Именно так печатается поле АДРЕС (5 цифр).

print_command1() (extra.c:1555-1581) печатает
"рег код адрес" для 1-й структуры и long address.

Столбцы листинга (заданы не C, а гостевой программой):

| поле              | где в строке                |
|-------------------|-----------------------------|
| ПЕРЕМ             | 12..29, запись +N           |
| КОМАНДА           | с 31-й колонки              |
| N ГЕН / N ИСХ     | с 49-й колонки              |

Источник: siprod_bemsh.py:458 RIGHT_COL=49,
:461-463 CODE_RE, :465-466 RELOC_RE, :479-481 таблица
символов (5 октальных цифр). Описание полей:
simh/BESM6/docs/ВВОД_АНАЛИЗ.md:419-434,
bemsh-analyzer/SKILL.md.

Пример (dispak/tests/pprog01/output.txt:45):

    001 00001 02 24 00000 0015 0015 УИА 0(2)

## 3. ФАКТ: СТАРТ, HAM и значение метки

Парсер СТАРТ в C-исходниках отсутствует. optab.c:21-95
содержит только аппаратные opcode (atx, stx, ...),
мнемоник ПВ, ПБ, ЭКВ, СТАРТ там нет. Штамп
"ИПМ МАКРО-БЕМШ ВЕР.06/78" печатает гостевая программа.

Наблюдаемое правило (листинги dispak/tests):

| тест             | СТАРТ      | HAM   | слово 0 |
|------------------|------------|-------|---------|
| bemsh-standalone | 512 дес.   | 01000 | 01000   |
| pprog01          | 1          | 00001 | 00001   |

512 дес. = 01000 восьм. Значит HAM = значение СТАРТ,
а адрес слова = HAM + индекс (индекс 0-based).

Подтверждение в siprod_bemsh.py (не в C dispak):

- :45-46 LOAD = 1, адрес загрузки в скомпилированном
  образе;
- :325-331 комментарий и строка "<имя> СТАРТ 1";
- :338-349 метка берётся из позиции команды;
- :583 want = (LOAD + shift) & 0o77777.

re-siprod/notes/linker.md:60-62: база всегда 1, адреса
меток на единицу больше, чем в DMS (там база 0).
Заголовок без адреса не шапка (linker.md:203-205).

Минимальная база 1. re-bemsh docs/SEMANTIC/
START-SPECIAL-FIX.md:53-58: нулевые формы транслятор
отвергает (НОЛЬ ЗАПРОШЕН), HAM=00001 минимален.
Проба СТАРТ '0': HAM=00001, 1 ошибка, FAIL
(re-bemsh/analysis/REAL-LABELS-0137.md:56).
Ещё вариант написания диагностики: НОЛЬ ЗАПР0Щ1
(re-bemsh/analysis/RESIDENT-BASE-AUDIT.md:64).

Директивы (все вне C-кода dispak):

- ЭКВ '<адрес>': абсолютное значение, без перемещения;
  siprod_bemsh.py:390, проверка :571-576.
- ВНЕШН: внешняя связь, +N в ПЕРЕМ и бит 21 в команде;
  siprod_bemsh.py:353-380, :564-568, :66-67.
- ВХОДН: entry point, не меняет значение метки;
  siprod_bemsh.py:332-337, :391-402.
- Номер связи - НОМЕР, а не разность адресов
  (re-bemsh/docs/VHODN-VNESHN-SYNTAX.md:181-185).

## 4. ФАКТ / НЕ ИЗВЕСТНО: режим без базы?

Проверены все переключатели из задания:

1. 0-0 против 1-1. siprod_bemsh.py:423-426 listing_job()
   меняет только запись объектного модуля. Адрес не
   меняется: в dispak/tests/bemsh-standalone/output.txt
   стоит 0-0, а адреса 01000... с базой 01000.
   re-siprod/notes/linker.md:34: 1-1 запись модуля,
   0-0 только листинг.

2. росп 0. Поле паспорта ЗС1 макрокода БЕМШ
   (re-dispak/docs/Dispak-compat-guide.md:230-241),
   не переключатель адресации. Разбора в C нет.

3. START 0 или пропуск. СТАРТ 0 зажимается в 1 и даёт
   НОЛЬ ЗАПР0Щ1. Пропуск: транслятор не считает строку
   шапкой, HAM=00001 (B-START-TOP-1.md:10-17) и ошибка
   ОШ ПРОСТ 0Ы0 (linker.md:204).

4. Флаги C. pout_enable/pout_disable (dispak.c:268-285,
   :377-381) лишь включают и выключают вывод. xnative
   (cu.c:1197) выбирает декодер. Ни один не трогает базу.

ВЫВОД: в изученном коде режима "адрес = индекс" НЕТ.

НЕ ИЗВЕСТНО: недокументированная директива смены
адресации в бинарнике 1978 г. В каталоге 37 команд
её нет (re-bemsh/docs/MACRO-COMMANDS.md:16-56).

## 5. ФАКТ: внешние символы и бит перемещения

Причина: транслятор не знает адрес загрузки внешнего
символа. Он оставляет номер связи X и смещение D,
помечает команду битом 21 (DMS_BIT = 0x200000,
siprod_bemsh.py:66-67) и печатает "+X+D" в ПЕРЕМ.
Разбор: siprod_bemsh.py:465-466, 490-495.
РВС подставляет базу(X) + D позже
(re-bemsh/docs/VHODN-VNESHN-SYNTAX.md:195-214).

Подавление перемещения:

- ЭКВ '<адрес>' делает символ абсолютным: перемещения
  нет, адрес пишется прямо (siprod_bemsh.py:390,
  :571-576). Рабочий способ.
- Ссылка на себя: база + сдвиг без перемещения
  (siprod_bemsh.py:578-587), но адрес зависит от базы.
- Символ постоянной библиотеки с известным адресом:
  тоже без перемещения (siprod_bemsh.py:588-599).
- ВХОДН не снимает бит у ссылок из других модулей
  (re-bemsh/analysis/BE-LISTING-MECHANICS.md:6).

## 6. ВЕРДИКТ по адресу 01036

Дано: индекс слова 1036, база 010000.

- 1036 восьм. (542 дес.): 010000 + 01036 = 011036.
- 1036 дес. = 02014 восьм.: 010000 + 02014 = 012014.
- база 1 (минимум) + 01036 = 01037.

Ни один вариант не даёт 01036. Метка первого поля не
может произвести 01036 при базе 010000: значение метки
= база + индекс, а ПВ кладёт в поле всё значение
операнда (re-bemsh/analysis/BE-LISTING-MECHANICS.md:0, §3).

Опыты с прямой ссылкой (LABEL-BASE-EXPERIMENT.md §2):

- ПВ I1036(М16) на слове 1036: поле 11036, FAIL.
- имя A01036 в первом поле: тоже 11036, FAIL;
  имя не влияет на значение.
- I1036 ЭКВ '1036': поле 01036, 1024/1024, PASS.
  Но это абсолютный символ, не метка на слове.

## 7. ГИПОТЕЗА

Эталон зоны 0137 хранит зонно-относительные адреса
(0-based). Подлинный исходник утрачен. Возможно, он
имел HAM=1; тогда метка на слове 1036 дала бы 01037,
а не 01036. Точное соглашение однозначно не
устанавливается (BE-LISTING-MECHANICS.md:7).

## 8. НЕ ИЗВЕСТНО

- Машинный алгоритм фазы АРАП, решающий, писать в поле
  индекс или абсолютное значение. Есть только поведение
  на листингах, нет исходника на БЭСМ-6.
- Существование недокументированной директивы смены
  адресации в трансляторе версии 06/78.
- Точный вид проверки СТАРТ 0 внутри гостевой программы
  (известна только диагностика НОЛЬ ЗАПР0Щ1).
