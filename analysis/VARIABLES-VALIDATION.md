# Валидация имён `sym/MBE.named.tab` по факту дизассемблирования

Дата: 19.11.2026; перепроверка и правки: 22.11.2026. Проверено 76 записей
`sym/MBE.named.tab` по 65 зонам (33 B + 32 B2); после правок 75 записей,
из них 74 вошли в `sym/MBE.named.validated.tab`.

**Это аннотационное удобство, а не ground truth.** Ни одно из имён не
подтверждено исходником транслятора (исходника на диске нет).
См. `docs/ANCHORS.md` §1: соответствие «листинг ↔ дамп» не установлено,
0 совпадений характерных слов. Настоящая проверка отвечает только на
вопрос «подставляется ли имя дизассемблером в операнд», а не на вопрос
«верна ли семантическая роль ячейки».

## 1. Методика

Прочитаны: `docs/ANCHORS.md`, `docs/DISBESM6-GUIDE.md`,
`docs/XREF-METHODOLOGY.md`, `analysis/VARIABLES.md`,
`analysis/CROSSREF.md`, `AGENTS.md`.

Точные команды (выполнялось в `/tmp/.private/azizz/re-bemsh`):

```bash
# 1) дизассемблировать КАЖДУЮ зону с полной именованной таблицей
for z in gold/MBE-Z*-L1.bin gold/MBE2-Z*-L1.bin; do
  disbesm6 -a0 -e0 -nsym/MBE.named.tab "$z" \
    | sed -r 's/\x1B\[[0-9;]*m//g' \
    > /tmp/.private/azizz/named_zones/"$(basename "$z")".asm
done
# 2) поиск подстановок (OCT-адреса, names латиницей)
grep -n 'SYSCALL\|ERRCELL1\|CNT6' /tmp/.private/azizz/named_zones/*.asm
# 3) сверка с каноническим xref
grep -n 'D00717\|A00474\|D00632\|D00722' analysis/xref.txt
```

`-e0` обязателен (иначе весь код печатается как `конд`). Зоны не
склеивались: `memory[32768]`, границы зон при склейке не видны
(`docs/DISBESM6-GUIDE.md` §3). Перепроверка 22.11.2026 повторила
тот же прогон по 65 зонам с исправленной таблицей (`LIMIT2213` →
`02213`, без `ERRCELL3`); счёт подстановок по-прежнему ведётся
только по последнему табулированному полю строки (операнд).

### Ключевая ловушка: метка ≠ подстановка

`disbesm6 -n` печатает символ **дважды**:

* в колонке метки (строка адреса, например
  `3 00 000 0000 ⇥ INITCELL ⇥ зп ⇥ MBEENTRY`);
* в колонке операнда (после мнемоники: `зп INITCELL`).

Наивный `grep -c NAME` даёт 60+ совпадений почти для каждого имени —
это **определения меток**, а не реальные использования. В отчёте
считается только **последнее табулированное поле строки** (операнд).
Метка — второе поле, оно в счёт не идёт.

Окно `findsym()` с `fuzz=64` (`praddr`, `docs/DISBESM6-GUIDE.md` §1)
печатает `NAME+N` / `NAME-N`. Такие вхождения помечены WEAK и в
очищенную таблицу не попали.

### Классификация

| класс | критерий |
|---|---|
| STRONG | точное имя в поле операнда, ≥1 реальное usage |
| WEAK   | только `NAME±N` (fuzz), точных usage нет |
| NONE   | имя не появляется ни в операнде, ни как fuzz |
| BAD    | адрес вне памяти или конфликт типов |

## 2. Результаты

Первый прогон (19.11.2026), все зоны (65): **STRONG 73, WEAK 3,
NONE 0, BAD 0**. Только B-зоны (33): STRONG 69, WEAK 7 (4 имени
сильны лишь в B2 — см. §5). Ошибок чтения символов
(`dis: error reading symbol table`) не было: `exit=0`, stderr пуст.
Ни один байт эталонных образов не изменён (md5
`MBE-Z0137-L1.bin` = `60e09c37…`; сверка всех 70 md5 из
`.localdocs/gold-md5-before.txt`: 70/70 совпадений).

Три WEAK-имени разобраны по отдельности и по каждому принято
решение (22.11.2026):

| адр | имя | точных | fuzz | решение |
|---|---|---|---|---|
| 00060 | MNEMTAB | 0 | 31 | **оставить как исключение**: зона 0137.0060–0120 — 7-битный текст мнемоник (`конд`), операнда с адресом 00060 нет; только `MNEMTAB+42`, `+56`, `+51` … Имя на данных-тексте, в очищенную таблицу не входит |
| 02113 → 02213 | LIMIT2213 | 0 → 9 | 29 → 27 | **исправить адрес**: реальный операнд `'2213'` = `02213₈` (9× `сч` в зоне 0171); `02113` — перестановка цифр. После правки имя перешло в STRONG и добавлено в очищенную таблицу |
| 04135 | ERRCELL3 | 0 | 8 | **удалить**: нет ни одного операнда `'4135'`; данные зоны 0173 содержат `04154/04155/04157`, но не `04135`; только fuzz |

| | записей | STRONG | WEAK | NONE | BAD |
|---|---|---|---|---|---|
| было (19.11.2026) | 76 | 73 | 3 | 0 | 0 |

Единственная WEAK — `MNEMTAB` (исключение, см. выше). Подстановки

## 5. Оговорки

1. `MBEENTRY (00000)` оставлен в STRONG по механическому критерию
   (6473 точных подстановки), но все они — операнд 0 / авто-`START`.
   Это не «вход транслятора»: физический адрес входа неизвестен
   (`docs/ANCHORS.md` §3). При использовании таблицы имя стоит
   понимать как «нулевая ячейка».
2. Четыре имени сильны **только в старшей копии B2** (адреса
   совпадают, но точные использования есть лишь в 0547/0573/0555):
   `SUB0514`, `ERRCELL4`, `SUB0472`, `LIMIT6173`. Точные операнды:
   `SUB0472 (00472)` — 10 × `пв SUB0472(М15)` в 0547; `SUB0514
   (00514)` — 6 × `пв SUB0514(М15)` в 0547; `ERRCELL4 (04155)` —
   14 × `зп '4155'` в 0573; `LIMIT6173 (06173)` — 9 × `сч '6173'`
   в 0555/0557/0576. В B-зоне 0147 вызовов 00472/00514 нет (там
   `пв A00477(М15)`), адреса 00472/00514 встречаются лишь как
   метки-определения (`мода`, `зп CNT6`). Разница B и B2 — версии
   06/78 и 12/77, а не артефакт статического анализа. Имена
   оставлены: B2 — та же программа 12/77
   (`analysis/VARIABLES.md` §7).
3. У 40 имён есть и fuzz-вхождения (`NAME±N`) — это шум окна ±64,
   а не дополнительные ссылки. Примеры: `WORK76336-12` (0151:19),
   `TAB2+4` (0577:13), `ERREXIT+31` (0157:67). В счёт STRONG они
   не входят; учитывались только точные.
4. `CONST3554` (03554): `зп CONST3554` (0145:18) — единственная
   точная подстановка; рядом `зп CONST3554-13` (0145:16),
   `зп CONST3554+9` (0145:20). Оставлено как STRONG по факту этой
   подстановки, но `analysis/VARIABLES.md` §6.3 предупреждает,
   что `рег`/`Э50…Э77` подавляют подстановку; роль не доказана.
5. Имена `SUB*`, `TAB*`, `CNT*` — шаблонные, по мнемонике opcode,
   а не по тексту программы. `D`-метки zone-local: одно и то же имя
   подставляется в разных зонах, но это не утверждение о глобальности.
6. Изменены четыре файла: `sym/MBE.named.tab`,
   `sym/MBE.named.validated.tab`, `analysis/VARIABLES.md` и настоящий
   отчёт. `sym/MBE.tab`, `gold/*.bin`, `dis/*.asm` не тронуты; все
   70 md5 эталонных файлов совпадают с
   `.localdocs/gold-md5-before.txt`. Перед правками созданы копии
   `.bak.20261122_141623`. Коммитов и push не делалось.
7. `LIMIT2213`: адрес `02113` исправлен на `02213` (реальный
   операнд `сч '2213'` в зоне 0171, 9 раз). Перепрогон 65 зон дал
   9 точных подстановок, WEAK → STRONG, имя добавлено в очищенную
   таблицу.
8. `MNEMTAB` — исключение: 0 точных, 31 fuzz; 7-битный текст
   мнемоник 0137.0060–0120, имя на данных, не на операнде.
   Оставлено только в `MBE.named.tab`.
9. `ERRCELL3 (04135)` удалён из обеих таблиц: операнда нет,
   `4135` встречается только внутри слов `конд`; данные 0173 —
   `04154/04155/04157`, для них есть `ERRCELL1/4/5`.
