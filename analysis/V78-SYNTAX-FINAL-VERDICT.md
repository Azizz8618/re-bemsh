# Финальный вердикт: разбор строки ВЕР.06/78

Дата: 23.11.2026. Фаза G плана docs/V78-SYNTAX-NEXT-PLAN.md.
Ответ на вопрос: найден ли механизм выделения полей
МЕТКА / ОПЕРАЦИЯ / ОПЕРАНД / КОММЕНТАРИЙ.

## 1. Критерий §0

PC считается парсером, если он:
(a) читает байт исходной строки;
(b) по-разному решает для одного знака в разных полях;
(c) меняет адрес назначения или структуру записи.

## 2. Применение критерия

| Кандидат | (a) | (b) | (c) | Вердикт |
|---|---|---|---|---|
| сбр/рзб 076600 и др. | да | нет | частично | не парсер, нормализация |
| диспетчер 076031-076123 | да | НЕТ | по адресу | не парсер |
| упаковщик 077421-077502 | да | нет | да, таблица | не разметка полей |
| цикл 075344-075401 | да | нет | нет | не парсер |
| проверка маркеров 075353-357 | да | нет | ветка | не парсер |
| решение METKA 075377/075357 | да | нет | нет | не парсер |
| селектор слотов 04201 | НЕТ | нет | да | не парсер |
| writer слотов 04206 | да | нет | да | не парсер |

Ни один кандидат не проходит критерий §0 целиком.

## 3. Что реально происходит

ФАКТ. Цепочка transports строки:

```
Э70 05755 *70 6612 → 072000 (текст)
  → 06427+ → 06405+
  → 077320 xta 6405(1) → 06451
  → диспетчер 076031-076123 (классификация по ЗНАЧЕНИЮ байта)
  → упаковщик 077421-077502 → таблица 075235+r6
  → проверка маркеров 075353-357 (aex XOR, 0xbe/0xbf)
  → решение METKA 075377/075357
  → 06404 → 06061 atx 72000(16) (дескриптор)
```

ФАКТ. Слоты листинга создаются МЕХАНИЧЕСКИ:
`04201: utm 1(2)` инкрементирует r[2] каждые 6 байт
(r[1] считает байты внутри слова), затем `04206: atx
2035(2)` пишет слово в слот 02035+r[2], `06155: atx (3)`
копирует в 06520-06524. Это позиция в потоке, а не
семантическая граница поля.

ФАКТ. Диспетчер 076031 классифицирует байт по значению
через XOR-константы 0x46/0x0E/0x0F/0x4C/0x11/0x49 и
маску 0xC0. В матрице 8×4 ветвь не зависит от поля для
7 из 8 знаков; исключение `,` объясняется признаком
первой 6-байтовой группы r[5], а не номером поля.

## 4. Ответ

НЕТ. Механизм выделения четырёх семантических полей
не найден, и теперь это НЕ просто «не нашли»: найдены
все механизмы, которые могли бы его образовывать, и
ни один не принимает на вход номер поля.

Найдены вместо него:
- побайтовая нормализация `0x40 → 0x01` и RLE;
- классификация байта по значению;
- проверка маркеров конца строки и подчёркивания;
- решение о наличии метки;
- механический слотовый writer для печати;
- регистрация пар ЗНАЧЕНИЕ/ТЕГ макроопределений.

ГИПОТЕЗА. Понятие «поле» в 1978-й версии может быть
не операцией разбора строки, а соглашением о ТОМ, в
каком 6-байтовом слове оказался текст. Проверить это
полностью не удалось: нет исходников 1978 года.

## 5. Что закрыто за сессию

- писатель текста пула: Э70, а не store;
- мост 012000 → барабан (12,0) → 072000, 24/24 слова;
- смысл aex: XOR, 0xbe конец строки, 0xbf подчёркивание;
- направление ветки 075357 по строкам 12878-12880;
- знак дельты ГС: `:` даёт −2 (одна регистрация меньше);
- колонка 1 единственная позиционная граница;
- правила 1967 besides ведущего пробела не действуют;
- слоты листинга создаются механически через 04201/04206.

## 6. Что осталось НЕ ИЗВЕСТНО

- кто выбирает 75673;
- исходник загрузчика 064063;
- смысл `ПФ`;
- причина затирания вывода 01413 каналом 01675;
- семантика кода 0200 в потоке ГОСТ.

Механику архива, проходов и макрокода НЕ объявляем
разобранной до конца.
