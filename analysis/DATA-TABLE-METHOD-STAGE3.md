## 1. ВХОД ФАЗЫ 3

ВХОД [Д/структура]: сегментированный массив, полученный в
фазе 2. Это список непересекающихся пробегов адресов

Каждый сегмент = упорядоченный набор 48-битных слов:

Фаза 2 уже дала (пример, SERVICE-TABLES-B2.md:32-83):

(§2e) с перечислением требований к доказательствам

исходник транслятора.

Ограничение входа [Д]: "конд" из disbesm6 - НЕ доказа-

## 2. АЛГОРИТМ ДЕКОДИРОВАНИЯ (шаги a-f)

### 2a. Расщепление 48 бит и разбор полей [Д]

Для каждого слова:
  L = word >> 24        (старшие 24 бита)
  R = word & 0xffffff   (младшие 24 бита)

L и R подаются в re-siprod/tools/siprod_asm.py:100 decode.
Возвращаемые поля (siprod_asm.py:102-117):
  name   - мнемоника из таблицы OPS (или illegal)
  reg    - номер регистра (half >> 20) & 0xF, т.е. М0..М17
  op     - код операции (1-я структура: биты 18..15,
           2-я структура: биты 17..12)
  addr   - поле адреса (1-я: 15 бит, 2-я: 12 бит +
           EXP-расширение до 0o700000)
  struct - 1 = первая структура (с регистром)
  dms    - бит 0x200000, признак DMS-перемещаемости
  exp    - бит 0x40000, признак расширения адреса

Правило [Д]: reg/KOP/addr/dms/exp - структурные факты.
Смысл поля - [Г], пока не найден читающий код.
Пример (Z0172-STRUCTURE.md:24):
  L=`2240IIII` = уиа М4, addr=IIII  (ID)
  R=`0300TTTT` = пб М0, addr=TTTT  (TARGET)
Мнемоника "уиа"/"пб" здесь - просто форма битов, не
исполнение: в 0172 CALL=0 и штампа нет (:97).

Дополнительно: \):
  - DMS_BIT выставлен -> адрес логический, не физический;
    физическая привязка требует START зоны (linker.md §7.3);
  - EXP_BIT выставлен -> адрес в 0o70000..0o77777;
  - если OPS даёт "illegal" в обеих половинах - это почти
    всегда константа-тег, а не команда (SERVICE-TABLES-
    0153-0155-0157.md:56-58: 0x080000/0x280000 ILLEG).

### 2b. Четыре кодировки; как отличить текст от числа [Д]

Таблицы dtran.cc:
  GOST-8   dtran.cc:167 gost_to_utf[0x00..0x7F]
  6-бит TEXT dtran.cc:183 text_to_utf[0..63]
  ITM      dtran.cc:195 gost_to_itm / itm_to_utf
  KOI-7    таблица besmtool view --encoding=k
             (docs/TEXT-CONSTANTS.md §3, колонка 26:38)

Практический вызов (docs/TEXT-CONSTANTS.md:85):
  besmtool view 2348 --start=<ЗОНА> --length=1 \
    --encoding=g,k,t,i
Печает 2 слова в строке, 4 колонки G|K|T|I по 12 символов;
чётное слово = первые 6, нечётное = вторые 6 знаков
(:89-91).

ПОСЛЕДОВАТЕЛЬНОСТЬ проверки (TEXT-CONSTANTS.md §2):
  1. disbesm6 "п'...'" - НЕ доказательство текста. Это лишь
     прохождение is_good_gost (disbesm6.c:531):
       байт < 0x10 ИЛИ 0x20 <= байт <= 0x4D.
     Пример-ловушка: 0140.0044 = `2000000002200000` байты
     40 00 00 09 00 00 -> "п'F00900'", но это ЧИСЛО
     (:61-65).
  2. dtran is_valid_gost / is_likely_gost (dtran.cc:502,
     519) - байты < 0x116, плюс "запрещённые" 020/021/024/
     034; is_likely требует (word>>40) или >2 знаков.
  3. dtran is_likely_text (dtran.cc:454-476) для 6-бит:
     нет "дыр" в середине, >1 знака; ВНИМАНИЕ: все 64 кода
     TEXT печатные, поэтому 734/817 слов 0172 дают "текст"
     - артефакт таблицы (Z0172-STRUCTURE.md:82-84).
  4. KOI-7 читается у таблицы мнемоник 0137/0540, там же
     GOST-колонка - мусор (TEXT-CONSTANTS.md:93-96, §6.1).
  5. Итоговый признак текста [Д]: РЯД из >=3 соседних слов
     с осмысленными словами + besmtool search '<фраза>' ->
     зона.слово (:69-76). Одиночные 'F'/'N' - не текст.

Вывод [Д]: в 0172/0156/0153/osновных числовых пулах фраз
НЕТ (Z0172-STRUCTURE.md:86; SERVICE-TABLE-0156.md:80-81;
SERVICE-TABLES-0153-0155-0157.md:66). Текст есть только в
штампах и сообщениях (0147.1315, 0173.0655, 0176.1743 -
TEXT-CONSTANTS.md §5) и таблицах мнемоник/алфавита.

### 2c. VARYING vs CONSTANT по записям (метод 0172) [Д]

Цель: различать поле-индекс (ID) и поле-указатель (TARGET)
внутри однородной группы слов.

Алгоритм:
  1. Сгруппировать слова сегмента по постоянному полю
     (например, по R-половине или по байтам 3-5).
  2. Внутри группы посчитать, какой байт/поле меняется,
     а какой инвариантен.
  3. Меняющееся поле = ID/индекс; константное = TARGET/tag.

Образец (Z0172-STRUCTURE.md:29-44) [Д]:
  TARGET a3010: 0774-1001 (8 записей),
    ID 0012 0014 0030 0016 0020 0022 0026 0136
  TARGET a3656: 1642-1655 (12 записей)
  TARGET a3676: 1660-1675 (14 записей)
  Байтовая проверка: 0172.1642 `4a004e0c07ae` vs
  1645 `4a003a0c07ae` - отличается ТОЛЬКО байт 2 (ID);
  байты 3-5 (`0c07ae` = 03003656) постоянны.
  1660 vs 1663: снова только байт 2; `0c07be`=03003676.
[Г] F = ID -> адрес обработчика (диспетчеризация): ID растут
с шагом 2, несколько ID отображаются в один TARGET (:45-47).

ЗЕРКАЛО 0165/0170 [Д] (там же :51-60):
  0165.0367 `0900000c0591` (02200000|03002621)
  0165.0370 `0900000c067c` - меняются байты 4-5 (указатель)
  0170.0003 `5c84380c062d` (27102070|03003055)
  0170.0006 `5c84380c056c` - меняются байты 4-5
Итого: 0165/0170 = [константный тег | переменный адрес],
а 0172 = [переменный ID | константный адрес]. Оба из
семейства [поле | указатель], но 0172 инвертировано [Г].

### 2f. Управляемые эксперименты [Д]

## 3. ДЕРЕВО РЕШЕНИЙ / ЧЕК-ЛИСТ
##    (требования к доказательствам)

Шаг 0. Прочитать байты gold и forced-листинг. [Д] обяза-
  тельно: слово из dis - не факт само по себе.

Шаг 1. Вся группа почти нули (AA/55 или 0)?
  ДА + есть читатель зп/сч -> K6 БУФЕР [Д].
  ДА + читателя нет -> K6 FILL [Д].
  НЕТ -> шаг 2.

Шаг 2. Есть >=3 соседних слов с осмысленной фразой
  (GOST/TEXT/KOI/ITM по §2b) + besmtool search?
  ДА -> MESSAGE TEXT / ШТАМП (не 6 классов, отдельный
        вердикт) [Д]. Пример 0147.1315
        (TEXT-CONSTANTS.md:115).
  НЕТ -> шаг 3.

Шаг 3. Одна константная L-половина (тег) + меняющееся
  поле, найден индексный читатель (мода/сда/и Мn)?
  ДА -> K2 DESCRIPTOR [Д] (смысл [Г]).
  НЕТ -> шаг 4.

Шаг 4. Дубль ячеек (шаг 2) при L=`сч0`, R=тег+индекс,
  и счётчик КОЛИЧ ЯЧ ГС реагирует на число макросов?
  ДА -> K3 TAG ГС [Д] (биты ячеек - [Г]/ненаблюдаемы).
  НЕТ -> шаг 5.

Шаг 5. Поле меняется (ID), TARGET константен (метод §2c),
  есть читатель, отбирающий по ID?
  ДА -> K4 DISPATCH [Д].
  НЕТ -> шаг 6.

Шаг 6. Есть пары (входной код -> выходной код) ИЛИ
  монотонный индекс-сдвиг (`сд`)?
  ДА -> K5 RECODING [Д] (в данных зонах - 0 таких [Д]).
  НЕТ -> K1 CONST/MASK [Д], смысл [Г].

Шаг 7 (обязательный для всех классов): двойная читаемость.
  Если каждая половина даёт валидный opcode, но CALL/BR=0
  и тег ILLEGAL - это ДАННЫЕ, случайно похожие на код [Д]
  (SERVICE-TABLE-0156.md:15-18; B-OTHER.md §14.3).
  Обратная ошибка: "конд"-хвост 0155/0157 - это КОД,
  оборванный `пб (М5)` при -a0 (SERVICE-TABLES-0153-
  0155-0157.md:16-26, :197-203).

   пары команд; 99.3% половин 0156 дают именованный opcode
   (SERVICE-TABLE-0156.md:15-18), но это НЕ исполнение.
   И наоборот: "конд" 0155/0157 - код с ложной reachability.
4. Логические адреса листинга (65xx/76xxx/7777, '36436',
   '4154') не являются физическими без START-базы зоны
   (SERVICE-TABLES-0153-0155-0157.md:245-246;
   linker.md §7.3).
   "Физ 06000 + лок 0613" для 0156 пока [Г] (:27-37).
5. K3: биты ячеек ГС ни в одном опыте не наблюдались;
   "[TAG(24)|VAL(24)]", TAG_M/P/B и смещения полей -
   гипотеза (MACRO-TABLE-FORMAT-VERIFIED.md:168-192).
6. Читатели не найдены для 0153.0000-0050, 0165, 0166,
   0170, 0172 (B2.md:359-360; B1.md:170-172). Привязка
   0165/0166/0170 к коду 0171 - [Г] без доказательства.
7. Границы кода/данных в 0155/0157 без трассировки
   `-R<N>=<адрес>` не доказаны (B2.md:174-176).
8. Текст vs число: "п'...'" и 6-бит TEXT дают ложные
   срабатывания (0140.0044; 734/817 слов 0172);
   только ряд + search считается текстом [Д].
9. B -> B2: номер зоны +0400₈, но часть таблиц сдвинута
   внутри зоны (152/174/176/177), пары 170/570 различаются
   тегами (SERVICE-TABLES-B2.md:164-186). Не переносить
   вердикт B на B2 побайтово без сверки.
