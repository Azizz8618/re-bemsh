# V78-LABEL-INDEX: глобальный индекс меток БЕМШ 06/78

Дата: 24.11.2026. WRITE-SET: только 3 новых файла.
Коммитов и пушей нет. Эталоны и `.be` только читаются.

## 1. НАЗНАЧЕНИЕ

Индекс собирает все метки первого поля файлов `bemsh/*Z*.be`
и вычисляет абсолютный адрес каждой метки:
база зоны плюс номер слова из имени метки.
Все числа восьмеричные, арифметика без переполнения
в пределах 15-разрядного поля адреса БЭСМ-6.

Имена: `A#####` и `G#####` это код, `D#####` данные.
Инструмент нужен для разрешения смещений при анализе
версии 06/78 и её копий B2 и АСМ.

## 2. ЗАПУСК

    python3 tools/v78_label_index.py --help
    python3 tools/v78_label_index.py --check
    python3 tools/v78_label_index.py --format json
    python3 tools/v78_label_index.py --zone 0137 \
        --kind data --summary
    python3 tools/v78_label_index.py --asm-check --check

Флаги:

    --root ПУТЬ   корень репозитория
    --format      json или text
    --check       проверка целостности
    --kind        code или data
    --zone Z      зона, 4 восьмеричные цифры
    --summary     печать счётчиков
    --asm-check   сверка с dis-forced/Z*.asm

Коды выхода: 0 успех, 1 ошибка `--check`, 2 ошибка
командной строки или ввода. При `--format json`
без `--summary` stdout это массив записей. С `--summary`
stdout это объект `{records, summary}`. Сводка `--check`
печатается в stdout, ошибки и предупреждения в stderr.
Массив `--format json` пригоден как `--labels idx.json`
для `tools/v78_offset_resolve.py`.

## 3. СХЕМА ЗАПИСИ

Поля ровно восемь, порядок фиксирован:

    {label, zone, base, offset, absolute,
     kind(code|data), file, line}

`offset` это номер слова из имени метки (5 цифр).
`absolute` это `base + offset` в восьмеричном виде.
`file` путь от корня репозитория, `line` номер строки
в исходном `.be` (десятичное, с единицы). Вид `code`
для префиксов A и G, вид `data` для префикса D.
Сортировка: зона, смещение, метка, файл, строка.

## 4. ИСТОЧНИКИ БАЗ

1. `analysis/ZONE-BASE-MAP.md`: Приложение A (строки

3. HAM `00001`: для `0545` по `LABELS-B2-0540-0545.md:60`
   и для зон с `СТАРТ 1`.
4. Зоны 06/78 без измеренной базы: `СТАРТ` из `.be`.
   Это условная база сборки, не измеренный адрес.
5. Особые случаи перечислены в §5.

Все 69 зон карты разбираются, но метки есть в 55
файлах. Зона без меток в индекс не попадает.

## 5. ОСОБЫЕ СЛУЧАИ

- `0137`: индекс использует базу `00000`, HAM `00001`
  это fallback транслятора. Карта зон помечает
  физическую базу как НЕ ИЗВЕСТНО (`§5.8`). Выбор
  `00000` это соглашение данного инструмента,
  не измеренный факт.
- `0147`: база `00000` по карте, `СТАРТ 1` не
  подменяет физическую базу (`§5.1`).
- `0152`: физическая база `76000` имеет приоритет
  над `СТАРТ '75777'` (`§5.5`).
- `0174`, `0175`, `0177`: база `72000` помечена
  как ГИПОТЕЗА (`§5.7`).
- `030000`: внешняя область, том 2099 зона `0076`
  (`MM-030000-SOURCE.md:162`). Это НЕ база зоны.
  Парсер принимает только 4-значные номера зон и
  отвергает `030000` как базу.
