# Фаза 3: путь строки и классификация байта

Дата: 23.11.2026. Только ВЕР.06/78, зоны 0137-0177.
Четыре отчёта фазы 3 плана docs/V78-SYNTAX-PLAN.md.

## 1. Найден классификатор байта

ФАКТ. В зоне 0151 по адресам 075353-075357 стоит
двухступенчатая проверка класса символа через маски
из памяти:

```
075353: xta 76502
075353: aex 76316       маска M[076316] = bf 00 ...
075354: u1a 75356
075356: xta 76502
075356: aex 76315       маска M[076315] = be 00 ...
075357: uza 75364
```

Значения масок прочитаны из gold/MBE-Z0152-L1.bin:
076313 = 40 40 40 40 40 40, 076315 = be, 076316 = bf,
076317 = 40.Это в точности гипотеза фазы 2D: байт выделяется
памятной маской, сравнивается, за сравнением ветка.
Почему поиск фазы 0Б не нашёл его: immediates нет,
все константы лежат в памяти.

ФАКТ. Точка решения по METKA: `075377: utm 1(6)` читает
слово с колонкой METKA (EA 14005). `075357: uza 75364`
ветвит: P1a (ведущий пробел, METKA пустая) ветку НЕ
берёт, P1b (метка ZLBL1) уходит в 075364. Проверено
по строкам 12878-12880 трасс: acc=7360... против acc=0.
Направление в предыдущей версии отчёта было указано
наоборот, исправлено по трассе. То же решение в D0/D1
по строке 7207 есть первое расхождение потока PC.

## 2. Путь нормализованного потока

ФАКТ (`analysis/V78-RLE-STREAM-PATH.md`):

1. цикл 076600-076623: RLE `0x40 → 0x01`, счёт повторов;
2. потребитель `001412: xta (5)` (R5=076642) и
   `001413: atx (11)` (R11=012000): 6 блоков по 16 слов;
3. дальше потока НЕТ: 0 чтений адресов 012000-012177;
4. 072000 получает только 7 записей от `06061`, все
   суть заголовки `2010000N0005200M`, одинаковые в P2a/P2b;
5. текстовые слова 072000+ различаются (`...32` против
   `...01`), но в трассе НЕ пишутся, присутствуя с начала.

ФАКТ. Нормализованный поток доходит до текста строки
(парсер 077320 через 06405) и одновременно до листинга
(01563/01564 → 020036). Это НЕ только листинг.

## 3. Направление цепочки буфера

ФАКТ (`analysis/V78-LINE-BUFFER-CHAIN.md`). Проверка
показала, что 06405+М1 это рабочая копия, ЧИТАЕМАЯ ИЗ
ПУЛА, а не входной буфер:

  RLE → пул → 06427+ → 06405+ → 06451 → 06404 → 06061

Пишут 06417: `03461/04754: atx 6417(16)` из 06427+,
читают `077320: xta 6405(1)`, байт уходит в 06451.
Кто пишет текст в 072001+, НЕ ИЗВЕСТНО.
`04633: atx 72004(1)` работает только в MONITOR-80.

## 4. Снятые кандидаты и уточнения

ФАКТ (`analysis/V78-BUF077300-DEEP.md`). 077300 НЕ
сканер лексем: прелюдия 077300-077315 имеет 0 попаданий,
ядро 077316-077322 копирует байт 06405 → 06451,
эпилог 077323-077330 тестирует флаги. База 0157 = 076000
подтверждена: 077316 - 01316 = 076000. Реальная маска
в цикле `-63` (0377), а не 077646/077635.

ФАКТ (`analysis/V78-METKA-CHAIN.md`). В P1a/P1b все
целевые PC имеют одинаковые счётчики: 03454-57 = 900,
04633 = 2, 06061 = 26, 01534 = 42, 05035 = 6.
Рост 900 → 1382 и байт 0x43 относились к паре D0/D1,
где убран пробел из директивы МАСRО, а не к P1.
03454-57 подтверждён как цикл SETA/AIF.

## 5. Вердикт фазы 3

Частично успешно. Найдены классификатор байта
(075353-075357) и точка решения по METKA (075377/075357),
но полная цепочка от карты до текста пула НЕ замкнута:
неизвестно, кто пишет текстовые слова в 072001+.

Разрыв с автором записи текста ЗАКРЫТ в фазе 4C
(`analysis/V78-POOL-TEXT-WRITER.md`): это Э70 по
`05755: *70 6612`, адрес считается как
`(uil.i_addr & 03700) << 4 = 072000` (extra.c:3577,
memcpy в core по 4076). `-tt` печатает только store,
поэтому Э70 в трассе не видно как запись.

НЕ ИЗВЕСТНО:
- результаты чтения 012000+ (в трассе их нет);
- смысл масок be/bf как классов символов;
- почему K в дескрипторе не меняется от ведущего пробела.
