# ТОЧНЫЙ СМЫСЛ КОДА 0x01 В ЦИКЛЕ АРАП 076600

Дата: 22.11.2026. Write set: только этот файл.
Коммитов и push нет. `gold/`, эталоны, существующие
файлы и образы дисков не менялись. Диск читался
только через `besmtool view/dump` и выгрузку зоны
в `/tmp/.private/azizz/z0646.raw`.

Статусы: [ФАКТ], [ГИПОТЕЗА], [НЕ ИЗВЕСТНО].
Адреса восьмеричные. Степень: ↑. Ширина <=60 колонок.

## 0. Главный результат

[ФАКТ] `0x01` НЕ знак кода БЕМШ и НЕ "невидимый
пробел". Это НАЧАЛЬНОЕ ЗНАЧЕНИЕ СЧЁТЧИКА ПОВТОРОВ.

Цикл `076600-076623` не делает простой замены
`0x40 -> 0x01`. Он считает подряд идущие байты
`0x40` и пишет в ОДИН байт выхода их КОЛИЧЕСТВО:

    один   0x40 -> байт выхода 0x01
    два    0x40 -> байт выхода 0x02
    пять   0x40 -> байт выхода 0x05

[ГИПОТЕЗА] Точный смысл `0x01`: счётное значение
"один пропуск (пробел)" в RLE-представлении поля
каталога. Формулировка "замена 0x40 на 0x01" из
`ARAP-CODES-40-01.md` верна лишь как частный случай
серии длиной 1.

## 1. Что реально лежит на диске

[ФАКТ] Том 2048, зона 0646, слова 1040-1047,
сырые байты (выгрузка `besmtool dump
--to-file`):

    0646.1040: 2d 20 27 0f 0f 0f   "НАЗ" + 3 пробела
    0646.1041: 2f 34 23 2f 4d e1   "ПФГП" + 0x4d
    0646.1042: 21 32 2c 20 2b 34   "БТМАЛФ"
    0646.1043: 32 2f 31 4d e1 e1   "ТПС" + 0x4d
    0646.1044: e1 e1 e1 20 31 32   ... + "АСТ"
    0646.1046: 2a 2d 36 57 57 57   "КНЦ" + 3 ромба
    0646.1047: 4d 5a 57 e1 e1 e1   знаки + заполнение

[ФАКТ] Разделитель полей В КАТАЛОГЕ НА ДИСКЕ -
`0x0F` (GOST_SPACE, `gost10859.h:29`). Слово
`0646.1040` = `2d 20 27 0f 0f 0f`: за "НАЗ"
стоят три байта `0x0F`.

[ФАКТ] Там же встречаются `0x4D` (GOST_OVERLINE,
"надчеркивание"), `0x57` (GOST_DIAMOND, ромб),
`0x5A` (GOST_UNDERLINE) и `0xE1` (неопределённый
код GOST, декодер печатает его как пробел).

[ФАКТ] Ни `0x40`, ни `0x01` в этих словах каталога
НЕТ. Оба возникают позже, в памяти, при переводе
GOST-текста во внутренний 7-битный код БЕМШ
(таблица `0147.0561`: индекс `0x0F` даёт байт
`0x40`) и затем в цикле `076600`.

## 2. Механика цикла: почему это счётчик

[ФАКТ] Разбор `076611-076622` (`LOOP-76600-BRANCHES.md`):

    76611 aex 76317   байт == 0x40 ?
    76612 сч 77173    ACC := 0x01 (константа)
    76612 зп 76503    M[76503] := 0x01
    76613 сч 76501   _prev := M[76501]
    76613 aex 76317   prev == 0x40 ?
    76614 uza 76621   да: R4 НЕ растёт
    76614 uj  76615   нет: R4++, новая позиция
    76621 рзб ...      UNPACK: 0x01 -> число 1
    76622 слц ...      прибавить к байту выхода

[ФАКТ] Если прошлый байт тоже был `0x40`, R4 не
увеличивается. Следующая единица попадает в ТУ ЖЕ
позицию выхода и складывается с предыдущей. Отсюда
`0x01 + 0x01 + ...` даёт `0x02, 0x03, 0x04, 0x05`.

[ФАКТ] Прямая трасса `B-explore.err:1042373+`: пять
подряд `0x40`, младший байт `M[076645]` проходит
`01 -> 02 -> 03 -> 04 -> 05`. Это не пять байтов
`0x01`, а ОДИН байт со значением 5.

[ФАКТ] Константа `M[077173] = 0020000000000000`
есть `0x01` в старшем байте. `UNPACK` (`aux`) с
маской `0x0000000000000377` (`076332`) превращает
её в число 1 в младшем байте.

## 3. КОП 020 / 021 (`сбр`/`рзб`)

[ФАКТ] `apx` (`dispak/dispak/arith.c:406-425`, КОП
020) и `aux` (`:428-455`, КОП 021) - чисто
битовые операции сжатия/развёртки полей по маске
из `enreg`. Никакой символьной семантики у значения
`0x01` в них нет. `0x01` ведёт себя как любое
число: сдвигается и складывается побайтово.

[ФАКТ] Поэтому искать в `0x01` смысл "код знака"
внутри `сбр`/`рзб` неверно: это операнд-счётчик,
а не символ.

## 4. Отвергнутые версии

- "0x01 = непечатный пробел БЕМШ". Опровержено:
  серия из пяти пробелов даёт `0x05`, а не пять
  `0x01` (§2).
- "0x01 = код знака надчеркивания". Опровержено:
  `GOST_OVERLINE = 0115 = 0x4d` (`gost10859.h:91`),
  в 7-битном коде БЕМШ - байт `0x4e`
  (TAB[0x0d], `GOST-BYTE-FORMULA.md`).
- "0x01 = цифра 1". Опровержено: GOST-код `001`
  даёт байт `0x51` (`GS-TABLE-0147-0561.md:43`),
  TEXT-код 1 тоже не пробел и не `0x01`
  (`encoding.cpp:614`).
- "0x01 = пробел в TEXT". Опровержено: пробел в
  6-битном TEXT есть код 0 (`text_to_gost[0]`),
  а не 1.
- "0x01 = терминатор имени". Опровержено: имена
  модулей в объекте дополняются `0x40`
  (`re-siprod/notes/linker.md:191-194`), в таблицах
  ГС `0x01` тоже не встречается.
- "0x40 на диске - разделитель". Опровержено:
  на диске разделитель `0x0F` (§1).

## 6. Сводка статусов

ФАКТ:
  на диске каталог в GOST, разделитель `0x0F`;
  `0x40` и `0x01` в нём отсутствуют;
  `0x01` - константа из `077173`;
  N подряд `0x40` дают один байт со значением N;
  `0x01` - это N=1, начальное значение счётчика;
  КОП 020/021 не придают `0x01` символьный смысл;
  `0x01` не есть надчеркивание, цифра 1, пробел TEXT
  или терминатором имён.

ГИПОТЕЗА:
  `0x01` - счётное поле "один пропуск" в
  RLE-представлении каталога;
  преобразование нужно для сжатия полей пробелов
  перед передачей дескриптора машине.

НЕ ИЗВЕСТНО:
  кто и как читает байты `076643+` дальше;
  разворачиваются ли счётчики обратно в пробелы;
  зачем именно RLE, а не фиксированные поля;
  прямое описание формата каталога АРАП
  (исходника АРАП нет: ARAP-ARCHIVE-STRUCTURE.md §0).
