# RESIDENT-BASE-AUDIT: аудит баз СТАРТ 13 зон

Дата: 20.11.2026. READ-ONLY исследование.
Изменён только этот файл. Эталоны, `.be`, `tools/`,
`gold/`, образы и иные документы не трогались.

## 1. МЕТОД И ОГРАНИЧЕНИЕ ИНСТРУМЕНТА

Копии `.be` лежат в
`/tmp/.private/azizz/vneshn-probe/variants/`.
Прогон каждой зоны:

    bash tools/vneshn_probe.sh probe <be> <zone> B <label>

Два варианта на зону:

* `asis` исходный `.be` без правок;
* `first` СТАРТ первая некомментарная строка.

Ограничение штатного `extract` в `vneshn_probe.sh`:
он берёт слово по адресу `i+1`, то есть только базу 0.
Для ненулевых баз он даёт 0/1024 и не годится.
Мы берём слово по адресу `HAM+j` и сверяем его
с `gold[j]` для `j=0..1023`. Это корректно.

HAM в листинге есть адрес первого слова модуля.
При базе 0 HAM=00001, адрес 0 не раздаётся.

## 3. ЗОНА 0147: БАЗА 0

`bemsh/MBE-Z0147.be:216` есть `Z0147 СТАРТ '0'`.
Первая некомментарная строка там же файл :122,
это `OUT477 ЭКВ '477'`, то есть СТАРТ не первая.

* `asis`: 0 ошибок, HAM=00001, 1024/1024.
  Модуль реально лежит в странице 0.
* `first`: 1 ошибка `НОЛЬ ЗАПРОШ1` в строке
  `listing.out:20`. HAM остался 00001.

Вывод: база 0 верна по смыслу, но не может быть
первой картой: транслятор требует ненулевой адрес.
Поэтому СТАРТ отодвинут за блок ЭКВ.
Вердикт SPECIAL, не новая ошибка.

## 4. ЗОНЫ 0152 И 0157: БАЗА 76000

`bemsh/MBE-Z0152.be:43` есть СТАРТ '76000',
первая некомментарная строка файл :24.
`bemsh/MBE-Z0157.be:83` есть СТАРТ '76000',
первая некомментарная строка файл :23.
В обоих файлах сразу за СТАРТ идут `Е` и `М`
(строки 44-45 и 84-85).

* `asis`: 0 ошибок, но HAM=00001. СТАРТ не первая
  карта и не действует. Модуль лежит в странице 0,
  а не по объявленному адресу 76000.
* `first`: HAM=76000, но 1 ошибка `ПEPEПOЛH CЧA`
  (ПЕРЕПОЛН СЧА): `listing.out:2280` у 0152
  и `listing.out:2544` у 0157.
  Причина: 76000+02000 = 100000, выход из 15 бит.

ГИПОТЕЗА (подтверждена всеми 13 прогонами):
СТАРТ задаёт базу, только если он стоит первой
картой модуля. Иначе адрес берётся по умолчанию.

Вывод по байте: база 76000 физически верна
(`analysis/RAM-SNAPSHOT-MAP.md:118,134` дают
1024 EXACT для страницы 37). Ошибка есть
структурное ограничение ИПМ МАКРО-БЕМШ 06/78:
1024 слова занимают 76000..77777, а счётчик
следующего адреса переходит через 100000.
Подробнее `docs/SEMANTIC/B-START-TOP-2.md:61-67`
и `analysis/Z0152-Z0157-BASE-RECHECK.md:1-24`.
В текущем виде база инертна, HAM=00001.
Вердикт SPECIAL: объявленный адрес корректен,
но не кодируется без 1 ошибки. Сдвиг на 75777
даёт 0 ошибок, но физически неверен.

## 5. ЗОНЫ 0161 И 0162: AMBIG С B2

В `analysis/RESIDENT-ZONES.md:33-36` зоны 0161,
0162 помечены ВЫС* как байтовые двойники B2.
Проверка gold дала:

* `MBE-Z0162-L1.bin` = `MBE2-Z0562-L1.bin`
  полностью;
* `MBE-Z0150-L1.bin` = `MBE2-Z0550-L1.bin`
  полностью;
* `MBE-Z0161-L1.bin` против `MBE2-Z0561-L1.bin`
  различается в 19 байт, слова 65, 89, 110, 123,
  126-131, 135.

ГИПОТЕЗА: пометка AMBIG для 0161 неточна,
это близкая, но не равная копия.

Сам базовый тест у 0161 и 0162 чистый:
HAM=24000 и 26000, 0 ошибок, 1024/1024.
Вердикт OK, SPECIAL только по происхождению.

## 6. ЗОНЫ 0170 И 0171: ОВЕРЛЕИ

По `analysis/RESIDENT-ZONES.md:83-84`:

* 0170 делит базу 02000 с зоной 0154;
* 0171 делит базу 04000 с зоной 0155.

Обе зоны в прогоне дают HAM=02000 и 04000,
0 ошибок, 1024/1024. Перекрытие адресов
относится к фазам загрузки, не к базе СТАРТ.
Вердикт OK, SPECIAL по контексту.
