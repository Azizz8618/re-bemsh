Коммитов, push и правок существующих файлов НЕТ.
Промежуточные скрипты и колода: /var/tmp/v78-syntax/masks/.
Адреса восьмеричные. Степень: ↑. Стрелка ->.
Ширина строк <=60 колонок. Типографского тире нет.

Статусы: [ФАКТ], [ГИПОТЕЗА], [НЕ ИЗВЕСТНО].

## 0. ВЕРДИКТ

[ФАКТ] `aex` есть побитовое ИСКЛЮЧАЮЩЕЕ ИЛИ (XOR), а не
И и не И с дополнением. Исходник:
dispak/dispak/arith.c:131-137, строки 134-135:
`acc.l ^= enreg.l; acc.r ^= enreg.r;`.

[ФАКТ] Обе проверки работают в ЛОГИЧЕСКОМ режиме переходов
(G_LOG). Поэтому `uza` (`по`) ветвит тогда и только тогда,
когда слово ACC равно нулю, а `u1a` (`пе`) тогда,
когда ACC ненулевой.

[ФАКТ] Следовательно каждая пара `aex <маска>; uza/u1a`
есть проверка РАВЕНСТВА байта этой маске (для `uza`) либо
НЕРАВЕНСТВА (для `u1a`):

  маска 0xbe + `uza 75364` -> байт == 0xbe
  маска 0xbf + `u1a 75356` -> байт != 0xbf

[ФАКТ] 0xbe есть код БЕМШ маркера конца строки (ASCII 0x5e,
GOST 0115, крышка): это прямо видно в трассе M1.
[ФАКТ] По правилу БЕМШ (dump.c:304-318, зона 0240-0337)
0xbf есть код подчёркивания ASCII 0x5f. Ни один из двух
не есть буква, цифра или разделитель 1967 года.

### 1.3 Какой режим был активен

[ФАКТ] Режим ставится `ntr`/`xtr`, cu.c:615-623:
  G_LOG = enreg.o & 004; G_MUL = & 010; G_ADD = & 020.
В трассах перед 075353 есть `74000: ntr 3`. Какое именно
значение режима действует в 075354 и 075357, прямо из
трассы не прочитать, но поведение ветвлений однозначно
соответствует ТОЛЬКО G_LOG (доказательство ниже).

[ФАКТ] Доказательство по трассе P1a (inp -> res -> ветка):

  0x45 -> 0xe7, u1a ВЗЯТ   (G_ADD дал бы НЕ взят)
  0xbf -> 0x1d, u1a ВЗЯТ   (G_ADD дал бы НЕ взят)
  0xa2 -> 0x1c, uza НЕ ВЗЯТ (G_MUL дал бы ВЗЯТ)
  0xbe -> 0x00, uza ВЗЯТ    (G_ADD дал бы НЕ взят)

Только G_LOG объясняет все четыре строки. Итого: режим
логических переходов. [ФАКТ]

## 2. АЛГЕБРА И ТАБЛИЦА 256 ЗНАЧЕНИЙ

Пусть b есть старший байт ACC перед `aex`. Маска M лежит
в старшем байте слова. После `aex M` старший байт равен
b xor M; остальные 40 битACC в трассах равны нулю.

[ФАКТ] Для 0xbf: `u1a 75356` берётся, если b xor 0xbf != 0,
то есть b != 0xbf. Единственное исключение: b = 0xbf.

[ФАКТ] Для 0xbe: `uza 75364` берётся, если b xor 0xbe == 0,
то есть b == 0xbe.

### 2.1 Группы всех 256 значений старшего байта

  диапазон   кол-во  u1a после 0xbf   uza после 0xbe
  ---------  ------  --------------   --------------
  0x00-0xbd     190   ВЗЯТ             НЕ ВЗЯТ
  0xbe           1   ВЗЯТ             ВЗЯТ
  0xbf           1   НЕ ВЗЯТ          НЕ ВЗЯТ
  0xc0-0xff      64   ВЗЯТ             НЕ ВЗЯТ

### 2.2 Наложение известных байтов БЕМШ

  байт  symb   класс        u1a(0xbf)  uza(0xbe)
  ----  -----  -----------  ---------  ---------
  0x40  space  пробел       ВЗЯТ       НЕ ВЗЯТ
  0x4a  *      знак          ВЗЯТ       НЕ ВЗЯТ
  0x4c  ,      разделитель   ВЗЯТ       НЕ ВЗЯТ
  0x5a  :      разделитель   ВЗЯТ       НЕ ВЗЯТ
  0x5b  ;      разделитель   ВЗЯТ       НЕ ВЗЯТ
  0x50-0x59    цифры         ВЗЯТ       НЕ ВЗЯТ
  0xa1-0xdf    буквы         ВЗЯТ       НЕ ВЗЯТ
  0xbe  ^      конец строки  ВЗЯТ       ВЗЯТ
  0xbf  _      подчёркивание НЕ ВЗЯТ    НЕ ВЗЯТ

[ФАКТ] 0xbe и 0xbf не входят в таблицу 0147.0561 (64 байта),
поэтому это не буквы и не цифры. Их символы определены
через вторую таблицу преобразования GOST -> БЕМШ в
070263+GOST: трасса даёт GOST 0115 (крышка) -> 0xbe.

[ГИПОТЕЗА] GOST 0132 (подчёркивание) -> 0xbf по той же
таблице. Прямо из GOST это не выводилось, так как
подчёркивания в колоде M1 нет.

## 4. ЧТО ЭТО НЕ ЕСТЬ

[ФАКТ] Маски НЕ проверяют старший бит: при `uza` проверяется
нуль всего слова, а не знак. Режим G_MUL исключён трассой.
[ФАКТ] Маски НЕ проверяют класс "буква" или "цифра": все
буквы и цифры дают одинаковый результат.
[ФАКТ] Маска 0xbf не есть проверка на допустимый байт:
она лишь инвертирует условие для одного значения 0xbf.
