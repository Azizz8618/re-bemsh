# КОДЫ 0x40 И 0x01 В КАТАЛОГЕ АРАП

Дата: 22.11.2026. Write set: только этот файл.
Коммитов/push нет. `gold/`, эталоны и существующие
файлы не менялись. Опыты на копиях в
`/tmp/.private/azizz/codes-4001/`, guard `BESM6_PATH`,
md5 образов до/после прогонов совпали.

Статусы: [ФАКТ], [ГИПОТЕЗА], [НЕ ИЗВЕСТНО].
Адреса восьмеричные. Степень: ↑. Ширина <=60 колонок.

## 0. Главный результат

[ФАКТ] `0x40` это ПРОБЕЛ 7-битного внутреннего кода
БЕМШ. Это печатный знак, а не мусор и не "пусто".

[ФАКТ] `0x01` НЕ печатный знак этого кода. Ни одна из
двух ветвей декодера `dump.c` его не покрывает.
Это служебный (непечатный) код.

[ФАКТ] Цикл `076600-076623` меняет в байте `0x40` на
`0x01`. То есть он заменяет пробел архивного каталога
на непечатный код. Назначение этой замены прямо в
коде или текстах не описано (см. §6).

## 3. Что такое 0x40: доказательство по таблице

[ФАКТ] `besmtool/dump.c:330-345`, режим `-b`:

    case 0100 ... 0137: print_iso_char(p[i] - 040);
    case 0240 ... 0337: print_iso_char(p[i] - 0140);
    default: putchar('`');

Отсюда `0x40 - 0x20 = 0x20` = ISO пробел.
Диапазоны кода (GOST-TABLE-DETAILS.md:82-85):

    0x40-0x5f -> ISO 0x20-0x3f (пробел, цифры, знаки)
    0xa0-0xdf -> ISO 0x40-0x7f (латиница + кириллица)

[ФАКТ] Таблица GOST -> БЕМШ в `0147.0563` даёт для
GOST 0o17 (пробел) байт `0x40`. Правило
ISO < 0x40 -> байт = ISO + 0x20 (GOST-TABLE-DETAILS,
§2.3) подтверждена 61/61 на печатных знаках.

[ФАКТ] Независимое подтверждение из
`re-siprod/notes/linker.md:190-194`: имя модуля в
объекте - шесть байт, буквы как `0x80 | код_текста`,
а лишние знаки дополняются "пробелами (`0x40`)".
Пример `CONSUL` = `a3 af ae b3 b5 ac`.

[ФАКТ] Значит байты входного слова цикла надо читать
как 7-битный внутренний код БЕМШ (с омоглифами
C=С, O=О, T=Т, A=А, P=Р, B=В, E=Е).

## 4. Что такое 0x01: граница знания

[ФАКТ] `0x01` не попадает ни в `0x40..0x5f`, ни в
`0xa0..0xdf`. Декодер `dump.c` печатает для него "`".
В таблице GOST -> БЕМШ (`0147.0561-0601`)нет ни
одного значения `0x01`. Это НЕ текстовый знак.

[ФАКТ] В 6-битном коде TEXT (`text_to_gost`,
encoding.cpp:614-615) код 0 есть пробел, код 1 есть
точка. То есть `0x01` не пробел и в TEXT.

[ФАКТ] В GOST-10859 байт `0x01` есть цифра `1`.
Это тоже не пробел.

[НЕ ИЗВЕСТНО] Почему выбран именно `0x01`. Прямого
указания в коде, в текстах 0151/0152 и в документах
`docs/TEXT-CONSTANTS*.md` не найдено.

## 5. Откуда берётся входное слово

[ФАКТ] Точка `76600`, трасса `run-B.err:1041963`.
Первое входное слово берётся `76604 xta 76517(6)`.
R6 = `77766`, база `076517`, адрес `076505`.

[ФАКТ] `M[076505]` пишется кодом `074463-074465`
(трасса `arap-dyn/B-explore.err:1041705`) из таблицы
`076713 + R15`. Таблица `076700+` в gold нулевая,
она заполняется во время счёта из ячеек `00607+`
(зона архива, загруженная с ленты 42).

[ФАКТ] Преобразование `074463-074465` (проверено
арифметикой) есть:

    t := M[076713 + R15]
    M[076522 + R15] := ((A xor B) + t) mod 2↑48

    A = 076406 = 40 40 40 40 40 40
    B = 076407 = 20 20 20 20 20 20
    A xor B       = 60 60 60 60 60 60

[ФАКТ] Источник в младшей памяти - 7-битный код
с пробелом `0x20`, например ячейка `00611`:

    `20 31 30 32 34 20`  = " 1024 "

Пример: t = `43 4f 43 54 41 42` ("COCTAB") даёт
вход цикла `a3 af a3 b4 a1 a2` ("СОСТАВ").

[ФАКТ] Как именно `0x20` источника превращается в
`0x40` перед циклом, подробно не прослежено. Видно
только, что `0x40` на входе уже есть.

## 7. Что означают пробелы в тексте каталога

[ФАКТ] Разбор входных слов по правилу §3 даёт:

    COCTAB    СОСТАВ
    " CTAPT"  СТАРТ с ведущим пробелом
    " 1024 "  число 1024 с пробелами по краям
    TECT C    ТЕСТ, пробел, С
    TAPT 1    СТАРТ, пробел, 1

[ФАКТ] Пробел стоит на границе между именами и
между именем и числом. В job B слово 2 начинается
с `0x40`, то есть пробел отделяет "СОСТАВ" от
"СТАРТ" через границу слов.

[ГИПОТЕЗА] Каталог хранит имя(на) одним потоком
по 6 знаков в слове, а `0x40` разделяет поля.
Цикл оформляет этот поток для машины, меняя знак
разделителя с печатного пробела на `0x01`.

## 8. Сводка статусов

ФАКТ:
  0x40 - пробел 7-битного кода БЕМШ (dump.c:334,
    GOST-TABLE-DETAILS.md:84, таблица 0147.0563);
  0x01 - не печатный знак, декодер печатает "`";
  вход цикла - слово архивного каталога из 006xx;
  замена 0x40->0x01 позиционная, подтверждена
  на двух заданиях и на 6 позициях байт;
 константа 077173 = 0020000000000000.

ГИПОТЕЗА:
  0x01 - внутренний код "пусто"/разделителя в
    машинном представлении каталога (ср.
    HIGH-CORE-LOOP-76600.md:252-255);
  0x40 - разделитель между именами в потоке
    каталога, а не только дополнение поля.

НЕ ИЗВЕСТНО:
  Semantic reason for choosing 0x01;
  ветка `76614 uza 76621` для двух подряд `0x40`;
  почему 077170/077171 лежат рядом с константой;
  полный формат записи каталога АРАП.
