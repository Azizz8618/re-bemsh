Дата: 23.11.2026. WRITE-SET: только этот НОВЫЙ файл.
Коммитов, push, правок существующих файлов НЕТ.
Промежуточные скрипты: /var/tmp/v78-syntax/encoding/.
Адреса восьмеричные. Степень: ↑. Стрелка ->.
Ширина строк <=60 колонок. Типографского тире нет.

Статусы: [ФАКТ], [ГИПОТЕЗА], [НЕ ИЗВЕСТНО].

## 0. ВЕРДИКТ

[ФАКТ] Байт пробела в коде ИСТОЧНОЙ СТРОКИ 06/78 есть
0x40 (BESM-кодировка, таблица 0147.0561). Байты
разделителей 1967 года в той же кодировке:
`:` = 0x5a, `,` = 0x4c, `;` = 0x5b, `*` = 0x4a.

[ФАКТ] Шесть масок 076325-076332, прочитанные из образа,
есть ровно шесть независимых 8-разрядных масок
(0xff в одном байте). Они нужны `сбр`/`рзб`, чтобы
выделить и собрать по одному байту 48-битного слова.

[ФАКТ] Ни в одном принудительном листинге зон 0137-0177
нет ни одной НЕПОСРЕДСТВЕННОЙ константы, равной
байтам БЕМШ-разделителей (0x5a, 0x4c, 0x5b, 0x4a),
ни байту пробела 0x40. Единственная найденная
побайтовая проверка есть тест на 0x40 (076317) в
цикле 076600-076623. Проверки на `:`, `,`, `;`
в сохранившемся коде НЕ НАЙДЕНЫ.

[НЕ ИЗВЕСТНО] Существовала ли в 06/78 процедура, которая
переводила бы 0x5a/0x4c/0x5b в 0x40 по правилу 1967
года. Прямого свидетельства в зонах 0137-0177 нет.

## 2. ТАБЛИЦА БАЙТОВ

[ФАКТ] "БЕМШ" ниже есть байт кодировки БЕМШ из TAB.
Это 8-битное значение с двумя зонами; его "7-битность"
означает лишь происхождение от 7-битного ISO
(GS-TABLE-0147-0561.md §2). TEXT есть 6-битный код
ASCII-0x20.

### 2.1 Пробел, разделители, цифры

  сим    GOST   БЕМШ   TEXT   роль
  -----  -----  -----  -----  ---------
  space  0x0f   0x40   0x00   пробел
  :      0x1f   0x5a   0x1a   разделитель
  ,      0x0d   0x4c   0x0c   разделитель
  ;      0x16   0x5b   0x1b   разделитель
  *      0x19   0x4a   0x0a   знак
  .      0x0e   0x4e   0x0e   точка
  /      0x0c   0x4f   0x0f   слэш
  -      0x0b   0x4d   0x0d   минус
  0..9   0x00.. 0x50.. 0x10.. цифра
         ..0x09 ..0x59 ..0x19

[ФАКТ] Все значения проверены побайтово:
GOST-столбец из GOST_CYR, БЕМШ из TAB, TEXT из
ord(сим) - 0x20. Скрипт
/var/tmp/v78-syntax/encoding/byte_table.py.

### 2.2 Буквы

[ФАКТ] Кириллица (реальный алфавит исходных строк):

  А 20 a1   Б 21 c2   В 22 a2   Г 23 c7
  Д 24 c4   Е 25 a5   Ж 26 d6   З 27 da
  И 28 c9   Й 29 ca   К 2a ab   Л 2b cc
  М 2c ad   Н 2d a8   О 2e af   П 2f d0
  Р 30 b0   С 31 a3   Т 32 b4   У 33 b9
  Ф 34 c6   Х 35 b8   Ц 36 c3   Ч 37 de
  Ш 38 db   Щ 39 dd   Ы 3a d9   Ь 3b d8
  Э 3c dc   Ю 3d c0   Я 3e d1

[ФАКТ] Явные латинские глифы GOST есть только для
14 букв: 0x3f D, 0x40 F, 0x41 G, 0x42 I, 0x43 J,
0x44 L, 0x45 N, 0x46 Q, 0x47 R, 0x48 S, 0x49 U,
0x4a V, 0x4b W, 0x4c Z. Остальные A B C E H K M O P
T X Y пишутся кириллическими омоглифами.

[ФАКТ] TEXT-код латинской буквы есть ord - 0x20,
то есть A = 0x21, B = 0x22, ..., Z = 0x3a. Для
кириллицы 6-битного кода нет; 6 омоглифов читаются
как A B E M O P (a1 a2 a5 ad af b0).

## 3. МАСКИ 076325-076332 ИЗ ОБРАЗА

[ФАКТ] Зона 0152 имеет базу 076000 (ZONE-BASE-MAP.md
§3, код RSM/MAR, статус ФАКТ). Поэтому адресу 076325
соответствует слово 0325 файла gold/MBE-Z0152-L1.bin.

[ФАКТ] Прочитано напрямую побайтово:

  адрес   слово  байты         вид
  ------  -----  ------------  ------------
  076317  0317   40 00 00 00 00 00  тест 0x40
  076325  0325   ff 00 00 00 00 00  байт 0
  076326  0326   00 ff 00 00 00 00  байт 1
  076327  0327   00 00 ff 00 00 00  байт 2
  076330  0330   00 00 00 ff 00 00  байт 3
  076331  0331   00 00 00 00 ff 00  байт 4
  076332  0332   00 00 00 00 00 ff  байт 5
  077172  1172   38 00 00 00 00 00  старт ACC
  077173  1173   01 00 00 00 00 00  замена 0x01

[ФАКТ] Это ровно шесть масок вида 0xff << (8*k),
k = 0..5. Ни одна не содержит битов вне своего байта.
Подтверждено HIGH-CORE-LOOP-76600.md §2.

## 4. 6 СИМВОЛОВ В 48 БИТ И РАБОТА сбр/рзб

[ФАКТ] Слово БЭСМ-6 есть 48 бит = 6 байт. Порядок:
старший байт на позиции 47..40, младший на 7..0
(text_decode_all.py, bytes8).

[ФАКТ] apx() / КОП 020 / `сбр`:
dispak/dispak/arith.c:405-425, тело 406-425.
Цикл по битам маски `enreg` (строки 408-421): для
каждого установленного бита маски берётся очередной
младший бит `acc` и вдвигается вправо в `accex`.
Строки 422-424: результат пишется в `acc`.
С маской 0xff0000000000 это выделяет байт 0 в
младшие 8 бит. Это ПЕРЕСТАНОВКА битов, не И/ИЛИ.

[ФАКТ] aux() / КОП 021 / `рзб`:
dispak/dispak/arith.c:427-456, тело 428-456.
Два цикла по 24 бита (433-442 и 443-451) перебирают
биты маски и раскладывают младшие биты `acc` по
позициям маски. С байтовой маской это обратная
операция: один байт из младших 8 бит уходит на свою
позицию в слове. Строки 452-455: запись в `acc`.

[ФАКТ] В цикле 076600 индексы масок идут
(076332 + R) & 077777 при R = 77773(-5) ... 0
(HIGH-CORE-LOOP-76600.md §2, §6). R2 для `сбр` и
R4 для `рзб` пробегают все шесть байт, по одному за
итерацию. Формула одного байта:

  out_b = (in_b == 0x40) ? 0x01 : in_b

[ФАКТ] Символьного смысла у 0x01 внутри `сбр`/`рзб`
нет: это обычный операнд-счётчик (CODE-01-EXACT.md
§3). Проверка 0x40 делает `нтж 76317` (076611),
то есть XOR с условным словом 076317.

## 5. ПОИСК НЕПОСРЕДСТВЕННЫХ КОНСТАНТ

[ФАКТ] Просканированы 23 файла dis-forced/Z01*.asm
от Z0137 до Z0176 (принудительных листингов Z0147 и
Z0177 нет). Скрипт
/var/tmp/v78-syntax/encoding/scan_immed.py:
для каждой команды выделялся операнд без кавычечных
адресов, а голые восьмеричные числа сравнивались
по значению с байтами таблицы §2.

### 5.1 Чистый отрицательный результат

[ФАКТ] БЕМШ-байты разделителей НЕ встречаются ни в
одном голом операнде:

  0x40 = 0100 : 0 попаданий
  0x5a = 0132 : 0 попаданий
  0x4c = 0114 : 0 попаданий
  0x5b = 0133 : 0 попаданий
  0x4a = 0112 : 0 попаданий

То есть ни один `:`, `,`, `;` или пробел кода строки
не загружен непосредственной константой.

### 5.2 Положительные, но неспецифичные попадания

[ФАКТ] ГОСТ-байты и TEXT-коды совпадают с мелкими
смещениями, которых в листингах сотни. Примеры с
точными file:line:

  GOST space 0x0f (oct 17), 77 hits:
    dis-forced/Z0137.asm:369   сч 17(М7)
    dis-forced/Z0140.asm:813   и 17(М7)
  GOST ':' 0x1f (oct 37), 46 hits:
    dis-forced/Z0137.asm:318   сч D00100+37(М7)
    dis-forced/Z0137.asm:535   и 37(М7)
  GOST ',' 0x0d (oct 15), 144 hits:
    dis-forced/Z0137.asm:416   сда 64+15
    dis-forced/Z0137.asm:888   сда 64-15
  GOST ';' 0x16 (oct 26), 53 hits:
    dis-forced/Z0137.asm:449   и 26(М7)
    dis-forced/Z0137.asm:1300  сч D00100+26(М7)
  GOST '*' 0x19 (oct 31), 27 hits:
    dis-forced/Z0137.asm:480   сл 31(М7)
  TEXT ':' 0x1a (oct 32), 53 hits:
    dis-forced/Z0137.asm:514   сч 32(М7)
  TEXT ',' 0x0c (oct 14), 76 hits:
    dis-forced/Z0137.asm:356   и 14(М7)
  TEXT ';' 0x1b (oct 33), 43 hits:
    dis-forced/Z0137.asm:520   сч 33(М7)
  TEXT '*' 0x0a (oct 12), 156 hits:
    dis-forced/Z0137.asm:340   и 12(М7)
    dis-forced/Z0137.asm:1226  сда 64-12

[ФАКТ] Все они суть индексы регистров, сдвиги
`сда 64 +/- N` или смещения `D00100+N`, а не
проверки байта. Контекст побайтового сравнения
(PACK затем `нтж` с константой) у них отсутствует.

### 5.3 Слова-константы

[ФАКТ] Принудительные листинги не содержат строк
`конд` вообще (проверено: 0 по всем 23 файлам),
поиск слов вида 0xXX0000000000 в них бессмыслен.

[ФАКТ] В сырых gold-зонах 0137-0177 слова с нужным
старшим байтом есть (например 0x40 в старшем байте
встречается 285 раз). Но единственное слово,
подтверждённо используемое как побайтовая маска,
есть 076317 = 0x400000000000. Аналогов для
0x5a, 0x4c, 0x5b в роли маски сравнения не найдено.

## 6. ЧТО ДОЛЖЕН СРАВНИВАТЬ ТОКЕНИЗАТОР

[ФАКТ] По правилу 1967 года (BEMSH-SYNTAX-SOURCES.md
§3.1-§3.2) разделители `:`, `;`, левая `,` заменяются
пробелами. В кодировках 06/78 это было бы:

  код       space  :     ,     ;
  BESM      0x40   0x5a  0x4c  0x5b
  GOST-8    0x0f   0x1f  0x0d  0x16
  TEXT-6    0x00   0x1a  0x0c  0x1b

[ФАКТ] Для побайтовой проверки по образцу 076611
потребились бы слова-маски с байтом в старшей позиции:

  0x400000000000  уже есть: 076317
  0x5a0000000000  (2640000000000000) не найдено
  0x4c0000000000  (2300000000000000) не найдено
  0x5b0000000000  (2660000000000000) не найдено

[ГИПОТЕЗА] Если разбор строк всё же существует в
несохранившейся или внешней части 06/78, он должен
сравнивать распакованный байт с 0x5a / 0x4c / 0x5b
(код строки) либо с 0x1f / 0x0d / 0x16 (GOST-текст
констант). Прямого кода в зонах 0137-0177 нет.

[НЕ ИЗВЕСТНО] Где именно в 06/78 хранится текст
программы на входе: в коде БЕМШ (тогда 0x40) или в
GOST (тогда 0x0f). Трасса цикла 076600 показывает
БЕМШ-байты на входе архива, но это каталог АРАП, а
не исходный текст символ за символом.

## 7. СВОДКА СТАТУСОВ

ФАКТ:
  TAB 0147.0561 прочитана из gold, 64 байта;
  space=0x40, ':'=0x5a, ','=0x4c, ';'=0x5b (БЕМШ);
  GOST space=0x0f, ':'=0x1f, ','=0x0d, ';'=0x16;
  TEXT space=0, ':'=0x1a, ','=0x0c, ';'=0x1b;
  маски 076325-076332 есть 6x 0xff в своём байте;
  076317 есть 0x40 в старшем байте;
  apx=arith.c:406-425, aux=arith.c:428-456;
  сбр/рзб суть перестановка битов по маске;
  ноль голых immediates равных БЕМШ-байтам;
  единственная проверка байта есть тест 0x40.

ГИПОТЕЗА:
  таблица разделителей 1967 года действовала и в
  06/78, но в другой (несохранившейся) процедуре;
  замена 0x5a/0x4c/0x5b на 0x40 происходила до
  попадания строки в пул текста.

НЕ ИЗВЕСТНО:
  адрес и мнемоника такого сканера;
  есть ли он вообще в 06/78;
  где именно хранится входной текст: БЕМШ или GOST;
  почему в 06/78 нет ни одной маски для ':' ',' ';'.
