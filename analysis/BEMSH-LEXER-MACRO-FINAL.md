# Лексический разбор и макромашина БЕМШ 06/78: полный отчёт

Дата: 24.11.2026. Цель: установить и полностью описать механику
лексического разбора входящего потока и макромашины БЕМШ.
Объект: только ВЕР.06/78, зоны 0137-0177 тома 2048/2348.
Авторитетный код: только dis-forced/*.asm.
Адреса восьмеричные, степень ↑, тире НЕ используется.

## 0. Короткий вердикт

ФАКТ. Механика входящего потока установлена и описана: Э70-ввод,
барабанный мост, RLE-нормализация, побайтовый диспетчер, упаковка,
проверка маркеров, решение о метке, рабочая копия, слоты листинга
и дескриптор пула. Цепочка из 28 шагов имеет PC- и байтовое
подтверждение (`analysis/LEX-INPUT-STREAM-FULL.md`).

ФАКТ. Четырёхполевого парсера МЕТКА/ОПЕРАЦИЯ/ОПЕРАНД/КОММЕНТАРИЙ
в версии 1978 года НЕТ. Ни один из проверенных PC не получает на вход
номер поля: все реагируют на ЗНАЧЕНИЕ байта. Поля листинга создаются
механически, каждые 6 байт (04201, 04206). Это НЕ «не нашли», а
положительное описание того, что работает вместо парсера.

ФАКТ. Макромашина идентифицирована: её интерпретатор лежит в зоне
**0172** (база 02000), а не в 0170, как считалось раньше. Байтовое
доказательство по 27 полукомандам подряд. Зона 0170 работает только
на входе, зона 0154 — редактор до неё.

ГИПОТЕЗА. Отождествление конкретных PC с мнемоникой макрокоманд
(ЭКВ, АIF) остаётся гипотезой: исходника транслятора 1978 года нет.
Само исполнение адресов — ФАКТ.

## 2. Макромашина

### 2.1. Оверлеи и байтовое доказательство

```
0154 (редактор) → 0170 (вход: ntr 3, uj 2214, штамп 02216)
                → 0172 (ядро интерпретатора), всё по базе 02000
```

Байтовая проверка PC 03453 (offset 01453):

```
0172:01453 = 3e 07 33 10 80 00 → пио '3463'(М3) / сч (М1)
0170:01453 = f0 d0 02 0c 05 2a → или 2(М17) / пб '2452'
```

Трасса даёт именно первую пару. 27 полукоманд подряд совпали по
тройке (код, адрес, регистр). Полная карта:
`analysis/MM-STATIC-DYN-MAP.md`, `analysis/MM-ZONE-0172-FULL.md`.

Две причины «один PC — разные команды»: чередование L/R половин
одного 48-битного слова и смена оверлея 0154 → 0170 → 0172.

### 2.2. Ядро интерпретатора (зона 0172)

| Адрес | Мнемоника | Роль |
|---|---|---|
| 03451-03452 | пролог | подготовка |
| 03453-03460 | тело | работа с параметром |
| 03461-03462 | `пе '3453'` | возврат в цикл |
| 03463-03465 | выход | при М3 = 0 |
| 03515 | счётчик | 0060 → 0001, 48 шагов |

Счётчик М3 идёт `00061 → 0`. Результат ЭКВ идёт
`02002/3/4 → 02001 → 73266 → *МЕТ*`.
Статика 0172 на `03573/03574/03607/03610/03611` совпала с трассой.

### 2.3. Подстановка ∧-параметров

- `07776/07777+r4` — пара VALUE/TAG;
- одна регистрация = **+2 ячейки ГС**; счётчик `01201` пишется
  командой `03440 зп 1201`;
- `:` объединяет метку и операцию → на одну регистрацию меньше →
  −2 ячейки (`analysis/V78-COLON-GS.md`);
- `AIF`: `04160/03342/03343` вычисляют 1/0 из `&v` в `77000`;
- `ЕВНЕШ`: `Δ BHEШH = 00056₈ = 46` внешних символов E1..E48.

Полное описание: `analysis/MM-PARAM-SUBSTITUTION.md`.

### 2.4. Каталог команд

37/37 команд из `macros.be:1-234` перечислены в
`analysis/MM-COMMAND-CATALOG.md`, совпадают с `MACRO-COMMANDS.md`.
Исходные колоды объявляли макрос, но не вызывали его (`ДЛИHA=00000`),
поэтому динамики не было. Новый корпус из 24 колод
(`tests/decks/macro_manifest.json`, `analysis/MM-CALL-DECKS.md`) дал:

- 23/24 колоды с реальной развёрткой;
- эффект развёртки у **37/37** команд;
- собственный исполненный PC в MACHINE у **8/37**
  (позиции 4, 8, 10, 11, 12, 14, 15, 21);
- впервые исполнены `03515, 03573, 03574, 03607, 03610, 03611,
  04146, 04147, 04151, 03342, 03343` и запись `73266`;
- 29 позиций имеют эффект развёртки, но их PC остаются
  НЕ ИЗВЕСТНО.

## 3. Что НЕ ИЗВЕСТНО

1. Привязка PC к мнемонике макрокоманд без исходника 0170 —
   ГИПОТЕЗА.
2. 29 позиций каталога без собственного исполненного PC.
3. Причина затирания вывода `01413` каналом `01675`.
4. Триггер выбора нормализованного потока для печати или пула.
5. 57 литералов зоны 0137 без значения.
