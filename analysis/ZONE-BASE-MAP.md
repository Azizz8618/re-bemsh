# ZONE-BASE-MAP: базы загрузки 69 зон B/B2

Дата: 22.11.2026. WRITE-SET: только этот файл.
Коммитов/push нет. Эталоны, `.be`, `gold/` не менялись.
Цель: карта «дисковая зона -> база ОП» как основа для
классификации 2676 процедурных меток
(`analysis/PROC-LABEL-INVENTORY.md:64`).

Статусы, как в смежных отчётах:

- [ФАКТ] база измерена снимком ОП, bp или DD-трассой.
- [ГИПОТЕЗА] есть кандидат, прямого измерения нет.
- [НЕ ИЗВЕСТНО] база нигде не измерена.

Восьмеричные адреса: `076000` = `76000` (одиночные ведущие
нули опущены). Ширина строк <=60 колонок. Степень: `↑`.

## 1. МЕТОД И ПРАВИЛА

1. База страницы ОП = `страница * 02000₈`. Механизм в
   `dispak/dispak/extra.c:1914-1916` (`disk_readi` в
   `core + page*02000`) и `extra.c:2766-2796` (`addr =
   (uil.i_addr & 03700) << 4`). См. `MEMORY-MAP.md:29-30`.
2. Штамп: `адрес в ОП = база + номер слова зоны`.
   Подтверждено для 0154 (`02000 + 0751 = 02751`) и 0170
   (`02000 + 0216 = 02216`), `PCL:62,88`.
3. `СТАРТ` в `.be` задаёт базу листинга/сборки, а не всегда
   физическую базу. Для резидентных зон они совпадают
   (кроме 0147, 0152, 0157). Для остальных `СТАРТ '10000'`
   это условие трансляции по указанию оператора, не факт
   загрузки (`RESIDENT-ZONES.md:238-243`,
   `B-START-BASES-1.md:10-14`). Поэтому статический
   `СТАРТ '10000'` сам по себе НЕ даёт статус ФАКТ.
4. Окно зоны = `[база, база + 02000₈)`, то есть 1024 слова.
   Адрес цели ВНУТРЕННИЙ, если он попадает в окно.
   Для базы 76000 окно обрезано 15-битным максимумом
   `077777` (`76000 + 02000 = 100000` вне поля).

## 5. ОСОБЫЕ СЛУЧАИ

### 5.1 0147: база 00000 против `СТАРТ 1`

[ФАКТ] Физическая база `00000₈`: штамп `0147.1315` лежит
по адресу `01315₈`, страница 00 совпадает с gold на
1024/1024 (`RZ:10-25`, `MM:113`, `RSMAP:103`).
[ФАКТ] Гипотеза «1-based слово, база 00001» опровергнута
сверкой штампа 0154 (`RZ:27-31`).
[ФАКТ] Транслятор отвергает нулевой операнд
(`НОЛЬ ЗАПРОШЕН`), поэтому `СТАРТ 1` даёт HAM 00001
(`RZ:56-60, 83-92`, `SFIX:53-64`).
Вывод: база ОП = 00000, база сборки = 1. Это не
«база неизвестна». См. `RESIDENT-ZONES.md:266-271`.

### 5.2 Оверлей страницы 01: 0154 -> 0170 -> 0172

[ФАКТ] Три загрузки Э70 в базу 02000 за прогон
(`POV:74-94`):

| N | строка трассы | зона | первая команда 02000 |
|---|---------------|------|----------------------|
| 1 | 887201 | 0154 | `xta 6065` |
| 2 | 1136221 | 0170 | `ntr 3` |
| 3 | 1249619 | 0172 | нет (буфер) |

[ФАКТ] 0154: штамп `0154.0751` по `02751`, база
`02751 - 0751 = 02000` (`PCL:57-69`).
[ФАКТ] 0170: штамп `0170.0216` по `02216`, база
`02216 - 0216 = 02000` (`PCL:71-95`).
Побайтовая сверка 0154 против 0170 = 0/1024, значит
это разные зоны в одной странице, а не artefact
энтропии (`RX:78-85`).
Старая гипотеза «0170 лежит на 072000» ошибочна
(`MM:10-12`, `PCL:177-195`).

### 5.3 Общие базы пар 0151/0153 и 0152/0157

[ФАКТ] 74000: ранняя фаза = 0151, фаза транслятора =
0153. 76000: ранняя фаза = 0152, фаза транслятора =
0157 (`RSMAP:190-193`, `RSM:158-161`).
Различает фаза, не адрес. Для классификации меток
адрес в 74000-75777 внутренний и для 0151, и для 0153.

### 5.4 0152 -> 076000 (АРАП)

[ФАКТ] В задании B (sostav.b6) DD-трасса даёт
`DD pc=01223L u=30 z=0152 RD,
uil=10/0/3700 -> база 076000` (`MAR:60-67`).
`076000` это та же восьмеричная база, что `76000`
(6 цифр против 5), страница 37.
[ФАКТ] Дамп по `01735`: слово `076000` побайтово равно
слову 0 `gold/MBE-Z0152-L1.bin` (`MAR:68-75`).
[ФАКТ] Код зоны 0152 исполняется: 67011 командных
строк в `076000-076077`, 481 переход на `076000`
(`MAR:77-140`).
[ФАКТ] Физическая база `76000` также подтверждена
снимками (`RSMAP:118`, `Z0152-Z0157-BASE-RECHECK.md:9-16`).
Конфликт: `PAT:102-135` (задание REG-listing) не нашёл
0152 ни в трассе, ни в дампе, а `MAR:24-27` прямо
называет этот вывод неверным для задания B. Разные
задания, разные фазы.

### 5.5 0157 и компромисс `СТАРТ '75777'`

[ФАКТ] Физическая база 0157 = 76000 (`RSMAP:134`).
В `.be` записано `СТАРТ '75777'` (`SFIX:6-12`): при
76000 транслятор даёт `ПEPEПOЛH CЧA`, так как 1024
слова плюс служебное слово выходят за `100000₈`.
`75777` даёт 0 ошибок и 1024/1024 слов, но окно
`75777-77776` на 1 слово короче физической страницы.
То же относится к 0152. См. `RBA:72-104`,
`Z0152-Z0157-BASE-RECHECK.md:18-25, 56-85`.

### 5.6 0172: третья загрузка страницы 01

[ФАКТ] Строка 1249619 DD-трассы: `z=1772`, физическая
зона 0172, база 02000 (`POV:83-91`). После неё
выполнение по 02000 не возобновляется, это буферная
подсадка.
[ФАКТ] Независимо: дамп конца прогона REG-listing
показывает страницу 01 = 0172, 884/1024 слова
(`PAT:119-136`).
[НЕ ИЗВЕСТНО] Роль буфера и момент смены не
установлены (`POV:188-189`, `PAT:164-165`).
Конфликт: в 18 снимках `RAM-SNAPSHOT-EXTRA.md:102-116`
0172 помечена NON-RESIDENT (max 203/1024). Картина
зависит от задания и фазы.

### 5.7 0174/0175/0177: таблицы без основной копии

[ГИПОТЕЗА] Кандидатская база 72000 (страница 035) даёт
991/1020/669 совпавших слов, но та же область
совпадает и со страницей 033 (база 66000)
(`MM:122-124`, `RX:113-116`, `MM:209-214`).
Низкая энтропия: это таблицы ошибок, не код. Какая
копия «основная», по содержимому дампа неразличима
(`RESIDENT-ZONES.md:216-218`, `MM:170-171`).
Поэтому база помечена ГИПОТЕЗА, а не ФАКТ.

### 5.8 0137: гипотеза `СТАРТ 1` -> 00001?

[НЕ ИЗВЕСТНО] Физическая база 0137 не измерена. Прямой
перебор всех Э70-чтений не нашёл загрузки зоны 0137
ни в одном задании (`POV:172-178`, `MM:134-142`,
`RX:127-128`). Снимки дают max 1/1024 (`RX:104`).
[ФАКТ] Текущая шапка: `Z0137 СТАРТ '10000'`
(BER). Это произвольная база для паспортной зоны,
не измеренный адрес (`B-START-BASES-1.md:10-14`).
[ГИПОТЕЗА] Старые записи фиксируют `Z0137 СТАРТ 1`
(`DIS:27-29`) и HAM 00001 до переноса строки
(`BS1:16-17, 43`). Отсюда гипотеза «база 00001?».
Она НЕ подтверждена: HAM 00001 это fallback
транслятора, а не физический адрес (аналогично
0147, `RZ:60-61`). База 00001 в Приложении A не
приписана ни одной зоне как факт.

## 6. ПРОТИВОРЕЧИЯ МЕЖДУ ИСТОЧНИКАМИ

1. 0147: база 00000 (`MM:113`, `RZ:31`) против
   `СТАРТ 1`/HAM 00001 (`SFIX:5`). Разрешено: физика
   против синтаксиса сборки, обе записи верны.
2. 0152/0157: 76000 физическая против 75777 в `.be`
   (`SFIX:6-12`) и 00001 в старых шапках
   (`RBA:40,45`). Разрешено: физическая база ОП = 76000.
3. 0170: 02000 (`PCL:88`) против старого поиска по
   072000 (`MM:10-12`). Старый поиск признан ошибкой.
4. 0152: 076000 в задании B (`MAR:66`) против
   «не найдена» в REG-listing (`PAT:135`). Разные
   задания, вывод PAT для B неверен (`MAR:24-27`).
5. 0172: Э70-загрузка 02000 (`POV:83`) и 884/1024
   (`PAT:133`) против NON-RESIDENT в 18 снимках
   (`RX:112`). Фазы и задания различаются.
6. 0137: `СТАРТ 1` (`DIS:28`) против текущего
   `'10000'` (BER) против HAM 00001 (`BS1:43`).
   Физическая база остаётся неизвестной.
7. `RSM:163` говорит «0152-0153 на ранних точках
   (оверлей)», но таблица `RSM:146-158` и §5
   относят их к найденным. Принята таблица, как в
   `RESIDENT-ZONES.md:169-172`.
8. `AMBIG` у 0150/0161/0162 (`RSM:39-43`) не отменяет
   базу: байтовые двойники B2 лежат на тех же
   страницах, том 2048 грузит копию 06/78.
