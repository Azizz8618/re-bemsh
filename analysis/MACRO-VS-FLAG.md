## 1. СТАТИКА: точные условия АIF

Из `/home/azizz/Yandex.Disk/re-dispak/macros.be`.

| № | макрос | строки | условие | ветка |
|---|--------|--------|---------|-------|
| 25 | ВХОДС | 16-21 | `АIF (∧ВS ЕQ 0).К` | 19 `ВХОД` |
| 24 | ВХОДБ | 24-29 | `АIF (∧ВS ЕQ 1).К` | 27 `ВХОД` |
| 19 | ВНЕШБ | 32-37 | `АIF (∧ВS ЕQ 1).К` | 35 `ВНЕШ` |
| 20 | ВНЕШС | 40-45 | `АIF (∧ВS ЕQ 0).К` | 43 `ВНЕШ` |

| 28 | КОНДС | 55-59 | `АIF (∧ВS ЕQ 0).К` | 57 `КОНД` |

[ФАКТ] Б-вариант означает 1, С-вариант означает 0.
 метка `.К` всегда ведёт к `АНОП/АNОР` (кода нет).
 В ВХОДС/ВХОДБ/ВНЕШБ/ВНЕШС перед АIF стоит
 `GВLА ∧ВS` (строки 17, 25, 33, 41).
 В КОНДБ/КОНДС объявления нет: читают глобал напрямую.

[ФАКТ] Конфигурационный регион СВС, строки 120-164:
```
 120 МАСRО
 121 Б
 122 GВLА ∧ВS,∧G,∧МЫ,∧В,∧НС,∧GL,∧SАS
 123 GВLВ ∧З,∧С,∧Ф,∧Н,...
 129 * ... ДЛЯ СВС МЕНЯЮТ ЗНАЧЕНИЕ
 130 ∧ВS SЕТА 1
 135 ∧С SЕТВ 1
 136 ∧Н SЕТВ 0
 161 АIF ((∧ВS ЕQ 0) ОR (∧ЭФ ЕQ 1)).НЕТАС
 162 ∧SАS SЕТА 1
 163 .НЕТАС АNОР
```

[ФАКТ] В macros.be `∧ВS` объявлен в `GВLА`
 (арифметическая), а не в `GВLВ`, и пишется
 через `SЕТА`, а не `SЕТВ` (C:24,28 называют его
 булевым). Противоречие источника налицо.

Две конфигурации по тексту макросов:

* `∧ВS == 1`: срабатывают ВНЕШБ, ВХОДБ, КОНДБ;
  ВНЕШС, ВХОДС, КОНДС пропускаются (АНОП).
* `∧ВS == 0`: ровно наоборот.

## 2. ДИНАМИКА: снятие прежнего отрицания

### 2.1 Что мешало раньше

[ФАКТ] `MACRO-OPS-MISC-DYN.md` §3.7: V60/V61 дали
одинаковую сводку. Причины по нашим пробам:

1. На верхнем уровне `gbla &vs` и `&vs seta 0/1`
   дают `TEPM HE OПP` (S_GBLA_SETA_1, S_SETA_*).
   `∧ВS` там ещё не объявлен.
2. В user-макросе `gbla &vs` + `seta 0/1` и
   `setv 0/1` меняют только локальную переменную:
   FPM_0/FPM_1, M_SETA_*, M_SETV_* дали одинаковый
   вывод (Б-варианты), `MAKPO C OШИБ` для SETV.
3. В V20_C1/V21_C0 строка `&m внешб xb` есть
   рекурсивный вызов самого `тконд`, а не встроенный
   `ВНЕШБ`. Вызова конфигурации не было вовсе.
4. В V50-V53 стоял `&m текст п'...'`; по §3.4 того
   же файла `&m` перед ТЕКСТ даёт `OПEPAЦИИ HET`,
   то есть слов не было по независимой причине.

[ФАКТ] Рабочий переключатель, найденный в опытах:
 вызов встроенного конфигурационного макроса `Б`.
 Без вызова `∧ВS` равен 1 (P1_BUILTIN, S_NONE).
 Вызов `б` после блока `MACRO` даёт 0 (GATE_0,
 DUP_B_CALL, B_DUP_ARG_*). Прямое `seta 0/1`
 внутри переопределённого `Б` разницы не даёт
 (REDEF_B_0 == REDEF_B_1 == CFG_FULL_0 ==
 CFG_FULL_1): все дают С-варианты.

### 2.2 Два минимальных задания

Оба задания одинаковы до последнего аргумента.
Разница ровно один символ: `тф 1` против `тф 0`.

```
 macro
 &m тф &v
  aif (&v eq 1).к
  б
 .к анop
  mend
  тф 1        | тф 0
  внешб xb
  внешс xc
  входб eb
  входс ec
  кондб kb
  кондс kc
  финиш
```

Идея: AIF на формальном параметре открывает вызов
`Б`. Это реальный конфигурационный регион
(macros.be:120-164), а не самодельная запись флага.

[ФАКТ] GATE_1 (`тф 1`): AIF истина, переход на `.к`,
 `б` НЕ вызывается. GATE_0 (`тф 0`): AIF ложь,
 `б` вызывается.

## 3. ТРАССА: где читается и пишется флаг

### 3.1 Статическая невидимость

[ФАКТ] `disbesm6 -a3450 -e3466 dis/MBE-Z0170-L1.asm`
печатает 03450-03465 как `конд в'...'`, то есть
данные. Мнемоники `vzm`, `utm`, `u1a`, `v1m`
получены только из живой трассы. Это совпадает
с `MACRO-OPS-LOOP-DYN.md` §6. Полного статического
соответствия «слово зоны 0170 ↔ команда» нет.

### 3.2 Вход в макромашину

[ФАКТ] Обе трассы: `02000: ntr 3` на строке 192584.
Дальше идёт оверлей page 01 (02000-03777).

### 3.3 Чтение значения AIF (формальный &v)

Номера строк = позиции в `.stderr.txt` (1-based).

| линия | GATE_1 (`1`) | GATE_0 (`0`) |
|-------|--------------|--------------|
| 199305 | `05651: store ...0121` | `...0120` |
| 199311 | `04160: aex 5542` acc=0121 | acc=0120 |
| 199351 | `03342: aex 5640` acc=1 | acc=0 |
| 199352 | `03343: u1a 3434` не взят | взят |
| 199354 | `03433: xta 5441 (=1)` | - |
| 199353 | - | `03434: xta 5447 (=0)` |
| 199359 | `77000: store ...0001` | - |
| 199358 | - | `77000: store ...0000` |

[ФАКТ] 05651 содержит код аргумента: `0121` это `1`,
 `0120` это `0` в печати GOST. `04160 aex 5542`
 сравнивает с константой `0120`, результат 1 или 0.
 `03342` превращает его в логический результат.
 `03343 u1a 3434` ветвит: при 0 идём на 03434
 (константа 0), иначе на 03433 (константа 1).
 Результат пишется в `77000` через `02452 atx (17)`
 с `r[17]=77000`. Это адрес ОП, не зона диска.

## 4. Итог по уровням

ФАКТ:
* шесть АIF-условий выписаны в §1; `Б=1`, `С=0`;
* `∧ВS` в macros.be объявлен GВLА и пишется SЕТА;
* default без вызова `б` даёт `∧ВS=1`;
* вызов `б` даёт `∧ВS=0` и переключает Б/С;
* прямой `seta/setv 0/1` на `&vs` в user-макросе
  переключения не даёт;
* два задания, разные одним символом, дают
  разные имена в *MET*: XB/EB/KB против XC/EC/KC;
* счётчики `ВНЕШН`, `ВХОДН`, меток, слов и ошибок
  одинаковы; разница только в выбранных символах;
* трасса локализует чтение и ветвление AIF
  (05651, 04160, 03342, 03343, 03433/03434, 77000).

ГИПОТЕЗА:
* `0121/0120` в 05651 есть GOST-коды цифр 1 и 0;
* `77000` есть вершина стека макропеременных;
* встроенная библиотека транслятора может
  отличаться от файла macros.be, поэтому её
  `∧ВS SЕТА 1` (строка 130) может давать 0.

НЕ ИЗВЕСТНО:
* физическая ячейка глобального `∧ВS`;
* инструкция, которой `б` пишет флаг;
* почему `seta 1` внутри `б` даёт 0;
* поведение в B2 (0554/0570);
* полное статическое прочтение зоны 0170.
