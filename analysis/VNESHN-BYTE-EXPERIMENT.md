# Эксперимент: ВНЕШН/ВХОДН и побайтовая сверка
Дата: 20.11.2026.Все прогоны только на копиях в /tmp.
Ни один `.be`, `gold/`, `dis/` или образ не изменён.

[Д] дословно из листинга; [В] вывод; [Э] опыт.
Источник синтаксиса: docs/VHODN-VNESHN-SYNTAX.md,
docs/MACRO-COMMANDS.md:36-43, re-dispak/macros.be:1-13.

## 0. КОРОТКИЙ ОТВЕТ
Да, объявления можно вставить байтобезопасно, НО только
с новым (не определённым в модуле) именем:

    NEWX ВНЕШН MBE.NEWX
    MBE ВНЕШ NEWX,NEWZ
            ВХОДН OUT477      (пробел перед директивой)

Все три размещения равны: до `СТАРТ`, после `М`,
перед `ФИНИШ`.0 ошибок, `ДЛИНА ПРОГ=02000`,
6144 из 6144 байт совпадают с gold. [Э]

НЕТ, если объявить внешней уже используемую в коде
метку (`X2000 ВНЕШН MBE.X2000`): ошибка
`METK YЖE 0П0`, 4 слова и 8 байт меняются. [Э]

Даже байтобезопасная форма меняет объектный модуль:
счётчики `ВНЕШН=N` / `ВХОДН=N`, `*МЕТ*`, таблицу
символов [Д].Поэтому в репозиторий добавлять
настоящие директивы нельзя, только комментарий
после запятой [В].

## 1. МЕТОД И ГАРАНТИИ
1. Эталонные md5 сняты до и после всех прогонов:
   `MBE-Z0147-L1.bin` = 14a3e2bfc75b370e47643d99fbb341c4;
   `ASM-Z0055-L1.bin` = baa12e8c42bf8081b8498798c9a3ed62.
   Оба совпадают.Образы 2048/2053/2099/2248 читались
   только, копии в /tmp/.private/azizz/vneshn-probe/images.
2. Копия `.be` и варианты лежат в
   /tmp/.private/azizz/vneshn-probe/variants/.
   Репозиторные `.be` не трогались: вариант создаётся
   вставкой строк в копию репозиторного `bemsh/*.be`.
3. `tools/vneshn_probe.sh` копирует задание и парсер
   листинга из `tools/rebuild-zone.sh` дословно,
   параметризуется только путь к `.be`.Guard отказывается
   (exit 3) при любом пути каталога образов вне /tmp.
4. Каждый вариант: `dispak -l` с `BESM6_PATH` на копии,
   разбор `ЧИCЛO OШИБOK`, `ДЛИHA ПPOГ`, `BXOДH`, `BHEШH`,
   сборка silver.bin и `cmp` с gold по 6144 байтам.
5. Воспроизводимость:

       bash tools/vneshn_probe.sh variant \
         bemsh/MBE-Z0147.be 0147 B t1 before-start \
         'NEWX ВНЕШН MBE.NEWX'
       bash tools/vneshn_probe.sh probe \
         /tmp/.private/azizz/vneshn-probe/variants/\
       B-t1-Z0147.be 0147 B t1

   Тесты: `python3 -m unittest tools/tests/\
   test_vneshn_probe.py -v` -> 8 tests, OK.

## 4. ТОЧНЫЕ СВИДЕТЕЛЬСТВА ОШИБОК [Д]
Строки пронумерованы по листингу dispak варианта.

    vn_before_start:68
      OПEPAЦИИ HET ... //////      X2000
    vh_before_start:68
      OПEPAЦИИ HET ... //////      X2000
      (ВНЕШН/ВХОДН без метки прочитаны как метка,
       а X2000 как операция)
    vn_indent_fresh:67
      HET METKИ001  ...  BHEШH NEWX
    vh_indent_existing:67
      HEOП MET BЫP  ...  BXOДH Z0147
      (операнд ВХОДН должен быть ЭКВ/символом,
       не меткой СТАРТ)
    vn_label_numeric:67
      HET TOЧKИ001  ...  BHEШH ’2000’
    vn_owner_numeric:68
      OШИБ HAЗB001  ...  BHEШH NEWMOD.2000
    vnesh_owner:217 / vn_label_existing:217
      METK YЖE 0П0 00001 ... X2000 ЭKB ’2000’
      ,ЗOHA 0154 (CTP.01); CALL-OUT  6

`ВНЕШН X2000`, `ВХОДН X2000` без отступа дают одну и ту
же ошибку: имя смещено в поле метки.Отступ 8 пробелов
исправляет разбор, но `ВНЕШН` всё равно требует метки
слева, а `ВХОДН` требует определённого имени справа.

## 5. СЛУЧАЙ С ИЗМЕНЕНИЕМ БАЙТОВ [Э]
Варианты `MBE ВНЕШ X2000` и `X2000 ВНЕШН MBE.X2000`:
`METK YЖE 0П0`, ошибок 1, 1020/1024 слов,
6136/6144 байт.`ДЛИНА ПРОГ` осталась 02000, сдвига
кода нет.Изменённые слова (восьмеричные адреса):

    1236: 0c0400090000 -> 018000090000
    1276: 0c0400090000 -> 018000090000
    1310: 0c0400090000 -> 018000090000
    1314: 0c0400090000 -> 018000090000

Это 4 команды `ПБ X2000` из листинга (`1551`, `1615`,
`1635`, `1643`).В `*МЕТ*` запись `X2000 02000 A`
заменяется на `X2000 00001CA`:символ получает атрибут
внешней связи и становится перемещаемым.Левая половина
команды меняет код адресации, отсюда 8 байт разницы.
Вывод [В]: extern-объявление уже используемой метки
никогда не бывает байтобезопасным.

## 6. ВЕРДИКТ
1. Байтобезопасно (0 ошибок, 6144/6144, ПРОГ=02000):
   * `NEWX ВНЕШН MBE.NEWX` и `MBE ВНЕШ NEWX[,NEWZ]`
     с новым именем, все три размещения;
   * `        ВХОДН OUT477`: операнд уже определён
     как ЭКВ;
   * обе формы вместе, вставка до `СТАРТ`: ВНЕШН=1,
     ВХОДН=1, 0 ошибок, 6144/6144.
2. Не байтобезопасно: `ВНЕШН` на уже определённом и
   используемом имени (4 слова, 8 байт).
3. Форматы без метки или с числами дают ошибки
   транслятора, но байты не меняют.
4. `ДЛИНА ПРОГ` не меняется ни в одном варианте:
   директивы не порождают машинных слов [Э].
5. Объектный модуль всё же меняется: `ВНЕШН/ВХОДН`
   счётчики и `*МЕТ*` [Д].Микро-опыт параллельного
   агента (docs/VHODN-VNESHN-SYNTAX.md §2.3) показал
   разницу одного слова таблицы символов на диске
   объектного модуля.Наша проверка gold на это не
   смотрит: она сравнивает только 6144 байт зоны.

## 7. РЕКОМЕНДАЦИЯ
Не добавлять настоящие `ВНЕШН`/`ВХОДН` в `bemsh/*.be`
без прямого указания оператора: AGENTS.md §0 и
re-dispak/AGENTS.md:13-22 разрешают только комментарии
после запятой.Владельцы и номера СА для наших зон
утрачены, выдумывать их нельзя.

Рекомендуемый формат (docs/EQU-VS-XREF.md §5.2,
docs/VHODN-VNESHN-SYNTAX.md §4.3):

    PRINT8 ЭКВ '1205' , ВНЕШ: PRINT8 [СА 1],
    * адрес 01205; L:376,386; S:28
    X7417B ЭКВ '7417' , ВНЕШ: ? [СА ?],
    * CALL-OUT:72; владелец неизвестен

Правила: ≤60 колонок, комментарий ≤55, перенос со
звёздочкой `*`, степень только через `↑`, номер СА
только из подлинного `*МЕТ*`, гипотеза помечается.
Таблицы связей держать в docs/ и sym/, не в `.be`.

## 8. ЧЕСТНЫЕ ОГОВОРКИ
1. Проверены зоны 0147 (MBE) и 0055 (ASM), не все 69.
2. Сравнение идёт по KiB зоны (6144 байт), не по
   объектному модулю целиком.
3. В ASM-Z0055 добавление `ВХОДН JMP762`
   зарегистрировалось в `*МЕТ*` (`03762BA`), но счётчик
   `ВХОДН` остался 1; на байты это не влияет.
4. Ошибки транслятора фиксировались как
   `ЧИCЛO OШИБOK=000N`, включая омоглифы C/O/K.
5. Ни один репозиторный `.be` не изменялся этим
   экспериментом; параллельные агенты могут править
   другие файлы одновременно.
