## 1. ВОПРОС И МЕТОД [Д]

Искать плотные числовые массивы (>=8 подряд слов-данных) и
решать, есть ли среди них ПЕРЕКОДИРОВОЧНЫЕ ТАБЛИЦЫ.
Метод: 6 байт каждого слова `gold/ASM-Z00NN-L1.bin` читаются
как 48-битное число (big-endian); ищутся прогоны слов
ZERO / SMALL (<2^24) / MASK. Затем сверка с принудительными
листингами `dis-forced/Z00NN.asm` и `.be`.
Ограничение: в `.be` всего 12/14/2/5 слов `КОНД В'...'`,
поэтому массивы видны именно в дампе (в `.be` они разметены
как пары команд `зп`/`сч`), а не как явные `КОНД`-кластеры.
Ранее установлено: `КОНД`-кластеры - шум, не таблицы
(`analysis/SIMILAR-BLOCKS-ASM.md:125-132`,
`INLINE-CONSTS-ASM.md:195-203`,
`docs/SEMANTIC/KOI7-TEXT-ASM.md:148-152`).

## 4. КРИТИЧЕСКОЕ: ПЕРЕКОДИРОВОЧНЫЕ ТАБЛИЦЫ [Д]

Эталон re-dispak (structura):
1. `nrkod.be:233-254` - КОДЫ: пары `ДК '06',МУ-Н(3)` /
   `ДК 8,ПУ-Н УПП` = (входной код, выходная кодировка);
   доступ индексирован: `УИА -КОНКОД+КОДЫ+1(М4)` (:198);

   в'1400007700000314'`, `в'0003727117503000'` -
   упакованные поля (код -> код), чтение `сч ячпрм2(М15)`
   (:2130); заголовок `mott.be:358`.
3. `konfus.be:75,143,146` - `сд КТОМ+2(М17)` - сдвиг
   по таблице КТОМ для перевода кодов.

Сравнение с ASM-зонами [Д]:
- НИ ОДИН массив не содержит пар «входной код ->
  выходной код» и не имеет индексированного доступа
  `(Мn)` по входному коду. Нет аналога `nrkod.be:233`,
  `mott.be:2194`, `konfus.be:75`.
- 0237-0267 - плоский список констант, читаемый
  командами `нтж`/`и` напрямую, без индекса.
- 0060.1104 - двупольная маска `7777000077777777`,
  но НЕ пара код->код и не читается.
- 0057 - «векторная диспетчеризация КОДОМ»
  (`Z0057.md:42-44`), т.е. переход по адресу, а не
  перекодировка; tables в 0057 нет [Д].
