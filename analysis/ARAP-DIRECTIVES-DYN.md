## 3. ФАКТ: эхо управляющих карт

Карты ТРН печатаются в НАЧАЛЕ stdout-листинга,
сразу после штампов `ИПМ МАКРО-БЕМШ ВЕР.06/78` и
`АРАП ВАР.04/78`, ДО первого `ВРЕМЯ СЧЕТА`.
Пример, `list-C-macros-orig.txt:30-34`:

```
---------------------------------------------------
      BBД◇◇◇
      TPH◇◇◇
      ЗПKOMП430070
      БTMAЛФ
```

В листинге латинские `B`, `P`, `K` вместо кириллических
`В`, `Р`, `К`: это особенность печати, не другая карта.
`B-explore.out:27-31` содержит тот же порядок для
`ЧTKOMП420070`, `БTMAЛФ`, `ЗOHMOД430146  0001`.

Эхо карты НЕ совпадает с моментом её действия.
См. §5.

## 4. ФАКТ: кто обрабатывает директивы

Прямой поиск по C-исходникам dispak:

```
grep -i 'ЗПКОМП|ЗОНМОД|ЗОНГП|БТМАЛФ|ЧТКОМП|BTMALF'
  /home/azizz/Yandex.Disk/dispak/{dispak,besmtool}/*.c
```

Результат: 0. Имена директив НЕ разбираются в C.
dispak исполняет машинный код транслятора, а
директива проходит через его конвейер ввода как
управляющая карта. Разбор живёт в машинном коде зон
0137-0177 тома 2048; там же статические слова
(ARAP-ARCHIVE-
STRUCTURE.md §4: `0144.1774` П'ЗОНГП ',
`0144.1455` П'ЗОНГП=').

ФАКТ: единственный наблюдаемый механизм записи на
диск это экстракод Э70. В C он обрабатывается здесь:

```
cu.c:437   печать "%05o: %-4s%-5o (=%08o%08o) ..."
cu.c:280   if (ui.i_opcode == 070) печать E70at
extra.c:2766 ddio(void)
extra.c:2785 u = uir.i_opcode & 077   (номер ЛУН)
extra.c:2796 zone = uir.i_addr & 07777 (зона)
extra.c:3132 else -- запись целой зоны
extra.c:3133 r = disk_writei(...)
disk.c:453 disk_writei(void *ud, ...)
disk.c:476 disk_writei1(...)
```

Экстракоды в трассе печатаются как `*70`, `*64`,
`*50`, `*75`. Примеры из B: `*50:12 *57:464 *60:114
*64:55 *70:250 *75:5974` (всего 5 141 914 строк).

## 6. ФАКТ: операнд 6 цифр в коде

B, первое появление `430146`:

```
@1 409 634 75720: asn 136  acc=4301460000000000
@1 409 635 75720: aox 76337 acc=0000000000430146
@1 409 636 75721: atx 1115  acc=7777777700430146
@1 409 637        01115: store 7777777700430146
```

Затем операнд переносится в дескриптор:

```
@4 850 285 07047: xta 1115  acc=7777777700430146
@4 850 286 07050: aux 55(11) acc=4301460000000000
@4 850 488 07056: *70 53(11) DESC=0000040000430146
```

То есть число из карты сохраняется в ячейку `01115`,
оттуда берётся кодом `07047...07056` и только через
Э70 уходит на диск. Прямого вызова записи из АРАП
в трассе как `uj`/`vjm` не найдено: запись идёт
через экстракод.

## 7. ФАКТ: запись на диски и дампы

md5 копий до/после (только перечисленные изменились):

```
A 2048/2053/2099/2248 -- без изменений
B 2099 90971c33 -> 888c355f
C 2099 90971c33 -> 16573d56 (C2,C3: -> 26546aeb)
D без изменений
F 2248 c11067b3 -> 56862116 (F2,F3: -> 71e9fdc)
G 2248 c11067b3 -> 56862116
H без изменений
J 2248 c11067b3 -> c40f9582
```

Причина: у B и C лента 43 в колоде привязана к 2099
(`лен 43(2099-зп)`), у F/G/H/J -- к 2248
(`лент 43(2248-ЗП)`). У A ленты 43 нет вовсе,
у D тоже. Это подтверждает: запись идёт на тот том,
куда `лент` поставила ЛУН 43, с меткой ЗП.

B, дамп копии 2099 зоны `0146` (`besmtool dump 2099
--start=0146 --length=1`), первые слова:

```
0000: 1
0001: GOST "СОСТАВ"
0002: 02000  (старт)
0004: 077777
```

Листинг B не печатает слов объекта: `ДЛИHA ПPOГ=00000`.
Сравнить 16 слов с листингом в этом задании нельзя.

J, дамп копии 2248: объявленная зона `430160`, но
байтовое сравнение с эталоном показало изменения в
физических зонах `0233`, `0234`, `0235`. Модуль
начинается в `0234`:

```
0234.0000 = 1
0234.0002 = 0000060000000022
```

Листинг J:22 содержит `01000 00 22`, то есть правое
полуслова `00000022` из `0234.0002`. Совпадение
одного слова подтверждено; полного соответствия
"все 16 слов" не установлено.

F, дамп зоны `03100` копии 2248: `0000=1`,
`0001=GOST "ТЕСТ  "`. Сообщение листинга:

```
МОДYЛЬ TECT ЗAПИCAH B ЗOHЫ C 433100 ПО 433100
```

То есть `ЗОНМОД433900  0001` привело к записи в
`433100`, а не в `433900`. Цифра 9 не октальная.
Соответствие `433900 -> 433100` остаётся [НЕ ИЗВЕСТНО].

## 8. ФАКТ: что делает БТМАЛФ (наблюдаемое)

[ФАКТ] БТМАЛФ подавляет печать таблицы меток

но раскрытие аббревиатуры не найдено.

## 9. ФАКТ: отрицательные результаты

1. A: `ЗПКОМП430070` + `0-0` + `БТМАЛФ` при ленте 43
   вообще -- ни одного изменения диска. Карта
   напечатана, записи нет. Режим 0-0 блокирует запись.
2. D: `ЗОНГП 270000` + `0-0` -- записи нет, но печать
   отчёта есть (`list-D-standalone-orig.txt:36`):

```
ЗOHГП=270000  CB.ЗOHA = 270001
AМИH=01000 AMAKC=01011 ACBOБ=01012
```

3. H: `ЗОНГП 433900` + `1-1` + лента 43 на 2248 --
   записи НЕТ. То есть ЗОНГП в этих опытах печатает
   учётную справку, но не пишет группу программ.
   Это расходится с формулировкой ARAP-ARCHIVE-
   STRUCTURE.md §3, где ЗОНГП приписана запись ГП.
   Причина расхождения [НЕ ИЗВЕСТНО].
4. E: `1-1` + `ЗПКОМП430070` + лента 43 на 2248 упал
   с `МАССИВ ПУСТ` до начала трансляции. Положительного
   результата по ЗПКОМП на 2248 нет; получен только
   результат C на 2099.
5. В C-коде dispak нет ни одной строки с именами
   этих директив. Приписать их обработку конкретной
   C-функции нельзя; виден только общий Э70.

## 10. ГИПОТЕЗЫ (не доказаны)

1. `ЧТКОМП420070` читает с ленты 42 зону 0070 комплект
   макросов, который `ЗПКОМП430070` записывает на
   ленту 43 зону 0070. Пара симметрична по именам
   и по дескрипторам Э70, но совпадение содержимого
   зон 42/43 не проверялось.
2. `БТМАЛФ` управляет печатью таблицы меток листинга:
   включал/выключал страницу `*MET*`. Возможно,
   БТ = "без таблицы", но это только догадка.
3. Разница md5 у одного и того же задания F
   (56862116 и 71e9fdc) объясняется нестабильными
   байтами служебной зоны. Проверка не делалась.
4. Запись идёт минуя обычные `STORE` в ОП: breakpoint
   на адрес кода АРАП не ловит момент записи, виден
   только Э70. Аналогично PASSES-ARAP-TRANSFER.md §6.2.

## 11. НЕ ИЗВЕСТНО

1. Точное место и код в зонах 0137-0177, который
   разбирает эти четыре карты.
2. Почему `ЗОНМОД433900` даёт `ЗОНЫ С 433100`.
3. Почему `ЗОНМОД430160` (J) дал физические зоны
   0233-0235, а сообщение -- 430160. Соотношение
   логической зоны ПЕРСО и физической зоны тома
   не установлено.
4. Почему `ЗОНГП` в H не записала группу программ.
5. Что именно означают `КОМП`, `ГП`, `БТМАЛФ`.
6. Не проверены ЗОНГП на архивном томе с реальной
   группой программ и режим 1-1 без ЧТКОМП.
