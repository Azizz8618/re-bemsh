# Генератор контролируемых колод ВЕР.06/78, ФАЗА A

Дата: 24.11.2026. Write set: четыре НОВЫХ файла.
Коммитов, push и правок существующих файлов НЕТ.
Только ВЕР.06/78, зоны 0137-0177. Источник инструкций:
dis-forced/*.asm. Адреса восьмеричные, степень ↑,
типографского тире НЕТ. Строки <= 60 колонок.

## 1. Назначение

Генератор `tools/v78_deckgen.py` строит детерминированный
корпус дифференциальных колод по плану
`docs/PLAN-TEST-CORPUS.md`, раздел 3.1 и 4. Каждая колода
получается из одной базы заменой РОВНО ОДНОГО признака.
Остальные байты побайтно равны базе. По умолчанию программа
только печатает план. Запись идёт только по ключу `--emit`.

## 2. Использование

    python3 tools/v78_deckgen.py --help
    python3 tools/v78_deckgen.py
    python3 tools/v78_deckgen.py --format json
    python3 tools/v78_deckgen.py --check
    python3 tools/v78_deckgen.py --emit
    python3 tools/v78_deckgen.py --emit --out /var/tmp/x

Ключи: `--format json|text`, `--check`, `--emit`, `--out`,
`--manifest`. Коды выхода: 0 успех, 1 нарушение `--check`,
2 ошибка входа, 3 отказ guard. По умолчанию читается
`tests/decks/manifest.json`, запись идёт в
`tests/decks/generated/`. Имя файла колоды: `<id>.job.b6`.

## 3. Схема манифеста

Манифест есть JSON-массив случаев. Обязательные поля:

    {
      "id": "P1a",
      "group": "prior-token",
      "base_deck": "P1a.job.b6",
      "mutation": {"kind": "leading_space",
                   "value": "on"},
      "expect": {"feature": "ведущий пробел",
                 "note": "METKA пуста, скелет иной"},
      "dims": {...}
    }

Поле `dims` необязательно. Это полный вектор из 11
измерений, нужный только для проверки попарного покрытия.
Байты колоды от `dims` НЕ зависят: меняет только `mutation`.
Так сохранены два правила плана: один признак на колоду
и полное попарное покрытие в корпусе.

Измерения и домены (42 значения, 55 пар измерений,
784 пары значений):

    leading_space       off on
    label_separator     space colon
    comment_separator   semi comma
    token_column        1 3 8 15 30
    character_class     digit letter colon semi comma
                        star space arrow
    label_length        1 6 7
    macro_params        0 1 2 4
    macro_body          1 3 6
    nesting             0 1 2
    line_kind           МАСRО ЭКВ ВНЕШН ВХОДН КОНД
                        ordinary
    directive           СТАРТ ФИНИШ ПАМ КОНД

Класс знака пишется как `digit@METKA` и так далее. Поля:
METKA, OP, OPR, CMT. Вид `custom` несёт именные колоды
прошлых фаз: R1a-R4d, BASE1967, COLBASE.

## 4. Состав корпуса

Всего 120 случаев, все id уникальны.

    группа          число  что унаследовано
    prior-token         8  P1a-P4b, фаза 2
    prior-column        9  BASE + 8 сдвигов
    prior-char         32  8 классов x 4 поля
    prior-1967         11  BASE1967, R1a-R4d
    pair               60  попарное покрытие
    ИТОГО             120

Все 784 пары значений покрыты, `pairs_missing` равно 0.
Каждое из 11 измерений встречается и как главная мутация.
Размеры колод: от 433 до 617 байт, 73 разных md5.

## 5. База и guard

Оригинальный скретч-шаблон
`/var/tmp/v78-syntax/token-exp/P1a.job.b6` отсутствует.
В генератор встроена реконструкция по
`docs/V78-SYNTAX-PLAN.md`, `analysis/V78-TOKEN-DECKS.md`
и `analysis/SOURCE-LINE-PARSER-EXP.md`: обвязка из
`tools/rebuild-zone.sh`, макроопределение ZMAC01, строка
с ZLBL1 как 22-я строка файла. Размер реконструкции
482 байт, md5 `0681dd780329790f8de0601d94ff10d2`.
Терминатор строки в байтах есть 0x5E, в тексте отчёта
он пишется как ↑.

Guard отказывает для `/usr/local/share/besm6` и его
подкаталогов, в том числе при `--emit --out`. `--check`
сверяет md5 эталонных томов с зафиксированными в
`analysis/V78-TOKEN-DECKS.md` значениями:

    2048 4b94cc188969c110dcc78d1958b80fe0
    2053 4c6abfc5068a94f8766fc38e360acabd
    2099 90971c339b8744a545c8719a5d134650
    2248 c11067b35e2b85a51433e7d7b5efdd19

Проверка `--check` дала 0 нарушений, все четыре md5
совпали. Чтение образов идёт только на чтение, запись
в эталонный каталог невозможна по guard.

## 6. Статусы

ФАКТ. Манифест содержит 120 случаев, 60 из них несут
попарное покрытие, остальные 60 повторяют именные колоды
фаз 2, COLUMN, CHAR и 1967 без перевывода выводов.

ФАКТ. Все 11 измерений имеют канонические домены, все
784 пары значений покрыты. Проверка на убранном `dims`
обнаруживает пропуск, то есть тест не валит контроль.

ФАКТ. Guard отклонил путь `/usr/local/share/besm6` и его
подкаталог. Попытка `--emit` в этот каталог тоже
отклоняется. Запись идёт только в scratch-каталог.

ФАКТ. Признаки P1 и P2 меняют управление гостя, P3 только
эхо, P4 лишь объём чтения. Это НЕ перевыводится, а
перенесено в `expect.note` из
`analysis/V78-SYNTAX-PHASE02-RESULT.md`.

ГИПОТЕЗА. Вектор `dims` для именных случаев выставлен из
базового контекста, а не из параграфов отчётов. Байты
колод от этого не зависят, но трактовка покрытия опирается
на аннотацию, а не на прогон dispak.

ГИПОТЕЗА. Реконструированная база воспроизводит структуру
working deck 1978 года. Побайтовое совпадение с утерянным
скретч-файлом не доказано.

НЕ ИЗВЕСТНО. Точные байты исходного `P1a.job.b6` (было
сообщено 451 или 452 байт) и его md5. Скретч удалён, в git
и в рабочих каталогах копии нет.

НЕ ИЗВЕСТНО. Как поведёт себя каждая из 120 колод в dispak.
Прогон и атлас расхождений относятся к ФАЗЕ B и здесь НЕ
выполнялись.
