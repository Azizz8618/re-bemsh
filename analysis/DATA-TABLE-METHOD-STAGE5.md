## 1. ВХОД ЭТАПА 5

На вход подаётся результат этапов 1-4 для одной зоны:

1. МАССИВ - границы, размер, паттерн слова. Формат:
   зона, адрес начала/конца, n слов, префиксы полей.
   Пример: 0172.0260-1740, 812 слов, префикс 0220.
   [Д: NUMERIC-ARRAYS-B2.md §3.8]
2. КЛАССИФИКАЦИЯ этапа 3/4 - один из:
   CONST/MASK, NAME/ATTRIBUTE, DESCR/PTR, FILL,
   CODE, TAG/TEXT, ALPHA, DISPATCH, TABLE?.
   [Д: NUMERIC-ARRAYS-B1.md §5; B2.md §5; B2A.md §6]
3. РЕЗУЛЬТАТ ЧИТАТЕЛЯ этапа 4 - найден ли код,
   читающий массив (УИА/СЧ/ЗП/МОДА/пб/сд), есть ли
   индексный доступ (Мn) или сдвиг сд. Если читатель
   не найден, это фиксируется как факт, а не как
   доказательство отсутствия смысла.
   [Д: NUMERIC-ARRAYS-ASM.md §4; B2B.md §5.2]
4. эталонные дампы B и B2 (по 6144 байт на зону),
   их размеры и md5 из manifest.sha256 / versions.md §1.

Выход этапа 5 - вердикт: переименование / перекодировка /
сдвиг текста / различие установки, плюс оценённый
аналог в re-dispak со ссылкой module.be:line.

## 2. АЛГОРИТМ СРАВНЕНИЯ ВЕРСИЙ

### Шаг a. Карта зон B -> B2 и проверка дампов

1. Для зоны B с номером Z (восьм.) counterpart в B2 -
   Z + 0400: 0140->0540, 0172->0572, 0177->0577.
   Соответствие найдено сдвигом склейки:
   02400 - 0400 = 01000 = 1024 слова = одна зона,
   то есть OLD 0540+j <-> NEW 0140+j, j=0..31.
   [Д: versions.md §4]
2. NEW 0137 не имеет пары (логически 0537 пуста).
   [Д: versions.md §8.2; reloc.md §5]
3. Проверить дампы: ровно 6144 байт = 1024 х 6;
   md5 склейки NEW 2f503f..., OLD a14315...;
   штампы 0147.1315 = ВЕР.06/78 и
   0547.1315 = ВАР.12/77. [Д: versions.md §1-2]
4. Отнести зону к классу карты версий:
   I (идентична), L (загрузчик), S (сдвиг текста),
   C (правка кода/таблицы), M (смешанная).
   [Д: versions.md §5-6]
5. Зоны 0137-0143 (класс L) из вывода о версии
   ИСКЛЮЧИТЬ: они меняются при установке на другой
   том, а не между редакциями. [Д: reloc.md §1, §4]

### Шаг b. Побайтовое сравнение и klas слов

1. Сравнить слова по индексу wa = 0..1023:
   diff = [wa : A[wa] != B2[wa]].
   [Д: Z0172-COMPARE.md, воспроизведение]
2. Каждое diffs-слово отнести к одному из классов:

   DEL - запись удалена: значение A[wa] больше не
     встречается ни в одном из 1024 слов B2;
   SHFT - чистая релокация: A[wa] == B2[wa-k];
   EDIT - правка поля: A[wa] != B2[wa-k] (или
     A[wa] != B2[wa] при k=0), но тег/префикс
     сохраняется.

3. DEL проверять только по всей зоне B2, а не по
   одной позиции: иначе удаление путается с релокацией.
   [Д: Z0172-COMPARE.md §2]

### Шаг c. Поиск сдвига k по якорям LCS

1. Найти равные слова-якоря в хвосте зоны и взять
   k = wb - wa, где A[wa] == B2[wb].
2. Если k постоянен на всех якорях - одна вставка/
   удаление в начале. Если k кусочно-постоянен -
   записи переменной длины, вставок/удалений несколько.
   [Г: Z0172-COMPARE.md §2, §4]
3. Проверить гипотезу k на всех словах хвоста:
   доля A[wa]==B2[wa-k] должна резко вырасти
   относительно доли совпадений при k=0.
   [Д: versions.md §6 для класса S]

### Шаг d. Числовой разбор EDIT-дельта

1. Вычесть пары A[wa] - B2[wa-k] и построить
   гистограмму дельт (восьм. число, знак, число слов,
   какая половина слова изменилась).
   [Д: Z0172-COMPARE.md §3]
2. Разложить слово на 16 окт. цифр (0 - левая,
   старшая; 15 - правая, младшая):
   - цифры 13-15 = младшие 9 бит ПРАВОГО полуслова;
   - цифры 5-7 = младшие 9 бит ЛЕВОГО полуслова;
   - цифры 0-4 и 8-12 = тег/код/мода.
3. Локализовать дельту по разрядам. Примеры:
   -0o43   -> цифры 13-15, бит 0-8   (адрес правый);
   -0o6    -> цифры 14-15, бит 0-5   (адрес правый);
   +0o1    -> цифра 15,    бит 0     (адрес правый);
   -0o600000000 -> цифра 7, бит 24-26 (адрес левый);
   +0o100000000 -> цифры 6-7,бит 24-27 (адрес левый).
   [Д: Z0172-COMPARE.md §3, разбор по разрядам]
4. Классификация дельты:
   - постоянная дельта в полях адресов, теги
     стабильны и неизменны -> ПЕРЕНУМЕРАЦИЯ адресов;
   - произвольная дельта, но теги стабильны ->
     ПРАВКА ЗАПИСИ (корректировка адресов);
   - изменение тегов/кодов операций ->
     ПЕРЕКОДИРОВКА содержимого.
   [Г: Z0172-COMPARE.md §3, §7]

### Шаг e. Вывод о смысле полей

1. Поля, которые меняются между изданиями, - адреса
   или индексы. Поля, стабильные во всех EDIT, -
   семантические теги/коды. [Г]
2. Сверить структуру с эталоном дескрипторов:
   [константная метка | указатель], читается как
   пара полукоманд; 0165.0367 `0220 0000 0300 2621`
   -> `мода | пб '2621'`. [Д: MACRO-TABLE-FORMAT.md §4.2]
3. Если меняются только адресные поля, а коды 0220,
   2240, 0300, 0010 сохраняются - это таблица
   указателей/дескрипторов, чьи адреса перенумерованы.
   [Г: Z0172-COMPARE.md §6-7]
4. Если читающий код не найден (BR=1/CALL=0), объект
   указателей не доказан; написать это прямо. [Д]

### 3.2. Порядок поиска

1. Сначала по комментариям: grep ПЕРЕКОД|КОДИРОВК|
   ЯЧКОД|ЯЧТБКД по .be зоны. 0 совпадений - уже
   аргумент против таблицы перекодировки.
   [Д: NUMERIC-ARRAYS-B2.md §2; B2A.md §3(c)]
2. Затем по структуре: монотонный индекс (nrkod),
   4x12-поля (konfus), пары код->значение (slojka),
   сдвиговые маски (КТОМ). [Д]
3. Затем по читателю: есть ли сд / УИА(Мn) /
   СЧ(Мn) с операндом внутри массива. Без сд нет
   индексного доступа konfus-типа.
   [Д: NUMERIC-ARRAYS-B2B.md §5.2]
4. Отсечь ложные массивы: конд-хвосты, валидные
   opcode, поля адресов с шагом - это КОД, а не
   таблица. [Д: NUMERIC-ARRAYS-B2B.md §4]

### 3.3. Как цитировать аналог

Формат одной строки вывода:
  `модуль.be:A-B (данные); модуль.be:C-D (читатель)`
  [Д] - сам факт; [Г] - то, что мы назвали аналогом.

Правила:
- источник - re-dispak как поведение/структура, код
  не копируется; фиксировать module:line;
- если совпала только упаковка полей, но нет
  индексного читателя - писать «структурный аналог»;
- если совпала только роль (dispatch, код->объект),
  но нет 4-полевой упаковки - «функциональный аналог»
  и помечать звездочкой, как в
  NUMERIC-ARRAYS-B1.md:196;
- одиночная константа (diski.be:70) и рабочая ячейка
  (slojka.be:1260) НЕ are таблицы и аналогом таблицы
  не считаются. [Д: Z0172-COMPARE.md §5]

### 3.4. Что найдено для 0172 (аналоги частичные)

Ближайшие: konfus.be:670-691 (та же упаковка 4x4 окт.
цифры, меняющееся поле в конце) - структурно;
nrkod.be:231-253 (поле-код в слове) - функционально;
slojka.be:1260 - поясняет 4-полевую упаковку;
diski.be:70 - код как сдвиг. [Д: Z0172-COMPARE.md §5]
Все аналоги частичные: прямого читателя и полного
совпадения сигнатур нет. [Г]

## 5. ПРИМЕР: ЗОНА 0172 (B) ПРОТИВ 0572 (B2)

Вход: gold/MBE-Z0172-L1.bin и gold/MBE2-Z0572-L1.bin,
по 6144 байт = 1024 слова х 6 байт. READ-ONLY. [Д]

Результаты независимой проверки (Python, только чтение):
- diffs-слов: 316; diffs-байт: 1040;
- диапазон 0242-1740, 46 участков; [Д]
- ненулевых слов в 0260-1740: 812 (B) и 806 (B2);
- последнее ненулевое слово: 1740 (B), 1732 (B2);
- 6 слов 1374-1401 отсутствуют в B2 целиком. [Д]

Классификация 316 diffs (сумма сходится):
  DEL = 6 (1374-1401), SHFT = 117, EDIT = 193. [Д]

Компонента 1 - удаление записи. Блок 1374-1401
(6 слов, значения 2405 4400 0000 4420 и др.) в B2
не встречается ни в одной из 1024 ячеек. Хвост
1402-1740 сдвинут на k = -6; уже на 120 из 223
слов хвоста A[wa] == B2[wa-6]. [Д]

Компонента 2 - 193 правки. Гистограмма дельт:
  -0o6 (70), -0o600000000 (42), -0o43 (35),
  +0o1 (16), -0o600000006 (14), +0o100000000 (9),
  -0o4300000000 (4), прочие (3). [Д: COMPARE §3]
Все дельты попадают в младшие 9 бит полуслов:
правый адрес (цифры 13-15) или левый (цифры 5-7).
Примеры A -> B2:
  0266  0220 0000 4710 4613 -> ...4550  (-0o43)
  0242  0000 4636 0001 0000 -> ...4573  (-0o4300)
  0710  0300 3677 0220 0000 -> ...3671  (-0o600)
  0622  0230 2167 0020 3420 -> ...3412  (-0o6)
  0506  0010 2212 0260 4156 -> ...4157  (+1)
Коды 0220/2240/0300/0010 сохраняются; замен opcode
и перестановок записей (кроме одной) нет. [Д]

Вердикт:
  [Д] 0172/0572 - плотный массив 4-полевых слов;
      0572 короче на 6-словную запись; 193 адресных
      поля скорректированы.
  [Г] Роль - таблица указателей/дескрипторов
      ([метка/код | адрес]), адреса перенумерованы
      между изданиями. Полное имя и потребитель
      НЕ установлены: читающий код в 0172 не найден.

## 6. ЧЕСТНЫЕ ОГОВОРКИ

1. B2 - более старая редакция ВАР.12/77 (12.1977),
   а не «новая версия 0172». Направление правки
   06/78 <- 12/77 не доказывает причину изменений.
   [Д: versions.md §2]
2. Написание на диске ВАР.12/77; ВЕР.12/77 поиск не
   даёт 0 попаданий. [Д: VERSIONS-SCAN.md §3]
3. 0137-0143 отличаются между 2048 и 2148/2248
   почти побайтно (>99.7% слов) - это другая
   установка той же редакции, не вторая версия.
   Исключать из вывода о версии. [Д: reloc.md §1-4;
   NUMERIC-ARRAYS-B1.md §4]
4. 0537 пуста во всех копиях; NEW 0137 пары не имеет.
   Не утверждать, что она «просто сдвинута». [Д]
5. Класс S (вставка/удаление слов) - рабочая гипотеза
   по бинарнику; исходника транслятора нет, побайтово
   доказать нельзя. [Д][Г: versions.md §8.5]
6. Адреса disbesm6 с -a0 локальны; физические якоря -
   текстовые штампы (0147.1315, 0547.1315 и др.).
   Логический адрес листинга не подставлять как
   физический без доказательства. [Д]
7. Аналоги из re-dispak - структура/поведение, не
   исходник транслятора; аналогия по функции не
   доказывает, что 0172 делает то же самое.
8. Байты 1040 и 316 слов проверены пересчётом;
   разбиение 6/117/193 совпадает с
   analysis/Z0172-COMPARE.md. [Д]
