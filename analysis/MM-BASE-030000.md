## 1. Требования к enviroment хуков

[ФАКТ] CU:241 берет `dbg = dd_debug()`, а CU:329 ставит
дамп под условие `dbg && core_on_pc > 0 && abpc == pc
&& !core_done`. dd_debug() (CU:25-30) это только
`getenv("BESM6_DD_DEBUG") != NULL`. Значение роли не
играет, важна само переменная. Без DD_DEBUG дампа НЕТ,
хотя PC исполняется. Это подтверждено пользователем и
нашими четырьмя прогонами.

[ФАКТ] BESM6_CORE_ON_PC: восьмеричный PC через
`strtol(s,NULL,8)`, должен быть > 0. Пишет в cwd два
файла: core-pc.bin и core-uic.bin, по 65536 слов x 6
байт = 393216 байт. BESM6_CORE_SKIP (десятичное)
пропускает K попаданий. core_done ставит только один
дамп на прогон.

[ФАКТ] BESM6_WATCH (CU:478-510) НЕ требует DD_DEBUG и
печатает WATCH-строки в stderr безусловно. Адрес тоже
восьмеричный. BESM6_WATCH_RW: 0 все (умолч.), 1 только
запись, 2 только чтение. Пишущие КОПы: 000,001,004,
005,006,016,017,020,021,022,023; 002 (MOD) не пишет.
Адрес берется как XADDR(addr + reg[ui.i_reg]) & 077777,
то есть по факту, не по полю команды.

Проверка: WATCH=30000, RW=1, DD_DEBUG=0 дал 2 строки,
rc=0. DD_DEBUG для WATCH не нужен.
