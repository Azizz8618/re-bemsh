## 1. МЕТОД: КАК ПОЛУЧЕНО 8-ЧНОЕ ЗНАЧЕНИЕ

Мнемоника берется как напечатано: сч, зп, сбр,
рзб, нтж, пе, рег, цикл, пб, ... Латинские
обозначения трассы не используются.

Правило вывода числа и блокировка BASE 8
взяты из disbesm6.c, функция praddr():

  1. Операнд в кавычках 'nnnn':
     число УЖЕ восьмеричное, берем как есть.
     Пример: '3554' -> 03554, '77316' -> 077316.
  2. Операнд без кавычек с регистром, n(Мk):
     disbesm6 печатает его ДЕСЯТИЧНЫМ, если
     адрес < 0100 или >= 077700 (строки 369-375).
     Переводим: 19 -> 023, 8 -> 010, -1 -> 077777.
  3. Метка Dnnnnn+off / Annnn+off:
     цифры метки ВОСЬМЕРИЧНЫЕ, сдвиг off
     печатается ДЕСЯТИЧНЫМ (%d, строка 369).
     Пример: D00100+40 -> 0100(8)+40(10)=0150(8).
  4. Выражение 64-27: обе части десятичные,
     результат 37(10) -> 045(8).
  5. в'nnnnnnnn': слово КОНК, 8 восьмеричных
     цифр, значение - само слово.
  6. (Мn), Мn, Мn(Мj): регистра, числа НЕТ.

Проверка правила 2 по коду команды:
  word 0213: код 07 004 0010, операнд 8(М7).
  Адресное поле 0010(8) = 8(10). Совпало.
  word 0267: код 07 010 0023, операнд 19(М7).
  Адресное поле 0023(8) = 19(10). Совпало.
Проверка правила 3:
  word 0152: D01237-24, код 00 22 01207.
  01237(8)-24(10) = 671-24 = 647(10) = 01207(8).

Правило 1 дано как ФАКТ из исходника disbesm6;
результаты translate - ФАКТ для этого листинга.

### 5.2 ГИПОТЕЗА (нужны внешние доказательства)

  1. Смысл ЭКВ-имени. Имена из .be суть подставные
     метки реконструкции (Z0137-EQU-AUDIT.md),
     в forced-листинге их нет. Совпадение числа

     0060-0121 названа в .be:17, в листинге
     есть только числа. Нужен внешний KOI-7.
  5. Разделение (b) адрес против (c) константа:

  6. Статусы [Д] в G4/G5/G6 остаются гипотезами
