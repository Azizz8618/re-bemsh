# Служебные слова зон 0153/0155/0157: пословный разбор

Дата: 21.11.2026. Режим READ-ONLY; эталоны не менялись.
md5 до/после: 0153 f37741e7…, 0155 4b78496d…,
0157 55449c36… (см. verify/report.md).

Источники: `bemsh/MBE-Z0153.be`, `Z0155.be`, `Z0157.be`,
`gold/MBE-Z0…-L1.bin`, `dis/MBE-Z0…-L1.asm`,
`dis-forced/Z0….asm`, `docs/SEMANTIC/INDEX.md`,
`Z0153.md`, `Z0155.md`, `Z0157.md`,
`docs/MACRO-TABLE-FORMAT-VERIFIED.md`,
`docs/DISBESM6-GUIDE.md`.
Обозначения: [Д] = disbesm6, [Г] = побайтовый дамп,
[F] = принудительная дизассембляция (все слова W_CODE).

## 0. Главный вывод

Ярлык «таблица служебных слов» ([INDEX:25-29]) оправдан
только для 0153. В 0155 и 0157 подавляющая часть слов —
КОД. Надпись `конд` там есть артефакт reachability:
трасса шла с `-a0 -e0`, а выход — `пб (М5)` /
`пб '4024'`, который анализатор не проводит.
С базами из `START` зон (`0155='4000'`, `0157='75777'`,
[Z0155.be:28; Z0157.be:33]) те же слова читаются как
связная программа. Аналогичный самообман уже зафиксирован
для 0156 ([Z0156.md:16-31]).

Метод: 6 байт/слово, big-endian; L = word>>24,
R = word&0xffffff. Таблица opcode — из
`re-siprod/tools/siprod_asm.py` (OPS), совпадает с [Д].
Регистры ниже — в восьмеричной нотации БЭСМ-6 disbesm6
(М12 = 12₈ = 10₁₀), как в `.be`.

## 1. ЗОНА 0153 — ДАННЫЕ (подтверждено)

[Г] 1024 слова: 445 нулей (1103₈-1777₈), 220 слов
заполнителя `0000538000000000`, 359 прочих.
[Д] `dis/MBE-Z0153-L1.asm:8-10`: трасса обрывается
на слове 0; все слова 1-1777 — `конд` [Д:10-587].
Ветвлений/вызовов нет (XR:72: `BR=0 CALL=0`).

### 1.1 Шапка: 25 пар, слова 0000-0050 [Г][F]

Каждое слово пары: `L=00100000₈` = `сч 0` (все 50
одинаковы), `R=TTTT|III`. Поле R — не opcode целиком,
а **тег в байтах 2-3 + индекс в младших 2 байтах**:

```
0000  0010000002000000  тег 0x08 инд 0  (×2)
0002  0010000012000001  тег 0x28 инд 1  (×2)
0010  0010000010000004  зп 4(M2,DMS)    (×2)
0034  0010000060000016  зп 16(M12)      (×2)
0046  0010000002000023  тег 0x08 инд 23 (×3)
```
[Г] gold-Z0153; [Д] dis/…:8-58; [F] dis-forced:10-101.
Тэги `0x080000/0x280000` — ИЛЛЕГ как opcode
(проверено по OPS), значит это константы-теги, не код.
`0x200004`/`0x0c000e` — настоящие `зп` [F:28-29,68-69].
Индексы идут 0..23₈; каждый дубль — «2 ячейки ГС на
макрос» [MACRO-TABLE-FORMAT-VERIFIED.md:13-17,121-129].

### 1.2 Заполнитель и хвост [Г]

`0000538000000000` ×220; L=`Э70 0(M5)`, R=0;
редкие `00007f8000000000` ×6, `0000718000000000` ×4,
`00006f8000000001` ×4. Ни одна кодировка не даёт фразы.
1103₈+ — нули `пам 445` [G:588]. Смысл тегов 0x08/0x28,
0x51/0x67/0x7f и константы 0x538000… НЕ установлен.

### 1.3 Вкраплённые TEXT-имена [Г][K]

14 слов в зоне 0437₈-1102₈ дают 6-битный TEXT
(код = ASCII-0x20), напр. 0446 `*VEN*FT`, 0564 `LZFN`,
0573 `VJBAJP`, 0616 `QLFHR=L`, 0653 `HMG0L`,
0710 `T*A1JP`, 0747 `MJRM`, 0754 `MKJM`, 0762 `JDNM`,
1001 `IJFN`, 1045 `MJJMK`, 1054 `HZ6QM0`,
1076 `HJ6GK`, 1102 `K*FSM` [SEMANTIC/Z0153.md:103-199].
Это имена/идентификаторы (4-8 симв.), не сообщения;
GOST/KOI/ITM дают мусор. Читающий код НЕ найден.

### 1.5 Вердикт 0153

* 0000-0050: **адресно-теговая таблица** [Д][Г];
  данные, т.к. R-теги — не opcode, ветвлений нет,
  трасса обрывается. Читатель НЕИЗВЕСТЕН (BR=0,
  косвенных `уиа` в зону не найдено).
* 0051-1102: **заполнитель с редкими тегами +
  разреженный пул TEXT-имён** [Г]; данные.
* 1103-1777: **забел нулями** [Г]; не код, не данные.

## 2. ЗОНА 0155 — КОД, а не таблица

База `START='4000'` [Z0155.be:28]. С `-a4000 -e4000`
`disbesm6` читает слова 4004-4036+ как код: 890 `конд`
вместо 1016 при `-a0`. Здесь `пе 4004`, `пе 4012`,
`пб 4024` — это переходы на слова 4, 10, 20 самой зоны.

### 2.1 Разбор слов 0000-0003 [Д][Г]

```
0000 0010656100116214  сч 6561  и 6214   маска №1
0001 0270400400106561  пе 4004  сч 6561  →WORD4
0002 0011620402704012  и 6204  пе 4012  →WORD10
0003 0300402402200000  пб 4024  мода 0  →WORD20
```
[Д] dis/MBE-Z0155-L1.asm:8-13; [G:8-13].
Две проверки с перезагрузкой 6561 — выбор одного из
трёх продолжений. 6214/6204 — маски; 6561 — константа.

### 2.2 CPU-ветки 4004-4036 (слова 4-36) [Д][F]

### 2.4 Вердикт 0155

* 0000-0003 — **диспетчер проверок** [Д][Г], код.
* 0004-0523 — **цепочка call-stub и проверок**
  [Д][F], код; `конд` — только из-за `-a0`.
* 0524/0605/0645/0661 — одиночные `пам` [D:350,399,
  431,442] — забелы/выравнивание, не таблица.
* Входных ссылок извне нет (XR:74, ДМ=0). Читатели —
  сам диспетчер внутри зоны; адреса 6561/6214/6204
  логические, в физическую зону не отображаются.

## 3. ЗОНА 0157 — КОД-диспетчер

База `START='75777'` [Z0157.be:33]. С `-a75777 -e75777`
трасса доходит до 76035 (742 `конд` против 975 при -a0).

### 3.5 Вердикт 0157

## 5. Честно не установлено

1. Бизнес-смысл тегов 0x08/0x28/0x20/0x60 в 0153.
2. Смысл 14 TEXT-имён 0153 (имена макросов? меток?).
3. Точная граница кода в 0155/0157 без динамической
   трассировки `-R<reg>=<адрес>`; `конд`-хвост может
   быть и данными, но каждое его слово — валидный opcode.
4. INLINE проверка INDEX:28 («плотная таблица
   служебных слов») относится к зоне **0156**, а не
   к 0157; в списке задач стояли 0153/0155/0157.
5. Попарное сравнение 0153↔0553, 0155↔0555,
   0157↔0557 (B2) не проводилось.
