## 4. Тест 076613-076614

[ФАКТ] Ячейка ПРЕДЫДУЩЕГО байта - `M[076501]`.
Записывается в 076603: `M[76501] := M[76502]`, где
`M[76502]` содержит PACK-байт предыдущей итерации
(установлен в 076605).

[ФАКТ] Сравнение (076613-076614):

    076613 xta 76501   ACC := M[76501]
    076613 aex 76317   ACC := ACC XOR 2000000000000000
    076614 uza 76621   если ACC == 0 (лог. режим ntr 3)
    076614 uj  76615   иначе (RIGHT-полуword)

`M[076317] = 2000000000000000` - PACK-код байта `0x40`.
ACC == 0 после XOR означает: предыдущий байт равен `0x40`.

[ФАКТ] Разница маршрутов:

    предыдущий == 0x40: uza -> 076621, R4 НЕ тронут
    предыдущий != 0x40: uj  -> 076615, R4++ или R4 := -5

[ФАКТ] В 076621 `рзб`/UNPACK берёт маску по индексу R4,
в 076622 `слц` добавляет байт к слову `M[076642+R5]`.
Если R4 не увеличивается, два соседних `0x40` (каждый
заменён на `0x01` в 076612) попадают в ОДНУ и ту же
позицию выхода и складываются.

[ФАКТ] Прямое подтверждение (B-explore.err:1042373+),
пять подряд идущих `0x40`, R4 = 0 всё время:

    M[076645] младший байт: 01 -> 02 -> 03 -> 04 -> 05

То есть N подряд `0x40` дают в выходе один байт со
значением N. Это счётчик длины серии, а не N отдельных
байтов `0x01`.

[ФАКТ] Статистика полной трассы:

    076614 uza  3694 раза  (LEFT, проверка всегда)
    076614 uj    432 раза  (RIGHT, предыдущий != 0x40)

[ГИПОТЕЗА] `0x40` - маркер повтора/пробела в архиве АРАП;
цикл 076600 преобразует серию маркеров в счётчик повторов.
Прямого текста в доступных модулях не найдено.
