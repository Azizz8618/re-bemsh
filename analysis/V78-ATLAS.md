## 1. СХЕМА СОБЫТИЯ

Одна строка JSONL:

```
{"n": 12, "kind": "exec", "pc": "076505",
 "mn": "uza", "operand": "76230",
 "acc": "0", "phase": "RLE"}
```

Поля n, kind, pc, mn, phase обязательны. operand и acc
необязательны. kind: exec | store | dd. phase: BOOT,
RLOAD, RLE, INPUT, EDITOR, MACHINE, LISTING, UNKNOWN.
PC нормализуется в 5 восьмеричных знаков: "076505" и
"76505" дают одно число.

## 3. ВЫХОД

Ключи JSON для пары:

| Ключ | Содержание |
|---|---|
| mode | "pair" |
| sources | пути A и B |
| summary | события, команды, фазы по сторонам |
| first_line_diff | строка и две записи (a, b) |
| pc_seq_diff | индекс и две записи (exec только) |
| count_delta_top | топ 20 дельт B минус A |
| only_a_top | топ 20 PC только в A |
| only_b_top | топ 20 PC только в B |
| phase_counts | счётчики событий по фазам |
| first_divergence_phase | фаза первой вилки |
| coverage | сегменты и PC вне сегментов |

Запись в first_line_diff и pc_seq_diff содержит поля
n, kind, pc, mn, operand, acc, phase. При разной длине
файлов отсутствующая сторона равна null.

Ключи JSON для каталога:

| Ключ | Содержание |
|---|---|
| mode | "catalog" |
| fixtures | список файлов и их счётчики |
| fixture_count | число файлов |
| covered_pcs | число исполненных PC |
| candidates | источник, всего, кластеры |
| candidate_count | число кандидатов |
| uncovered | список непокрытых PC |

## 4. КОДЫ ВОЗВРАТА

| Код | Значение |
|---|---|
| 0 | расхождений нет, все кандидаты покрыты |
| 1 | есть расхождение или непокрытый кандидат |
| 2 | ошибка входа или CLI |

--check включает строгую проверку схемы: n возрастает,
kind и phase из множества, pc восьмеричный. Нарушение
даёт код 2. Без --check неизвестная фаза превращается в
UNKNOWN, неизвестный kind в other.

## 5. ТАБЛИЦА СЕГМЕНТОВ

Встроена в tools/v78_atlas.py из docs/PLAN-TEST-CORPUS.md.

| Сегмент | Адреса | Роль |
|---|---|---|
| S-INPUT | 076505-076642 | ввод RLE |
| S-DISPATCH | 076031-076123 | байтовый диспетчер |
| S-PACK | 077421-077502 | упаковка в 075235 |
| S-MARK | 075344-075401 | цикл классификатора |
| S-METKA | 075353-075377 | решение о метке |
| S-SLOT | 04200-04207 | слоты 02035-02041 |
| S-DESCR | 006061 и 001534 | дескриптор пула |

Один PC может попасть в два сегмента: 075353-075377
лежит и в S-MARK, и в S-METKA. Покрытие сегмента это
наличие хотя бы одного исполненного PC сегмента.
Своя таблица задаётся --segments: JSON вида
{"S-NAME": ["076505-076642"]} или строки
"S-NAME 076505-076642".

## 7. Ограничение фазовых меток (23.11.2026)

Проверка на реальных фикстурах показала: установленная карта фаз
даёт грубую таймлайн-разметку. Например PC 075377 (METKA)
исполняется и до, и после якоря 076600 (RLE), поэтому его
метка фазы может быть BOOT или RLE. Для атрибуции команды
использовать СЕГМЕНТНОЕ покрытие по PC (раздел 4), а не
фазовую метку. Фазы годятся только как порядковые вехи:
BOOT → RLOAD → RLE → INPUT → EDITOR → MACHINE → LISTING.
Покрытие по каталогу из 4 фикстур: 2610 PC, 66 кандидатов,
непокрыты 40034 и 42007; расхождение в 18 поименованных
PC между отчётом FSM (84) и списком в нём же (66).
