## 1. СХЕМА СОБЫТИЯ

Одна строка JSONL:

```
{"n": 12, "kind": "exec", "pc": "076505",
 "mn": "uza", "operand": "76230",
 "acc": "0", "phase": "RLE"}
```

Поля n, kind, pc, mn, phase обязательны. operand и acc
необязательны. kind: exec | store | dd. phase: BOOT,
RLOAD, RLE, INPUT, EDITOR, MACHINE, LISTING, UNKNOWN.
PC нормализуется в 5 восьмеричных знаков: "076505" и
"76505" дают одно число.

## 2. ЗАПУСК


расходящиеся записи. Полная трасса НЕ хранится.

## 3. ВЫХОД

Ключи JSON для пары:

| Ключ | Содержание |
|---|---|
| mode | "pair" |
| sources | пути A и B |
| summary | события, команды, фазы по сторонам |
| first_line_diff | строка и две записи (a, b) |
| pc_seq_diff | индекс и две записи (exec только) |
| count_delta_top | топ 20 дельт B минус A |
| only_a_top | топ 20 PC только в A |
| only_b_top | топ 20 PC только в B |
| phase_counts | счётчики событий по фазам |
| first_divergence_phase | фаза первой вилки |
| coverage | сегменты, PC вне сегментов и все |
|          | перекрытия PC (overlap_pcs) |

Запись в first_line_diff и pc_seq_diff содержит поля
n, kind, pc, mn, operand, acc, phase. При разной длине
файлов отсутствующая сторона равна null.

Ключи JSON для каталога:

| Ключ | Содержание |
|---|---|
| mode | "catalog" |
| fixtures | список файлов и их счётчики |
| fixture_count | число файлов |
| covered_pcs | число исполненных PC |
| candidates | источник, всего, кластеры |
| candidate_count | число кандидатов |
| uncovered | список непокрытых PC |

## 4. КОДЫ ВОЗВРАТА

| Код | Значение |
|---|---|
| 0 | расхождений нет, все кандидаты покрыты |
| 1 | есть расхождение или непокрытый кандидат |
| 2 | ошибка входа или CLI |

--check включает строгую проверку схемы: n возрастает,
kind и phase из множества, pc восьмеричный. Нарушение
даёт код 2. Без --check неизвестная фаза превращается в
UNKNOWN, неизвестный kind в other.

## 10. Ограничение фазовых меток (24.11.2026)

[Ф] Проверка на реальных фикстурах показала: карта фаз
даёт грубую таймлайн-разметку. Например PC 075377
(METKA) исполняется и до, и после якоря 076600
(RLE), поэтому его метка фазы может быть BOOT или
RLE. Для атрибуции команды использовать СЕГМЕНТНОЕ
покрытие по PC (раздел 5), а не фазовую метку.
Фазы годятся только как порядковые вехи:
BOOT → RLOAD → RLE → INPUT → EDITOR → MACHINE
→ LISTING.

[Ф] Страница 37 физически общая у 0152 и 0157.
Один и тот же 076031 в RLE это слово 0152:031,
в трансляторе слово 0157:031. PC 02000 общий у
EDITOR (0154), MACHINE (0170) и буфера 0172.
По одному PC без метки фазы эти владельцы НЕ
различимы, поэтому атлас возвращает все владельцы
сразу, а не выбирает одного молча. Метка фазы
остаётся единственным разделителем внутри PAGE37
и P02000, но она НЕ заменяет сегментную атрибуцию.

[?] S-BOOT объединяет два якоря, 00110 (BOOT,
MONITOR-80) и 064000-064077 (RLOAD, обменная
страница без исходного текста). Это удобная
группировка загрузчика, а не доказательство того,
что обе фазы имеют общий статический код.
