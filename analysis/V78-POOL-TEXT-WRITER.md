# ФАЗА 4C: КТО ПИШЕТ ТЕКСТ В ПУЛ 072001+ (ВЕР.06/78)

Дата: 23.11.2026. Только ВЕР.06/78, зоны 0137-0177.
Write set: только этот НОВЫЙ файл. Коммитов и push нет.
Scratch: /var/tmp/v78-syntax/poolwriter/.
Адреса восьмеричные. Степень ↑. Ширина строки <=60 колонок.
Статусы: ФАКТ / ГИПОТЕЗА / НЕ ИЗВЕСТНО.

## ВЕРДИКТ

ФАКТ. АВТОР ЗАПИСИ НАЙДЕН. Текст пула 072000-072377 пишут
команды Э70 (ввод с ленты/барабана) в НИЗКОЙ памяти
(вне зон 0137-0177):

    PC 05755: *70 6612   PC 05756L: DD RD uil=10/0/3500
    PC 06006: *70 6612   PC 06007L: DD WR uil=0/0/3500
    PC 01573: *70 1610   PC 01574L: DD RD uil=10/0/3500

Все три адресуют ОДНУ страницу: uil.i_addr = 03500,
откуда по `extra.c:4048` `addr = (uil.i_addr & 03700) << 4`
получаем `(03500 & 03700) << 4 = 072000`, диапазон
072000-072377 (1024 слова). Это и есть текстовый пул.

НИ ОДНА `atx`/`зп` в трассе текст в 072001+ НЕ пишет.
Причина прежнего negatives: фильтр `-tt` печатал только
`store`-строки, а Э70 пишет в ОП помимо команды `atx`.

## ВАЖНОЕ ПРЕДУПРЕЖДЕНИЕ

ФАКТ. В строке `DD pc=... z=0000` поле `z=` есть ЗОНА
ДИСКА или ТРАКТ БАРАБАНА (`extra.c:3585-3587`: при u<030
`zone = uir.i_addr & 037`). Это НЕ код и НЕ адрес памяти.
Адрес памяти лежит в поле `uil=.../.../3500`, не в `z=`.
Зона `z=0000` НЕ имеет отношения к 072000.

## 2. ДОКАЗАТЕЛЬСТВО 2 (WATCH: отрицание cmd-записи)

ФАКТ. В dispak есть аппаратная точка наблюдения:
- `cu.c:478-517`: `BESM6_WATCH=<восьм.>`,
  `BESM6_WATCH_RW=1` только запись;
- `ea = XADDR(addr + reg[ui.i_reg])` (
  `cu.c:501`), то есть учитываются и регистровые формы
  `atx (Mn)` (угол 5);
- `debug.c:173-175`: команда отладчика `W OCT` (C_BPW).

ФАКТ. Прогон с наблюдением:

    BESM6_WATCH=072001 BESM6_WATCH_RW=1 \
    dispak -l -tt P2a.job.b6

Результат: `WATCH`-строк = 0 за весь прогон
(до `*74`). Положительный контроль тот же бинарник:

    072000: 1 запись (06061, заголовок)
    012000: 5 записей (01413 и др.)
    010011: 2 записи (077426/077427)

Следствие: ни одна инструкция не пишет 072001.
Запись делает только Э70, который в `cu.c` не проходит
через `STORE`, поэтому `BESM6_WATCH` его не видит.
Это и есть причина, почему `store`-фильтр трассы
показывал текст «с начала» и «никогда не пишется».

ФАКТ. Интерактивная проверка `-b` + `W 72001`:

    printf 'W 72001\ng\n' | dispak -b -l P2a.job.b6

вывела `- set break on data write to72001`,
остановов не было. Формулировка команды подтверждена.

## 3. ДОКАЗАТЕЛЬСТВО 3 (кодирование адреса в -tt трассе)

ФАКТ. `P2a.trace`, строки 61559-61567, подготовка CW:

    61559: 05752: atx 6612   acc=0010000000120000
    61560-61566: xta 1(1)=...72000, asn 54,
                 aax 6274 маска 0000370000000000
                 -> acc=0000350000000000
                 aox 6612 -> acc=0010350000120000
    61567: 05755: *70 6612   (=0010350000120000)

Значение `072000` (база страницы) превращается в `03500`
в поле `uil.i_addr`, что есть адрес страницы для Э70.
Далее первое чтение текста:

    62197: 05764: xta 72000(16)
           (=5652624253050532) r[16]=00011

То есть Э70 в строке 61567 загружает пул за 630 строк
до первого чтения нормализованного текста. Противоречия
с «присутствует с начала» нет: фильтр видел только
`store`-строки.

ФАКТ. Повторные вызовы той же подпрограммы:

    73785: 06006: *70 6612 (=0000350000120000) WR
    149100: 01573: *70 1610 (=0010350000120000) RD

PC 01573 universalен: с другими CW он грузит 010000
(`0010040000120000`, строки 151328, 179676).

## 5. ФАКТ / ГИПОТЕЗА / НЕ ИЗВЕСТНО

ФАКТ. Пишут текст Э70 PC 05756 (RD), 01574 (RD);
читает-пишет назад 06007 (WR). Адрес 072000 из
uil.i_addr=03500. Доказательства §1 и §2.

ФАКТ. Исходная колода содержит `ZLBL1:ZOPC1 ZOPR1 ;
ZCMT1` (P2a.job.b6:22). Нормализованный вид
`5652624253050532` прочитан в 62197.

ГИПОТЕЗА. PC 05756 есть основная загрузка пула на
первом проходе, 01574 есть повторная подкачка страницы
для печати (4 вызова в TP2). Разделение ролей между
ними не доказано.

НЕ ИЗВЕСТНО. Какой физический файл стоит за u=12
(барабан, тракт 0) и где лежит RLE-источник текста.

НЕ ИЗВЕСТНО. Почему 06007 (WR) пишет страницу пула
обратно на барабан (сохранение правки или сброс).

НЕ ИЗВЕСТНО. Точная схема 05753 asn 54 (сдвиг базы
072000 в 03500) нуждается в отдельном разборе битов.
