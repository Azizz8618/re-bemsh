# ПУТЬ ПОТОКА 076600: ТЕКСТ СТРОКИ ИЛИ ЛИСТИНГ?

Дата: 23.11.2026. Только ВЕР.06/78, зоны 0137-0177.
Write set: только этот НОВЫЙ файл. Коммитов и push нет.
Scratch: /var/tmp/v78-syntax/rlepath/.
Статусы: ФАКТ / ГИПОТЕЗА / НЕ ИЗВЕСТНО.
Адреса восьмеричные. Степень ↑. Ширина <=60 колонок.

## 0. Главный результат

ФАКТ. Нормализованный поток 076600 доходит до ТЕКСТА
ИСТОЧНОЙ СТРОКИ, а не только до листинга. Парсер
077320 читает слово `5652624253050532` (P2a) против
`5652624253050401` (P2b) из буфера 06405. Разница
`...32` против `...01` есть наш `:` против пробела
(0x40 → 0x01).

ФАКТ. ПРЯМОГО копирования 012000 → 072000 в трассе
НЕТ. Ни одна команда не читает 012000-012177
(0 попаданий по эффективному адресу). Буфер 012000
в этом окне только приёмник, не источник
текста для 072000.

ФАКТ. В DD-строках поле `z=` есть ЗОНА ДИСКА, не
адрес памяти. В самих трассах P2a/P2b и TP1/TP2
DD-строк нет. Путать зону `z=` с адресом 072000
нельзя.

## 3. Что происходит с 072000 (действие 2, продолжение)

ФАКТ. Все 7 записей в 072000 идут от одной команды:

    06060: xta 6404
    06061: atx 72000(16)  r[16]=0,3,10,16,21,24

Значения: `2010000100052003`, `2010000200052005`,
`2010000300052006`, `2010000400052003`,
`2010000500052003`, `2010000600052004`.
Это ЗАГОЛОВКИ блоков с флагом `0010..`, не текст.

ФАКТ. Источник заголовка - 06404:

    04746: xta 6404   (=2000000100052003)
    04747: atx 6404   пишет 2010000100052003
    06060: xta 6404   (=2010000100052003)
    06061: atx 72000(16)

Читатель заголовков:

    01525: xta 2(1)   (=0300473200072000)
    01527: m+j 6(3)   r[3]=00000
    01534: xta (6)    r[6]=72000
    01534: aax 1626   маска 076000

ФАКТ. Текстовые слова 072000+ НЕ писались в трассе.

## 4. Путь к парсеру

ФАКТ. Цепочка копирования в буфер строки:

    05764: xta 72000(16)  текст из 072000
    05765: atx 6426(2)    пишет 06427+
    03461: xta 6442(16)   читает 06427+
    03461: atx 6417(16)   пишет 06404+
    077316: vlm 77320(2)  цикл по словам
    077320: xta 6405(1)   ЧТЕНИЕ слова строки
    077320: asx 6362(2)   сдвиг на индекс

Строки P2a 61827-61947 показывают 120 чтений
077320; P2b - 118. Разница в слове:

    P2a 63270: 77320: xta 6405(1)
               (=5652624253050532)
    P2b 63277: 77320: xta 6405(1)
               (=5652624253050401)

ФАКТ. Это и есть путь от нормализованного текста
к ПАРСЕРУ. Листинг получает тот же поток через
01563/01564 → 020036 (строки 177912/177915):

    01563: xta 10015(4) (=5652624253050532)
    01564: atx 2042(4)
       02036: store 5652624253050532

ГИПОТЕЗА. 020000-020077 есть буфер печати листинга,
06404/06405 - текст строки для разбора. Оба
потребителя берут один и тот же нормализованный
словарь.
