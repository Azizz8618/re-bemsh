# Разрешение оставшихся неопределённых границ (протокол 2)

Дата: 22.11.2026. Объект: зоны `0147`, `0145` транслятора МАКРО-БЭМШ
(ВЕР.06/78). Настоящий отчёт закрывает два пункта, которые
`analysis/procedures-RESOLVED.md` оставил открытыми (§2 и §5 того отчёта):

* `0147:0445–0476` — точная граница `0473` против `0476`;
* `0145:A01322` — `пб (М15)` или `зп (М15)`.

Write set: только настоящий файл и обновление статусов в
`analysis/procedures.md`. Файлы `gold/` не изменялись; md5 эталонов
до и после всех прогонов одинаковы (см. §4).

---

## 1. Методика

1. Воспроизведение эталона: `disbesm6 -a0 -e0 gold/…` для `0147` и
   `0145`. Число строк совпало с `dis/*-L1.asm` (1266 и 836), побайтовый
   diff = 0. Значит все последующие прогоны идут по тем же словам,
   что и канонические листинги.
2. Ре-трассы `0147` с `-R13=<адрес>` для четырёх новых значений
   `0474 0475 0476 0477` (в RESOLVED были перебраны `561 563 610 474 0`).
3. Прогон `0147` с `-n<таблица>`: 10 точек входа типа `2 = W_CODE`
   (`00445 00470 00473 00474 00476 00477 00061 01100 00426 00534`).
4. Свип `-R<v>=0` для `0145`, `v = 1..7, 10..15` (значение `0` отвергается
   самим `disbesm6`: `Bad base reg 0`). Регистр `(М15)` в печатном виде
   есть поле `opcode>>20 = 13₁₀`, поэтому он задаётся ключом `-R15`,
   а не `-R13`; перебран весь диапазон, чтобы исключить зависимость
   трассы от регистра.
5. Чтение сырых слов `gold/*` (6 байт/слово, big-endian) и разбор opcode
   по `disbesm6.c:45,130` (`зп` = `0x000000` при маске `0x0bf000`,
   `пб` = `0x0c0000` при маске `0x0f8000`).
6. Статический подсчёт входящих ссылок (grep по `dis/MBE-Z0147-L1.asm`
   и `analysis/CROSSREF.md` §4) и сверка границы `0534–0560`.
7. Контроль побайтовой идентичности: из каждого вывода `disbesm6`
   извлекалась последовательность напечатанных 16-разрядных
   восьмеричных слов и сравнивалась с базовой (0 отличий).

Промежуточные файлы: `/tmp/.private/azizz/proc_resolve2_work/` (вне
репозитория).

## 2. Таблица вердиктов

| кандидат | вердикт | ключевое свидетельство | ув. |
|---|---|---|---|
| `0147:0445–0476`, конец | **0473** (было 0476) | `пб A00061` на 0473 — безусловный переход (терминатор); `A00474` на 0474 — 18 входящих ветвлений, общий эпилог; `-R13`/`-n` не добавили ни одного слова | средне-высокая |
| `0145:A01322`, первое слово | **зп (М15)** (не `пб (М15)`) | сырое полуслово `64000000₈` → opcode `0` = `зп`, поле регистра `13₁₀` печатается как `(М15)`; настоящий `пб (М15)` был бы `67000000₈`; свип `-R<v>` дал 0 новых строк | высокая |
| `0147:0534–0607` (ре-верификация RESOLVED) | **0560** (было 0607) | 0560 `по (М13)` + `пб A00474`; 0561–0607 — `конд`; `-R13`/`-n` без изменений | высокая |

Расшифровка уверенности: **высокая** — вердикт следует из самого
сырого слова (opcode); **средне-высокая** — вердикт следует из
структуры кода (терминатор + метка + число входящих ссылок), но не
является прямым байтовым доказательством «возврата».

## 3. Доказательства

### 3.1 `0147:0445` — граница 0473, а не 0476

Сырые слова `gold/MBE-Z0147-L1.bin` (проверены по байтам):

```
0472: 02200000 47100445   мода START / пв A00445(М11)
0473: 03000061 02200000   пб A00061 / (мода START, подавлена)
0474: 02200000 00700631   мода START / Э70 D00631   <- метка A00474
0475: 02200000 00700705   мода START / Э70 D00705
0476: 03001100 02200000   пб A01100 / (мода START, подавлена)
0477: 00100717 00360070   сч D00717 / сда 64-8      <- метка A00477
```

Цифры:

* `0473` = `00 30 00061` — opcode `0c0000` = `пб`, **безусловный
  переход** по прямому адресу `A00061` (там `уиа -5(М3)`, то есть
  M3-зависимый трамплин; отсюда «М3-обрыв» статической трассировки). Правая
  половина слова `02200000` (`мода START`) подавляется `disbesm6`
  (`W_NORIGHT`) и не исполняется, потому что левая половина — переход.
  Следовательно, **перетекания в 0474 по потоку управления нет**.
* `A00474` (0474) — не хвост процедуры `0445`, а **общий эпилог**:
  18 входящих ссылок из разных концов зоны (`по` в строках 81, 84,
  88, 129, 151, 497, 698; `пе` в 398, 544, 552, 581, 624, 724;
  `пб` в 321, 387, 726, 730; `пио` в 705 — всего 18, плюс строка 628
  с самим определением метки). `analysis/CROSSREF.md` §4 тоже
  относит `A00474` к «код: BR по/пе» (18 входов, 0 fuzz).
* `0476` = `00 30 01100` — `пб A01100`, терминал **этого общего
  эпилога**, а не процедуры `0445`. `A01100` — дальше переходник
  `пб A01217` (строка 873).
* `0477` — метка следующей процедуры `A00477` с 10 входящими `пв`.

Вывод: граница «кода до `A00477`» проходит по **0473**: последние
три слова `0474–0476` образуют отдельный разделяемый блок `A00474`.
Старый конец `0476` появился из эвристики «следующая метка + последний
`пб`» (`docs/SEMANTIC/Z0147.md` §6.3) и объединил процедуру с чужим
эпилогом. Размер уточнённого кандидата: `0445–0473` = `027₈` слов
(23 десятичных); отдельный блок `0474–0476` = `3` слова.

Ре-трассы это подтверждают отрицательным результатом: при
`-R13=0474/0475/0476/0477` добавлено **0 строк**, вывод побайтово
равен базовому; `-n` с 10 входами `W_CODE` добавил 1 строку только за
счёт переименования `A##### → P####`, ни одного нового машинного слова.
То есть скрытого продолжения за `0473` статический анализ не даёт.

### 3.2 `0145:A01322` — `зп (М15)`, не `пб (М15)`

Сырое слово `gold/MBE-Z0145-L1.bin` по адресу `1322`:

```
1322: 64000000 000000    word = 6400000000000000₈
```

Разбор левого полуслова `64000000₈` по `disbesm6.c`:

| поле | значение | следствие |
|---|---|---|
| `opcode & 0x0bf000` | `0` | мнемоника **`зп`** (таблица `disbesm6.c:45`) |
| `opcode & 0x0f8000` | `0` | для `пб` требовалось бы `0x0c0000`; **не `пб`** |
| `opcode >> 20` | `13₁₀` | `prreg()` печатает `М%o` → **`М15`** |
| `opcode & 07777` | `0` | адрес 0, печатается `(М15)` без смещения |

Для сравнения: настоящая команда `пб (М15)` с тем же полем регистра
имела бы полуслово `0x0c0000 | (13<<20)` = `67000000₈`, то есть
**совсем другие биты opcode**. В эталоне стоит `64000000₈`, поэтому
прочтение `пб (М15)` невозможно без искажения слова.

Канонический листинг `dis/MBE-Z0145-L1.asm:742` печатает именно
`зп (М15)`; базовый прогон `disbesm6 -a0 -e0` совпал с ним на 836 строк
(diff = 0). Свип `-R<v>=0`, `v = 1..7, 10..15`, не добавил **ни одной**
строки и не изменил ни одного слова (789 word-токенов, 0 отличий):
`зп` пишет в память по адресу из M15 и не зависит от начального
значения регистра, тогда как `пб (М15)` сделал бы трассу
регистрозависимой.

Вердикт совпадает с уже существующим выводом
`docs/PROCEDURES-B.md:395-399` («первое слово — `зп (М15)`, дальше
забел нулей и цикл `-1(М17)`; подставная цель»). Следовательно
`0145:A01322` **не является процедурой**; это подставная цель/данные.
Аналог `0545:1322` в B2 хранит другое слово (`000017₈` → `зп D00017`),
то есть это ещё и правка кода между редакциями, а не только сдвиг
`+0400₈`.

## 4. Побайтовая сверка и честные оговорки

**Сверка.** Все выходы `disbesm6` (база, четыре `-R13`, `-n`, тринадцать
`-R<v>` для `0145`) дали одну и ту же последовательность слов:
`0147` — 905 токенов, `0145` — 789 токенов, отличий 0. База также
побайтово равна `dis/*-L1.asm` (1266/836 строк, diff = 0). md5 эталонов
после всех прогонов:

```
14a3e2bfc75b370e47643d99fbb341c4  gold/MBE-Z0147-L1.bin
59b00be6c3034d5007506cd9a74e5def  gold/MBE-Z0145-L1.bin
d20cb6c156d5daeb45b52abe5500ead3  gold/MBE-Z0176-L1.bin
a3f614097744a26c16c0a946a8cb6ca4  gold/MBE2-Z0576-L1.bin
fd671b0cd5f33ae0ddba1c286b11f057  gold/MBE2-Z0547-L1.bin
```

**Оговорки (обязательные).**

1. Ре-трассы дали **отрицательный** результат: все новые значения
   `-R13` для `0147` и весь свип `-R` для `0145` добавили 0 строк и
   0 слов, то есть не принесли новой информации по сравнению с
   прогонами RESOLVED (`561 563 610 474 0`). Решение по `0473` принято
   по статическим признакам (терминатор, метка, 18 входов в `A00474`),
   а не по впервые обнаруженному динамическому следу.
2. Пункт «dispak breakpoint 0474 (A00474)» из задания **не выполнен**:
   по правилу «no new breaks beyond disbesm6 re-runs» новый
   breakpoint не ставился, а готового следа с точкой `0474` в репозитории
   нет (поиск по `*.md` и `/tmp/.private/azizz` не дал релевантного
   лога). Динамическое подтверждение «общего эпилога» остаётся
   непроверенным; статическое доказательство (18 входящих ветвлений) —
   факт.
3. Вердикт `0473` — **структурная гипотеза средне-высокой уверенности**,
   а не байтовое доказательство возврата: `пб A00061` является прямым
   переходом на общий трамплин, а не `пб (М15)`. Следовательно можно
   утверждать «конец блока `0445` — 0473, дальше идёт отдельный общий
   эпилог», но нельзя утверждать «процедура возвращается именно здесь».
4. Вердикт `зп (М15)` для `0145:1322` — **факт** (сырой opcode), он не
   зависит от гипотез о семантике M15 и не требует сверки с листингом
   транслятора.
5. Самомодифицирующийся код (`docs/DISBESM6-GUIDE.md` §3) статическим
   анализом не отслеживается; данная оговорка RESOLVED сохраняет силу
   для всех verdict-ов настоящего отчёта.

**Итого:** 2 из 2 открытых пункта закрыты (одно уточнение границы,
одно байтовое опровержение мнемоники); 0 пунктов остались полностью
открытыми. Динамическое (dispak) подтверждение не проводилось и
остаётся вне write set.
