**Соглашение о формальных параметрах.** Шапка макроса задаёт до 16 параметров
буквами `А Б В Г Д Е Ж З И Й К Л Н О П Р` (буквы `Ё` и `М` пропущены; `∧М`
используется как имя макроса). Например, `∧М ВНЕШ ∧А,∧Б,…,∧Р` — `∧М`
получает имя определения, остальные — фактические аргументы по позиции.
Глобальные (`GВLА`/`GВLВ`) живут между макросами, локальные (`LСLА`) — внутри
одного `МАСRО…МЕND`.

**Самые важные команды.** `АIF` + `SЕТА` + `.МЕТКА` — единственный механизм
условной генерации и циклов макромашины (в macros.be циклы 48→0 в макросах
`Е`, `ЕЕ`, `ОПРЕ`, `ЕВНЕШ`); `ЭКВ/ЭКВИВ` связывают символы с кодами;
`ВНЕШ/ВХОД` формируют таблицы модуля. Ключевой флаг — глобальная
булевая `∧ВS`, от которой зависят `ВНЕШБ/ВНЕШС`, `ВХОДБ/ВХОДС`,
`КОНДБ/КОНДС` (конфигурация СВС, строки 129–194).

## 2. Трёхпроходный конвейер

```
МАКРОРЕДАКТОР (20.06.78)  →  МАКРОМАШИНА (1.11.78)  →  АРАП (04/78)
   таблица МАСRО…МЕND         подстановка ∧-параметров,     генерация слов,
   (0154.0751; B2 0554.0751)  АIF / SЕТА / .МЕТКА          *МЕТ*, листинг
                              (0170.0216; B2 0570.0274)    (0152.1164)
```

### Фаза 1 — макроредактор
Читает исходник, находит пары `МАСRО … МЕND`, строит таблицу определений
(имя, список формальных `∧А…∧Р`, тело). Счётчик таблицы виден как сообщение
`-КОЛИЧ ЯЧ ГС` (`0154.1450–1451`, PLAN §2.2). Штамп `0154.0751`
«МАКРОРЕДАКТОР ОТ 20.06.78»; в B2 — `0554.0751` «…10.04.76».

### Фаза 2 — макромашина
Разворачивает вызовы: каждой formal-ной букве подставляется фактический
операнд, затем исполняются `SЕТА/SЕТВ`, `АIF (cond).LABEL`, `ЭКВ/ЭКВИВ`,
`GВLА/GВLВ/LСLА` и ветвления по `∧ВS`. Пример из macros.be — макрос `Е`
(строки 101–108):

```
LСLА ∧N          ; локальный счётчик
∧N SЕТА 48       ; начать с 48
.СЛ АNОР         ; метка цикла
Е∧N ЭКВ '103'+48-∧N
∧N SЕТА ∧N-1
АIF (∧N NЕ 0).СЛ ; повторить, пока счётчик не 0
```

**Иллюстрация из листинга `mbe60_*` (НЕ исходник транслятора!).** В листинге
есть колонки `ИСП N` (номер исходной строки / место вызова) и `ГЕН N`
(номер сгенерированной строки). Расхождение означает развёрнутый макрос:
`0118 CALL PRINT8 → 0121 Э74 0`, обе строки имеют `ИСП N = 0119` (PLAN §2.3).
Макрос `CALL ∧T` разворачивается в `ПВО ∧T.(М15)` + `ПАМ 0`; адрес возврата
лежит в М15, внешний символ помечается `СА` и подставляется загрузчиком
(`PRINT8 01205`). Листинг принадлежит **тестовой программе связи с ДКС
МВЕ60**, которую транслятор только оттранслировал (ANCHORS.md §1): он
используется исключительно как пример синтаксиса/развёртки, а не как код
транслятора и не как физический адрес зоны.

### Фаза 3 — АРАП (архив БЕМШ)
Генерирует машинные слова, таблицу `*МЕТ*` и модуль (`ДЛИНА ПРОГ`,
`ВНЕШН=…`, `ВХОДН=…`). Штамп `0152.1164` «АРАП ВАР.04/78»; сообщения
`НЕТ УПРАВЛЯЮЩИХ КАРТ АРАПА` (`0152.0151`), `ОШИБКА СПРАВКИ` (`0152.0157`).
Заголовок листинга (`0176.1743–1763`) содержит колонки
`А Д ИСП N ГЕН N ИСХ МЕТКА ОПЕРАЦИЯ ОПЕРАНД КОММЕНТАРИЙ` — это и есть
интерфейс между фазами 2 и 3.

**Привязка к штампам.** Единственные надёжные физические якоря — текстовые
штампы (ANCHORS.md §2): `0147.1315` «ИПМ МАКРО-БЕМШ ВЕР.06/78»,
`0154.0751`, `0170.0216`, `0152.1164`. Логические адреса листинга
(`01000₈` и т.п.) — адреса памяти тестовой программы, **не** адреса зон
диска; подставлять их как физические запрещено.

## 3. Декодер `tools/macro_decode.py`

```bash
# 1) Печать каталога (37 макрокоманд) в формате Markdown
python3 tools/macro_decode.py --catalog

# 2) Сканирование текстовых констант dis/*.asm
python3 tools/macro_decode.py [--scan-dir dis] [--out analysis/macro_hits.md]

# Тест:_output направляем в /tmp (не в analysis/)
python3 tools/macro_decode.py --scan-dir dis --out /tmp/macro_hits_test.md
```

**Алгоритм.**

1. Разбор строк disbesm6 по шаблону `docs/TEXT-CONSTANTS.md` §1:
   `^\s*(\d+)\s+([0-7]{16})\s+.*\sконд\s+п'(.*?)'` — адрес слова и
   GOST-текст. Зона берётся из имени файла (`MBE-Z0170-L1.asm` → `0170`).
2. Омоглиф-толерантное сравнение: каждый символ написания из каталога
   превращается в класс символов-омоглифов (`G↔Г`, `L↔Л`, `S↔С`,
   `N↔Н`, `D↔Д`, `R↔Р`, `E↔Е`, `F↔Ф`, …), поиск идёт с границами буквы.
   Это позволяет найти `GВLА` и в виде `ГВЛА`, и в виде `GВLА`.
3. Выдача таблицы: `команда | зона.слово | декодированный контекст |
   семантика из каталога | строка macros.be`.

Скрипт только читает входные файлы; он не трогает `dis/*.asm`,
`bemsh/*.asm`, `gold/*` и эталонные образы томов.

## 5. Оговорки и неопределённость (обязательно)

1. **macros.be — не исходник транслятора.** Это набор макроопределений
   той же экосистемы (МАКРО-БЕМШ / ДИСПАК). Семантика команд выведена из
   *использования* в macros.be и из синтаксиса листингов, а не из
   дизассемблированного кода транслятора (PLAN §2.1, ANCHORS.md §1).
2. **Только текстовые штаммы — надёжные якоря.** Атрибуция зон `0154`
   («МАКРОРЕДАКТОР») и `0170` («МАКРОМАШИНА») подтверждена
   динамически 22.11: обе зоны грузятся по `02000₈` как оверлей page 01,
   входы `xta 6065` (0154) и `ntr 3` (0170), штампы в RAM по
   `02751`/`02216`, читаются как данные (`PASSES-CODE-LOCATION.md`).
3. **`mbe60_*` — чужой листинг.** Это оттранслированная тестовая программа
   ДКС `МВЕ60`, а не транслятор. `ИСП N`/`ГЕН N`, `CALL → ПВО …(М15)`,
   `ПАМ 0` используются только как **иллюстрация** развёртки макросов.
   Соответствие «слово листинга ↔ слово дампа» не установлено: 0 совпадений
   (ANCHORS.md §1).
4. **Омоглифы.** Написания `МАСRО`, `GВLА`, `SЕТА`, `АNОР`, `DК`, `МNОТЕ`,
   `МЕND` сохранены как в OCR-источнике. Канонизация в декодере — поисковый
   приём, а не утверждение об исходном символе (например, латинское `N`
   сведено к `Н`, хотя визуально `N` ближе к `И`).
5. **Гипотетическая семантика.** `КОНД`, `DК`, `МNОТЕ`, `ЭКВ/ЭКВИВ` и
   точное поведение `∧ВS` реконструированы по контексту; прямого
   дизассемблированного подтверждения нет. Помечено в каталоге.
6. **Декодер ищет только `п'…'`.** Текст, напечатанный как `в'<восьм>'`
   (GOST-байт за пределами `0x00–0x0F`/`0x20–0x4D`), не разбирается;
   продолжение фразы в соседних словах не склеивается. Поэтому таблица
   попаданий — нижняя оценка.
