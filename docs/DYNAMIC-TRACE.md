# Динамическая трассировка транслятора МАКРО-БЕМШ под `dispak`

Дата: 19.11.2026. Задача: проверить гипотезу «исполняемый код
макроредактора/макромашины лежит вне зон `0154`/`0170`» путём динамической
трассировки, а не только по текстовым штампам (`docs/ANNOT-MACRO.md` §3).

**Итог:** трассировка технически возможна и выполнена, но
гипотеза остаётся **НЕ ПОДТВЕРЖДЁННОЙ И НЕ ОПРОВЕРГНУТОЙ** — см. §5
(категориальное рассогласование «зона диска» ↔ «адрес памяти»).

---

## 1. Что найдено в `dispak` (возможности трассировки)

Бинарник: `/usr/local/bin/dispak`, `dispak version 2.6.458-9b5cabe`,
md5 `944a91c7a0e2adce3cd7763b63774ea7`.

### 1.1 Ключи CLI (из `dispak -h`, дословно)

```
  -b, --break            break on first cmd
  -v, --visual           visual mode for debugger
  -t, --trace            trace all extracodes
  --trace-e64            trace extracode 064
  -s, --stats            show statistics for machine instructions
  --path=dir1:dir2...    specify search path for disk images
  --no-insn-check        all words but at addr 0 are treated as insns
  --drum-dump=file       output drum 27 to file
```

`-t` **инкрементирует** `trace` (`dispak/dispak.c:261: ++trace`).
Значит `-tt` даёт `trace = 2`, а `-ttt` — `trace = 3`.

Формат печати при `trace >= 2` (`dispak/dispak/cu.c:379–399`):

```c
fprintf(stderr, "%05o: %-4s", abpc, op.o_name);
```

то есть **каждая исполненная машинная команда печатает свой адрес**
`abpc` в восьмеричном виде в `stderr`. Строки `store` (обращение к
памяти) печатаются с отступом и в анализе адресов команд не участвуют.

### 1.2 Интерактивный отладчик

В `dispak/dispak/debug.c` / `debug.y` есть команды
`breakpoint <восьм.>`, `b <восьм.>`, `trace [цифра]`, `where`,
`step`, `execute`, `bpw`. Но **из CLI точки останова напрямую не
задаются**: нужно войти в отладчик через `-b`/`-v` и подавать команды
на stdin. Для данного эксперимента это не потребовалось.

### 1.3 Чего в установленном бинарнике НЕТ (отрицательный результат)

В исходниках `/home/azizz/Yandex.Disk/dispak/dispak/{cu,extra,vsinput}.c`
есть хуки `BESM6_WATCH`, `BESM6_WATCH_RW`, `BESM6_CORE_ON_PC`,
`BESM6_MTR_LO/HI/N/SKIP`, `BESM6_DD_DEBUG`, `BESM6_AOX17_LOG`
(точки наблюдения, дамп ядра по PC, MTR-окно). Проверка
`strings /usr/local/bin/dispak` показывает, что **все эти строки
ОТСУТСТВУЮТ** в установленном бинарнике. То есть «поставить watch на
адрес» или «дампнуть ядро при попадании на PC» штатно **нельзя**.
`disbesm6 -RN=x` — статическая трассировка переходов, не динамическая.

## 4. Ключевое ограничение: зона диска ≠ зона памяти

`abpc` в `dispak/dispak/defs.h` — `ushort`, а `ADDR(x)` маскирует
`& 077777` (15 бит). Следовательно адрес исполнения ≤ `077777₈`, а
`адрес / 1024 (=02000₈)` даёт **зону памяти не выше `037₈`**.

Зоны `0137–0177₈` — это номера **зон на диске** тома 2048 (по 1024
слов каждая), а не адреса оперативной памяти. При загрузке транслятора
ОС раскладывает оверлеи по адресам памяти, и обратного соответствия
«адрес памяти → зона диска» трасса не содержит.

Поэтому нули в таблице §3 **не** означают, что зоны 0154/0170 «не
исполняются»: это ожидаемый артефакт неверного отображения. Для
сопоставления нужна карта загрузки/оверлеев ОС ДИСПАК
(какой дисковой зоне соответствует каждый участок памяти в каждом
проходе), которой в этом эксперименте нет.

## 5. Вывод по гипотезе

- **Установлено фактами:** оба прохода (макроредактор, макромашина)
  выполняются; их код исполняется из младшей памяти, преимущественно
  в зонах `001–002₈` (на них ≈ 458 тыс. из 735 тыс. команд), а также
  в зонах `000, 003, 006, 012–014, 034, 036–037₈`. Ни одна команда не
  исполняется по адресу с номером зоны ≥ `040₈`.
- **Не установлено:** к какой именно дисковой зоне 0137–0177 относится
  тот или иной исполненный адрес. После загрузки в память штамп
  «МАКРОРЕДАКТОР» из `0154.0751` и штамп «МАКРОМАШИНА» из `0170.0216`
  оказываются в памяти со смещениями, зависящими от базы загрузки и
  оверлеев; трасса базу загрузки не показывает.
- **Итог:** гипотеза «код макроредактора/макромашины лежит вне
  0154/0170» динамической трассировкой **ни подтверждена, ни
  опровергнута** (неопределённый результат). Статический вывод
  `docs/ANNOT-MACRO.md` §3 («штампы — текст, код разрежен») сохраняет
  силу, но данный эксперимент его не усиливает.
