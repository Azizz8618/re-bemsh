# Команда РЕГ (opcode 002₈) — точная семантика и диапазон аргумента

Дата: 20.11.2026. Режим: READ-ONLY (изменены только этот файл).
Источники: `simh/BESM6/besm6_cpu.c`, `old/besm6_cpu.c`,
`besm6_defs.h`, `besm6_sys.c`, `besm6_cpu.c.rez`;
`dispak/dispak/{cu.c,optab.c}`; `dispak/disbesm6/disbesm6.c`.
Эталонные образы не трогались.

## 1. Машинное кодирование

Слово БЭСМ-6 = 48 бит = две 24-битные половины. disbesm6 и simh
работают с 24-битным кодом `RK` (половина слова).

Поля (simh `besm6_cpu.c:1032-1045`):

    RK &= BITS(24);
    reg = RK >> 20;              /* старшие 4 бита */
    addr = RK & BITS(12);        /* младшие 12 бит */
    if (RK & BBIT(19))
        addr |= 070000;          /* знаковое расширение */
    opcode = (RK >> 12) & 077;   /* 6 бит */

- opcode = 002₈ (биты 13..18) — это и есть РЕГ.
- `reg` = биты 21..24, 4 бита, значения 0..17₈ (М0..М17).
  simh `besm6_sys.c:424`: `reg = (cmd >> 20) & 017;`.
- адрес = младшие 12 бит + бит 19 (`BBIT(19)`) даёт 070000₈
  при установке, т.е. 15-битное значение 000000..077777₈.
- `BBIT(n) = 1 << (n-1)` (`besm6_defs.h:86`), значит
  `BBIT(19) = 0x040000` — в точности бит, который проверяет
  disbesm6 в `arg1` (см. §4). Расхождений нет.

Исполнительный адрес (simh `besm6_cpu.c:1097-1101`):

    Aex = ADDR (addr + M[reg]);
    if (! IS_SUPERVISOR (RUU))
        longjmp (cpu_halt, STOP_BADCMD);   /* только привилегия */
    cmd_002 ();

То есть операнд РЕГ — это ПОЛЕ АДРЕСА, а не номер регистра,
не маска и не абсолютный адрес зоны. `reg` — отдельное поле
модификатора, печатается как `(Мn)`.

dispak: `optab.c:24` — `{"mod", 0, I_MOD, F_PRIV}, /* 002 */`.
Русский мнемоник `рег` = latin `mod` (модификатор), привилегированная.

## 2. Допустимые значения аргумента

simh `besm6_cpu.c:527-594` (идентично в `old/besm6_cpu.c:513-581`):

    switch (Aex & 0377) {

Маскируются только МЛАДШИЕ 9 БИТ (`0377₈` = 255₁₀). Старшие
биты адреса на семантику не влияют. Перечисленные коды (восьм.):

| Код Aex&0377 | Действие | Источник |
|---|---|---|
| 000..007 | запись в БРЗ (кэш) | `cmd_002:533-536` |
| 020..027 | запись в регистры приписки | `cmd_002:537-541` |
| 030..033 | запись в регистры защиты | `cmd_002:542-545` |
| 036 | маска гл. регистра прерываний | `cmd_002:546-549` |
| 037 | сброс гл. регистра прерываний | `cmd_002:550-554` |
| 0100..0137 | биты режима РУУ (БРО/ПКП/ПКЛ) | `cmd_002:555-575` |
| 0200..0207 | чтение БРЗ | `cmd_002:576-580` |
| 0237 | чтение гл. регистра прерываний | `cmd_002:581-584` |
| 0140..0177 | watchdog, НЕ реализован → STOP | `cmd_002:585-589` |
| всё остальное | "invalid special register address" | `cmd_002:590-593` |

Итог: осмысленный диапазон — **000₈..0377₈** (0..255₁₀),
и в нём только перечисленные выше коды. "Больших" аргументов
(типа 3554₈ = 1900₁₀) не существует: 1900 & 255 = 0154₈,
что не попадает ни в один case.

Подтверждение на наших данных (АСМ ИТМ, подлинные РЕГ):
- `dis/ASM-Z0055-full.asm:258,266,267,272-277` — `'20','24','25','30'..'33'`.
- `dis/ASM-Z0055-full.asm:1197,1233` — `'36','37'`.
- `dis/ASM-Z0055-full.asm:289,174` и `ASM-Z0060:1424,1429` —
  `'105','101','107'` (коды 0100..0137₈, управление режимом).
- `dis/ASM-Z0057-full.asm:108` — `рег` без операнда (= Aex 0).

## 3. Поведение при выходе из диапазона

- simh: НЕ trap. `cmd_002:590-593` — только
  `besm6_debug("*** ... invalid special register address ...");`
  затем `break` — команда становится no-op.
  Единственный stop внутри `cmd_002` — `(Aex & 0340) == 0140`
  → `longjmp(cpu_halt, STOP_UNIMPLEMENTED)` (нереализованный
  watchdog), это останов симулятора, не ловушка ЦП.
- Привилегия проверяется отдельно: вне супервизора
  `besm6_cpu.c:1099-1100` → `STOP_BADCMD`. От аргумента не зависит.
- dispak ещё проще: `cu.c:721-725`

      case I_MOD:
          if (supmode)
                  NEXT;
          else
                  ABORT(E_PRIV);

  Операнд вообще не читается. РЕГ = привилегированный no-op.

Вывод: ни simh, ни dispak не используют аргумент как константу
и не грузят его в ACC. Гипотеза «рег 'NNN' загружает NNN в
аккумулятор» исходным кодом эмуляторов НЕ подтверждается.

## 4. Как disbesm6 печатает операнд

`disbesm6.c:441-443`:

    int reg = opcode >> 20;
    int arg1 = (opcode & 07777)
             + (opcode & 0x040000 ? 070000 : 0);
    int arg2 = opcode & 077777;

`disbesm6.c:485-496` (ветка `OPCODE_IMM`, куда попадает `рег`):

    if (arg1) printf ("'%o'", arg1);
    if (reg) { putchar ('('); prreg (reg); putchar (')'); }

То есть кавычечное `'NNN'` — это восьмеричная печать `arg1`
(адресного поля), а `(Мn)` — поле `reg`. Сырые поля печатает
`disbesm6.c:400`: `printf("%02o %03o %04o ", reg, поле_op, адрес);`
Строка таблицы `disbesm6.c:47`:
`{ "рег", 0x002000, 0x0bf000, OPCODE_IMM, PRIV }`.

Почему возникает ложное чтение: disbesm6 — статический
дизассемблер, он не знает, где код, а где данные. Любое 24-битное
слово, у которого биты 13..18 равны 002, печатается как `рег`,
а его младшие 12 бит — как `'NNN'`. Если слово на самом деле
данные/константа, получается осмысленная на вид строка
`рег '3554'`, хотя реального спец-регистра 3554 не бывает.

## 5. Конкретные примеры из наших данных

| Пример | zone:word | Значение | Вердикт |
|---|---|---|---|
| `рег '3554'` | 0137:3 (правая половина) | 3554₈=1900₁₀, >0377 | **НЕвалидно**, данные/ложное чтение |
| `рег '60'` | 0173:1522 | 060₈=48₁₀, «дыра» 040..077 | **Подозрительно**, не в списке кодов |
| `рег '3'` | в dis/*.asm не найдено | 003₈ → запись БРЗ(3) | Формально валидно (гипотетический пример) |

Обоснование:

- `docs/EXTRACTION.md:126-127` и `dis/MBE-Z0137-L1.asm:16`:
  зона 0137, слово 3, правая половина —
  `00 002 3554  рег '3554'`. Левая половина того же слова
  `00 000 0000 зп START`, и в `EXTRACTION.md:125` прямо
  помечено `* next insn used as data` — уже на этапе извлечения
  это слово помечено как ДАННЫЕ. `docs/LABELS-KEY-BE.md:34`
  ведёт `3554` как `CONST3554 / CONST3554 РЕГ`, т.е. константу.
  3554₈ & 0377 = 0154₈ — невалидный адрес спец-регистра.
- `dis/MBE-Z0173-L1.asm:872-933`: таблица из 36 пар
  `рег 'NNN'` / `зп '4154'` (и `'4231'` и др.), значения
  '60','440','210','200','450','140','220','250','300','500',
  '510' и т.д. Часть (`'140'`=0140₈ → watchdog STOP,
  `'440'`,`'500'`,`'510'`) вообще выходят за 0377₈ или в
  неразрешённые «дыры». `docs/VARIABLES-VALIDATION.md:121`
  называет это «36 пар «код ошибки → запись в ячейку»».
  Поскольку dispak/simh делают из РЕГ no-op, правдоподобнее,
  что оба слова пары — ДАННЫЕ: первое хранит код, второе адрес
  ячейки, а disbesm6 читает их как `рег`/`зп` по opcode-полям
  002/000. Это ровно случай §4.
- `docs/TEXT-CONSTANTS-ALL.md` не содержит строк с `рег`/`3554`
  (проверено: 0 совпадений) — он каталогизирует только `конд`
  словесные константы, так что прямых свидетельств там нет;
  использованы `dis/*.asm`, `docs/EXTRACTION.md`,
  `docs/LABELS-KEY-BE.md`, `docs/VARIABLES-VALIDATION.md`.

## 6. Правило переинтерпретации подозрительных `рег`

1. Вычислить `v = Aex & 0377` (для `рег 'NNN'` без `(Мn)`
   это просто NNN & 0377).
2. Если `v` входит в множество
   `000-007, 020-027, 030-033, 036-037, 0100-0137,
   0200-0207, 0237` — это подлинная команда РЕГ, оставить как есть.
3. Если `v` попадает в 0140-0177 — это нереализованный watchdog;
   для кода БЕМШ подозрительно, проверить выравнивание.
4. Если `v` в «дыре» (`010-017, 034-035, 040-077, 0210-0236,
   0240-0377`) или операнд > 0377₈ — НЕ считать РЕГ.
   Это почти наверняка данные/константа, которая случайно
   декодировалась как opcode 002. Перемаркировать как данные
   (`конд в'...'` / `D#####`) либо как константу в
   таблице, сверившись с соседними словами и листингом.
5. Отдельно: наличие `(Мn)` не спасает большое значение — `Aex =
   addr + M[reg]`, но маска 0377 остаётся; статический анализ
   не знает значение M, поэтому такие строки тоже подозрительны
   (например `рег '75423'(М4)` в `ASM-Z0055:736`).
6. Никогда не «исправлять» число в исходных листингах: только
   комментарий после запятой и пометка данных по правилам
   `AGENTS.md`.

Краткий вывод: **валидный диапазон аргумента РЕГ — 000₈..0377₈
с перечисленным набором кодов; '3554' — невалидно (данные), '60' —
в «дыре» (подозрительно), '3' — валидно; при v вне набора слово
считать данными, а не командой.**
