# Формат таблицы макроопределений БЭСМ-6

Дата: 19.11.2026. Образ `2348`, зоны `0137–0177`
(B, ВЕР.06/78). Статус: **структурная гипотеза**.
Прямого дампа записи «имя + ∧-параметры + тело» в этих
зонах НЕ найдено. Ниже разделены ФАКТЫ (адреса, слова,
байты) и ГИПОТЕЗА (формат записи).

---

## 1. Методика

Прочитаны: `PLAN.md` §2.2–2.3, `MACRO-COMMANDS.md`,
`TEXT-CONSTANTS.md`, `ANNOT-MACRO.md`, `LABELS-B.md`,
`analysis/procedures.md`, `analysis/CROSSREF.md`,
`AGENTS.md`.

Инструменты (только чтение эталонного образа):

```
besmtool view 2348 --start=<зона> --length=1 \
  --encoding=g,k,t,i
besmtool dump 2348 --start=<зона> --length=1 \
  --to-file=/tmp/z.bin
besmtool search 2348 '<фраза>'
disbesm6 -a0 -e0 gold/MBE-Z<зона>-L1.bin
линейная развёртка -n<tab> -> proc_work/*sweep.asm
```

Правило `AGENTS.md`: не домысливать; гипотеза →
проверка → вывод. Адреса восьмеричные; `besmtool
--start` тоже восьм. Числа ниже — восьм., если не
помечено `dec` / `hex`.

## 3. Кодировка текста (ФАКТ)

GOST-10859: **6 символов на 48-битное слово**
(1 байт на символ). Подтверждено байтами
(`besmtool dump` + `xxd`):

```
0165.0107: 2c 20 31 47 2e 0f -> «МАСRО »
0176.0535: 22 35 2e 24 2d 0f -> «ВХОДН »
0176.0537: 22 2d 25 38 2d 0f -> «ВНЕШН »
0171.0321: 32 25 2a 31 32 0f -> «ТЕКСТ »
```

В `R` слове `0165.0107` — латинская буква
(`GOST_R` = `0x47`), омоглиф кириллической `Р`.
Колонки KOI7/TEXT/ITM для этих слов — мусор:
признак GOST-кодировки (`TEXT-CONSTANTS.md` §3–4).

Код `∧` = `GOST_OVERLINE` = `0115` восьм. = `0x4D`
(`gost10859.h:91`). Пример: `∧А` = байты `4d 20`.
В зонах `0147–0177` байт `0x4D` **не встречается
ни разу** (сканирование всех `gold/MBE-Z*.bin`):
∧-параметры не хранятся GOST-текстом в этих зонах.

## 4. Повторяющиеся таблицы-дескрипторы (ФАКТ)

### 4.1 Зона 0170, слова 0003–0067

53 подряд идущих слова, шаг = 1 слово,
константа-префикс `2710 2070 0300`,
меняющееся поле `XXXX` (4 восьм. цифры):

```
0170.0003  2710 2070 0300 3055
0170.0004  2710 2070 0300 3670
0170.0005  2710 2070 0300 3565
...
0170.0067  2710 2070 0300 3261
0170.0070  7400 0000 2637 7777
```

Линейная развёртка (`sweep.asm`) читает слово
как пару полукоманд:

```
0170.0003: пв '2070'(М5) | пб '3055'
0170.0004: пв '2070'(М5) | пб '3670'
```

Структура: **[константная метка | указатель]**.
Первое полуслово постоянно; меняется только
адрес перехода. Значения `XXXX`: 2551–4750 восьм.,
часть образует почти арифм. прогрессию
(3344, 3351, 3356, 3363, 3370) — признак
указателей на соседние блоки текста.

### 4.2 Зона 0165, слова 0367+ (аналогично)

69 слов с префиксом `0220 0000 0300`:

```
0165.0367  0220 0000 0300 2621
        -> мода | пб '2621'
0165.0370  0220 0000 0300 3174
        -> мода | пб '3174'
```

### 4.3 Счётчик

`0154.1450–1451` = «-КОЛИЧ ЯЧ ГС»
(`TEXT-CONSTANTS.md:164`) — сообщение со счётчиком
ячеек таблицы «ГС». Привязка счётчика к таблице
макросов — гипотеза.

## 5. Отрицательные доказательства (ФАКТ)

1. Имена макрокоманд найдены в диагностических
   и справочных таблицах: `0165.0107` «МАСRО»,
   `0176.535/537` «ВХОДН/ВНЕШН», `0171.321`
   «ТЕКСТ» (`macro_hits.md:14–18`). Они печатаются
   `конд п'…'`, а не как исполняемый код.
2. Байт `0x4D` (`∧`) отсутствует во всех
   GOST-зонах `0147–0177`.
3. Записей «имя + параметры + тело» в развёртках
   `0154/0165/0170` не найдено: таблицы 0170.3–67
   и 0165.367+ — дескрипторы [метка | указатель],
   ближе к таблицам перехода/сообщений.
4. `macros.be` — внешний набор макроопределений
   той же экосистемы, не исходник транслятора
   (`MACRO-COMMANDS.md` §5).

Вывод: формат таблицы макроопределений **не
восстановлен прямо**. Ниже — правдоподобная модель,
согласованная с разделами 3–4.

## 6. Гипотеза: формат записи

Слои (сверху вниз):

```
A. ТАБЛИЦА ДЕСКРИПТОРОВ
   шаг 1 слово = 2 полукоманды
   +0  [TAG | VAL]   48 бит
   TAG = тип токена (МАСRО/ПАРАМ/КОМАНДА/MEND)
   VAL = указатель в пул или индекс параметра

B. ТЕКСТОВЫЙ ПУЛ (GOST, 6 симв/слово)
   имя, ∧-параметры, строки тела

C. ИНДЕКС
   счётчик «КОЛИЧ ЯЧ ГС» (0154.1450)
```

Предполагаемые поля записи (ГИПОТЕЗА):

```
поле        смещ. пример слова      доказат.  ув.
МАСRО-тег   +0    [TAG_M | 0]       стр. 0170  низк.
имя         +1    «ПРЕ  »           GOST 0107  сред.
N парам.    +2    [TAG_P | N]       ∧ нет      низк.
∧-параметры +3    «∧А∧Б» (0x4d..)   gost.h    низк.
указатель   +k    [TAG_B | адрес]   0170.3–67  сред.
тело        +k+1  «УИА ∧А» (GOST)   6 симв/сл  сред.
MEND-тег    +m    [TAG_MEND | 0]    macros.be  низк.
```

`∧М` зарезервировано под имя макроса; 16 букв
`А Б В Г Д Е Ж З И Й К Л Н О П Р`
(`MACRO-COMMANDS.md` §1).

## 7. Рабочий пример (ГИПОТЕЗА)

`macros.be:223–226`:

```
МАСRО
∧М ПРЕ ∧А
 УИА ∧А
 МЕND
```

Токены в GOST (восьм. / hex):

```
МАСRО  054 040 061 107 056 017
       = 2c 20 31 47 2e 0f
∧М     115 054           = 4d 2c
ПРЕ    057 060 045       = 2f 30 25
∧А     115 040           = 4d 20
УИА    063 050 040       = 33 28 20
МЕND   054 045 105 077   = 2c 25 45 3f
```

Гипотетическая укладка (дескрипторы + пул):

```
+D0: [TAG_M | адрес_имени]  пул: «ПРЕ  »
+D1: [TAG_P | 0x4d2c]       ∧М (имя)
+D2: [TAG_P | 0x4d20]       ∧А (1-й пар.)
+D3: [TAG_B | адрес_тела]   пул: «УИА ∧А»
+D4: [TAG_MEND | 0]
```

**Ни одно число `TAG_*` не прочитано из дампа.**
Это модель, а не байт-за-байтом формат.

## 9. Открытые вопросы

1. Где пул с ∧-параметрами? В зонах 0147–0177
   байта `0x4D` нет — возможно, 6-битная внутренняя
   кодировка БЭСМ-6 (8 симв/слово), не GOST.
2. Что означают 53 указателя `0170.3–67` и 69
   указателей `0165.367+` — сообщения, обработчики
   или тела макросов? Нужна трассировка вызова
   `2070`(М5) и чтение по адресам `пб 'XXXX'`.
3. Куда ведут прямые `пб '2757'` (0154:9) и
   `пб '2214'` (0170:8) — в ту же зону или в 0147?
4. Связан ли счётчик `0154.1450` с логическим
   `001332` из листинга `mbe60_*`? Не доказано.
5. Есть ли та же таблица в B2 (`0554/0570`,
   сдвиг `+0400`)? Задача B2 не покрывала.
