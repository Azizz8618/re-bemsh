# Блок-схемы МАКРО-БЕМШ на языке ДРАКОН

Шесть схем, документирующих транслятор `ТРАНСЛЯТОР С М/К БЕМШ`
(том 2348, зоны `0137–0177₈`, `ВЕР.06/78`) и практику чтения
его дискового образа. Синтаксис — подмножество ДРАКОН-1 по
`re-siprod/DRAKON.md`; эталонный генератор разметки —
`re-siprod/tools/drakon_markup.py`.

## Состав

| файл | содержание |
|---|---|
| `01-pipeline.drakon` | трёхпроходный конвейер: вход → 0154 → ГС → 0170 → 0152 → модуль и листинг |
| `02-macro-editor.drakon` | `MACRO … MEND`, `∧`-параметры, `GВLА/SЕТА/АIF`, таблица ГС, `-КОЛИЧ ЯЧ ГС` |
| `03-macro-machine.drakon` | подстановка параметров, `АIF`/`SЕТА` циклы, `ИСП N → ГЕН N` |
| `04-arap.drakon` | машинные слова, `*МЕТ*`, листинг, внешние связи (`СА`, `*EXECUTE`) |
| `05-vyzov-i-vozvrat.drakon` | `CALL → ПВО ∧T.(М15) + ПАМ 0 → ВЖМ`, возврат `ПБ (М15)`, регистры M13–M16 |
| `06-chtenie-dampa.drakon` | `besmtool dump` → 6-байтовые слова → `W_CODE` → GOST/TEXT → `EQU` → сверка сборки |

Источники доказательств перечислены в комментариях (`*`) в начале
каждого файла: `docs/PLAN.md` §2–3, `docs/MACRO-COMMANDS.md`,
`docs/FINAL-REPORT.md`, `analysis/MEMORY-MAP.md`,
`docs/PROCEDURES-{ASM,B,B2}.md`, `AGENTS.md`.

## Правила синтаксиса, использованные в схемах

* Одна икона — одна строка: `КЛЮЧЕВОЕ_СЛОВО: подпись`.
  Ключевые слова — только из `DRAKON.md` §1: `ЗАГОЛОВОК`, `ВЕТКА`,
  `АДРЕС`, `ДЕЙСТВИЕ`, `ЕСЛИ`, `ТО`, `ИНАЧЕ`, `ВЫБОР`, `ВАРИАНТ`,
  `ЦИКЛ`, `КОММЕНТАРИЙ`, `КОНЕЦ`. Краткие формы (`ЗГ`, `ВТ`, …)
  допустимы по `DRAKON.md`, но здесь не применяются.
* Отступ — кратен 4 пробела. `ВЕТКА` — только на уровне 0;
  переходы между ветками — `АДРЕС`, последняя ветка заканчивается
  `КОНЕЦ` на уровне 0.
* `ТО`/`ИНАЧЕ` стоят на один уровень глубже `ЕСЛИ`;
  `ВАРИАНТ` — на один уровень глубже `ВЫБОР`; тело `ЦИКЛ` —
  на уровень глубже вопроса. Это соответствует разбору
  `tests/drakon/*.drakon` (эталоны `.out`).
* Строки, начинающиеся с `*`, — комментарии, в схему не попадают.
  Ведущий блок комментариев содержит ссылки на доказательства
  и пометки гипотез.
* Подпись иконы ≤40 знаков; длина строки ≤60 колонок
  (`AGENTS.md` §0). Формальные параметры БЕМШ пишутся `∧L`, `∧T`;
  знак `^` не используется.

Пример фрагмента:

```
ВЕТКА: Чтение
    ДЕЙСТВИЕ: Взять карту исходника
    ЕСЛИ: Строка = MACRO?
        ТО
            ДЕЙСТВИЕ: Начать определение
            АДРЕС: Шапка
        ИНАЧЕ
            ДЕЙСТВИЕ: Ждать следующую MACRO
            АДРЕС: Чтение
```

и записи не подлежит (`re-siprod/DRAKON.md` §6).

## Оговорки

1. Схемы — документация по текстам отчётов, не реконструкция
   исходного кода транслятора. Роли проходов (`0154`, `0170`,
   `0152`) приписаны по текстовым штаммам; динамически доказана
   только загрузка `0154` по `02000₈` (`analysis/MEMORY-MAP.md` §6).
   Для `0170` гипотеза оверлея остаётся открытой.
2. `mbe60_*` — листинг тестовой программы связи с ДКС
   (`МВЕ60`), а не исходник транслятора. Колонки `ИСП N`/`ГЕН N`,
   макрос `CALL`, `PRINT8 01205` используются только как иллюстрация
   синтаксиса и развёртки. Соответствие «слово листинга ↔ слово
   дампа» не установлено (0 совпадений).
3. `macros.be` (`re-dispak`) — набор макроопределений той же
   экосистемы, не исходник транслятора. Семантика `GВLА`,
   `SЕТА`, `АIF`, `ЭКВ` выведена из использования; прямого
   дизассемблированного подтверждения нет.
4. `[TAG|VAL]` для ячеек ГС не подтверждена (Фаза B); в схемах
   отражена только доказанная цифра: +2 ячейки на простой
   макрос, +4 при `LСLА`/`SЕТА`/`АIF`.
5. Логические адреса из `*МЕТ*`/`*EXECUTE` не являются
   физическими якорями зон; физическими якорями служат только
   текстовые штампы (`AGENTS.md` §3).
