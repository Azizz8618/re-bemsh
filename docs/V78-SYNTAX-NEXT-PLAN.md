# План закрытия вопроса: разбор строки ВЕР.06/78

Дата: 23.11.2026. Фокус: зоны 0137-0177 тома 2048/2348.
Цель: ответить ДА или НЕТ на вопрос, найден ли механизм
выделения полей МЕТКА / ОПЕРАЦИЯ / ОПЕРАНД / КОММЕНТАРИЙ.
Адреса восьмеричные, степень ↑, тире НЕ используется.

## 0. Формулировка критерия (сначала, до опытов)

Чтобы не повторить «ищем и не находим», зафиксируем,
что считать ответом:

НАЙДЕНО, если существует PC (или небольшая связная
процедура), для которого выполнены ТРИ условия:
1. он читает байт исходной строки;
2. он принимает РАЗНОЕ решение для двух колод, где
   один и тот же знак стоит в разных полях;
3. после него меняется адрес назначения или
  структура записи, то есть поле реально выделено.

НЕ СУЩЕСТВУЕТ (отдельного разбора), если для всех
кандидатов выполнено обратное и дополнительно
показано, что поля вычисляются позиционно позже:
при печати листинга или при генерации слов.

НЕ ИЗВЕСТНО фиксируется, если после всех фаз есть
 неопознанный PC с разным поведением, но без условия 3.

## 1. Фаза A. Статический разбор диспетчеров

Цель: понять, что делает `076031-076123` и два других
кластера, реагирующих на токены.

Шаги:
- принудительный W_CODE дизассембль зон 0152, 0153,
  0157 с полным all-code.tab;
- разобрать `076031-076123`: цепочку `uza`, маску
  `aax 77635`, возврат `077502 uj (16)`;
- разобрать потребителя `077421-077502` и цикл
  `075344-075401`, активный в управляемых колодах;
- для каждого вывести: входной байт, таблицу ветвлений,
  выходной адрес, роль.

Критерий: таблица «PC | вход | сравнение | выход» для
всех трёх кластеров с подтверждением по gold-слову.
Результат: `analysis/V78-DISPATCHERS-DECODE.md`.

## 2. Фаза B. Матрица колонок

Цель: проверить, существует ли позиционная логика
(по колонкам), которую мы не видели.

Шаги:
- построить 8-10 колод: уникальный токен `QQQQ` стоит
  последовательно в колонках 1, 3, 5, 8, 10, 15, 20, 30;
- все остальные байты колод побайтно одинаковы;
- прогон под `-tt` + дифференциального анализатора;
- для каждого сдвига фиксировать: меняется ли METKA,
  ГС-счётчик, код команды, echo, дескриптор 06061.

Критерий: если есть колонка, где поведение меняется
скачком, это граница поля. Если нет — сильный аргумент
за отсутствие позиционного разбора.
Результат: `analysis/V78-COLUMN-MATRIX.md`.

## 3. Фаза C. Матрица типов знаков

Цель: увидеть, различает ли гость КЛАСС знака в каждом
поле, а не только маркеры конца строки.

Шаги:
- колоды с цифрой, буквой, `:`, `;`, `,`, `*`, пробелом
  и `^` в позиции метки, операции, операнда, комментария;
- брейкпоинты на `076031-076123`, `075353-357`,
  `075377`, `077320`, `06061`;
- снять аккумулятор и ветку для каждого знака.

Критерий: таблица 8 знаков × 4 поля × PC-реакция.
Результат: `analysis/V78-CHAR-MATRIX.md`.

## 4. Фаза D. Кто печатает колонки листинга

Цель: найти тот PC, который читает готовые поля.

Шаги:
- взять колоду с уникальными меткой/операцией/операндом;
- потоково отфильтровать трассу по Э70-выводу и по
 строки в stdout листинга;
- проверить кандидата `0147:0477 OUT_PRINT`;
- найти PC, который берёт байты из 06405/06451 для
  колонки METKA и отдельно для ОПЕРАЦИИ.

Критерий: PC + мнемоника для печати каждой из 4 колонок.
Результат: `analysis/V78-LISTING-COLUMNS.md`.

## 5. Фаза E. Почему `:` даёт +2 ячейки ГС

Цель: объяснить единственный надёжный «семантический»
эффект знака-разделителя.

Шаги:
- трассировать счётчик `01201` и запись ячеек ГС;
- найти PC, который вызывается на 2 больше при `:`;
- сверить с правилом +2 за макрос и +4 за LСLА/СЕТА/АIF.

Критерий: PC из макроредактора, отвечающий за +2.
Результат: `analysis/V78-COLON-GS.md`.

## 6. Фаза F. Непроверенные правила 1967

Короткий хвост: `:` в колонке 1, смешанные формы,
внутренние пробелы, лимит 58 знаков. Одна колода на
правило. Результат: `analysis/V78-1967-RESIDUAL.md`.

## 7. Фаза G. Вердикт и консолидация

- свести все PCs в один список токен-реактивного кода;
- применить критерий из §0 и вынести ДА / НЕТ / НЕ ИЗВЕСТНО;
- обновить `FINAL-REPORT.md`, `V78-FOCUS.md`, `ROADMAP.md`;
- если найдены новые инварианты, добавить probe и тесты;
- `make check-all` (база 661 тест OK).

## 8. Параллелизация и ограничения

- Фазы A и B независимы и идут вместе.
- Фаза C зависит от адресов фазы A.
- Фазы D, E, F независимы друг от друга.
- По 3-4 субагента на фазу, Write set только новые
  отчёты и инструменты.
- Все прогоны на копиях в /var/tmp/v78-syntax/;
  guard отказывает /usr/local/share/besm6; md5 до и после.
- Трассы читаются потоково, полные логи не хранятся.
- Критерий остановки: два независимых отрицательных опыта
  по кандидату закрывают его как НЕ ИЗВЕСТНО.
