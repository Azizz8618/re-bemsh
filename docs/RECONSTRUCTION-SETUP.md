### Полный цикл записи (бонус, **PASS** с оговоркой)

`poc3.py` использует `make_job()` (`1-1^` + `БТМАЛФ^` вместо `0-0^`):

```bash

  --start=03100 --length=1 --to-file=.../z3100.bin

```

В `z3100.bin` первое слово `000000000001`, далее `b4 a5 a3 b4 40 40` —
имя модуля `ТЕСТ` в кодировке KOI-7. То есть «433100» в листинге читается
как **лента 43, зона 03100₈**, а не как номер зоны для `besmtool`:
попытка `besmtool dump 2248 --start=0433100` даёт `Writing 0 zones`
(файл 0 байт). **Оговорка:** точное соответствие «ЗОНМОД433900» → зона
03100₈ не выведено из текста транслятора; это эмпирическое наблюдение,
требующее проверки перед module-level записью.

## 3. Эксперимент 2 — `siprod_asm.decode` против `disbesm6`: **PASS (частично)**

 Первые 3 слова `gold/MBE-Z0137-L1.bin` (6 байт/слово, big-endian):

| Слово | hex (48 бит) | left half | right half |
|---|---|---|---|
| 0 | `000000040000` | `000000` | `040000` |
| 1 | `000000010000` | `000000` | `010000` |
| 2 | `000000000003` | `000000` | `000003` |

Результат (`poc2.py`, `from siprod_asm import decode, encode`):

| Полу слово | `decode()` | `disbesm6 -a0 -e0` | Совпадение |
|---|---|---|---|
| 0.L | `зп`, reg 0, op 000, addr 00000 | `00 000 0000 START зп START` | **да** |
| 0.R | `зп`, reg 0, op **000**, exp=1, addr **70000** | `00 100 0000 зп '70000'` | мнемоника и адрес — **да**; числовое поле opcode — **нет** (000 vs 100) |
| 1.L | `зп`, reg 0, op 000, addr 00000 | `00 000 0000 зп START` | **да** |
| 1.R | `сбр`, reg 0, op 020, addr 00000 | `00 020 0000 сбр START` | **да** |
| 2.L | `зп`, reg 0, op 000, addr 00000 | `00 000 0000 зп START` | **да** |
| 2.R | `зп`, reg 0, op 000, addr 00003 | `00 000 0003 зп D00003` | **да** |

Причина расхождения 0.R: бит 18 (`EXP_BIT=0x40000`) в `decode()` входит в
`exp` и адрес (`+0o700000`), а `op = (half >> 12) & 0o77` его отбрасывает;
`disbesm6` же печатает его в трёхзначном числовом поле opcode как `100`.
Семантически обе записи означают «зп с адресом 70000₈». Round-trip
`encode(decode(half)) == half` выполняется для всех 6 полуслов
(`reenc=OK`), так что для побайтовой сборки декодер пригоден. Для поозонной
сверки с листингом `disbesm6` нужно сравнивать **операнд и мнемонику**, а не
сырое числовое поле opcode в случае `exp=1`.

Команды:

```bash
python3 /tmp/.private/azizz/rebuild-poc/poc2.py
disbesm6 -a0 -e0 /tmp/.private/azizz/re-bemsh/gold/MBE-Z0137-L1.bin \
  | sed -r 's/\x1B\[[0-9;]*m//g' | head -12
```

## 4. Что доказано, а что нет

**Доказано:**

- `dispak -l` запускает минимальное задание МАКРО-БЕМШ на копиях томов
  2048/2099/2248; `ЧИCЛO OШИБOK=0000`, exit 0.
- Каркас `ВВД$$$^ … КВЧ$$$^ … ТРН$$$^ … 0-0/1-1` из `siprod_bemsh.py`
  применим в этой среде (совпадает с описанием `docs/ADJACENT-2.md §1`).
- Режим `1-1` действительно записывает объектный модуль в рабочий том;
  `besmtool dump --start=03100` возвращает 6144 байт с именем `ТЕСТ`.
- `siprod_asm.decode/encode` даёт корректный round-trip и совпадает с
  `disbesm6` по мнемонике/адресу на 6/6 полуслов (по числовому opcode — 5/6).

**Не доказано (гипотезы / blockers):**

- Нет ни одного реального `.be` модуля зоны 0137, собранного в `.dis` и
  сравненного с `.orig`. `convert()` из `siprod_bemsh.py` рассчитан на
  библиотеку СИПРОДа; для БЕМШ 06/78 он не адаптирован.
- Соответствие сообщения «ЗОНМОД433900 / ЗОНЫ С 433100» конкретному номеру
  зоны `besmtool` не установлено из исходника транслятора.
- Не проверено, что `dtran` даёт те же имена/метки, что `disbesm6`, на зоне
  0137 (в `docs/ADJACENT-2.md §2` это только рекомендация как перекрёстная
  проверка).
- В `re-bemsh` нет каталога `bemsh/*.be`, поэтому шаг «взять `.be` и собрать»
  пока не чем запускать.

## 6. Конкретные следующие шаги — собрать зону 0137 как `.be`

1. Выбрать один модуль внутри зоны 0137 по `dis/MBE-Z0137*.asm` +
   `analysis/procedures.md` (границы процедур — гипотезы, брать модуль с
   чётким `СТАРТ` / текстовым штампом).
2. Написать минимальный `.be` по правилам `AGENTS.md` (комментарии после
   запятой, `↑` вместо `^`, строка ≤60, комментарий ≤55, шапка процедуры
   ИМЯ/ВХОД/ВЫХОД/ИСПОЛЬЗУЕТ/ВЫЗЫВАЕТ). Не удалять метки и внешние ссылки.
3. Адаптировать `siprod_bemsh.convert()` под формат `re-bemsh`: вход —
   аннотированный `.asm`, выход — исходник МАКРО-БЕМШ с `<ИМЯ> СТАРТ <1>`,
   `Е`, `М`, командами и `ФИНИШ`.
4. `listing_job()` → `dispak -l` → листинг; сверить каждую команду через
   `siprod_asm.decode` (с поправкой на `exp=1`, §3). Добиться
   `ЧИCЛO OШИБOK=0000`.
5. `make_job()` (`1-1`, `БТМАЛФ`) → записать модуль в **рабочую** копию
   тома; `besmtool dump --start=0<зона> --length=N` → `silver.bin`.
   Перед этим выяснить точный номер зоны (§2, оговорка) — например,
   прогнав `make_job()` с известной зоной и найдя имя модуля через
   `besmtool search 2348 <имя>`.
6. `gold.bin` — `besmtool dump` с эталонного тома (read-only).
   `bash tools/disbesm_verify.sh gold.bin silver.bin` → exit 0, пустой diff.
   Оформление по `monitor80-re/permanent/Makefile`: `%.diff: %.dis %.orig`.
7. Повторить для остальных модулей зоны 0137, затем перейти к 0140–0177.
