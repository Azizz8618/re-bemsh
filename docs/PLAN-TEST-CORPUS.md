# План: расширение базы тестов для разбора входной программы

Дата: 23.11.2026. Фокус: только ВЕР.06/78.
Источник инструкций: dis-forced/*.asm.
Адреса восьмеричные, степень ↑, тире НЕ используется.

## 1. Почему текущих 661 теста мало

Сейчас 661 тест проверяют в основном инструменты (probe, diff,
trace) и побайтовую сборку. Поведение ПАРСЕРА проверяют лишь
несколько колод: P1-P4, матрица колонок (9), матрица знаков
(32), остатки 1967 (11). Однако:

- нет единого корректного корпуса колод с манифестом;
- нет карты покрытия: какие из 84 токен-реактивных PC
  отклоняются хотя бы одним тестом;
- трасса одной колоды смешивает все фазы (RLE, ввод,
  редактор, машина, листинг), поэтому PC нельзя устойчиво
  отнести к стадии;
- нет автоматического «атласа расхождений» между парой колод.

## 2. Принципы

1. Единица теста — ДИФФЕРЕНЦИАЛЬНАЯ ПАРА колод, отличающихся
   одним признаком. Это уже дало результат на P1/P2.
2. Оракулов два: побайтовая сборка (0 отличий) и
   воспроизводимая первая вилка PC в трассе.
3. Сегментация: разбить и модули, и трассу на функциональные
   участки, чтобы тест проверял конкретный участок.
4. Быстрые тесты на синтетических фикстурах отделить от
   медленных прогонов dispak.

## 3. Архитектура

### 3.1 Генератор колод tools/v78_deckgen.py

- вход: манифест `tests/decks/manifest.json` (список случаев);
- каждый случай: имя | базовая колода | одно изменение |
  ожидаемый признак;
- детерминированный вывод в `tests/decks/generated/`;
- неизменение эталонов: guard + md5.

### 3.2 Прогон tools/v78_runner.py

- запуск dispak на КОПИЯХ в /tmp с BESM6_PATH;
- сохранение: listing, отфильтрованные события (PC + мнемоника
  + аккумулятор), dd-события, md5 до/после;
- потоковая фильтрация, полная трасса не хранится.

### 3.3 Атлас tools/v78_atlas.py

- для каждой пары: первая расходящаяся строка, первый PC-дифф,
  дельта счётчиков, односторонние PC;
- карта покрытия: PC → список колод, его исполняющих;
- список PC без покрытия.

### 3.4 Сегментация модулей

Разбить каждую зону dis-forced на функциональные сегменты:

| Сегмент | Адреса | Роль |
|---|---|---|
| S-INPUT | 076505-076642 | RLE-вход и нормализация 0x40→0x01 |
| S-DISPATCH | 076031-076123 | классификация байта по значению |
| S-PACK | 077421-077502 | упаковка в таблицу 075235 |
| S-MARK | 075344-075401 | проверка маркеров be/bf |
| S-METKA | 075353-075377 | решение о метке |
| S-SLOT | 04200-04207 | слоты 02035-02041 |
| S-DESCR | 06061/01534 | дескриптор пула |

Для каждого сегмента правило: тест считается покрывающим, если
в трассе есть исполнение хотя бы одного PC сегмента.

### 3.5 Сегментация трассы по фазам

Добавить в event-поток метки фаз: BOOT → RLOAD → RLE → INPUT →
EDITOR → MACHINE → LISTING. Определить фазы по якорям:
`00110: uj 64000`, `076600` (RLE), `076000` (АРАП), `02000`
(редактор/машина), `04201` (листинг). Это позволит различать
одинаковые адреса в разные моменты.

## 4. Матрица колод (расширение)

| Измерение | Значения |
|---|---|
| ведущий пробел / метка | да / нет |
| разделитель метка/операция | пробел, `:` |
| разделитель операнд/комментарий | `;`, `,` |
| позиция токена | кол. 1, 3, 8, 15, 30 |
| класс знака | цифра, буква, `:`, `;`, `,`, `*`, пробел, `^` |
| длина метки | 1, 6, 7 знаков |
| число параметров макроса | 0, 1, 2, 4 |
| тело макроса | 1, 3, 6 строк |
| вложенность | 0, 1, 2 уровня |
| тип строки | МАСRО, ЭКВ, ВНЕШН, ВХОДН, КОНД, обычная |
| директива | СТАРТ, ФИНИШ, ПАМ, КОНД |

Полная декартова матрица слишком велика; использовать
попарное покрытие (all-pairs) и отобрать ~120 колод.

## 5. Слои тестов

| Слой | Что | Скорость | Сколько |
|---|---|---|---|
| L0 | парсеры/декодеры на синтетических строках | мс | ~80 |
| L1 | воспроизведение сохранённых event-фикстур | мс | ~40 |
| L2 | прогон 8-12 контрольных колод | секунды | 8-12 |
| L3 | полный корпус ~120 колод, ручной режим | минуты | 120 |

В `make check-all` входят L0-L2; L3 запускается отдельной
целью `make v78-corpus` и не замедляет обычную проверку.

## 6. Фазы работ

| Фаза | Результат | Критерий |
|---|---|---|
| A | манифест и генератор колод | 120 детерминированных колод, guard |
| B | runner и event-фикстуры | для каждой колоды listing + события |
| C | атлас расхождений и покрытия | таблица PC → колоды, список непокрытых |
| D | сегментация модулей и фаз | карта сегментов с file:line |
| E | L0/L1/L2 тесты | `make check-all` ≥ 700 тестов OK |
| F | анализ непокрытых PC | новые гипотезы или НЕ ИЗВЕСТНО |

## 7. Ограничения

- только 06/78, зоны 0137-0177;
- эталонные образы read-only, прогоны на копиях;
- трассы потоково, полные логи не хранятся;
- не добавлять тесты, которые могут случайно изменить `.be`
  или `gold/`.
