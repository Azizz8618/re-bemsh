# Якоря для верификации дизассемблирования МВЕ60

## 1. Главное ограничение (проверено)

**Прямое соответствие «слово из листинга → слово в дампе» не установлено.**
Искались ~30 характерных 48-битных слов из `mbe60_bemsh_list.txt` и
`mbe60_bemsh_dtran.txt` во всех 33 зонах (33792 слова) трёх копий образа 2348:

- 0 совпадений в прямом виде;
- 0 при всех 720 перестановках 6 байт, 48 циклических сдвигах, инверсии,
  обращении битов/половин и на любом битовом смещении потока.

Причина (гипотеза, не доказательство): на диске текст хранится в 7-битном коде
БЭСМ-6 по 6 символов на слово (`0147.1315` = `28 2f 2c 0f 2c 20` = «ИПМ МА»),
тогда как листинг печатает слова в другой кодировке (например
`1403006014030060` = `303030303030` = ASCII «000000»). Числовые константы
этим не объясняются — значит, программа на диске является **другой компиляцией**,
не тождественной модулю из листинга.

**Следствие:** не заполнять «физический адрес» для строк листинга спекулятивно.
`*EXECUTE` даёт **адреса памяти** (`01000` — вход, `02000` — `*PAGE*`,
`04000` — `MON*ITOR`), а не адреса зон диска.

## 3. Логические якоря из листинга (без физической привязки)

Адреса 1-based; вход `МВЕ60 = 00001` → память `01000₈` (`память = логический +
0777₈`). DTRAN нумерует с нуля: `DTRAN_addr = listing_addr − 1`.

Маркеры листинга: `‾` — адрес пересчитан после макроподстановки; `_` — строка
без кода; `+ N` — приращение адреса от развёрнутого макроса. Это **артефакты
листинга**, не relocate-биты на диске.

## 4. Практическая рекомендация

1. Для верификации дизассемблирования использовать **только текстовые штампы
   §2** как физические якоря.
2. `sym/MBE.tab` строить из `*МЕТ*`/`*EXECUTE` только как **логические**
   имена с пометкой «версия 06/78, list»; не подставлять их как физические
   адреса зон без доказательства.
3. В `analysis/uncertain.md` зафиксировать: «соответствие листинг ↔ дамп не
   установлено; 0 совпадений characteristic words».
4. В листинге `mbe60_bemsh_list.txt:29–43` — **три** макроопределения
   (`CALL`, `Э70`, `Э74`); четвёртый элемент — `US ЭКВ '133'` (ст. 46).
5. `DUBNA CALL`: `CALL PRINT8` → `13, VJM, PRINT8` (`00531531 74001`),
   следующее слово `0022 00000` — адресная ячейка; возврат `ПБ (М15)`.
   В extern-таблице `PRINT8 EXTRD PRINT8`; загрузчик подставляет 01205
   (в korot — 01134).
