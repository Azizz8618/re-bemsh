# Якоря для верификации дизассемблирования транслятора «ТРАНСЛЯТОР С М/К БЕМШ»

Листинги `mbe60_*` описывают **тестовую программу связи с ДКС** `МВЕ60`,
которая была оттранслирована этим транслятором. Это пример его работы, а не
исходник или объектный код транслятора.

## 1. Главное ограничение (проверено)

**Прямое соответствие «слово из листинга → слово в дампе» не установлено.**
Искались ~30 характерных 48-битных слов из `mbe60_bemsh_list.txt` и
`mbe60_bemsh_dtran.txt` во всех 33 зонах (33792 слова) трёх копий образа 2348:

- 0 совпадений в прямом виде;
- 0 при всех 720 перестановках 6 байт, 48 циклических сдвигах, инверсии,
  обращении битов/половин и на любом битовом смещении потока.

**Повторная проверка (22.11.2026):** 19 характерных 48-битных слов из
`mbe60_bemsh_list.txt`, `mbe60_bemsh_dtran.txt` и
`mbe60_korot_bemsh_list.txt` (`5032226020121664`, `2367551323252120`,
`7701000040000001`, `1403006014030060`, `0000440002400013`,
`2024212010041524`, `6437400100220000` и др.) сверены со всеми 65
бинарниками зон `gold/MBE-Z*` и `gold/MBE2-Z*`: 0 совпадений в прямом
виде, при 720 перестановках байт, 48 циклических сдвигах и инверсии.
Литеральный grep по `dis/` и `docs/` дал попадания только в самих
документах (`ANCHORS.md`, `MACRO-TABLE-FORMAT-VERIFIED.md`), не в
дизассемблированных зонах. Оговорка: тривиальные константы (все единицы,
малые числа `0000000000000001`, `0000000000000037`) присутствуют и в
листинге, и в зонах, но характерными словами не являются и в счёт не идут.

Причина (по уточнению заказчика): листинг принадлежит **другой программе** —
`МВЕ60`, тесту связи с ДКС, написанному на БЕМШ; транслятор её только
оттранслировал. Сравнивать слова листинга с зонами `0137–0177` бессмысленно:
это разные программы. Дополнительный фактор — на диске текст хранится в
7-битном коде по 6 символов на слово (`0147.1315` = `28 2f 2c 0f 2c 20` =
«ИПМ МА»), а листинг печатает слова в другой кодировке (`1403006014030060` =
`303030303030` = ASCII «000000»).

**Следствие:** не заполнять «физический адрес» для строк листинга спекулятивно.
`*EXECUTE` даёт **адреса памяти** (`01000` — вход, `02000` — `*PAGE*`,
`04000` — `MON*ITOR`), а не адреса зон диска.

**Статус проверки (22.11.2026): ПОДТВЕРЖДЕНО.** Все семь штампов найдены
grep по `dis/*.asm` (например `dis/MBE-Z0147-L1.asm:999` =

непосредственно с `gold/MBE-Znnnn-L1.bin` (7 из 7 совпадений с таблицей).

Старая редакция (B2, сдвиг `+0400₈`): `0547.1315` `ВАР.12/77` (на диске именно
`ВАР.12/77`, не `ВЕР.12/77` — проверено на 11 копиях тома 2048),
`0552.1154` `АРАП ВАР.10/75`, `0554.0751` `МАКРОРЕДАКТОР 10.04.76`,
`0570.0274` `МАКРОМАШИНА 15.12.76`.

Каталог: `0000.0445` → `0137-0177 ТРАНСЛЯТОР С М/К БЕМШ … 20.06.78`;
`0000.0542` → `0537-0577` (фактически данные с 0540).

Структурная гипотеза по зонам с явными статусами вынесена в §3b. Кратко:
33 зоны = 33792 слова ≫ 205₈ слов модуля листинга ⇒ в зонах несколько
независимых компонент, а не один модуль.

## 3. Логические якоря из листинга (без физической привязки)

Адреса 1-based; вход `МВЕ60 = 00001` → память `01000₈` (`память = логический +
0777₈`). DTRAN нумерует с нуля: `DTRAN_addr = listing_addr − 1`.
**Все адреса таблицы относятся к тестовой программе ДКС, не к транслятору.**

| Лог. адр | Мнемоника / роль | Слово ( восьм. ) | Источник |
|---|---|---|---|
| 00001 | `МВЕ60 СТАРТ 1 ТЕСТ ЗАПИСИ ЧЕРЕЗ ДКС` — вход | — | list:44,371 |
| 00005 | `СЧ =В'1'` / `132 4004` | `5010017601324004` | list:61–62; dtran:368 |
| 00012 | `МОДА СМ400` (`+0002`) | — | list:87 |
| 00054 | **`CALL PRINT8` → VJM** (ИСП 0118) | `6437400100220000` | list:169; dtran:446 |
| 00055 | `Э74 0` (макровызов) | — | list:172 |
| 00067 | **`CALL PRINT8` → VJM** (ИСП 0139) | `6437400100220000` | list:193; dtran:468 |
| 00074 | `МLОС ТЕКСТ Т'АDР СТАРТА'` | `5032226020121664` | list:201 |
| 00076 | `МLОС1 КОНД Д'000000'` (ASCII «000000») | `1403006014030060` | list:203 |
| 00102 | `ВWОRD КОНД В'440002400013'` | `0000440002400013` | list:207 |
| 00121 | `МАСЭ50 КОНД В'7701000040000001'` (тест Э60) | `7701000040000001` | list:230 |
| 00122 | `ОШКМТР Д'ОШКМТР'` — таблица ошибок | `2367551323252120` | list:232 |
| 00130 | `ОШКС Д'ОШ КС'` | `0004757310045503` | list:238 |
| 00177 | `КОНД 1` | `0000000000000001` | list:353 |
| 00200–00205 | таблица констант 37/6/3/60/20/200 | … | list:354–365 |

Маркеры листинга: `‾` — адрес пересчитан после макроподстановки; `_` — строка
без кода; `+ N` — приращение адреса от развёрнутого макроса. Это **артефакты
листинга**, не relocate-биты на диске.

## 3b. Структурная гипотеза по зонам (со статусами)

Роли зон транслятора `ТРАНСЛЯТОР С М/К БЕМШ ВЕР.06/78` (том 2348,
каталог `0000.0445`). Исходника транслятора на диске нет, поэтому роли
выведены из штампов §2 и структуры зон. Статус указан в каждой строке.

| Зона(ы) | Роль | Основание | Статус |
|---|---|---|---|
| `0137` | стартовая зона/загрузчик + таблица мнемоник | код 0000-0004, forced-код 0040-0117, KOI-7-таблица 0060-0121 (`ЗП СЧ СЛ ВЧ ... УИА ПО ПЕ ПБ ПВ ЦИКЛ`) | таблица и обрыв трассы ПОДТВЕРЖДЕНО; чтение мнемоник ГИПОТЕЗА (омоглифы C/B/K/Y/O) |
| `0147` | сообщения/ядро исполняемого кода | штамп 0147.1315; 82 метки, 152 ветвления, 32 CALL; `OUT_PRINT`; возврат `ПБ (М15)` | ПОДТВЕРЖДЕНО (штамп, код) |
| `0152` | АРАП, 3-й проход конвейера | штамп 0152.1164; пул диагностики АРАП (0152.0002, 0152.0151 и др.) | ПОДТВЕРЖДЕНО (штамп); код АРАП ГИПОТЕЗА (0147/хвосты зон) |
| `0154-0165` | макроредактор, 1-й проход | штамп 0154.0751; счётчик `КОЛИЧ ЯЧ ГС` 0154.1450; 0154 загружена по 02000₈; 0165 собственный штамп 0165.0043 | ПОДТВЕРЖДЕНО (штампы, загрузка) |
| `0170` | макромашина, 2-й проход | штамп 0170.0216; зона не найдена в снятой карте ОП | ПОДТВЕРЖДЕНО (штамп); код макромашины может быть в 0171 ГИПОТЕЗА |
| `0173-0177` | таблицы ошибок/справок, шапка листинга | штампы 0173.0655 (ОШ.СПР.НА БЕМШ1), 0173.0661 (ЛИМ.СТРЕЛ.НА БЕМШ1), 0176.1732 (ИПМ МАГ-БЕМШ ВАР.А(12/71), 0176.1743 (шапка листинга), 0177.0417 (ОШ. СПРАВКИ БЕМШ2) | ПОДТВЕРЖДЕНО (штампы) |

независимых компонент, а не один модуль. B2-копия (сдвиг `+0400₈`)
имеет те же роли со штампами 0547/0552/0554/0570/0573/0576/0577.

## 4. Практическая рекомендация

1. Для верификации дизассемблирования использовать **только текстовые штампы
   §2** как физические якоря; листинг `mbe60_*` использовать лишь как пример
   синтаксиса/вызова транслятора.
2. `sym/MBE.tab` строить из `*МЕТ*`/`*EXECUTE` только как **логические**
   имена с пометкой «версия 06/78, list»; не подставлять их как физические
   адреса зон без доказательства.
3. В `analysis/uncertain.md` зафиксировать: «соответствие листинг ↔ дамп не
   установлено; 0 совпадений characteristic words».
4. В листинге `mbe60_bemsh_list.txt:29–43` — **три** макроопределения
   (`CALL`, `Э70`, `Э74`); четвёртый элемент — `US ЭКВ '133'` (ст. 46).
5. `DUBNA CALL`: `CALL PRINT8` → `13, VJM, PRINT8` (`00531531 74001`),
   следующее слово `0022 00000` — адресная ячейка; возврат `ПБ (М15)`.
   В extern-таблице `PRINT8 EXTRD PRINT8`; загрузчик подставляет 01205
   (в korot — 01134).
6. Проверка зоны по штампу: `besmtool search 2348 '<фраза>'` даёт
   `зона.слово` первого слова фразы; затем `grep '<слово>'
   dis/MBE-Znnnn-L1.asm` и сверка hex-байт по
   `gold/MBE-Znnnn-L1.bin` (смещение = слово₈ × 6). Все семь штампов §2
   прошли проверку 22.11.2026, статус ПОДТВЕРЖДЕНО.
7. Листинги `mbe60_*` как ключ к зонам дают отрицательный результат:
   0 характерных слов в дампе (§1). Это пример работы транслятора над
   программой МВЕ60, а не его исходник.
8. ГС-карта (дисковая зона → адрес ОП): `analysis/MEMORY-MAP.md` и
   `analysis/MEMORY-MAP-PC2-NOTES.md`. Привязано 12 из 33 зон:
   0147 → 00000₈, 0154 → 02000₈, 0155 → 04000₈.
