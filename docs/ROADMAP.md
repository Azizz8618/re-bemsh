## Осталось открытым

### 1. Полная семантическая реконструкция RAW-зон

На момент написания 66 зон восстановлены семантически, 3 — в режиме
`RAW-ALL` (байты точны, мнемоники/операнды не восстановлены):
`0176`, `0545`, `0556`. **Точное число уточняется субагентом
RAW-RECOVERY** — не фиксировать число в отчётах, сверять с
`analysis/REBUILD-ALL.md` и шапками `bemsh/*.be`.
Цель: перевести RAW-зоны в семантический режим, сохранив 0 отличий.
Причина RAW: транслятор отклоняет отдельные мнемоники/операнды.

### 2. Ролевые имена во всех 69 `.be` (Фаза D)

Перенести имена из `docs/LABELS-B.md` (75) и `LABELS-B2.md` (43):
`INIT_/MAC_/ARA_/MNEM_/ERR_/TXT_/OUT_/CODE_` + суффиксы.
Обязательное условие: переименование **не меняет ни одного машинного
слова** — после каждого шага `make rebuild-zone` обязан давать 0 diff.
Константы оформить как `эквивалент` с ролью, восьмеричным значением
и ссылкой `file:line` (`docs/COMMENTING-STANDARD.md` §2).
Обновить `docs/REGISTERS.md` по результатам Фазы C.
Критерий: 69 `.be` с ролевыми именами, все проходят rebuild.

### 3. Уточнение динамической карты оверлеев (продолжение Фазы C)

Карта покрывает 12 из 33 зон (991–1024 точных слов). Не привязаны 21 зона,
в том числе загрузочные `0137–0143` и таблицы ошибок. Зоны `0174/0175/0177`
неоднозначны (страницы 33 и 35 дают одинаковый счёт). Зона `0137` не
перехвачена breakpoint'ами на `страница×02000 + {0..11}`.
Действия: снять дампы ОП в большем числе точек, проверить гипотезу
кратковременного оверлея `0170`, уточнить адрес/длину таблицы `ГС`
(вопрос Б.1). Критерий: подтверждённая карта для большего числа зон
или документированный отрицательный результат с причиной.

### 4. Независимое воспроизведение битов макротаблицы (продолжение Фазы B)

Эксперименты доказали существование и гранулярность таблицы (2 ячейки на
макрос), но не дали доступа к самим словам `ГС`. Нужно получить дамп ячеек
(например, breakpoint внутри макроредактора через отладчик `dispak`,
не модифицируя образы) и либо доказать, либо окончательно опровергнуть
схему `[TAG(24)|VAL(24)]` и TAG-коды. Открытые вопросы: природа «ячейки ГС»
(48-битное слово / полуслово / запись из двух слов), разбиение +4 для
макроса `Е` (`LСLА`/`SЕТА`/`АIF`), наличие той же таблицы в B2
(`0554/0570`). См. `docs/MACRO-TABLE-FORMAT-VERIFIED.md` §7.

## Ограничения, которые нельзя обойти

- `disbesm6` — статический анализ: не отслеживает значения регистров,
  не знает макросов, не различает перемещаемый код. `-R` задаёт только
  начальное значение одного регистра; `-e` обязателен, `-r`/`-b` инертны.
- Склейка зон >32768 слов вызывает segfault (`MBE-full.bin`); работать
  только по одной зоне.
- Том 2348 рабочий (`~/.besm6/2348`) меняется; эталон —
  `/usr/local/share/besm6/2348`, инвариант — md5 зон `0137–0177`
  `2f503f5b…`. Все эксперименты — только на копиях в `/tmp`.
- Коммиты и push — только по явной инструкции (`AGENTS.md`).
