## Что осталось

### 1. Реконструкция исходных текстов (`.be`)

Сейчас есть только *аннотированные дизассембли* (`bemsh/annotated-*.asm`),
не пересобираемые исходники. Для module-level проверки по образцу
`monitor80-re` нужно:

1. perl/asm.pl-подобный ассемблер (можно адаптировать
   `~/Yandex.Disk/re-siprod/tools/siprod_asm.py`);
2. задания для `dispak` (`*BEMSH` / `ВВД$$$^ … ТРН$$$^`) по шаблону
   `~/Yandex.Disk/monitor80-re/tools/debemsh.sh`;
3. пара `.orig` (эталон с тома) / `.dis` (реконструкция) и пустой `.diff`,
   как в `monitor80-re/permanent/Makefile`;
4. `verify.pl`-подобная побайтовая сверка зон (уже есть
   `tools/disbesm_verify.sh` и `tools/verify-roundtrip.sh`).

### 2. Снятие гипотез

- `analysis/procedures.md`: 7 неопределённых границ процедур;
- `analysis/VARIABLES.md`: 76 имён ячеек — все помечены ГИПОТЕЗА;
- `docs/REGISTERS.md`: роль М14/М17 и VJM-диспетчеризация М13 — гипотезы;
- `docs/ANCHORS.md`: соответствие листинг ↔ дамп не установлено
  (листинг `mbe60_*` — другая программа, тест ДКС).

### 3. Третья версия?

На томах 2048/2148/2248/2348 найдены только две редакции транслятора.
Если нужна версия `.02.87` из альтернативного каталога `0777.0726`,
следует проверить зоны `1000–1037₈` на других образах — по уточнению
заказчика это «МБ 2.0», к БЕМШ не относится, поэтому в скоуп не входит.

## Ограничения, которые нельзя обойти

- `disbesm6` — статический анализ: не отслеживает значения регистров,
  не знает макросов, не различает перемещаемый код. `-R` задаёт только
  начальное значение одного регистра.
- Склейка зон >32768 слов вызывает segfault (`MBE-full.bin`); работать
  только по одной зоне.
- Том 2348 рабочий (`~/.besm6/2348`) меняется; эталон —
  `/usr/local/share/besm6/2348`, его md5 фиксируется в `verify/`.
