### 1.2. Второе значение того же кода (книга, с.56)

`FULL:3318-3339`, `OCR page-0057.txt:58-65`:

### 1.4. Итог по Э74

- Имя: «конец задачи» / «конец задачи, передача управления»;
  вторая зафиксированная функция: запрос номера терминала.
- Операнд: исполнительный адрес `АИСП` (поле адреса).
  Книжный вызов: `00 074 0000`, то есть регистр 00, КОП 074,
  адрес 0000. Адрес передачи задаётся заранее через ЭК 072
  с константой 22642531 21233462В на сумматоре.
- Подкоды: `АИСП = 0` (обычный конец) и `АИСП != 0`
  (адрес программы обработки при перехвате). Двойная
  семантика `00 074 0000` помечена как `ГИПОТЕЗА`.
- Привилегии: в `disbesm6.c:105` помечен `BASIC`, НЕ `PRIV`.
  Это пользовательский вызов ОС, а не привилегированная
  команда вроде `СТОП`/`ВЫПР`. Книга (`FULL:2910-2915`):
  «внутренний язык общения решаемых П-задач
  с вычислительной системой».
- Управление: завершает задачу или передаёт управление по
  АИСП; `disbesm6.c:741-746` помечает `W_NORIGHT` (обрыв
  линейного участка) для `OPCODE_STOP`.

> необходимо разместить стандартную программу.
> Обращение к СП: ИР 066 А, Р4Р2 000 М.
> АИСП - адрес начала информации к стандартной программе

### 2.4. Итог по Э66

- Имя: «обращение к стандартным программам (СП)»; частный
  случай: вызов стандартной программы отладки (СПО).
- Операнд: `АИСП` (адрес информации/плана отладки), регистр
  M15 задаёт адрес размещения СП. В книге:
  `К 00 066 Аплли р`, `00 000 0015`, формат `Р4Р2 000 М`.
- Подкоды: номер СП `N`; флаги `P1` (бит 23, «оставить в
  ОЗУ») и `P2` (своя библиотека СП на МБ). Число рабочих
  ячеек экстракода 066 = 8.
- Привилегии: `disbesm6.c:99`: `BASIC`, не `PRIV`;
  пользовательский вызов ОС.
- Управление: передаёт управление СП; `disbesm6.c:764-768`
  для `OPCODE_IMMEX` сбрасывает `regvals[16]` (M16 портится,
  `OCR page-0052.txt:54-56`) и ставит `W_NORIGHT`.

## 3. Почему энкодер/декодер считают их неподдерживаемыми

### 3.1. Таблицы мнемоник

`/home/azizz/Yandex.Disk/re-siprod/tools/`

```
("Э65", 0x035000, 0x0bf000, "immex"),

("Э73", 0x03b000, 0x0bf000, "addrex"),
```

`/home/azizz/dispak/disbesm6/disbesm6.c:85,99,105`:

```

{ "Э66", 0x036000, 0x0bf000, OPCODE_IMMEX, BASIC },
{ "Э74", 0x03c000, 0x0bf000, OPCODE_STOP,  BASIC },
```

В ОБЕИХ таблицах мнемоники есть. Проблема не в `siprod_asm`,
а в таблице мнемоник транслятора МАКРО-БЕМШ 06/78, которая
их не содержит. `B-KOND-DECODE-1.md:28-31`:

> Пропуск: illegal/конк, мнемоника отсутствует в таблице
> транслятора (ПИО36, Э66, И, ИЛИ, Э72, Э74), либо левая
> половина относится к типам call/addrex/immex/stop
> и вызвала бы авто-вставку мода со сдвигом кода.

### 3.2. Требуемые раскладки полей

`disbesm6.c:10-28`: типы `OPCODE_IMMEX` (Э50...Э77),
`OPCODE_ADDREX` (Э60/64/67/70...),
`OPCODE_STOP` (только Э74).

`disbesm6.c:393-414` (`prcode`):

- `IMM`, `IMMEX`, `ADDREX`, `IMM64`, `REG1`, `STR1`:
  `%02o %03o %04o` = регистр, КОП, 12-битный адрес.
- `STOP` не попал ни в один `case` → `default`: `%08o`,
  то есть сырые 8 восьмеричных цифр без разбиения.

`disbesm6.c:452-496` (`prinsn`):

- `ADDREX`: `properand(reg, arg1)`, адрес памяти.
- `IMMEX`/`IMM`/`STOP`: `if (arg1) printf("'%o'", arg1)`
  и `(Мn)`: immediate-константа + регистр.

`siprod_asm.py:82-84,100-135`: `DMS_BIT=0x200000`,
`STRUCT_BIT=0x80000`, `EXP_BIT=0x40000`; для 2-й структуры
`op=(half>>12)&0o77`, `arg=low12+(0o700000 if exp else 0)`.
`round-trip decode/encode` для всех наших примеров проходит.

### 3.3. EXP-бит: расхождение представлений

`disbesm6.c:442`: `arg1 = (opcode & 07777) +
(opcode & 0x040000 ? 070000 : 0)` → 5 цифр (`'73447'`).
`siprod_asm.py:115`: `+ 0o700000` → 6 цифр (`'703447'`).
`B-KOND-DECODE-1.md:24-26`:

> disbesm6 искажает операнды типов reg1/imm ... и не
> различает EXP. Для EXP адрес пишется 5-значной формой
> '7abcd' (так его кодирует МАКРО-БЕМШ 06/78).

`B-KOND-DECODE-2.md:110`: «split меняет байты
(DMS/непредставимый операнд) | 68 | L `24400000` →
`25400000` (EXP)».

Итог: Э66 требует поля `IMMEX` (immex), Э74 требует
уникального поля `STOP` (stop), не совпадающего ни с
`IMM2`/`СТОП` (`0x0d8000`, `PRIV`, `disbesm6.c:120`),
ни с `ADDREX`.

## 5. Как представлять в `.be`

Корректного способа НЕТ. Таблица мнемоник МАКРО-БЕМШ 06/78
не содержит `Э66`, `Э74`, `Э72`, `ПИО36`, `И`, `ИЛИ`
(`B-KOND-DECODE-1.md:28-31,1094,1097`). Поэтому:

- слово с Э74/Э66 остаётся строкой `КОНД В'<16 цифр>'`;
  байты не изменяются, rebuild даёт `PASS 1024/1024`;
- `СТОП` НЕ является заменой: это `0x0d8000`, 1-я структура,
  привилегированная команда (`disbesm6.c:120`), тогда как
  Э74: `0x03c000`, 2-я структура, `BASIC`;
- `Э66` нельзя подменить `ADDREX`-экстракодом (Э64/Э70),
  так как у него `IMMEX`-семантика и порча M16.

`ГИПОТЕЗА`: решить задачу можно только расширением таблицы
мнемоник транслятора (добавить `Э66`/`Э74` с полями
`immex`/`stop`) либо сохранением сырого `КОНД`. Эксперимент
по расширению транслятора в этой задаче НЕ проводился.

## 6. Список ГИПОТЕЗ

1. OCR `974`/`962` = `Э74`/`Э62` (подтверждено косвенно
   константой из `Dispak-programmer-guide.md:9046`).
2. Две семантики `00 074 0000` различаются подкодом/адресом,
   который OCR не сохранил.
3. `02200000` перед `Э74`: авто-мода, «сдвигающая слово»
   при попытке разбить word на две команды.
4. Расширение таблицы мнемоник транслятора позволило бы
   записать Э66/Э74 в `.be` без потери байтов.

Факты (не гипотезы): наличие кодов в таблицах `OPS` и
`disbesm6`, раскладки полей, все процитированные строки
книги и docs, побайтовые сводки `PASS 1024/1024`.
