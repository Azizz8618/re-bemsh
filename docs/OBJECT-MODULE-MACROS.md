# Макрокоманды в открытом тексте объектных модулей томов 2048 / 2148 / 2248

Дата: 20.11.2026. Статус: **сканирование выполнено; выводы разделены по классам
ассемблеров**. Настоящий документ отвечает на вопрос, можно ли вывести полный
набор макрокоманд машины МАКРО-БЕМШ из открытого текста, лежащего в
объектных модулях на томах 2048 / 2148 / 2248, и сравнивает найденное с
каталогом из 37 позиций (`docs/MACRO-COMMANDS.md`, `re-dispak/macros.be`).

Источники читались **только на чтение**; эталонные образы
`/usr/local/share/besm6/{2048,2148,2248}` не изменялись.

---

## 1. Краткий ответ

1. **Открытый текст действительно содержит макроопределения**, но они
   **принадлежат разным ассемблерам, и их нельзя смешивать**. Главный
   макротекст тома 2248, зона `3156₈` — это **MASM (MACRO-32)**, драйвер диска
   для DOS: `MSG!MACRO!TEXT … !PUSH!DX … !CALL!SHOW__MSG … !ENDM`.
   Это **не** МАКРО-БЕМШ: у МАКРО-БЕМШ пара `МАСRО … МЕND` и параметры `∧А…∧Р`.
2. В GOST-тексте тома 2148, зона `0050₈` лежит **собственная таблица команд
   транслятора ИПМ МАКРО-БЕМШ** (`ЭКВ`, `ВХОД`, `ВНЕШ`, `НОП`, `ФИНИШ`,
   `МАСRО`, `МЕND`, `КОНК`, …), а в зонах `3230–3231₈` тома 2248 —
   **листинг программы на структурном макроязыке** (`МЕS`, `GЕТ`, `LЕТ`,
   `IЕQ`, `IGЕ`, `АDD`, `ЕLS`, `RЕР`, `UNТ`, `ЕND`, `SIZ`, `КОНД`, `ТЕКСТ`,
   `ЭКВ`, `НОП`, `ФИНИШ`).
3. **Каталог из 37 команд НЕ является полным набором команд машины.**
   Открытый текст подтверждает лишь его часть (~11–13 позиций), зато
   показывает **дополнительные** директивы и машинные мнемоники, которых в
   каталоге нет (§5). Полнота 37-каталога **не доказана и не следует** из
   текст object-модулей; он остаётся реконструкцией по `macros.be`.

## 2. Методика

### 2.1 Инструменты и кодировки

```bash
# поиск по всем кодировкам сразу (быстро, даёт зона.слово + контекст)
besmtool search 2248 'MACRO'
# просмотр зоны в одной кодировке
besmtool view 2248 --start=03156 --length=1 --encoding=k
```

Ведущий `0` в `--start` обязателен: `besmtool` парсит через `strtol(base=0)`,
поэтому `03156` = восьмеричное, а `3156` = десятичное (AGENTS.md §1).

Кодировки (`besmtool view --encoding=g,k,t,i`):

| Буква | Кодировка | Где используется в тексте модулей |
|---|---|---|
| `k` | KOI-7 | MASM/MACRO-32-исходники (ASCII-текст читается KOI-7), листинг БЕМШ `3273₈` |
| `g` | GOST-10859 | служебные таблицы и листинги транслятора (`2148:0050`, `2248:3230–3231`) |
| `t` | TEXT Дубны | 6-битные имена в таблицах, для макротекста не годится |
| `i` | ITM АКС Чайковского | для макротекста не годится |

`besmtool view` схлопывает повторяющиеся строки в `*`, поэтому сканер
разбирает только строки вида `^(\d{4})\.(\d{4}):\s?(.*)$`.

Побайтовая проверка зоны `2248:3156.1460`:
`4d 53 47 21 4d 41 43 52 4f 21 54 45 58 54` = `MSG!MACRO!TEXT`.
То есть текст **ASCII**, а `!` (0x21) и `` ` `` (0x20) — разделители
(табуляция/пробел) в исходнике; в GOST-колонке тот же участок — мусор.

### 2.2 Сканер

`tools/object_macro_scan.py <disk> [--start-zone OCT] [--end-zone OCT]`
вызывает `besmtool view` кусками по `--chunk` зон, ищет в строках токены
словаря (с омоглифной нормализацией `А↔A`, `Р↔R`, `П↔P`, `Н↔N`, …),
классифицирует каждый hit **по контексту строки** и печатает таблицу
`команда | класс | число адресов | адрес | кодировка | контекст`.

```bash
python3 tools/object_macro_scan.py 2248 --start-zone 3100 --end-zone 3500
```

Результат теста: **56 различных команд** (класс A — 13, A2 — 11, B — 32).
Сканер печатает факты; интерпретация классов — ниже.

## 5. Ограничения (обязательно)

1. **Разные ассемблеры.** Тексты MASM, MACRO-32, FORTRAN и ЛИСП-подобного
   языка лежат на тех же томах; попадание `MACRO` в зоне `3156₈` — MASM, а не
   МАКРО-БЕМШ. Классы A и B **не смешиваются**.
2. **Не каждая зона — объектный модуль.** Зоны `3005–3022₈` — упакованные
   данные; GOST-колонка случайно образует буквы (`Н`, `О`, `П`).
3. **Короткие токены.** `ПБ`, `ПВ`, `ЕQ`, `ОR`, `NЕ`, `IF`, `DB`, `DW` дают
   тысячи ложных срабатываний в сообщениях и бинарниках. Таблица §3.4
   фиксирует это как шум, а не как доказательство.
4. **Омоглифы.** `besmtool view --encoding=g` использует латинские
   омоглифы (`R`, `N`, `D`), поэтому `МАСRО`, `МЕND` — нормализованная
   форма таблицы, а не утверждение о исходном символе.
5. **Кодовая цифра в таблице `2148:0050`.** Назначение байтов 0 и 1 ячейки
   (порядковый символ и цифра `3/4/6`) не установлено; читаются только имена.
6. **`ФИНИШ` в `.be`-файлах.** В `bemsh/*.be` `ФИНИШ` стоит в конце каждого
   файла как терминатор листинга; это **не** доказательство, что компилятор
   использует его как макрокоманду. Надёжное подтверждение — только
   `2248:3231.0600`.
7. **Нижняя оценка.** Сканер ищет только готовый словарь; новые,
   неизвестные мнемоники листинга (`ВЫЙ`, `СLО`, `МЕХ`, `INF`) в таблицу не
   включены и требуют ручного разбора.
