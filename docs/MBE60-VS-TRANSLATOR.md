# MBE60 против зон 0137-0177: структурное сравнение

Дата: 20.11.2026. Все источники читались только для чтения.
Разрешено к записи: только этот файл.

## 0. Краткий ответ

MBE60 - пользовательская тестовая программа связи с ДКС.
Транслятор `ТРАНСЛЯТОР С М/К БЕМШ ВЕР.06/78` её только
оттранслировал. В зонах 0137-0177 лежит сам транслятор.
Слов MBE60 в зонах нет: 0 совпадений из ~30 характерных
слов (docs/ANCHORS.md:9-23). Модуль MBE60 имеет 205₈ слов;
33 зоны транслятора - 33792 слова (202752 байта).

## 4. Кто компилирует кого

- source:10: `*bemsh`; source:293:
  `*call dtran(MBE60)` - прогон MBE60 через BEMSH.
- list:8,17,21,27: при компиляции печатаются шапки
  `ИПМ МАКРО-БЕМШ ВЕР.06/78`,
  `МАКРОРЕДАКТОР ОТ 20.06.78`,
  `МАКРОМАШИНА ОТ 1.11.78`. Это шапки
  транслятора, а не текст пользовательской программы.
- docs/PROGRAM2-LOGIC.md:628-699: макрос `CALL ∧T`
  из исходника MBE60 разворачивается проходами
  0154 → 0170/0171/0165 → 0152/0147 и даёт
  `ВЖМ PRINT8, М15` = `00531531 74001`
  плюс адресное слово `ПАМ 0`.
- docs/PROGRAM2-LOGIC.md:691-698: `*МЕТ*` получает
  `PRINT8 00001СА`, `ВНЕШН=3`; загрузчик по
  `*EXECUTE` подставляет `PRINT8 → 01205₈`.
- docs/PROGRAM2-LOGIC.md:155-165: поток
  deck → 0154 → 0170/0171/0165 → 0152/0147 →
  объектный модуль. Таблица макроопределений
  (2 ячейки ГС на макрос) в модуль не попадает.
- docs/ANCHORS.md:109-114: `CALL PRINT8` →
  `13, VJM, PRINT8`, возврат через `ПБ (М15)`.

Итого: MBE60 - выход транслятора, не его вход
в смысле "исходник транслятора". Обратного
"MBE60 компилирует зоны 0137-0177" нет ни в одном
источнике. ГИПОТЕЗА: транслятор мог быть собран
ранее на этом же языке, но прямых свидетельств
само-компиляции в прогоне MBE60 нет.
Здесь и ниже "ГИПОТЕЗА" означает вывод без
исходника транслятора.

## 5. Ответ на сомнение пользователя

Может ли компилятор содержать такую программу
или такой текст? Коротко: MBE60 - нет, код
похожего вида - да, это его собственные модули.

1. MBE60 как программу зоны не содержат. Главное:
   0 совпадений характерных слов (ANCHORS.md:9-23),
   объём 205₈ против 33792 слов, `ВХОДН=1/01000₈`
   против `СТАРТ 1` без единой директивы `ВХОД*`,
   внешние PRINT8/CM400/PAGE только в листинге.
   В каталоге тома MBE60 вообще не значится.
2. Похожий код внутри компилятора есть: `A00477
   OUT_PRINT` (Z0147.md:49), 10 процедур ядра
   (Z0147.md:243-257), `пв ...(М15)` и `пб (М15)`
   (Z0147.md:233-234), счётчики и таблицы.
   Это программа на БЭСМ-6, поэтому она устроена
   так же, как пользовательская. Но она печатает
   сообщения компилятора, а не тест ДКС.
3. Частично пользователь прав: часть зон - сервисные
   модули, собранные как обычные объектные модули:
   `OUT_PRINT` 0147, шапка листинга 0176.1743-1763
   (TEXTS.md:277-278), справки 0173/0177
   (ANCHORS.md:39-41), сообщения 0154/0165.
   ГИПОТЕЗА: 0171 (пик BR=47, CALL=13) и 0165
   ("МАКРОКОМПИЛЯТОР ОТ 2.8.78") могут быть
   отдельными компонентами конвейера, а не ядром
   перевода (Z0170.md:15-25; TEXTS.md:151-155).
   Это всё равно модули транслятора, не MBE60.
4. Ложный след: `*PAGE* 02000₈` из `*EXECUTE`
   MBE60 (list:389) совпадает с адресом загрузки
   зоны 0154 (ENTRY.md:233-235). Совпадение адресов
   не доказывает тождество программ
   (ENTRY.md:142-144).
5. Диагностика MBE60 (`ОШКМТР`, `НЕЧАДР`,
   `ОШКСКЦ`, list:232-239) описывает ошибки
   записи в Э60. Диагностика зон описывает
   ошибки компиляции (`ПРПЛН ТАБЛ МЕТОК`,
   `НЕТ ВХОДН.МЕТКИ`, TEXTS.md:197-199).
   Разные предметные области, разные авторы текста.

Вердикт: транслятор может содержать в себе код,
структурно неотличимый от пользовательской программы,
но конкретно MBE60 и его текст в зонах 0137-0177
не находятся. MBE60 была оттранслирована этим
транслятором; следы её компиляции - счётчик
`КОЛИЧ ЯЧ ГС`, `*МЕТ*`, `*EXECUTE` - живут
в листинге, а не в дампе зон.
