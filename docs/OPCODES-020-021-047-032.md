# КОП 020, 021, 032, 047: ПОЧЕМУ ЭТО НЕ ЭКСТРАКОДЫ

Дата: 20.11.2026. Режим: только чтение. Изменён
только этот файл. Запрос оператора: «Э20/Э21/Э47/Э32 —
это еще что? Таких не бывает».

> УТОЧНЕНИЕ (20.11.2026): правильное имя КОП 032 - УВВ
> (привилегированный обмен с внешними устройствами).
> Ранние отчёты и рабочее имя в `disbesm6.c:71` называли
> его «увв32» ошибочно; ниже это имя осталось только
> в дословных цитатах исходника и в графе «БЫЛО».
> См. также `UVV-STOP-ANALYSIS.md`.

---

## 0. ДВА РАЗНЫХ ПРОСТРАНСТВА НОМЕРОВ — ИСТОЧНИК ПУТАНИЦЫ

1. КОП — 6-битное поле, биты 17..12 половины слова,
   значения 000..077₈. simh, `besm6_cpu.c:1045`:
       opcode = (RK >> 12) & 077;
   Это и есть «опкод 020/021/032/047» из задачи.
2. Код в таблицах disbesm6.c / siprod_asm.py —
   `half & 0x0bf000` для 1-й структуры (0x027000 =
   КОП 047) или `half & 0x0f8000` для 2-й структуры
   (0x080000 = «э20»).

«э20»/`0x080000` в `disbesm6.c:109` — НЕ КОП 020, а
код 2-й структуры. Это два разных объекта с одним
именем. Ниже разбираются оба.

---

## 1. ЧЕТЫРЕ КОП-ПОЛЯ: ЧТО ОНИ ЕСТЬ НА САМОМ ДЕЛЕ

### 1.1. КОП 020₈ = сбр / apx — УПАКОВКА

- `optab.c:38`:
      {"apx", apx, 0, F_STACK|F_OP|F_LG,}, /* 020 */
- `besm6_cpu.c:1242`: `case 020: /* сбр, apx */`
  (`ACC = besm6_pack(...)`, ст. 1242-1252).
- `disbesm6.c:61`: `{ "сбр", 0x010000, 0x0bf000,
  OPCODE_STR1, BASIC },` — базовая команда.
- `siprod_asm.py:50`: `("сбр", 0x010000, ..., "str1")`.

ВЫВОД: арифметико-логическая команда 1-й структуры,
НЕ экстракод. Называть её «Э20» НЕВЕРНО.

### 1.2. КОП 021₈ = рзб / aux — РАСПАКОВКА

- `optab.c:39`:
      {"aux", aux, 0, F_STACK|F_OP|F_LG,}, /* 021 */
- `besm6_cpu.c:1253`: `case 021: /* рзб, aux */`
  (`ACC = besm6_unpack(...)`, ст. 1253-1263).
- `disbesm6.c:62`: `{ "рзб", 0x011000, ...,
  OPCODE_STR1, BASIC }`.
- `siprod_asm.py:50`: `("рзб", 0x011000, ..., "str1")`.

ВЫВОД: обычная команда, НЕ экстракод. Называть «Э21»
НЕВЕРНО.

### 1.3. КОП 032₈ = УВВ — ПРИВИЛЕГИРОВАННЫЙ ОБМЕН

- `optab.c:48`: `{"ext", priv, 0, F_PRIV,}, /* 032 */`
  (и `optab.c:49` — то же для `/* 033 */`).
- `besm6_cpu.c:1361`: `case 032: /* э32, КАДОПАМ */`
  (цитата; `э32` = УВВ, КОП 032)
  (`dks_read`/`dks_write`, ст. 1362-1370).
- `disbesm6.c:71` (ЗАКОММЕНТИРОВАНО):
      /* { "увв32", 0x01a000, 0x0bf000,
           OPCODE_IMM, PRIV }, */

ВЫВОД: привилегированная команда обмена (в simh —
ДКС/«КАДОПАМ»), тип PRIV, а НЕ F_TRAP. Экстракодом
НЕ является. Правильное имя - УВВ (привилегированный
обмен с внешними устройствами). Ранние отчёты и disbesm6
называли его увв32 ошибочно; в siprod OPS мнемоники
КОП 032 нет.

### 1.4. КОП 047₈ = x47 — ПРИВИЛЕГИРОВАННАЯ КОМАНДА

- `optab.c:61`: `{"x47", priv, 0, F_PRIV,}, /* 047 */`
- `besm6_cpu.c:1485`: `case 047: /* э47, x47 */`
  (`M[Aex&17] += Aex`, ст. 1485-1492, SUPERVISOR).
- `disbesm6.c:84` (ЗАКОММЕНТИРОВАНО):
      /* { "Э47", 0x027000, 0x0bf000,
           OPCODE_IMM, BASIC },*/

ВЫВОД: привилегированная команда (PRIV), не экстракод.
CPU зовёт её «э47» по аналогу с экстракодами, но в
optab.c это F_PRIV, а экстракоды — F_TRAP (§1.5).

### 1.5. НАСТОЯЩИЙ ЭКСТРАКОД (для сравнения)

- `optab.c:62-81`: `{"*50",0,I_TRAP,F_TRAP,}, /* 050 */`
  … `{"*77",0,I_TRAP,F_TRAP,}, /* 077 */` —
  диапазон 050..077₈.
- `besm6_cpu.c:1493-1501`: `case 050 … case 077:`
  `/* э50…э77 */` и `case 0200: /* э20 */`,
  `case 0210: /* э21 */` → метка `stop_as_extracode`.
- `besm6_cpu.c:1531-1534`:
      if (opcode <= 077) PC = 0500 + opcode;
      else PC = 0540 + (opcode >> 3);
- Тюрин, `extract-codes.md:3`: приложение П
  «ЭКСТРАКОДЫ ОС ДИСПАК ДЛЯ ПОЛЬЗОВАТЕЛЕЙ»;
  все 140 записей — только Э050 … Э077. Кодов
  Э020/Э021/Э032/Э047 там НЕТ.

ИТОГ §1: оператор ПРАВ. Как экстракоды КОП
020/021/032/047 не существуют. Экстракоды
пользователя — только 050..077₈.

## 2. Э20/Э21 КАК СИСТЕМНЫЕ КОДЫ 2-Й СТРУКТУРЫ

`disbesm6.c:109-110` (ЗАКОММЕНТИРОВАНО):
    /* { "э20", 0x080000, 0x0f8000,
         OPCODE_STR2, BASIC },
       { "э21", 0x088000, 0x0f8000,
         OPCODE_STR2, BASIC },*/

Это НЕ КОП 020/021, а коды 2-й структуры
02000000₈ / 02100000₈. В CPU им соответствуют
opcode 0200₈/0210₈ (`besm6_cpu.c:1499-1500`),
которые ДЕЙСТВИТЕЛЬНО уходят в `stop_as_extracode`
(ловушка в супервизор, `PC = 0540+…`).
То есть в «железе» системные экстракоды э20/э21
существуют, но:

  - их НЕТ в книге Тюрина (там только пользова-
    тельские);
  - мнём. нет в трансляторе 06/78 (проверено по
    siprod OPS); decode их тоже не знает.

Поэтому в комментариях .be корректнее писать не
«э20», а «КОП2 02000000₈, системный код 020,
мнём. нет».

## 3. ПОЧЕМУ decode() ДАЁТ None И СТРОКИ В КОММЕНТАРИИ

- `siprod_asm.py:92-97`: `lookup()` ищет
  `half & mask == code` по `OPS`
  (`siprod_asm.py:41-80`) и при промахе возвращает
  `(None, 0, 0, "illegal")`.
- Кода `0x027000` (КОП 047) в `OPS` НЕТ: там только
  `("Э50",0x028000,…)` … `("Э77",0x03f000,…)`
  (`siprod_asm.py:60-72`). Нет и `0x080000`,
  `0x088000` (э20/э21), и `0x01a000` (УВВ, КОП 032).
- В `disbesm6.c` те же мнемоники выведены в
  комментарий: ст. 71 (УВВ/КОП 032), 83-84 (Э46/x47),
  109-110 (э20/э21). Остальные коды (сбр, рзб,
  уи, уим, Э50-Э77) оставлены активными.

ГИПОТЕЗА (§7): строки закомментированы, поскольку
этих мнемоник нет в таблице транслятора 06/78
(системные/привилегированные), и дизассемблер не
должен печатать несуществующую мнемонику. Прямого
пояснения в исходнике нет.

## 4. ЧТО ТАКОЕ «НЕЗАКОННЫЕ ПОЛОВИНЫ» 2047 70xx

Все адреса восьмеричные. Проверено по `gold`
(read-only):

    слово               байты (big-endian)   KOI-7
    2047704010010005 -> 42 7e 20 20 10 05   ВЧ
    2047711730410006 -> 42 7e 4f 62 10 06   ВЧОБ
    2047710130410007 -> 42 7e 41 62 10 07   ВЧАБ

Разбор:

  - `2047` = старшие 12 бит = reg 4, DMS=0,
    структура=0, EXP=0, КОП 047₈. Это просто
    биты первых трёх KOI-7-байтов: 0x42 ('В'),
    0x7e ('Ч'), 0x20/0x4f/0x41;
    `0x427e20 & 0xfff = 0o7040` — отсюда «70xx».
  - Префикс `7` в `70xx` — младшие биты байта
    0x7e/0x20, а НЕ бит EXP (бит 18 сброшен).
    См. `ILLEGAL-HALVES-ANALYSIS.md:151-176`.

ВЫВОД: код 047 «появляется» в тексте случайно —
совпадение битов KOI-7 «ВЧ» с битами КОП. Слова —
ДАННЫЕ (таблица мнемоник), не команды и не
экстракоды. То же для `20xx`: `0x080000` — биты
2-го/3-го байтов текста, EXP=0; это не «э20»,
а данные.

## 5. КАК НАЗЫВАТЬ ЭТИ ПОЛОВИНЫ В .be-КОММЕНТАРИЯХ

Правило: раз слово — данные, называть его командой
(даже «привилегированной») неверно. Замены:

  БЫЛО               СТАЛО (после запятой)
  L=Э20 резерв       KOI7/ДАННЫЕ; КОП2 02000000₈
  L=Э21 резерв       KOI7/ДАННЫЕ; КОП2 02100000₈
  левая э20, зп      ДАННЫЕ; маска КОП2 020
  правая э20, зп     ДАННЫЕ; маска КОП2 020
  э20:нет мн         ДАННЫЕ; мнём. 020 нет в 06/78
  L=УВВ32: резерв    ДАННЫЕ; КОП 032 = УВВ (priv)
  R=Э47 EXP-адрес    ДАННЫЕ; КОП 047 x47, не EXP
  правая Э47, пв     ДАННЫЕ; КОП 047 x47, не ЭК

Если половина реально исполняется как команда
(подтверждено трассой/ребордом), верные имена:

  КОП 020 -> сбр    (есть в 06/78, OPS, d.c:61)
  КОП 021 -> рзб    (есть в 06/78, OPS, d.c:62)
  КОП 032 -> УВВ  (PRIV, мнём. нет в OPS)
  КОП 047 -> x47    (PRIV, мнём. нет в OPS)

«сбр» и «рзб» — подлинные команды 06/78; «УВВ»
и «x47» — привилегированные, но не экстракоды.

## 7. ГИПОТЕЗЫ И ГРАНИЦЫ

- ГИПОТЕЗА: причины закомментирования строк в
  disbesm6.c прямо в исходнике не указаны;
  объяснение через отсутствие мнемоник в 06/78
  выведено из `B-ILLEGAL-HALVES-3.md:74-76` и
  `ILLEGAL-HALVES-ANALYSIS.md`.
- ФАКТ: экстракоды пользователя по Тюрину —
  Э050…Э077; КОП 020=sбр, 021=рзб, 032=УВВ(PRIV),
  047=x47(PRIV).
- ФАКТ: `case 0200/0210` в simh — системные
  экстракоды (ловушка), но это opcode 2-й структуры,
  НЕ КОП 020/021.
- ФАКТ: байты 2047… — KOI-7 «ВЧ»+атрибуты,
  EXP=0 (§4).
- Ни один эталон, .be-файл или инструмент не
  изменён.

ВЕРДИКТ: называть КОП 020/021/032/047
«Э20/Э21/Э32/Э47-экстракодами» НЕВЕРНО, оператор
прав. Корректные имена: сбр, рзб, УВВ (КОП 032, PRIV),
x47 (PRIV); системные э20/э21 существуют лишь как
opcode 0200₈/0210₈ 2-й структуры и в книге Тюрина
отсутствуют.
