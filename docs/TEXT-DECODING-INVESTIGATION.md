# Раскодирование текста транслятора МАКРО-БЕМШ: проверка гипотезы
# смещения/сдвига

Дата: 19.11.2026. Образ: `2348` (том Д-2048/2348 МГУ, только чтение).
Инструмент: `tools/text_decode_probe.py`. Зоны: `0137–0177₈` (B) и
`0540–0577₈` (B2).

---

## 1. Краткий ответ

**Смещения/биаса нет.** Текстовые штампы транслятора записаны в 8-битной
ГОСТ-10859 и читаются `besmtool view --encoding=g` и `disbesm6`
**точно, без какой-либо правки**: все 5 калибровочных штампов
совпадают с эталоном GOST-10859 побуквенно (exact 5/5 при identity).

У «нечитаемости» другая причина: в тех же зонах лежат **6-битные
TEXT-константы** (8 символов на слово, `код = ASCII−0x20`). Их
старшие байты часто лежат в `0xa0…0xdf`, вне печатной области
GOST-10859.
`disbesm6` умеет печатать текстом **только GOST-8** и для таких слов
выводит `в'…'` (сырой восьмеричный дамп), а не `п'…'`. Это **разная
таблица**, а не сдвиг и не обфускация.

Правильный способ: смотреть все четыре кодировки сразу
(`besmtool view --encoding=g,k,t,i`) и выбирать ту, где соседние слова
образуют осмысленную фразу; для TEXT-имён — 6-битная таблица Дубны.

## 2. Калибровка: отображение байт → символ

Эталон из `besmtool search 2348 'ИПМ МАКРО-БЕМШ'` → `0147.1315`.
Слово `0147.1315`: байты `28 2f 2c 0f 2c 20`, восьмеричное
`1202745403626040`.

| Байт | 28 | 2f | 2c | 0f | 2c | 20 |
|------|----|----|----|----|----|----|
| GOST-8 (кир.) | И | П | М | пробел | М | А |
| GOST-8 (лат., `GOST_LATIN`) | И | П | M | пробел | M | A |

GOST-8 здесь **каноничен**: `0x20…0x3e` = `А…Я`, `0x00…0x09` =
`0…9`, `0x0a…0x0f` = `+ − / , . пробел`, `0x3f…0x4d` = латинские
`D F G I J L N Q R S U V W Z`.

Те же байты в других таблицах дают бессмыслицу — это признак того,
что слово **не** в этих кодировках:

| Кодировка | Прочтение `0147.1315` |
|-----------|----------------------|
| GOST-8, кириллица | `ИПМ МА` — верно |
| GOST-8, латиница | `ИПM MA` — омоглифы M/A |
| KOI-7 | `(/,⩾, ` |
| TEXT, `ASCII−0x20` (8×6) | `*"\L#RP@` |
| TEXT, таблица Дубны (8×6) | `*БЭLЦRPЗ` |
| ITM | `> +\0: ` |

Калибровочные штампы (все — GOST-8, identity, exact):

| Адрес | Байты | Ожидаемый текст | GOST-8 |
|-------|-------|-----------------|--------|
| `0147.1315` | `28 2f 2c 0f 2c 20` | `ИПМ МА` | `ИПМ МА` |
| `0154.0751` | `2c 20 2a 30 2e 30` | `МАКРОР` | `МАКРОР` |
| `0170.0216` | `2c 20 2a 30 2e 2c` | `МАКРОМ` | `МАКРОМ` |
| `0173.0655` | `2e 38 0e 31 2f 30` | `ОШ.СПР` | `ОШ.СПР` |
| `0176.1732` | `28 2f 2c 0f 2c 20` | `ИПМ МА` | `ИПМ МА` |

B2-копии (`0547.1315`, `0554.0751`, `0570.0274`, `0576.1700`) имеют
те же байты и то же прочтение; сдвиг только в номере зоны `+0400₈`.

`disbesm6 -a0 -e0 gold/MBE-Z0147-L1.bin | grep '^ *1315 '` даёт
`конд п'ИПМ МА'` — **то же**, что `besmtool view --encoding=g`.
Расхождения нет.

## 3. Проверка гипотез смещения и поворота

`tools/text_decode_probe.py` применяет к каждому штампу:

- побайтовый биас `+0x20, −0x20, +0x40, −0x40, +0xa0, −0xa0,
  +0x10, −0x10` (по модулю 256);
- поворот 48-битного слова влево на `6, 12, 18, 24, 30, 36, 42`;
- обмен половин по 24 бита, обмен полубайт, обратный порядок байт.

Оценка: доля кириллических букв и число **точных** совпадений
с эталоном (из 5).

| Преобразование | кир./среднее | exact/5 |
|----------------|--------------|---------|
| identity | 0.900 | **5** |
| rotl 24 / halfword-swap | 0.900 | 0 |
| byte-reverse | 0.900 | 0 |
| rotl 18 / rotl 42 | 0.600 | 0 |
| bias +16 | 0.600 | 0 |
| bias −16 | 0.220 | 0 |
| bias +32 | 0.100 | 0 |
| bias −32 / ±64 / ±160 | 0.000 | 0 |
| rotl 6 / 12 / 30 / 36 | 0.000 | 0 |
| nibble-swap | 0.000 | 0 |

**Только identity даёт 5/5 точных прочтений.** Оговорка: одна
кириллическая оценка не различает identity и перестановки половин —
все байты штампов лежат в зоне `0x20…0x3f`, где почти каждый байт
даёт букву. Решающий критерий — **Exact match**, а не частота букв.

## 4. Где `disbesm6` действительно применяет «не ту таблицу»

6-битная TEXT-константа: 8 групп по 6 бит, `код = ASCII−0x20`
(ре-forex, docs 19/20). Пример `0173.0744`:

```
байты      b3 a9 ae 00 00 00
6-бит     54 72 46 56 00 00 00 00   (восьмеричные коды)
ASCII−20  L  Z  F  N  _  _  _  _     → 'LZFN    '
GOST-8    \0 \0 \0  0  0  0           → в'5472465600000000'
```

`besmtool view 2348 --start=0173 --length=1 --encoding=g,k,t,i`
(строка `0173.0744:` содержит чётное слово `0744` и нечётное `0745`):

```
0173.0744:     000 ≡∧000  ```````UQ```  LZFN    WФ51      ```000Ю``000
                 ГОСТ-8                KOI-7      TEXT (t)     ITM
```

Колонка `t` даёт `LZFN    WФ51` — осмысленные TEXT-имена; колонка
`g` — мусор. А `disbesm6` на том же слове печатает
`конд в'5472465600000000'`. Он **не пытается** 6-битную таблицу:
байты `0xb3 0xa9 0xae` ≥ `0x4e`, не печать, поэтому включается
ветка `в'%016llo'` из `disbesm6.c`.

То же для `0152.0472` (байты `ae ac a9 a6 a5 40`):

```
0152.0472:       F000000  `````@``````  КJRIIJ5           ``````000000
disbesm6:  конд в'5352625151522500'
6-бит TEXT: 'KJRIIJ5 '
```

Итого: **disbesm6 не «искажает» текст — он не распознаёт TEXT**.
Для GOST-констант он точен.

## 6. Оговорки (обязательно)

1. **«Нечитаемые» слова §6.3 TEXT не лечатся.**
   `0173.1475` (`20 30 00 00 09 20` → `АР009А` / TEXT `(# D@`),
   `0176.0125` (`К8FV/С` / `*@A 2@PQ`),
   `0170.1653` (`2А10+G` / ` B !  I!`),
   `0152.0053` (`4,Э7ZЦ` / `! T\!TPV`) — смешанные числа/коды,
   не TEXT-строки. Причина их неразборчивости **не установлена**;
   гипотеза о таблице здесь не работает.
2. **Длинных TEXT-фрагмент нет.** Поиск по всем зонам B нашёл 0
   последовательностей из ≥3 подряд идущих TEXT-слов. Все TEXT —
   отдельные имена в таблицах, а не «program text» сплошным потоком.
3. **6-битный GOST почти всегда даёт буквы.** Сканер re-forex
   предупреждает: у GOST-6 нет маски отбора, почти любой код даёт
   букву. Поэтому «кириллический score» сам по себе ничего не
   доказывает (см. §3: 0.900 у четырёх разных преобразований).
4. **TEXT vs TEXT-DUBNA.** Для кодов `<0o20` и `>0o72` таблицы
   расходятся (`ASCII−0x20` против `text_to_gost`). Все имена
   в §5 попадают в совпадающую область, но для новых слов надо
   проверять обе.
5. **Б2-копии.** Сдвиг зон `+0400₈`; байты и кодировки те же.

## 7. Правильный способ чтения текста

1. Штампы, сообщения, названия полей листинга — **GOST-8**:
   `besmtool view 2348 --start=0ЗОНА --length=1 --encoding=g,k,t,i`
   (или `disbesm6` для `п'…'`).
2. TEXT-имена в таблицах — колонка `t` того же `besmtool view`,
   либо `python3 tools/besm6_text_scan.py --word 0o…` из re-forex.
3. `disbesm6` использовать только для GOST-констант; появление
   `в'%016llo'` — сигнал «попробуй 6-бит TEXT/KOI-7/ISO», а не
   доказательство мусора.
4. Никаких биасов, поворотов и обменов полуба́йт применять не надо.

cd /tmp/.private/azizz/re-bemsh

# калибровка и все гипотезы
python3 tools/text_decode_probe.py

# только таблица нечитаемых констант

  | grep '^0173.0744:'
