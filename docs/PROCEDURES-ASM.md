# КАТАЛОГ ПРОЦЕДУР ЗОН АСМ ИТМ 0055–0060₈

Дата: 20.11.2026. Образ: `2348` (том Д-2048/2348,
МГУ; read-only).
Объект: исполняемые модули `ТРАНСЛЯТОР С А/К И Т М` (автокод
ИТМ, `.75`, каталог `0000.0204`). НЕ МАКРО-БЕМШ и не B2.

Базовые листинги: `dis/ASM-Z0055-full.asm` …
`dis/ASM-Z0060-full.asm`
(принудительный `W_CODE`, адреса `-a0`). Все адреса ниже —
восьмеричные смещения зоны; физическая привязка не доказана.

ВАЖНО: исходник автокода ИТМ на диске отсутствует.
Все «значения» процедур — гипотезы по коду; фактами
являются только адреса, мнемоники, регистры и номера строк.

## 1. МЕТОДИКА И ТОЧНЫЕ КОМАНДЫ

### 1.1 Построение полных листингов (уже сделано)

```bash
cd /tmp/.private/azizz/re-bemsh
python3 - <<'EOF'
with open('/tmp/asm-all.tab','w') as f:
    for a in range(6, 1544): f.write('%o 2 -\n' % a)
EOF
for z in 0055 0056 0057 0060; do
  disbesm6 -a0 -e0 -n/tmp/asm-all.tab \
    gold/ASM-Z$z-L1.bin > dis/ASM-Z$z-full.asm
done
```

Подробности — `docs/SEMANTIC/ASM-CODE-RECOVERY.md`
§2: 99.17–99.90% половин дают opcode, `конд` 0–4 на зону.

### 1.2 Правила кандидата

- **ВХОД**: цель `пв` (CALL, `A#####` или числовой операнд,
  который disbesm6 печатает в десятичной форме: `16(М1)` =
  `020₈`); либо метка `A#####` с ≥2 входящими переходами
  (`пб/по/пе/цикл/пио/пино`); плюс слово 0 (авто-START).
- **ВЫХОД**: первая после входа `пб (Мn)` (косвенный
  переход/возврат), `пб 'NNNN'`/`выпр 'NNNN'` (уход
  из зоны), `Э74`/`стоп`, нулевой забел, след. вход.
- **РАЗМ** = `кон - старт + 1` слов (восьм.).
- `пв` заносит адрес возврата в М15 [GUIDE §5]; `пб (М15)`
  в этих зонах НЕ встречается — возврат неявный.

### 1.3 Инструменты

Использованы два независимых прохода:

1. Собственный разбор (вне репозитория,
   `/tmp/.private/azizz/opencode/procscan_my.py`): учтены
   числовые CALL-операнды (`пв 16(М1)`, `пв 52(М3)` и т.п.).
2. `tools/procedure_scan.py --dir dis --zone-family ASM`
   (автор — другой агент), прочитан и запущен
   только на чтение:

```bash
python3 tools/procedure_scan.py --dir dis \
  --zone-family ASM \
  --out /tmp/procscan.tsv --quiet
```

Сравнение: 81 первичный кандидат у сканера против 94 у моего
разбора; расхождения — в обработке числовых операндов и в
дальних границах (сканер даёт `0060:0301-0532 size=232`,
что явно завышено). Ниже приведены мои границы, проверенные
по тексту листинга.

Итог по сканеру (его счёт): 0055 — 34/1; 0056 — 20/2;
0057 — 13/0; 0060 — 14/5 (осн./данные). STOP: 4/3/0/3.

### 1.4 Условные обозначения таблиц

```
C<n>  — n входящих CALL (пв)
B<n>  — n входящих ветвлений (пб/по/пе/цикл/...)
Rnnn  — RET: пб (Мn) в слове nnn
Xnnn  — уход из зоны: пб/выпр 'NNNN' в слове nnn
—     — признак выхода не найден (граница по след. входу)
ГИП   — гипотеза; ПОДТВ — текст/пара CALL-RET
```

## 2. ОБЩИЙ ШЛЮЗ `выпр '70707'(М17)` / CODE_ITM_GATE

Команда `выпр '70707'(М17)` (IRET, передача управления в
ячейку `70707₈` вне зоны) — системный шлюз ИТМ. Прямые
вхождения в четырёх полных листингах:

```
0055.0000  выпр '70707'(М17)   L9   (дубли слов 0003/0004)
0056.0000  выпр '70707'(М17)   L9
0060.0770  выпр '70707'(М17)   L1054
0060.0771  выпр '70707'(М17)   L1056
0060.0772  выпр '70707'(М17)   L1057
0060.0773  выпр '70707'(М17)   L1059
0060.0774  выпр '70707'(М17)   L1060
0060.0775  выпр '70707'(М17)   L1061
0060.0776  выпр '70707'(М17)   L1062
0060.0777  выпр '70707'(М17)   L1064
```

**В 0057 буквального `70707` НЕТ** (проверено `grep 70707
dis/ASM-Z0057-full.asm` → 0 строк). Там та же роль
выполняется парой `сч D00173; по '4012'` (слово 2) и
`сч START; пб '4012'` (слово 4) — общий выход зоны;
`D00172/D00173` — ячейки-команды, которые код перезаписывает
(слова 1–2). Это честное уточнение тезиса задания о
«общем шлюзе во всех четырёх зонах»: шлюз один и тот же
логический вектор ИТМ, но в 0057 он достижим
только косвенно.

В 0060 шлюз ещё и записывается кодом: слово 4
`зп D00777` записывает `выпр '70707'(М17)` в ячейку 0777,
после чего 0770–0777 — девять копий вектора (возможно,
таблица векторов ввода/вывода). См. `Z0060.md` §3, §6.

Дополнительные `выпр` (другие цели): 0055.0505 `'52026'`,
0055.1211 `'17716'`, 0056.0440 `'24050'`,
0057.1375 `'55240'`, 0057.1726 `'5174'`,
0060.0411 `'12437'`, 0060.1247 `'51426'`,
0060.1366 `'20400'`, 0060 `'выпр (М2)'`.
Они не являются общим шлюзом.

## 3. ВЕКТОРНАЯ ДИСПЕТЧЕРИЗАЦИЯ

### 3.1 Зона 0057: пары `сч 'NNNN'; пб '3762'`

Фактическое число (full-листинг): **35 ссылок** на `'3762'`,
из них **34 полные пары** `сч 'NNNN'` → `пб '3762'`:

```
4064 4065 4066 4067 4070 4071 4072 4073 4074 4075
4076 4077 4100 4101 4102 4103 4104 4105 4106 4107
4110 4111 4112 4113 4115 4123 4246 4247 4251 4306
4307 4503 4507 4302
```

Первая пара: `0057.0013` (L41–42), последняя: `0057.1577`
(L1909–1910). Аргумент `сч` — логический адрес/код ИТМ;
`пб '3762'` — общий обработчик вне зоны. Это **исполняемая
таблица переходов**: каждая пара — мини-процедура
«положить аргумент в сумматор → передать управление
диспетчеру». Смысл конкретных `NNNN` без карты ИТМ не
установлен.

⚠ В `Z0057.md` §1 и §6 написано «~250 пар». По полному
листингу подтверждается только 34 пары (35 ссылок на
`3762`; те же 35 даёт `ASM-CODE-RECOVERY.md` §4). Число
250, по-видимому, отражает общее число команд `сч` (391)
или оценку без прямого счёта. В каталоге используется
фактическое число 34/35.

### 3.2 Остальные зоны

`'3762'` встречается: 0055 — 2 (`пб`), 0056 — 4, 0060 — 2.
Всего 43 (совпадает с таблицей внешних целей
`ASM-CODE-RECOVERY.md` §4). Там же разрозненные пары
того же типа, но без массового повтора.

Аналог пары CALL/переход в 0060: `зп '6727'; пв 16(М1)`
(слово 5) → `CALL 020₈` → `0020 пб (М1)` (слово 20).
В 0055/0056 роль «общего входа» играют `A00220/A00221`.

### 3.3 Почему это процедуры, а не данные

- каждая пара — две исполняемые команды с адресным полем;
- цель `пб` одна и та же (общий обработчик);
- при принудительном `W_CODE` ни одна из этих пар не
  помечена `конд` (0 или 4 `конд` на всю зону);
- дублирующиеся аргументы отсутствуют — это не забел.

## 4. СВОДКА ПО ЗОНАМ

```
зона  слов  A-меток  CALL-целей  кандидатов  RET  STOP
0055  1033   107        12          36        13     5
0056  1031    49        15          24        21     5
0057   992    33         8          14        14     1
0060   985    38        12          20        51     3
```

`слов` — число адресов с хотя бы одной именованной
половиной (остальные до 1024 — нули/паддинг). CALL-цели
включают числовые операнды (`пв 16(М1)` и т.п.).

Подтвержденная общность кода: 0055 и 0056 имеют **169
одинаковых слов** в блоках `0103-0143`, `0200-0351`,
`0365-0375` [Z0055 §1; Z0056 §1]. Блоки `A0220/A0221/
A0301` в этих двух зонах — побайтово одна и та же
процедура. В 0057 и 0060 те же смещения содержат
**совершенно другой код** (проверено пословно, §9).
Поэтому «общая библиотека всех четырёх зон» — ОПРОВЕРГНУТА:
обща только пара 0055/0056.

### 9.1 Развёрнутые значения

**1–2, 5. `A0220/A0221` в 0055 и 0056 (общий блок).**
Одна и та же процедура, побайтово совпадает:
`0220 сч; зп D00720` → `0221 сч (М2); пв A0302(М1)` →
`зп D00005; по '5630'` → `нтж '6721'; пе A00225` →
`сч D00245; пб '5620'`; второй выход `0231 пб '6003'`.
Механический смысл: **базовая утилита ИТМ, работающая с
рабочими ячейками D00720–D00725 и вызывающая A0302**;
результат — переход к внешнему обработчику 5620/6003.
`0220` — точка входа-преамбула (основная работа в 0221).
Уверенность в «утилита» — ГИПОТЕЗА; в тождество
0055=0056 — ПОДТВЕРЖДЕНО (169 общих слов).

**3. `0060:0220`.** Однословная преамбула
`зп 2(М13); зпм`, переходит в 0221 (`пе '4642';
зп '6770/6771/6772'; пб (М2)`). Механический смысл:
**утилита записи в ячейки 6770–6772 с индексом М13**.
Отличается от 0055/0056.0220 — это НЕ общая библиотека.

**4. `0057:0221`.** `уиа 0(М3); сч (М3); зп D00743;
уи М4; сч (М4); и '5347'; ... пино A00655(М1);
цикл A00657(М1)`. Механический смысл: **циклическое
копирование/сравнение массива через регистры М1/М3/М4
с вызовом A00655/A00657**. Выход `пб '4551'`.

**6. `0056:0561`.** `и A00561-5(М15); мода (М2);
сч D01035+4(М15); ... зп '6602/6603'`. Механический
смысл: **проход по таблице с индексом М15, запись
в ячейки 6602/6603**; выход `пб '6153'`.

**7. `0057:0637`.** `нтж '4657'; по '4644'; нтж D00237;
нтж D00252; ... зп '6777'; пв '4655'(М5)`. Механический
смысл: **проверка набора ячеек (D0237/D0252/'4657') и
ветвление в общий обработчик 4644/5435/5451**.
`A0641` — вложенный вход той же логики.

**8. `0057:0533`.** `уи М3; пб A00001; зп (М15); ...
цикл 1(М1); пб (М3)`. Механический смысл: **короткий
trampoline/инициализация, передающая управление в START
зоны и сохраняющая возврат в М15**.

**9. `0060:0641`.** `сда 64+4; и D00262; нтж D00262;
сли М1(М4); пб '6577'`. Механический смысл: **выделение
поля адреса (сдвиг 64+4) и работа с ячейкой D00262 как
индексом массива**; 5 CALL, выход 6577.

**10. `0060:0533`.** `по '6417'; сч D00720; зп '7263';
сч '7270'; пио '6557'(М5); цикл '6540'(М1)`.
Механический смысл: **обработка группы ячеек 7260–7271
с циклом по М1 и записью в 6772/0777**; выход 6417.

## 10. НЕИЗВЕСТНОЕ И ЛОЖНЫЕ ЦЕЛИ

1. Бизнес-функция ИТМ и всех подпрограмм — исходника нет.
2. Физическая привязка внешних адресов: `70707`, `3604`,
   `3762`, `4012`, `5620`, `6003`, `5041`, `5132`, `3564`,
   `3705`, `6017`, `6727`, `726x` и др.
3. Роль ячеек: `D00720–D00727`, `D00240–D00260`,
   `D01035+`, `67200–67775`, `077200–077250`.
4. Природа `Э64/Э71/Э74`: экстракоды ИТМ или системные
   вызовы. `стоп` с десятичным операндом (например
   `0055.1231 стоп 901(М14)`) может быть не командой
   останова, а словом-константой.
5. Хвост 0057 `1544–1777` и 2 illegal-половины `1341`.
6. Две копии шлюза в 0055 слов 0003/0004 — зачем дубли?
7. 156 нулей 0055 `1544–1777` — свободный район или
   неиспользуемый код (zero-fill — гипотеза).
8. Ложные CALL-цели numeric: `пв 16(М1)` — это `020₈`,
   а НЕ «CALL в ячейку 16». Аналогично `17`→`021₈`,
   `28`→`034₈`, `48`→`060₈`, `52`→`064₈`, `53`→`065₈`.
9. A-метки с одинаковыми номерами в 0057/0060 — **другие**
   процедуры, не версия 0055/0056 (§9).

## 11. ЧЕСТНЫЕ ОГОВОРКИ

1. **Нет исходника транслятора ИТМ.** Все значения —
   механические гипотезы. Ни одно не помечено как
   «подтверждённый» по бизнес-смыслу.
2. **A/D-метки — артефакт принудительного симтаба**
   [AGENTS §3; ASM-CODE-RECOVERY §7.2]. Привязка `-a0`,
   не физическая. `'NNNN'` и `D00NNN` — разные
   представления; они не объединялись.
3. **Границы оценочные.** Линейный scan по первому RET
   не различает вложенные и чередующиеся процедуры;
   `IMP` (fallthrough) тоже не различается. Размер
   `fallthrough`-процедур занижен.
4. **CALL через `(Мn)` статически не разрешается.**
   disbesm6 не отслеживает регистры; многие `пб (М1)`,
   `пб (М3)`, `пб (М16)` — возвраты или косвенные
   переходы, что именно — неизвестно.
5. **Счётчики различаются.** Мой разбор: 94 кандидата;
   `procedure_scan.py`: 81 (с Stop/ДАН). Причины:
   числовые CALL-операнды и эвристика RET/ДАН.
6. **«~250 пар» в Z0057 не подтверждается** — реально
   34 пары / 35 ссылок на `3762` (§3.1).
7. **«Общий шлюз во всех 4 зонах» не подтверждается
   буквально** — 0057 не содержит `70707` (§2).
8. **«Общая библиотека 4 зон» опровергнута** — побайтово
   совпадают только 0055/0056 в трёх блоках (§4).
9. `стоп`/`Э74` в листинге могут быть ошибкой наложения
   полей (W_CODE на данных) — не доказаны как STOP.
10. Ни один байт `gold/`, `dis/`, `.be`, `analysis/` не
    изменён. Скрипт разбора лежит в `/tmp`, не в
    репозитории.
