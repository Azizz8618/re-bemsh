## 2. Выбранный основной образ

**Основной (primary) образ — `/usr/local/share/besm6/2348`.**

Подтверждено двумя способами:

1. `echo $BESM6_PATH` → `/usr/local/share/besm6`.
2. `strace -f -e trace=openat,open besmtool view 2348 …` → единственное
   открытие файла `"/usr/local/share/besm6/2348"` (лог в
   `/tmp/.private/azizz/phase0/strace.txt`, находится вне репозитория).

Отдельного ключа `--disk-path` у `besmtool` нет: выбор файла полностью
определяется переменной `BESM6_PATH`. Значение по умолчанию оставлено без
изменения, как рекомендует `docs/COPIES-2348.md`.

## 4. Побайтовая сверка зон транслятора

Из каждой копии 2348 дампировано по 33 зоны dec `95..127` (= `0137..0177₈`),
каждая по 6144 байт (`besmtool dump … --start=<z> --length=1 --to-file=…`).
Конкатенация даёт 202 752 байт. Временные файлы — только в
`/tmp/.private/azizz/phase0/` (каталоги `copy1/`, `copy2/`, `copy3/`).

```
md5(0137–0177, 202752 байт):
  ~/.besm6/2348              2f503f5b8f8fb6ad12632fed6f8cf17f
  /usr/local/share/besm6/2348 2f503f5b8f8fb6ad12632fed6f8cf17f
  EC5061/2348                2f503f5b8f8fb6ad12632fed6f8cf17f
```

`cmp` подтвердил попарную идентичность всех трёх склеек. Повторный дамп
`~/.besm6/2348` **после** изменения файла (см. аномалии) снова дал
`2f503f5b8f8fb6ad12632fed6f8cf17f` и `cmp`-совпадение с основной копией —
то есть менялись рабочие зоны, а не зоны транслятора.

## 5. Аномалии

1. **`~/.besm6/2348` менялся во время проверки.** В `docs/COPIES-2348.md`
   указан md5 `29987d509d1d75c9481b55a32ee4927c` (mtime 16:59); в начале
   фазы 0 измерено `65a9e8c52481ca20714698a6cc10df79` (mtime 18:33:01),
   затем `e8a7e1ee9adeaa709a29912bd2c2755c`, и наконец стабилизировалось:
   `2fc13cb8d118a14307081dadafb376e6` (mtime 18:35:33). В момент последней
   проверки процесс, держащий файл открытым, не обнаружен (опрос `/proc/*/fd`);
   в системе работает эмулятор SIMH BESM6 (PID 541793, конфиг
   `/tmp/.private/azizz/opencode/dispak_share.ini`), но он монтирует
   `/usr/local/share/besm6/2348`, не `~/.besm6`. Вероятная причина —
   параллельная работа другого субагента/процесса с рабочими зонами.
   **Вывод:** md5 `~/.besm6/2348` не является стабильной инвариантой; при
   сравнении `before`/`after` возможны отличия, не вызванные нашими
   операциями. Основной образ `/usr/local/share/besm6/2348` стабилен.
2. **Расхождение в документации исправлено.** `docs/COPIES-2348.md` указывал
   `md5(0137–0177) = 96ff5142ee1c856e307722c0f5c1f55c` (это md5 списка
   повзонных md5, а не md5 конкатенации). Фактическое значение для всех трёх
   копий — `2f503f5b8f8fb6ad12632fed6f8cf17f`, как в `docs/PLAN.md` и
   `docs/VERSIONS-SCAN.md`; документ обновлён.
3. Каталог зоны 0 в `EC5061/2348` записан как `UUUUUU…`, а на `2148`/`2248`
   не читается как KOI-7 — это ожидаемо (`docs/COPIES-2348.md`,
   `docs/VERSIONS-SCAN.md`); `besmtool` всё равно находит зоны по `md_pos`.
4. **`besmtool search` печатает BOM и NUL-байты** в выводе (`\xEF\xBB\xBF` в
   первой строке, NUL в строках попаданий), поэтому фильтрацию делали через
   `tr -d '\000' | sed '1s/^\xEF\xBB\xBF//'`; на результаты это не влияет.

## 6. Гарантия read-only

**Все операции выполнялись только на чтение.** Использовались команды
`stat`, `md5sum`, `besmtool view`, `besmtool search`, `besmtool dump
--to-file`, `strace`, `cmp`, `grep`, `cat`, `wc`. Запись в файлы образов не
производилась; обращение к томам шло только через read-only-режимы
`besmtool`. Все временные файлы создавались исключительно в
`/tmp/.private/azizz/phase0/`; в репозитории изменены только два разрешённых
файла — `verify/image-md5.before.txt` и настоящий `docs/IMAGES.md`.
