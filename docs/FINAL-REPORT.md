## 1. Объект исследования

На томе 2348 (пакет Д-2048/2348 МГУ, каталог зоны 0) находятся:

| Объект | Зоны (восьм.) | Дата | Роль |
|---|---|---|---|
| ТРАНСЛЯТОР С А/К И Т М | 0055–0060 | .75 | автокод ИТМ, не БЕМШ |
| **ТРАНСЛЯТОР С М/К БЕМШ** | **0137–0177** | 20.06.78 | искомый макро-транслятор, `ВЕР.06/78` |
| то же, старшая редакция | 0540–0577 | 1976–77 | `ВАР.12/77` (зона 0537 пуста) |

`МВЕ60` в листингах `mbe60_*` — **тестовая программа связи с ДКС**,
оттранслированная этим транслятором, а не его исходник. Поэтому слова
листинга не совпадают со словами дампа (0 совпадений из ~30 характерных) —
см. `ANCHORS.md`. **Листинг ≠ дамп** — один из ключевых выводов проекта.

Структура транслятора (по штампам): **МАКРОРЕДАКТОР (20.06.78)** →
**МАКРОМАШИНА (1.11.78)** → **АРАП (04/78)**. Штампы в зонах
`0154.0751`, `0170.0216`, `0152.1164`. Атрибуция ролей пока опирается на
текстовые штампы; динамические доказательства — только для 0154 (Фаза C).

### 1.1. Исключённые зоны 1000–1037₈ («МБ 2.0 ДЛЯ М3/М1»)

Зоны `1000–1037₈` (32 зоны) представляют собой отдельную
программу, не БЕМШ. По уточнению заказчика они не входят
в скоуп анализа зон `0137–0177₈` и B2 `0540–0577₈`
(`AGENTS.md` §1, `PLAN-NEXT.md` п. 5, `PLAN.md` §4 и §7,
`ROADMAP.md` п. 5). Проверено 22.11.2026 чтением эталона.

1. **Каталог паспортов.** `besmtool search 2348 'МБ 2.0'`:
   `(KOI7) 0000.0644: ... 1000-1037 МБ 2.0 ДЛЯ М3
   1201 25.12.90 ...`; дубликаты `0076.0716`,
   `0077.1000`, `1172.0716`, `1173.1025`. Соседняя запись
   `0000.0653`: `1040-1077 МБ 2.0 ДЛЯ М1 ( И М3 )`.
   В альт. каталоге `0777.0726` та же запись озаглавлена
   `1000-1037 ТРАНСЛЯТОР С М/К Б Е М Ш 1169 .02.87
   С48 56`. Это паспорт шифр 1169 от `.02.87`, а не
   штамп искомого транслятора `0000.0445`
   (`0137-0177 ... 20.06.78`).
2. **Содержимое зон.** `besmtool view 2348 --start=01000
   --length=32 --encoding=k`: все 32 зоны непустые.
   Первые слова зоны `1000` (восьм., 6 байт на слово):
   слова `0`–`7` нулевые, `0010: 4247777100100000`,
   `0011: 4000002743700011`, `0012: 4647753332477771`.
   Зона `1037`: `0000: 0002010112402260`,
   `0001: 5240250232477722`. Шапка отличается от
   `gold/MBE-Z0137-L1.bin` (`0000: 0000000001000000`,
   `0001: 0000000000200000`). Штампа `МБ 2.0` внутри
   зон `1000`–`1037` нет: поиск дал попадания только
   в зонах `0000/0076/0077/1172/1173` (каталог)
   и `0743` (текст «СТАНОВЛЕНИЕ МБ 2.0 ...»).
3. **Поиск текстов.** `besmtool search` по шаблонам
   `МАКРО-БЕМШ`, `ТРАНСЛЯТОР`, `БЕМШ`, `ВЕР.06/78`,
   `ВАР.12/77`, `МБ 2.0`: 0 попаданий с адресами
   вида `10xx.`. `МАКРО-БЕМШ` найдено только в
   `0147.1315` (`ВЕР.06/78`) и `0547.1315`
   (`ВАР.12/77`).
4. **Артефакты.** `gold/` содержит только зоны
   `0055–0060`, `0137–0177`, `0540–0577`; `dis/`
   содержит 71 листинг этих зон. `ls gold | grep Z10..`,
   `ls dis | grep Z10..` и
   `grep -rl 'МБ 2\.0\|1000-1037' gold dis` пусты.
   `zones.src` прямо помечает `1000–1037` как
   «НЕ включать».

Вывод: зоны `1000–1037₈` это отдельная прикладная
программа «МБ 2.0 ДЛЯ М3/М1», в реконструкцию 69 зон
транслятора не входят. Гипотеза о третьей версии
`.02.87` снята по уточнению заказчика. md5 образа
`f8efceb2e89064d36daf451efea469dd` до и после всех
вызовов `besmtool` совпадает: образ не изменялся.

## 2. Вызовы процедур МС «ДУБНА»

Два уровня:

1. **Карты монитора:** `*NAME`, `*CALL UESMEMORY` (`YESMEMOR` из `FICMEM*`),
   `*SYSTEM`, `*MAIN`, `*BEMSH`, `*EXECUTE`, `*CALL DTRAN(MBE60)`;
   шифр `419900000000`, Монитор-80 3.7 (25.09.84) на базе МС «ДУБНА» ИАЭ.
2. **Машинный уровень:** `EXTRD PRINT8` + макрос `CALL → ПВО ∧T.(М15), ПАМ 0`
   даёт `13, VJM, PRINT8` (`00531531 74001`), возврат через `ПБ (М15)`; внешние
   символы разрешаются загрузчиком по `*EXECUTE` (`PRINT8 01205`, `MON*ITOR 04000`).
   Параметры — в аккумуляторе/индексных регистрах и блоках `ИМЯ(П1,П2)`.

Транслятор не вызывает ДУБНА как библиотеку — он работает **внутри**
Монитор-80; `PRINT8`, `ОКНО`, `ARFA` и др. — процедуры заданий в этой среде.
Подробности в `PLAN.md` §3 и в отчётах субагентов.

## 5. Ключевые научные находки

1. **2 ячейки ГС на простой макрос.** Счётчик `КОЛИЧ ЯЧ ГС` растёт на +2 за
   каждое простое макроопределение независимо от числа параметров (0–3) и
   длины тела (1/3/6 строк); макрос с `LСLА`/`SЕТА`/`АIF` даёт +4. Укладка
   §7 (`D0…D4`, 5 слов на макрос) опровергнута. Схема `[TAG(24)|VAL(24)]`
   **не подтверждена**: биты ячеек в опытах не наблюдались.
2. **0154 исполняется по `02000₈`.** Зона 0154 загружена на страницу 01 и
   совпала 1024/1024 слов; breakpoint `02000` сработал и показал
   `xta 6065` = `сч '6065'` — первую команду зоны. Гипотеза «исполняемый код
   макроредактора лежит вне 0154» опровергнута. Для 0170 ИСПРАВЛЕНО 22.11: зона загружена по `02000₈` как оверлей
   page 01, штамп 0170.0216 найден в RAM по `02216`
   (`analysis/PASSES-CODE-LOCATION.md`).
3. **Листинг ≠ дамп.** Листинги `mbe60_*` — тестовая программа ДКС, написанная
   на БЕМШ; 0 совпадений характерных слов с дампом транслятора. Имена из
   `*МЕТ*`/`*EXECUTE` — логические адреса, а не физические якоря.
4. **Каталог макрокоманд — 37 позиций.** Омоглиф-толерантный декодер
   (`tools/macro_decode.py --catalog`) печатает 37 команд / 45 строк Markdown;
  casual-mapping написаний `G↔Г`, `L↔Л`, `S↔С`, `N↔Н`, `D↔Д`, `E↔Е`, `F↔Ф`.
   См. `docs/MACRO-COMMANDS.md`.
5. **Тексты и регистры аннотации.** 25 надёжно декодированных констант в
   GOST-10859 / KOI-7 / TEXT / ITM; `п'F00900'` — артефакт `gost_putc`, не текст.
   М15 — адрес возврата (подтверждено CALL и `ПБ (М15)`); М16 — двойная роль;
   М13 — ссылка; М5/М12 с ~5100 «попаданий» — данные таблиц ошибок, не регистры.
6. **Ограничение disbesm6 учтено.** `-r`/`-b` инертны, `-e` обязателен, метки
   `A#####` (в исходнике `G#####`), fuzz=64 даёт ложные `A00003+34`, склейка
   >32768 слов вызывает segfault. Все обходы зашиты в инструменты.
