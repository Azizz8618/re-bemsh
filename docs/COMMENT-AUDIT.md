# COMMENT-AUDIT — аудит галлюцинированных комментариев в `bemsh/*.be`

**Инструмент:** `tools/comment_audit.py` (только чтение `.be`-файлов).
**Дата:** 20.11.2026. **Область:** все 69 модулей `bemsh/*.be`
(`ASM-Z0055…0060`, `MBE-Z0137…0177`, `MBE2-Z0540…0577`).

> Цель — не «починить комментарии автоматически», а **дать список подозрительных
> мест** агентам-исправителям. Ни одного `.be`, `gold/`, `dis/` инструмент не
> трогает: он печатает отчёт в stdout.

---

## 1. Методология

### 1.1 Что считается комментарием

Строка `.be` разбирается по разделителю ` , ` (тот же, что в
`tools/annotate_zone.py:24`): всё **до** первого ` , ` — код (менты+операнд),
всё **после** — комментарий. Пропускаются:

* шапки/директивы (строки, начинающиеся с `*`), пустые строки;
* строки без ` , ` (в том числе все `ЭКВ`-определения вида `OUT477 ЭКВ '477'`);
* строки, где вторая колонка — `ЭКВ`.

Номер зоны берётся из имени файла regexp'ом `Z(\d{4})`: `ASM-Z0055.be → 0055`,
`MBE2-Z0540.be → 0540`.

### 1.2 Категории подозрений

| Категория | Правило (эвристика) |
|---|---|
| `EMPTY-OPERAND-SEMANTIC` | Операнд пуст/пробельный, а комментарий **не** содержит одного из маркеров нулевого слова (`нулевое слово`, `забел`, `пустое слово`, `нуль`, `ноль`, `слово 0` и т.п.). Такое слово — `00 000 0000`; у `ЗП` с пустым операндом нет ни адреса, ни `(Мn)`, значит утверждение «записать по адресу из УИА» — галлюцинация. Рекомендуемая замена: `, нулевое слово (забел)`. В `detail.claims` фиксируется, какой именно адресный/регистровый claim сделан (`адрес`, `уиа`, `регистр`, `сумматор`, `метка`). |
| `CONTRADICTION` | Комментарий называет регистр `[МM]\d{1,2}` или метку вида `CEL775`/`OUT477`/`AM763`, которой **нет** в операнде. Регистры и метки извлекаются отдельно; Stop-word'ы (`CALL`, `GOST`, `TEXT`, `DEKOD`, `MBEENTRY`, `SUB04*`…) не считаются метками. Пример: `СЧ CEL775 , записать в CEL776` → `missing_labels: [CEL776]`. |
| `REPETITION` | Одинаковый текст комментария встречается **более `N` раз** (по умолчанию `N = 20`) в корпусе **или** в одном файле. В `detail` — `count_corpus`, `count_file`. Признак pattern-map артефакта/штампа. |
| `TAUTOLOGY` | Комментарий содержит запрещённую `COMMENTING-STANDARD.md` фразу: `константа`, `цель ветвления`, `цель перехода`, `переход/возврат`, `обработка`, `конд`, `утилита`, `диспетчер`, `MBEENTRY`, `SUB04`, `SUB05`, `служебное слово` (последнее — banned как финальная роль, §2.6). |
| `LENGTH` | Длина комментария > 55 символов **или** длина всей строки > 78 колонок (`AGENTS.md` §0, стандарт §6). |

Одна строка может получить несколько категорий — они не исключающие.
`safe_comments` — строки, не получившие ни одного флага.

### 1.3 Классификатор «безопасных» комментариев

`CA.classify_safe(operand, comment)` возвращает `True`, когда:

1. все регистры и метки, названные в комментарии, присутствуют в операнде; **и**
2. либо операнд непуст, либо комментарий явно говорит о нулевом слове.

Примеры, проходящие классификатор (юнит-тесты `test_safe_comment_examples`):

```
        ЗП   CEL775      , записать в CEL775
        ПВ  OUT477(М15) , вызвать OUT477 через М15
        НТЖ  AM763(М5)  , поиск по AM763
```

Не проходят: `ЗП <пусто> , записать по адресу из УИА`,
`СЧ CEL775 , записать в CEL776`, `ПВ BR232(М3) , вызвать BR232, возврат в М15`.

CLI: `python3 tools/comment_audit.py [--all | --zone Z] [--top N]
[--repeat-threshold N] [--json]`. Если не указано ни `--all`, ни `--zone`,
сканируются все модули (`--all` — явный синоним).

**Команда для агентов-исправителей (рекомендуемая):**

```bash
python3 tools/comment_audit.py --all --json > /tmp/comment-audit.json && \
python3 -c 'import json; r=json.load(open("/tmp/comment-audit.json")); \
print(r["by_category"]); \
[print(x["file"],x["line"],repr(x["comment"]),"->", \
x["detail"]["suggestion"]) for x in \
[f for f in r["findings"] \
if "EMPTY-OPERAND-SEMANTIC" in f["categories"]][:50]]'
```

Подозрительную строку править **только комментарием после ` , `**, сохраняя
побайтовый инвариант (проверка: `tools/annotate_zone.py --verify-only` печатает
`0 differences`).

## 3. Верификация на известном баге зоны 0055

Заявка: комментарий `ЗП , записать по адресу из УИА` встречается 1169 раз;
нижележащее полуслово — `00 000 0000` (ZERO word), адреса и `(Мn)` нет.

**Воспроизведение:**

```bash
python3 tools/comment_audit.py --zone 0055 --top 5
grep -n 'записать по адресу из УИА' bemsh/ASM-Z0055.be
python3 -c 'import sys;sys.path.insert(0,"tools");import comment_audit as c;\
r=c.audit_corpus(".",zone="0055");\
print([f for f in r["findings"] if f["line"]==596])'
```

**Ожидаемый результат:**

* строка `bemsh/ASM-Z0055.be:596` — `        ЗП             , записать по адресу из УИА`
  помечена категориями `EMPTY-OPERAND-SEMANTIC` и `REPETITION`;
  в `detail`: `claims: [адрес, уиа]`, `suggestion: ", нулевое слово (забел)"`;
* в зоне 0055 такой комментарий найден **539 раз** (итого по корпусу — **1169**);
* в топе зоны 0055 также `взять по адресу из УИА` (16), `настроить адресацию`
  и др. — все с нулевым операндом;
* юнит-тест `KnownZoneAndCliTests.test_zone_0055_known_line` проверяет ровно
  эту строку.

Рекомендуемая правка строки 596 (только комментарий):

```
        ЗП             , нулевое слово (забел)
```

## 5. Честные оговорки

1. **Аудит эвристический.** Он не понимает семантику программы. Комментарий
   может быть неверным, но пройти все проверки (например, названа правильная
   метка, но неверно описано *зачем* она читается). Прохождение аудита — не
   доказательство корректности.
2. **Пустой операнд ≠ всегда нулевое слово.** Правило предполагает, что пустой
   операнд — это `00 000 0000`. Для части мнемоник (`СЧМР`, `МОДА`, `СЧИ`)
   возможна легитимная безадресная форма; такие строки попадут в
   EMPTY-OPERAND-SEMANTIC ошибочно. Требуется сверка с дампом/листингом.
3. **CONTRADICTION даёт ложные срабатывания.** По соглашению `ПВ X(Мn) …
   ПБ (М15)` возврат всегда в М15, поэтому комментарий «возврат в М15» при
   операнде `(М3)` может быть **законным** role-утверждением, хотя М15 и нет
   в операнде. Из 135 флагов значительная часть — такого вида (133 из них —
   `возврат в М15`). Проверять вручную.
4. **REPETITION — индикатор, а не приговор.** Массовые корректные маркеры
   (`забел` — 5075, `служебное слово` — 7241) тоже попадают под порог >20.
   Это не означает, что каждый такой комментарий плох; это означает, что
  pattern-map мог тиражировать шаблон без осмысления.
5. **TAUTOLOGY по списку фраз.** Список составлен по явно запрещённым
   формулировкам из `COMMENTING-STANDARD.md` §1/§2.6/§7; он не исчерпывает
   все возможные тавтологии.
6. **Метки — по тексту строки.** Сравнение идёт с буквальным текстом операнда.
   Если в комментарии использовано роль-имя из таблицы (`OUT_PRINT`) вместо
   метки дампа (`OUT477`), это не будет сочтено совпадением. LABEL_STOPWORDS
   частично снимает проблему, но не полностью.
7. **Грамматика разбора.** Предполагается ровно один разделитель ` , ` на
   строку (в корпусе 98467/98467 строк — ровно один). Изменение формата
   разметки потребует правки `parse_line()`.
