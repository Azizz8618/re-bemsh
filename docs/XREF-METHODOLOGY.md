# Методика Phase 4: символы и вызовы (`tools/xref.py`)

Документ описывает, как по листингам `disbesm6` (`dis/*.asm`) строить
граф переходов/вызовов транслятора «ТРАНСЛЯТОР С М/К БЕМШ»
(зоны `0137–0177` и `0540–0577`) и сверять его с картой `*EXECUTE`.

---

## 1. Что и где делаем

Phase 3 производит по одному `.asm` на зону (6144 байт = 1024 слова).
Phase 4 добавляет два слоя поверх дизассембля:

1. `sym/MBE.tab` — таблица символов формата `%o %d %63s`;
2. `analysis/xref.txt` — граф «адрес → мнемоника → цель → модификатор
   → символ», плюс сводка.

`tools/xref.py` **только читает** `.asm` и `.tab`. Никакие эталонные
образы и листинги не меняются (см. `AGENTS.md`, правила 0–1).

---

## 2. Команды (точная последовательность)

### 2.1 Грубый поиск по мнемонике (из `docs/PLAN.md`, Фаза 4)

```bash
grep -nE '\b(пб|пв|по|пе|цикл|выпр|э[0-7][0-7]|вжм)\b' \
  dis/MBE-*.asm > analysis/branches.txt
grep -nE 'увв|сда|счрж|конд' \
  dis/MBE-*.asm > analysis/io.txt
```

Первый `grep` ловит переходы, вызовы и экстракоды; второй — ввод/вывод
и данные. Это быстрая прикидка: `grep` не различает метки и операнды.

### 2.2 Таблица символов

`disbesm6 -n` читает файл формата `адрес_восьм %d имя`:

```
01000 2 MBE60       тип 2 = W_CODE (точка входа)
01205 2 PRINT8      внешняя процедура из *EXECUTE
00050 1 -           тип 1 = W_DATA (только пометить тип)
00000 0 ALIAS       тип 0 = экв
```

Ключ `-nfile`: имя файла — остаток аргумента; тип `1 = W_DATA`,
`2 = W_CODE`. `-` вместо имени означает «пометить тип, без имени».

⚠ Имена из `*МЕТ*`/`*EXECUTE` — **логические/памятные** адреса
листинга, а не физические адреса зон диска. Подробнее — §5.

### 2.3 Запуск xref

```bash
python3 tools/xref.py \
  --dis-dir dis \
  --out analysis/xref.txt \
  --symtab sym/MBE.tab
```

По умолчанию: `dis-dir=dis`, `out=analysis/xref.txt`,
`symtab=sym/MBE.tab`. Если `.asm` нет — сообщение и `exit 1`
(это нормально до завершения Phase 3).

Тест на отдельном файле (без создания `analysis/`):

```bash
disbesm6 -a0 -e0 /tmp/.private/azizz/mbe137.bin \
  > /tmp/.private/azizz/xref-test.asm
python3 tools/xref.py \
  --dis-dir /tmp/.private/azizz/xref-testdir \
  --out /tmp/.private/azizz/xref-out.txt \
  --symtab sym/MBE.tab
```

## 3. Формат разбираемой строки

Реальный вывод `disbesm6` (проверено на `mbe137.bin`):

```
  100:04 066 2101 <TAB>A00100<TAB>Э66<TAB>'2101'(М4)
  ^^^^^ ^ ^^^^^^^^^^      ^^^^^^  ^^^  ^^^^^^^^^^^^
  адрес : opcode-колонки   метка   мнемоника  операнд
```

- позиции `0..4` — адрес, восьмеричный, right-aligned (5 символов);
- позиция `5` — `:` (начало базового блока, `W_STARTBB`) или пробел;
- до первого TAB — колонки opcode: короткие `%02o %03o %04o`,
  длинные `%02o %02o %05o`, данные — одно 16-значное слово;
- дальше через TAB: **метка**, **мнемоника**, **операнд**;
- вторая строка слова адреса не имеет и наследит адрес первой;
- строка `* next insn used as data` помечает **следующую** ячейку
  как `W_CODE | W_DATA` (адресное слово/метка, не ошибка);
- `конд п'…'` / `конд в'…'` — данные; `пам N`, `nop`/`ноп`, `экв` — нули;
- первый байт потока — UTF-8 BOM (в скрипте `utf-8-sig`).

### Классификация мнемоник

| Класс | Мнемоники | Метка в «ПРИМ» |
|---|---|---|
| переходы | `пб`, `по`, `пе`, `пио`, `пино`, `цикл`, `выпр` | `BR` |
| вызовы | `пв`, `вжм` | `CALL` |
| останов | `э74` | `STOP` |
| экстракоды | `э00…э77` (в т.ч. `Э66`) | `EX` |
| данные | конд/пам/nop/ноп/экв | DATA / D+C |

Модификатор `(Мn)` вынимается из операнда в отдельную колонку `МОД`.
Целью считается первый токен операнда без `(Мn)`: `A00105`,
`D00641`, `START`, `'2101'`, `1`, `-5`. Для `PRINT8, М15` (макрос
`CALL → ВЖМ + ПАМ 0`) берётся `PRINT8`.

## 4. Метки `A#####` против `D#####`

- `A#####` — метка **кода**, создаётся трассировкой `disbesm6`
  (в authority-исходнике бинарника это `G#####`). Пример: `A00100`.
- `D#####` — метка **данных**: цель, помеченная как `W_DATA`
  (например, `сч D00632`, `Э70 D00643`). Это не адрес перехода,
  а ссылка на таблицу/константу; в графе вызовов она остаётся,
  но в `branches.txt` её легко принять за процедуру — проверяйте.
- Метка может быть напечатана **в колонке метки** (левая половина
  слова) или **в операнде** (цель перехода). Оба случая разбираются.
- `START` / `ФИНИШ` — псевдостроки шапки, не адреса.
- Имя из `.tab` подставляется в колонку `СИМВ`, если совпал адрес
  строки или цель (`A#####`/`D#####` переводится в восьмеричное
  число после первой буквы).

**Правило:** `A`-метка говорит «сюда передаётся управление»,
`D`-метка — «сюда обращаются как к данным». Превращать `D`-метку
в точку входа без доказательства запрещено; для этого служит
`-n` с типом `2` и `-R3=<адрес>` (см. `DISBESM6-GUIDE.md`, §3).

## 5. Два предупреждения

### 5.1 `fuzz=64` — артефакт, не ссылка

`praddr()` печатает `имя±<дец>`, если цель попала в окно ±64
от известного символа. Отсюда `сч D00003+34` и `A00003+34`:
это **не** реальная ссылка на `A00003+34`, а шум окна.
`xref.py` отделяет смещение, показывает его как `fz34` в колонке
«ПРИМ» и считает отдельной строкой «артефакты fuzz» в сводке.
Не использовать такие адреса как физические без проверки
`disbesm6 -R<N>=…` и побайтовой сверки.

### 5.2 Логические адреса листинга ≠ физические зоны

Карта `*EXECUTE` (`01000` — вход `МВЕ60`, `02000` — `*PAGE*`,
`04000` — `MON*ITOR`) даёт **памятные** адреса тестовой
программы ДКС, напечатанной в `mbe60_*`. Это **другая программа**,
которую транслятор только оттранслировал; её слова не найдены
в дампе зон `0137–0177` (0 совпадений из ~30 характерных слов).

Поэтому:

- подставлять `01000` из `*EXECUTE` как адрес зоны `0137` — нельзя;
- физическими якорями служат только текстовые штампы
  `0147.1315`, `0152.1164`, `0154.0751`, `0170.0216`, `0176.1733`,
  `0177.0421` (полный список — `docs/ANCHORS.md`, §2);
- `sym/MBE.tab` заполняется как **логические** имена с пометкой
  версии, а не как доказанные физические адреса;
- сверить граф `*EXECUTE` с `xref.txt` можно только на уровне
  имён/ролей (`PRINT8`, `MON*ITOR`, `PLREG`, `VJ-60`), не адресов.

## 6. Формат `analysis/xref.txt`

```
# XREF: граф переходов/вызовов по листингам disbesm6
# dis-dir: dis        symtab : sym/MBE.tab (N записей)
#   АДР     МНЕМ   ЦЕЛЬ              МОД  СИМВ     ПРИМ
#   ------  -------  ----------------  ---  -------  ----
 00100:  Э66      '2101'            М4   MBE60    EX
 00004  пб       A00105            М1   -        BR
 00635  пам      1                 -    -        -
# ИТОГО
# строк: всего=N  код=N  данные=N  неизв=N
# переходы BR=N  вызовы CALL=N  э74/STOP=N
# экстракоды эNN=N  (из них э74=N)
# метки в целях: A=N  D=N  артефакты fuzz=N
# символы symtab: всего=N  код(2)=N  данные(1)=N
# экв(0)=N  прочие=N  строк с символом=N
```

Строки отсортированы по адресу; ширина ≤60 колонок. Две половины
одного слова имеют один адрес и различаются порядком строк.

## 7. Что делать с результатом

1. `analysis/branches.txt` — быстрый список; `analysis/xref.txt` —
   структурированный граф с символами.
2. Для каждой `CALL`/`BR` сверить роль с `*EXECUTE` и макросом
   `CALL → ВЖМ(M15)` (возврат `пб (М15)`), см. `PLAN.md`, §3.2.
3. `D`-цели занести в `analysis/uncertain.md` как «данные или таблица»;
   `A`-цели с fuzz-смещением — в «не доказано».
4. Итог — таблица «процедура / адрес / роль» в `analysis/calls.md`
   с обязательной пометкой «логический адрес, физическая привязка
   не установлена», пока не найден текстовый штамп-якорь.

Тест выполнен на `/tmp/.private/azizz/mbe137.bin` (зона `0137₈`,
6144 байт), дизассемблированном в `/tmp/.private/azizz/xref-test.asm`

даёт явное сообщение и `exit 1`.
