## 2. Структура транслятора МАКРО-БЕМШ (МВЕ60)

### 2.1 Идентификация и запуск

Из листингов `re-dispak/testdks/mbe60_bemsh_list.txt`, `mbe60_korot_bemsh_list.txt`,
`mbe60_bemsh_dtran.txt` (шапка, строки 2–14):

```
М О Н И Т ОР-8 0 (3.7) 25.09.84* (МС "ДУБНА" ИАЭ) ШИФР 419900000000
*NAME
*      CALL UESMEMORY
*      SYSTEM
*MAIN MBE60
*BEMSH
ИПМ МАКРО-БЕМШ ВЕР.06/78
АРАП ВАР.04/78
```

- `*MAIN MBE60` — имя сборки; `*BEMSH` — выбор транслятора.
- **`ВХОД МВЕ60 = 01000₈`**; сводка модуля:
  `ДИАП ЗАГР=00001-07672`, `ДЛИНА МОДЛ=00021₈`, `ДЛИНА ПРОГ=00205₈`,
  `ВХОДН=1`, `ВНЕШН=3`, `ЧИСЛО МЕТОК=104` (короткий вариант — `00134₈`,
  `ВНЕШН=2`, `МЕТОК=77`).
- Таблица внешних связей (`*EXECUTE`): `MBE60 01000`, `PRINT8 01205`,
  `*CM400* C 01243`, `*PAGE* C 02000`, `MON*ITOR 04000`, `PLREG E 04007`,
  `PLSLO E 04015`, `ASAVE* E 04023`, `SAVE*HID E 04030`, `F*ALL E 04045`,
  `OH* E 04047`, `OH*1 E 04054`, `ISO/GOST 04063`, `СВОБОД 04132`.

### 2.2 Трёхпроходный конвейер

```
МАКРОРЕДАКТОР (20.06.78)  →  МАКРОМАШИНА (1.11.78)  →  АРАП (04/78)
  таблица макроопределений     подстановка тела,          генерация слов,
  MACRO … MEND                 ИСП N → ГЕН N              *МЕТ*, листинг, модуль
```

Штампы проходов видны в `mbe60_bemsh_list.txt:15–25`:
`001332-КОЛИЧ ЯЧ ГС` (счётчик ячеек таблицы; 001320 в korot, 001330 в dtran,
001476 в TESTER). В прогонах без макросов (`dispak/tests/bemsh-ms/output.txt`)
штампы макроредактора/машины **отсутствуют** — проходы запускаются только при
наличии макроопределений/вызовов.

### 2.3 Макроопределения — «транслятор макроопределений»

Форма (исходник `mbe60_bemsh.txt`, листинг `mbe60_bemsh_list.txt:29–43`):

```
MACRO
∧L CALL ∧T        →  ∧L ПВО ∧T.(М15)
ПАМ 0
MEND
MACRO
∧L Э70 ∧T         →  ∧L КК '70',∧T
ПАМ 0
MEND
MACRO
∧L Э74 ∧T         →  ∧L КК '74',∧T
ПАМ 0
MEND
```

- `MACRO … MEND` — ограничители; `∧L` (метка), `∧T` (текст/операнд) — формальные
  параметры; `ПАМ 0` — конец описания (0 ячеек).
- `test_term_dks_bemsh_list.txt:19–55` добавляет макросы `ПВ`, `ПВО`, `Э50`,
  `Э53`, `Э64`, `Э71`, `Э74` «для удобства сравнения с МАДЛЕНОМ» — это
  обёртки над `ПВО` и `КК`, фиксирующие кодировку экстракодов 050–077.
- В листинге `ИСП N` = номер исходной строки (место вызова), `ГЕН N` =
  номер сгенерированной; расхождение указывает на развёрнутый макрос.
  Пример: `0118 CALL PRINT8` → `0121 Э74 0`, оба с `ИСП N = 0119`.
- `КК 26,'74000'` → `00 132 4000` (код 26₁₀ = 032₈) — генерация машинного слова.

### 2.4 Поток управления заданием (диалекты)

1. `re-dispak/testdks`: `INP$$$` → текст → `EOI$$$` → `TRN$$$` → `0-0` → `END$$$`.
2. `bemsh-ms / besm6-legacy`: `ВВД◇◇◇`, `ТРН◇◇◇`, `0-0`, `БЛМАК`, `БТМАЛФ`, `КНЦ◇◇◇`.
3. `re-siprod/tools/siprod_bemsh.py:415`: `шифр/трак/лент/ацп …` → `ВВД$$$^` →
   текст → `КВЧ$$$^` → `ТРН$$$^` → `ЧТКОМП420070` → `1-1` (запись модуля;
   `0-0` — только листинг) → `БТМАЛФ` → `ЗОНМОД…` → `КНЦ$$$^` → `_$ЕКОНЕЦ`.
   Подводный камень: без завершающего `^` первая строка исходника поглощается
   командой `ВВД`.

## 3. Как транслятор вызывает процедуры МС «ДУБНА»

Различать **два уровня** (в OCR-листингах латиница заменена омоглифами:
`CALL → САLL`, `YESMEMORY → УЕSМЕМОRУ`, `PRINT8 → РRINТ8`, `EXTRD → ЕХТRD`):

### 3.1 Уровень задания — карты монитора

```
*NAME
*      CALL UESMEMORY      ; вызов YESMEMOR из FICMEM* (GIVCALL*/MONCARD*)
*      SYSTEM              ; системная загрузка (адрес 0 и выше)
*MAIN MBE60
*BEMSH                     ; выбрать транслятор БЕМШ
*EXECUTE                   ; выполнение с сохранением обменного листа
*CALL DTRAN(MBE60)         ; в dtran-прогоне — вызов DTRAN /01.06.84/
```

Источники: `monitor80-re/docs/СПРАВОЧНИК_КОМАНДЫ.md:302,366–374,393`;
реализация — `monitor80-re/permanent/star%.masm:204–214` (`IDENT6`, `MAIN*`,
`GIVCALL*`), entry `YESMEMOR:` — `permanent/ficmem%.asm:17`.
`*CALL UESMEMORY` резервирует фиксированную память под задачу-транслятор.

### 3.2 Уровень машины — `EXTRD` + `CALL` → `ВЖМ (VJM)`, возврат `ПБ (М15)`

```
0017 PRINT8 EXTRD PRINT8                 ; extern declaration
‾00054 0118 0118   CALL PRINT8           ; макрос CALL → ПВО PRINT8.(М15), ПАМ 0
00531531 74001    13, VJM, PRINT8        ; дизассемблированный DTRAN-листинг
-      0022 00000  NOP                   ; адресное слово, заполняется загрузчиком
…      ПБ (М15)                          ; return по адресу в М15
```

- Макрос `CALL &T` разворачивается в `ВЖМ` с внешним символом и **адресом
  возврата в M15**; следующее слово `ПАМ 0` — зарезервированная ячейка.
- Внешний символ помечается `СА` в `*МЕТ*` (`PRINT8 00001СА`, `ВНЕШН=3`);
  загрузчик по `*EXECUTE` подставляет адрес (`PRINT8 01205`, `MON*ITOR 04000`).
- Параметры — не стек, а аккумулятор/индексные регистры M13–M16 и блоки
  вида `CALL VJ-60(НАЧ.АДР,ДЛИНА)` (`mbe60_bemsh_list.txt:302–309`).
- Другие процедуры: `PRINT80`, `ОКНО` (11 вызовов в TESTER),
  `PAGE/SM400`, `VJ-60`, `JUNKI(ADDR,LENG,N)`, `ARFA`.

**Итог:** МВЕ60 не содержит «своего» вызова ДУБНА как библиотеки — он работает
*внутри* Монитор-80 (построенного на МС ДУБНА): карты `*CALL/*SYSTEM`,
а внешние подпрограммы своего задания вызывает через `VJM + M15` с разрешением
адресов загрузчиком.

## 5. Детальный план дизассемблирования

### Фаза 0 — Подготовка (результат: конфигурация инструментов)

```bash
which disbesm6 besmtool dispak                 # /usr/local/bin/...
besmtool --help | head -20
disbesm6 -h 2>&1                                # [-r] [-b] [-aN] [-eN] [-nSymtab] file...
md5sum ~/.besm6/2348 /usr/local/share/besm6/2348 \
  ~/Yandex.Disk/simh/BESM6/MD/EC5061/2348
cp ~/Yandex.Disk/simh/BESM6/MD/EC5061/2348 /tmp/.private/azizz/2348-work   # эталон не трогать
```

Семантика ключей `disbesm6` (из `dispak/disbesm6/disbesm6.c`, **проверено на
установленном бинарнике**): `-a` loadaddr и `-e` entryaddr — **восьмеричные,
только слитная форма** (`-a10000`, не `-a 10000`); `-RN=x` задаёт начальное
значение регистра (1…017) для трассировки переходов; `-nfile` — таблица
символов формата `"%o %d %63s"` (адрес восьм., тип десятич.), где
**`1 = W_DATA`, `2 = W_CODE`** (2 создаёт точку входа). Ключи `-r` и `-b`
**инертны** (`prrel()` под `#if 0`, `bflag` не читается); `crc` не выводится.
Метки кода в установленном бинарнике — `A#####` (в authority-исходнике
`G#####`), данные — `D#####`. Первый байт вывода — UTF-8 BOM. `-e` обязателен:
без него весь код печатается как `конд`. Склейка зон не размечает границы —
дизассемблировать **по одной зоне**; предел `memory[32768]` слова.

### Фаза 1 — Инвентаризация (`docs/inventory.md`, `zones.src`)

```bash
besmtool view 2348 --start=0 --length=16 --encoding=k > docs/catalog_zone0000.txt
besmtool search 2348 'ТРАНСЛЯТОР' > docs/search_translator.txt
for s in 'МВЕ60' 'МАКРО-БЕМШ' 'ВЕР.06/78' 'ВЕР.12/77'; do besmtool search 2348 "$s"; done
echo '0055 4  ASM A/K ИТМ (.75)' > zones.src
echo '0137 33 MBE M/K БЕМШ 20.06.78' >> zones.src
echo '0537 33 MBE2 M/K БЕМШ .78' >> zones.src
# 1000-1037 НЕ включать: «МБ 2.0 ДЛЯ М3» — отдельная программа, не БЕМШ
```

Проверить «живые» зоны: `besmtool view 2348 --start=95 --length=1`,
`--start=127`, `--start=352`, `--start=383` (0537 = 351 пуста).
Подтвердить `МВЕ60` по текстовым константам в 0137 (буквально на диске не найдено).

### Фаза 2 — Извлечение (`gold/*.bin`, `manifest.sha256`)

Хелперы скопированы в `tools/` (исходники — `simh/BESM6/scripts/`).
**Внимание:** оригинальный `disbesm_extract.sh` содержит баг: он ожидал
**восьмеричный** номер зоны (`137`, `537`), а при вызове с десятичным (`95`,
`351`) молча извлекал другую зону. В `tools/disbesm_extract.sh` баг исправлен —
номер зоны задаётся восьмеричным (`137`, `537`), `8#$ZONE` → dec. Ниже
используем прямой `besmtool dump` с десятичными номерами (эквивалентно).

```bash
mkdir -p gold
for z in 45 46 47 48;  do besmtool dump 2348 --start=$z --length=1 \
    --to-file=gold/ASM-Z$(printf %04o $z)-L1.bin >/dev/null; done
for z in $(seq 95 127);  do besmtool dump 2348 --start=$z --length=1 \
    --to-file=gold/MBE-Z$(printf %04o $z)-L1.bin >/dev/null; done
for z in $(seq 352 383); do besmtool dump 2348 --start=$z --length=1 \
    --to-file=gold/MBE2-Z$(printf %04o $z)-L1.bin >/dev/null; done   # НЕ 351!
for f in gold/*.bin; do stat -c '%s %n' "$f"; done            # 6144 байт
(cd gold && sha256sum *.bin | sed 's|  |  gold/|') > manifest.sha256
sha256sum -c manifest.sha256
: > gold/MBE-full.bin
for z in $(seq 95 127); do cat gold/MBE-Z$(printf %04o $z)-L1.bin >> gold/MBE-full.bin; done
sha256sum gold/MBE-full.bin >> manifest.sha256                # 202752 байт
```

Инвентаризация зон (ненулевые байты, первое слово) выполнена: B = 0137…0177,
B2 = 0540…0577; зоны `aa aa aa…` — заполнение, не код; таблицы ошибок —
0146/0160/0163/0164/0167 (B) и 0546/0560/0563/0564/0567 (B2). Именования
зафиксировать в `AGENTS.md` (стиль re-dispak `G<зона>-L<длина>`).

### Фаза 3 — Дизассемблирование (`dis/*.asm`)

```bash
for f in gold/*.bin; do
  n=$(basename "$f" .bin)
  disbesm6 -a0 -e0 "$f" > "dis/$n.asm" 2> "dis/$n.err"
done
# после определения базы (из листинга: вход 01000₈, загрузка 00001-07672):
disbesm6 -a10000 -e10000 -nsym/MBE.tab gold/MBE-Z0137-L1.bin > dis/MBE-Z0137-named.asm
disbesm6 -a0 -e0 -R3=100 gold/MBE-Z0137-L1.bin > dis/MBE-Z0137-R3.asm
grep -hoE '\b[AG][0-9]{5}\b|\bD[0-9]{5}\b' dis/*.asm | sort -u > dis/labels.raw
```

**Важно:** `-a/-e/-R` — восьмеричные, **слитно** (`-R3=100`); `besmtool --start`
— `strtol(base=0)`. Первый прогон всегда `-a0 -e0`, затем подобрать базу по
`СТАРТ` (печатает `loadaddr`, а не entry). `-e` обязателен; `-r` бесполезен.
Метки кода — `A#####` (в исходнике `G#####`), данные — `D#####`; возможен
артефакт `A00003+34` из-за окна `fuzz=64`. `пб (М3)` обрывает трассировку —
лечится `-R3=<адрес>` и `-n` с `W_CODE` на входах. disbesm6 не знает макросов:
макро-сгенерированный код аннотировать вручную по `bemsh-analyzer`.

### Фаза 4 — Символы и вызовы (`sym/*.tab`, `analysis/calls.md`)

- Построить `sym/MBE.tab` в формате `01000 2 MBE60`, `01205 2 PRINT8`, `00050 1 -`, …
  (тип `2` = `W_CODE` — точка входа, `1` = `W_DATA`; `0` = `экв`, `-` = только пометить тип).
  ⚠ **Имена из `*МЕТ*`/`*EXECUTE` — логические/памятные адреса листинга.** Прямое
  совпадение слов листинга со словами дампа **не найдено** (0 совпадений из ~30
  характерных слов во всех 3 копиях) — см. `docs/ANCHORS.md`. В качестве
  физических якорей использовать только текстовые штампы (`0147.1315`,
  `0154.0751`, `0170.0216` и др.); не подставлять логические адреса как
  физические без доказательства.
- Обнаружить точки входа/переходы:
  ```bash
  grep -nE '\b(пб|пв|по|пе|цикл|выпр|э[0-7][0-7]|вжм)\b' dis/MBE-*.asm > analysis/branches.txt
  grep -nE 'увв|сда|счрж|конд' dis/MBE-*.asm > analysis/io.txt
  ```
- Скрипт `tools/xref.py` строит граф «адрес → цель», сверить с картой `*EXECUTE`

## 6. Риски и меры

| Риск | Мера |
|---|---|
| 8 байт/слово в образе vs 6 в disbesm6 | всегда `besmtool dump`, контроль 6144 байт/зону |
| `besmtool --start` = `strtol(base=0)` | `95 == 0137`; ведущий ноль = восьмеричное; хелпер ждёт восьмеричное (`137`) — баг исправлен в `tools/` |
| Неверная база / забытый `-e` | `-e` обязателен (иначе всё `конд`); сначала `-a0 -e0`, затем `-a/-e/-R`; `-r` **не работает** |
| Три разных файла 2348 с разными md5 | зафиксировать md5, выбрать через `BESM6_PATH`, работать с копией в `/tmp` |
| Зона 0537 пуста во всех копиях (`md_pos==0`) | данные B2 = 0540–0577; не «брать другую копию» |
| Самомодификация/перемещения | `-R<N>=<адр>` + `-n` с типом 2 (`W_CODE`); отдельный `analysis/reloc.md` |
| Метки `A#####` vs `G#####`, `D#####+N` | исходящий бинарник печатает `A#####`; `+N` — артефакт окна `fuzz=64`, не реальная ссылка |
| BOM в выводе, ANSI в отчётах | `sed -r 's/\x1B\[[0-9;]*m//g'`; не редактировать числовые поля |
| Макро-сгенерированный код | аннотировать по `bemsh-analyzer`, не править автокод |
| `МВЕ60` буквально не найден на диске | считать внутренним обозначением версии; не домысливать |
| Запись `1000–1037` (`.02.87`) | «МБ 2.0 ДЛЯ М3/М1» — отдельная программа, не БЕМШ; исключена из области анализа по уточнению заказчика |

## 7. Критерии успеха

1. Инвентарь зон 0055–0060, 0137–0177, 0540–0577 подтверждён каталогом и `view`.
2. Все дампы по 6144 байт, sha256 совпадают с `manifest`.
3. `dis/*.asm` — осмысленный БЕМШ с корректными `-a/-e/-R` и placeholder-загрузкой 01000₈.
4. `-nMBE.tab` даёт именованные метки (MBE60, PRINT8, MON*ITOR).
5. `disbesm_verify.sh` — 0 отличий эталон ↔ реконструкция.
6. Версии 06/78 и 12/77 сравнены, отличия классифицированы.
7. `Makefile` воспроизводит результат; реальные тома не изменены (md5 до/после).
