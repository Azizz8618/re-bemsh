Дата: 20.11.2026. Образ тома 2348 (read-only). Инструмент:
`tools/find_entries.py`. Ни один файл `bemsh/`, `dis/`, `gold/`,
`analysis/`, `docs/SEMANTIC/` не изменялся.

## 1. МЕТОДИКА

Различаются три класса точек входа:

| Роль | Что это | Источник |
|---|---|---|
| `PROG_ENTRY` | вход пользовательской программы | `ВХОДН=N` в сводке листинга + `*EXECUTE` |
| `ZONE_START` | `СТАРТ 1` зоны (локальный старт) | строка `Старт` каждого `.be` |
| `EXT_SYMBOL` | внешний символ, подставляемый загрузчиком | `*EXECUTE`, `*МЕТ*` |

Правила сканера (`tools/find_entries.py`):

1. **`.be`-файлы.** Ищутся директивы `СТАРТ`, `ВХОД`, `ВХОДН`,
   `ВХОДС`, `ВХОДБ` **только в коде** (строки комментариев
   начинаются с `*` и отбрасываются). Сканер также понимает
   `*ENTRY` и отдельно стоящее `ВХОДН=N` в листингах.
   Все 69 файлов содержат
   ровно одну директиву `СТАРТ 1` и **ни одной** директивы
   `ВХОД*` в коде — упоминания `ВХОД` в них встречаются
   только в комментариях-пояснениях макрокоманд.
2. **De facto entry.** Считаются входящие `CALL` (`ПВ`, `ПВО`,
   `ВЖМ`) на цели **внутри зоны** `0…1777₈`. Метка
   разрешается через `ЭКВ '...'` (значение восьмеричное);
   числовой операнд (`ПВ 17(М3)`) читается как десятичная
   печать восьмеричного адреса: `17` → `021₈`,
   `28` → `034₈`, `53` → `065₈` (AGENTS.md §2,
   PROCEDURES-ASM.md §10 п. 8). Цель с максимальным числом
   CALL и есть де-факто точка входа процедуры зоны.
   Косвенные CALL через `(Мn)` статически не считаются.
3. **Листинг МВЕ60.** Сводка разбирается как
   `НАМ=… ВХОДН=… ВНЕШН=…`; таблица `*EXECUTE` даёт
   адреса памяти; внешние ссылки `*МЕТ*` помечаются
   суффиксом `С` (`00001СА`, `00002СА`, `00003СА`).
   Омоглифы листинга (`РRINТ8`, `*СМ400*`, `*РАGЕ*`)
   нормализуются в `PRINT8`, `*CM400*`, `*PAGE*`.
4. **Адреса.** `sym/ENTRY.tab` пишется в формате
   `%o %d %63s` (AGENTS.md §3): адрес восьмеричный,
   тип `2 = W_CODE`, имя выравнивается вправо.
   Для 12 зон с доказанной картой памяти
   (analysis/MEMORY-MAP.md §5) указан **физический** адрес.
   Для остальных 57 зон физический адрес неизвестен:
   в таблице стоит локальный `0` с суффиксом `_LOCAL`
   в имени. Это не физический якорь.

Уверенность в колонке «де-факто»: `high` — ≥5 входящих
CALL внутри зоны или подтверждение каталогом
`PROCEDURES-{ASM,B,B2}.md`; `medium` — 2–4 CALL;
`low` — 1 CALL либо в зоне нет разрешимых CALL.

## 3. ПОЛЬЗОВАТЕЛЬСКАЯ ПРОГРАММА МВЕ60 (ТЕСТ ДКС)

Источник: `mbe60_bemsh_list.txt` (листинг) и
`mbe60_bemsh.txt` (исходник) из `re-dispak/testdks/`.

| Поле | Значение | Свидетельство |
|---|---|---|
| Имя модуля (`НАМ`) | `00001` | листинг, строка 366 |
| Вход (`ВХОДН`, логический) | `00001` | листинг, строка 366 |
| Вход в памяти | `01000₈` | `*EXECUTE`, строка 385: `МВЕ60 01000` |
| `ВНЕШН` | `3` | листинг, строка 366 |
| `ДЛИНА ПРОГ` | `00205₈` | листинг, строка 366 |
| `ЧИСЛО МЕТОК` | `00104` | листинг, строка 366 |
| Объявление в исходнике | `СТАРТ 1` | `mbe60_bemsh.txt:27`: `МВЕ60 старт 1` |

Сводка листинга, строка 366 (дословно):

```
МВЕ60 НАМ=00001 ДИАП ЗАГР=00001-07672 ДЛИНА МОДЛ=00021 ДЛИНА ПРОГ=00205 ВХОДН=00001 ВНЕШН=00003 ЧИСЛО МЕТОК=00104
```

### Внешние символы `*EXECUTE` (строки 383–390)

| Символ | Адрес памяти | Строка | Примечание |
|---|---|---|---|
| `MBE60` (МВЕ60) | `01000₈` | 385 | точка входа программы |
| `PRINT8` (РRINТ8) | `01205₈` | 386 | внешняя процедура печати |
| `PRINT80` (РRINТ80) | `01205₈` | 387 | эквивалент `PRINT8`, метка `E` |
| `*CM400*` (*СМ400*) | `01243₈` | 388 | внешняя память, метка `C` |
| `*PAGE*` (*РАGЕ*) | `02000₈` | 389 | внешняя память, метка `C` |
| `MON*ITOR` (МОN*IТОR) | `04000₈` | 390 | монитор ОС ДИСПАК |

Остальные символы тех же строк (`PLBEG E 04007`,
`PLCLO E 04015`, `ASAVE* E 04023`, `SAVE*HID E 04030`,
`FOR*ALL E 04045`, `OH* E 04047`, `OH*1 E 04054`,
`ISO/GOST 04063`, `СВОБОД 04132`) — системные символы
ОС, а не внешние ссылки модуля МВЕ60.

### Три внешние ссылки (`ВНЕШН=3`)

В `*МЕТ*` (строки 369–377) три символа несут суффикс
`СА`: `PRINT8 00001СА`, `CM400 00002СА`,
`PAGE 00003СА`. Это ровно `ВНЕШН=00003` из сводки.
Загрузчик подставляет адреса из `*EXECUTE`:
`PRINT8 → 01205₈`, `*CM400* → 01243₈`, `*PAGE* → 02000₈`.
Символ `MON*ITOR 04000` в `*МЕТ*` модуля не входит —
он используется системой.

### Почему это НЕ зоны транслятора

`MBE60` — **тестовая программа ДКС** (проверка записи
через ДКС, `ТЕСТ ЗАПИСИ ЧЕРЕЗ ДКС`), которую транслятор
`ТРАНСЛЯТОР С М/К БЕМШ ВЕР.06/78` только оттранслировал.
Её логический адрес `00001` соответствует **памяти**
`01000₈` по `*EXECUTE`, а не дисковому адресу зоны.
Штампы транслятора (`0147.1315`, `0152.1164`,
`0154.0751`) — физические якоря **другой** программы;
слова листинга МВЕ60 с ними сверять нельзя
(docs/ANCHORS.md §1, docs/PLAN.md §2.1).
Аналогично `02000₈` — это и `*PAGE*` из `*EXECUTE`, и
адрес загрузки зоны `0154` (analysis/MEMORY-MAP.md §5):
совпадение адресов не означает совпадение программ.

Карта памяти доказана только для 12 зон
(analysis/MEMORY-MAP.md §5), например:

| Зона | Адрес ОП | Доказательство |
|---|---|---|
| `0147` | `00000₈` | штамп `0147.1315` по адресу `01315₈` |
| `0154` | `02000₈` | 1024/1024 слов, breakpoint `02000` → первая команда зоны |
| `0155` | `04000₈` | 1024/1024 слова |
| `0156` | `06000₈` | 1024/1024 слова |
| `0161` | `24000₈` | 1024/1024 слова |
| `0162` | `26000₈` | 1024/1024 слова |

Для зоны `0154` это важное уточнение: `СТАРТ 1` задаёт
лишь локальный старт, а **истинный вход модуля** в
памяти — `02000₈`, подтверждённый точной побайтовой
сверкой и сработавшим breakpoint'ом. Поэтому колонка
«де-факто» (CALL-цели внутри зоны) и колонка
«объявленный вход» не отвечают на вопрос о физической
точке входа — её даёт только карта памяти.

Самые надёжные де-факто входы (совпадают с каталогами
процедур): `0056:0221₈` (8 CALL), `0147:0477₈` (10 CALL,
`OUT_PRINT`), `0547:0472₈` (10 CALL, `OUT_PRINT`),
`0551:1354₈` (8 CALL), `0057:0221₈` (5 CALL),
`0060:0220₈` (6 CALL).

## 5. `sym/ENTRY.tab`

Формат `%o %d %63s`, роли в именах:
`PROG_ENTRY` (1), `EXT_SYMBOL` (4), `ZONE_START` (69).
Всего 74 строки. Фрагмент:

```
0 2                                          Z0055_ZONE_START_LOCAL
0 2                                          Z0056_ZONE_START_LOCAL
0 2                                          Z0057_ZONE_START_LOCAL
1000 2                                                MBE60_PROG_ENTRY
1205 2                                               PRINT8_EXT_SYMBOL
2000 2                                                Z0154_ZONE_START
```

Строки `Z…_ZONE_START_LOCAL` (57 штук) используют локальный
адрес `0` и **не являются физическими адресами**.

## 6. ЧЕСТНЫЕ ОГОВОРКИ

1. В коде `.be` нет ни одной директивы `ВХОД`/`ВХОДН` —
   все 69 модулей реконструированы из дизассембля, где
   такие директивы не сохраняются. «Объявленный вход»
   в таблице — это `СТАРТ 1`, то есть старт зоны.
2. Счётчик CALL учитывает только цели, разрешимые через
   `ЭКВ` или числовой операнд. CALL через `(Мn)`,
   `выпр`, `'NNNNN'` и внешние адреса не считаются, поэтому
   числа в колонке «де-факто»，**как правило ниже**, чем
   в каталогах `PROCEDURES-*.md` (там учтены все вхождения
   в принудительных листингах).
3. Де-факто адреса — локальные (`-a0`), а не физические.
   Переносить их в симтабы как физические нельзя
   (AGENTS.md §3, XREF-METHODOLOGY.md §5).
4. Карта памяти снята в двух точках трассы; между ними
   возможны оверлеи. Для зон `0174/0175/0177` привязка
   к странице 35 неоднозначна.
5. `*EXECUTE` даёт адреса **памяти**, а не адреса зон
   диска. `01000₈` — вход МВЕ60, `02000₈` — `*PAGE*`,
   `04000₈` — `MON*ITOR` (docs/ANCHORS.md §1).
6. Листинг напечатан омоглифами (кириллица вместо
   латиницы): `РRINТ8` = `PRINT8`, `*СМ400*` = `*CM400*`,
   `*РАGЕ*` = `*PAGE*`, `МОN*IТОR` = `MON*ITOR`.
7. `PRINT80 E 01205` — эквивалент `PRINT8`, а не
   отдельная внешняя ссылка; `ВНЕШН=3` подтверждает,
   что внешних ссылок ровно три.
8. Ни один эталонный образ, дамп `gold/`, листинг `dis/`
   или `.be`-файл не изменялся. Записаны только
   `docs/ENTRY-POINTS.md`, `sym/ENTRY.tab`,
   `tools/find_entries.py`, `tools/tests/test_find_entries.py`.
