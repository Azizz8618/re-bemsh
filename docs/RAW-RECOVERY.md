
`/tmp/.private/azizz/raw-recovery/mkcand.py` (замена выбранных слов на

## Ключевая находка: лимит длины строки транслятора

Строка исходника длиной **80 символов** вызывает перенос хвоста комментария
в следующую строку; транслятор трактует её как пустую операцию и выдаёт
`ОПЕРАЦИИ НЕТ` по следующему сгенерированному адресу. Строки длиной 78
символов собираются нормально (пример — `bemsh/MBE-Z0174.be`, 77 символов
с тем же видом комментария).

Признак в листинге (кавычки`’` — GOSTR-представление транслятора):

```
                        ‾01363                   0867  0796
OПEPAЦИИ HET            ‾01363                   0867 +0796+***** //////
```

То есть ошибка относится **не** к мнемонике, а к длине строки. Лечение —
сократить комментарий после запятой (например, убрать `-> адр. NNNN`,
оставив `(автометка DNNNNN)`). Машинное слово при этом не меняется.

Альтернатива, тоже проверенная для 0176: записать операнд пятизначным
(`'1250'` → `'01250'`); собирается в тот же 24-битный код. Выбран вариант
с сокращением комментария — он сохраняет исходную мнемонику и операнд.

## Зона 0176 (B)

**Диагноз.** Одна ошибка транслятора `ОПЕРАЦИИ НЕТ` по адресу `01363₈`
(слово `1362₈`). Число ошибок до правки: `ЧИCЛO OШИБOK=0001`.
 Bisection: замена слов 1361 и 1362 на `КОНД` убирала ошибку; замена только
слова 1361 убирала её полностью. Причина — строка 806 (.be) длиной ровно
80 символов:

```
        НТЖ  '1250'(М4) ,слово 1361, прав. часть (автометка D01315 -> адр. 1250)
```

**Замена (до → после):**

```
-        НТЖ  '1250'(М4) ,слово 1361, прав. часть (автометка D01315 -> адр. 1250)
+        НТЖ  '1250'(М4) ,слово 1361, прав. часть (автометка D01315)
```

Длина строки стала 68 символов. Операнд и мнемоника не тронуты.

**Результат:** `ДЛИHA ПPOГ=02000`, `ЧИCЛO OШИБOK=0000`,
`WORDS: всего=1024 совпало=1024 различий=0`, `RESULT: PASS`.

## Зона 0545 (MBE2)

**Диагноз.** Три ошибки `ОПЕРАЦИИ НЕТ` по адресам `01326₈`, `01370₈`,
`01373₈` (`ЧИCЛO OШИБOK=0003`). Все три строки имели длину 80 символов
(слова 1323, 1365, 1370) — тот же перенос комментария.

Дополнительно, после устранения ошибок сборка давала `ДЛИHA ПPOГ=02001`
и сдвиг всего модуля на полслова: слово 0 собралось как `ЗП + 00 22`.
Причина: `ПВ` в левой половине (`call`-тип, FIG. `is_right_half_only()`),
транслятор вставляет служебное слово `00 22`. `dis2be.py` должен был
вывести это слово сырым `КОНД`, но `raw_word_from_halves()` вернул `None`,
потому что колонка бит листинга содержит префикс `:` (`:16 31 01322`).

**Замены (до → после):**

```
-        ПВ   '1322'(М16),слово 0, лев. часть (адр. 1322)
-        РЖ   '26'       ,слово 0, прав. часть (автометка D00024 -> адр. 26)
+        КОНД В'7310132200270026'    ,слово 0 (ПВ слева)
```

```
-        ВЧАБ '2000'     ,слово 1323, прав. часть (автометка D01777 -> адр. 2000)
+        ВЧАБ '2000'     ,слово 1323, прав. часть (автометка D01777)
-        ЗП   '2001'     ,слово 1365, прав. часть (автометка D01777 -> адр. 2001)
+        ЗП   '2001'     ,слово 1365, прав. часть (автометка D01777)
-        ЗП   '2000'     ,слово 1370, прав. часть (автометка D01777 -> адр. 2000)
+        ЗП   '2000'     ,слово 1370, прав. часть (автометка D01777)
```

Проверенная, но отвергнутая альтернатива: `'2000'` → `'02000'` убирает
`ОПЕРАЦИИ НЕТ`, но при трёх таких заменах снова даёт `ДЛИHA ПPOГ=02001`.

**Результат:** `ДЛИHA ПPOГ=02000`, `ЧИCЛO OШИБOK=0000`,
`WORDS: всего=1024 совпало=1024 различий=0`, `RESULT: PASS`.

**Остаток:** 1 слово (0) оставлено `КОНД`. Причина — описанный выше дефект
`raw_word_from_halves()` на префиксе `:`; обход в `dis2be.py` запрещён
условиями задачи. Остальные 1023 слова — команды/данные с семантикой.

## Зона 0556 (MBE2)

**Диагноз.** Трансляторных ошибок нет (`ЧИCЛO OШИБOK=0000`), но
`WORDS: всего=1024 совпало=1022 различий=2`: расходятся слова `12₈` и
`14₈`.

* Слово `14₈`: листинг `_УИ М2(М12)_` собирался в `12 040 0002`
  (адрес `0002₈` вместо `2142₈`): числитель `М2` трактуется как номер
  регистра, а не как адрес. Достаточно явно задать адрес.
* Слово `12₈`: листинг `_УИ М12(М7)_` собирался в `07 040 0012`, эталон
  требует `07 140 6552` (поле операции `140₈`). Полный перебор всех 75
  мнемоник таблицы `OPS` (скрипт `probe.py`, все кандидаты в одном ребилде)
  не дал ни одной сборки с полем `140₈`: максимальное поле — `077₈`.
  `ЭКВ`, явные адреса и двойные `(Мn)` также не помогли.

**Замены (до → после):**

```
-        УИ   М2(М12)    ,слово 14, прав. часть
+        УИ   '2142'(М12) ,слово 14, прав. часть
```

```
-        ЗП   '242'      ,слово 12, лев. часть (адр. 242)
-        УИ   М12(М7)    ,слово 12, прав. часть
+        КОНД В'0000024235406552'    ,слово 12 (УИ: опкод 140 вне таблицы)
```

**Результат:** `ДЛИHA ПPOГ=02000`, `ЧИCЛO OШИБOK=0000`,
`WORDS: всего=1024 совпало=1024 различий=0`, `RESULT: PASS`.

**Остаток:** 1 слово (12₈) оставлено `КОНД`. Блокер зафиксирован: поле
операции `140₈` не воспроизводится ни одной мнемоникой `OPS` 06/78;
 disbesm6 печатает её как `уи`, но транслятор такой opcode не порождает.
