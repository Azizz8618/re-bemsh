# `dis2be` — конвертер листингов `disbesm6` в исходники БЕМШ

`tools/dis2be.py` превращает листинг `disbesm6 -a0 -e0` в собираемый
исходник ИПМ МАКРО-БЕМШ ВЕР.06/78 (`.be`). Фаза A1 плана
`docs/PLAN-NEXT.md`. Эталон регрессии — `bemsh/MBE-Z0137.be`
(см. `docs/REBUILD-0137.md`).

## 1. CLI

```bash
python3 tools/dis2be.py \
  --input dis/MBE-Z0137-L1.asm \
  --output /tmp/.private/azizz/dis2be-test/MBE-Z0137.be \
  [--zone 0137]
```

| Флаг | Назначение |
|---|---|
| `--input` | обязательный; листинг `dis/MBE-Z<зона>-L1.asm` (кодировка UTF-8 с BOM — BOM снимается) |
| `--output` | выходной `.be`; если не задан — `bemsh/<имя входа без .asm>.be` |
| `--zone` | номер зоны восьмеричным; по умолчанию извлекается из имени входа (`MBE-Z0137-L1.asm` → `0137`) |

⚠ По правилам репозитория **опытные выходы пишутся только в `/tmp`**
(например, `/tmp/.private/azizz/dis2be-test/`). Путь по умолчанию
остаётся `bemsh/…`, но при экспериментах его нужно явно переопределить.

Номер зоны сохраняется в шапке (`MBE-Z0137`, `* … зоны 0137₈`,
`Z0137   СТАРТ 1`, `gold/MBE-Z0137-L1.bin`,
`tools/rebuild-0137.sh`) — это важно для побайтовой регрессии.
Количество слов и байт в шапке вычисляется из листинга (1024 и 6144).

## 2. Правила преобразования

| Листинг disbesm6 | Строка(и) `.be` | Пояснение |
|---|---|---|
| `зп START` (лев. половина) | `ЗП` | `START` = адрес 0 → операнд не печатается |
| `зп '70000'` (прав. половина) | `ЗП   '70000'` | восьмеричная константа сохраняется |
| `сбр START` | `СБР` | нулевой адрес опущен |
| `рег '3554'` | `РЕГ  '3554'` | константа `'…'` сохраняется |
| `пб (М3)` | `ПБ   (М3)` | индекс `(Мn)` сохраняется как есть |
| `зп D00003` | `ЗП   '3'` + `, … (адр. 3)` | символ данных → `'восьм'` |
| `конд в'0000000000021173'` | `КОНД В'0000000000021173'` | 16 окт. цифр |
| `конд п'00000D'` | `КОНД В'0000000000000077'` | берётся **сырое слово** из 2-й колонки; GOSTR-символы (`D`, `F`, `G`, …) не попадают в `.be` — они дали бы `ЧУЖОЙ СИМВОЛ` |
| `пам 1` | `КОНД В'0000000000000000'` | нулевое слово |
| `ФИНИШ` | `        ФИНИШ` | отступ 8 пробелов как в эталоне |

Дополнительно:

* 48-битное слово печатается disbesm6 **двумя строками**; конвертер
  объединяет их по полю адреса (левая строка имеет адрес в первых
  5 колонках, правая — пробелы) и выпускает **две строки `.be`**:
  `,слово N, лев. часть` и `,слово N, прав. часть`.
* Выравнивание повторяет эталон: мнемоника — поле шириной 5,
  операнд — до запятой в колонке 24 (без операнда — колонка 23),
  `КОНД` — запятая в колонке 36.
* `В'…'` в МАКРО-БЕМШ — **восьмеричная** константа. Шестнадцатиричные
  цифры `8`, `9`, `A`–`F` внутри `В'` недопустимы.

## 3. Таблица `OPS`

Библиотека не копируется: `tools/dis2be.py` добавляет
`~/Yandex.Disk/re-siprod/tools` в `sys.path` и импортирует
`OPS`, `OPCODE_BY_NAME` из `siprod_asm.py`.

`OPS` — список кортежей `(мнемоника, код, маска, тип операнда)`,
полностью соответствующий таблице разбора `disbesm6.c`. Типы:
`str1`, `imm`, `imm64`, `reg1`, `reg2`, `addrmod`, `branch`, `jump`,
`call`, `iret`, `imm2`, `immex`, `addrex`, `stop`, `illegal`.
На зоне 0137 реально встречаются лишь четыре мнемоники:
`зп`/`сбр`/`рег` (STR1/IMM) и `пб` (JUMP).

Использование в конвертере:

1. канонизация мнемоники к верхнему регистру (`зп` → `ЗП`,
   `Э66` → `Э66`) через множество имён из `OPS`;
2. предупреждение на stderr, если мнемоника листинга отсутствует
   в таблице (операнд при этом переносится как есть).

## 5. Известные ограничения

1. **Код/данные после `пб (М3)`.** disbesm6 обрывает трассировку на
   `пб (М3)` (слово 4 зоны 0137) и печатает слова 5–1023 как `конд`.
   Конвертер честно сохраняет их как `КОНД` — семантика команд
   **не восстанавливается**. Для разделения нужны таблица точек входа
   (`-n` с типом 2 = `W_CODE`) и/или `-R3=<адрес>`; это работа Фазы A3.
2. **Макрорасширенный код.** `CALL → ВЖМ + ПАМ 0` (адрес возврата
   в M15) и экстракоды `Э50`–`Э77` разворачиваются транслятором. По
   бинарнику нельзя восстановить вызовы макросов — доступен только
   результат их раскрытия, который и копируется как `КОНД`/команды.
3. **Перемещаемые (relocation) слова.** В режиме записи `1-1`
   транслятор вставляет записи перемещений (например, после
   `конд 6400000000000000` — два слова `00000fffff00 004000000001`),
   поэтому дамп записанной зоны не идёт побайтово с эталоном.
   Конвертер ориентирован на листинг `0-0`, где таких записей нет;
   relocate-слова кодируются как обычные `КОНД`.
4. **Подавленная правая половина.** disbesm6 не печатает правую
   половину при `W_NORIGHT`, нуле или `02200000`. Тогда для слова
   получится только одна строка `.be` — нужно проверять число слов
   после конвертации (в зоне 0137 такой ситуации нет).
5. **GOSTR-представление теряется.** `конд п'…'` заменяется на сырое
   восьмеричное слово: объектный код сохраняется, но текстовый вид
   данных (GOST-символы) не восстанавливается.
6. **Шапка стилизована под эталон 0137.** Формулировки
   «Слова 0-4 — команды», `rebuild-<зона>.sh` и т. п. вычисляются,
   но для зон с иным числом командных слов могут быть неточными;
   на машинный код они не влияют (это комментарии).
7. **Неизвестные мнемоники.** Операнд переносится дословно и печатается
   предупреждение; корректность сборки для таких слов гарантировать
   нельзя.
