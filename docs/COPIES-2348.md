# Три копии тома 2348 в окружении

Все три файла имеют размер **33 024 000 байт** (4000 зон × 8256 байт в
«сыром» chained-образе), но **разные md5** — это независимые рабочие копии
одного пакета Д-2048/2348, по-разному изменённые разными проектами.

| Путь | md5 | mtime | Роль по смежным проектам |
|---|---|---|---|
| `/usr/local/share/besm6/2348` | `b4429a6cb69287309c974fb91a1c8942` | 2026-11-19 16:31 | «боевая» копия; выбирается **по умолчанию** (`BESM6_PATH=/usr/local/share/besm6`) |
| `/home/azizz/.besm6/2348` | **не фиксируется** (19.11.2026: `29987d5…` → `f5618ae2…` → `2fc13cb8…`) | меняется | локальная **рабочая** копия пользователя; по уточнению заказчика изменение md5 нормально |
| `/home/azizz/Yandex.Disk/simh/BESM6/MD/EC5061/2348` | `15e5a52c5efe7b62c53f3bbb335e16cc` | 2026-10-25 20:24 | копия в каталоге образов SIMH (`EC5061`), используется как «эталон» в части проектов |

Другие копии/бэкапы существуют в `~/Yandex.Disk/besm-crypto/{work,backups}`,
`~/Yandex.Disk/rezerv/BESM6_rez/MD/EC5061`, `/home/azizz/besm6/2348`,
`~/Yandex.Disk/dispak/tests/disks/2348.xz` — в анализ не включались.

## Что общего

Каталог (зона 0) в `/usr/local/share` и `~/.besm6` содержит
``ПAKET Д-2048 ДЛЯ K-71 (04.05.85-10.12.91)``; в копии EC5061 зона 0 записана
как `UUUUUU…`, но `besmtool` находит зоны через chained-таблицу `md_pos`,
поэтому `search`/`dump` работают и там.

`besmtool search 2348 'МАКРО-БЕМШ'` во всех трёх копиях даёт одинаковые
штампы `0147.1315 ВЕР.06/78` и `0547.1315 ВАР.12/77`.

**Зоны транслятора побайтово идентичны во всех трёх копиях:** конкатенация
дампов зон `0137–0177₈` (dec 95–127) имеет один и тот же md5
`2f503f5b8f8fb6ad12632fed6f8cf17f` для каждой копии. То есть для нашей задачи
разница между файлами несущественна.

## Чем отличаются

Различаются **рабочие зоны**, куда разные проекты записывали свои библиотеки:

| Зона (восьм.) | `/usr/local/share` | `~/.besm6` | `EC5061` |
|---|---|---|---|
| `02000` (dec 1024) | данные A | данные A | данные B |
| `02100` (dec 1088) | данные | пусто | пусто |
| `03000` (dec 1536) | данные A | данные B | данные C |
| `04000` (dec 2048) | пусто | данные | пусто |
| `05000` (dec 2560) | пусто | пусто | данные |

(«A/B/C» — разные md5 6144-байтовых дампов; `ff1ce201…` = пустая зона.)

Это следствие записи PERSO-библиотек: Pascal (`02000`), СИПРОД+DRAKON
(`02100`), GOSTLIB (`02560`), пользовательские библиотеки.
`DISK2348.md` из `re-dispak` и `FINAL_STATUS.md` из `besm-crypto` описывают
иные состояния тома — поэтому домысливать по ним нельзя.

## Практический вывод

1. Перед работой зафиксировать `md5sum` выбранного файла в
   `verify/image-md5.before.txt` и `verify/image-md5.after.txt`.
2. Выбор файла делается переменной `BESM6_PATH` (отдельного `--disk-path` у
   `besmtool` нет); приоритет — первый доступный каталог в списке.
3. Для извлечения зон транслятора можно взять любую копию — результат
   совпадает. Рекомендуем оставить значение по умолчанию
   (`/usr/local/share/besm6`) и записать его в `AGENTS.md`.
   `~/.besm6/2348` — **рабочий (изменяемый) диск**, его md5 может меняться;
   не использовать как неизменный эталон.
4. Образы **не изменять** (только read-only `dump`/`view`/`search`).
