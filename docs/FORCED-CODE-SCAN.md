Дата: 20.11.2026. Инструмент: `tools/force_code_scan.py`.
Образ: `gold/*-Z<зона>-L1.bin` (только чтение, sha256 сверен с `manifest.sha256`),
оригинальные листинги `dis/*-L1.asm`, эталон `disbesm6` md5
`f40ca3e302c45a5d650d849eb5db2882`. Таблица OPS берётся из
`/home/azizz/Yandex.Disk/re-siprod/tools/siprod_asm.py`.
Методика доказана на зонах 0055–0060 (`docs/SEMANTIC/ASM-CODE-RECOVERY.md`)
и здесь применена ко всем 69 зонам без исключения.

## 1. Краткий итог

```
summary: ALREADY-CODE=2, CODE=43, DATA=8, FILL=10, MIXED=6
need doc fix (11): 0140 0142 0143 0150 0151 0153 0166 0172 0173 0553 0573
```

Классы: **CODE 43** (были почти сплошь `конд`, принудительная разметка
вскрыла код), **MIXED 6**, **FILL 10**, **DATA 8**, **ALREADY-CODE 2**.

Подтверждено: зоны `0146/0160/0163/0164/0167` (B) и
`0546/0560/0563/0564/0567` (B2) классифицируются **FILL**, а не CODE.
Все десять дают 100.0% «валидных» половин, 3 уникальных слова и
`слиа:1024, вчп:1022, по:2` — это шахматный fill `AA/55`, а не программа.

Зоны, где семантический документ всё ещё описывает модуль как
«таблицы / забелы / N код-слов» и которые кандидатуют на ту же правку,
что и 0055–0060 (колонка «doc fix?» = YES), — список из итога выше.
Это **сигнал к ручной проверке**, а не готовый вывод: документы
`docs/SEMANTIC/` здесь не изменялись, а колонка вычисляется динамически
(перезапуск инструмента обновляет её по текущему тексту документа).

## 2. Методика

1. **Декодирование половин.** Каждое 48-битное слово читается big-endian
   и режется на две 24-битные половины. Обе подаются в
   `siprod_asm.decode()`; половина считается валидной, если
   `decode()['name'] is not None and kind != 'illegal'`, то есть opcode
   найден в таблице `OPS`. `valid% = valid / 2048 * 100`.
2. **Обнаружение FILL** — отдельно, см. §3: декодируемость сама по себе
   fill от кода не отличает.
3. **Принудительная разметка.** Для каждой не-fill зоны во временном
   симтабе пишутся 1024 строки `%o 2 -` (адреса 0…01777₈, тип `2` =
   `W_CODE`, имя `-` = только пометить тип). Затем
   `disbesm6 -a0 -e0 -n<симтаб> <gold.bin>`; вывод сохраняется в
   `dis-forced/Z<зона>.asm`. С `-e0` (обязательно) и `-a0` адреса
   листинга совпадают со смещениями слов зоны.
   Сравниваются: число строк с `конд` и число строк с мнемоникой из
   `OPS` до (оригинал `-a0 -e0`) и после (forced) разметки.
   Полный симтаб на 0…01777₈ — допустимая замена диапазону
   decimal 6…1543 из `ASM-CODE-RECOVERY.md §2.1`: он дополнительно
   вскрывает zero-fill хвост, поэтому `конд` после становится 0, а не 0–4.
4. **Классификация** (порядок правил важен):

   | правило | класс |
   |---|---|
   | `fill% >= 95` и уникальных слов `<= 8` | FILL |
   | уникальных слов `<= 8` **или** (`top-mnemonic >= 70%`, flow `< 150`, CALL `<= 30`) | DATA |
   | `конд` в оригинале `< 50%` | ALREADY-CODE |
   | `конд` в оригинале `>= 85%` | CODE |
   | иначе (50–85%) | MIXED |

   `flow` = сумма `пв/пб/по/пе/пио/пино/пио36/цикл/выпр/стоп/Э74`
   в forced-листинге; `top-mnemonic` — доля самой частой мнемоники.
   DATA-правило отделяет таблицы/заполнители: их forced-листинг
   почти целиком состоит из одной команды (`зп`/`слиа`) и не содержит
   осмысленного управления. CODE/MIXED имеют 250–580 flow-команд
   и десятки CALL.

## 3. Правило обнаружения шахматного FILL

Признаки (все одновременно):

* 24-битные половины принимают только значения `0xAAAAAA`,
  `0x555555` и `0xDB6DB6` (терминатор со сдвигом фазы «110»);
* такие половины составляют `>= 95%` от 2048;
* число различных 48-битных слов `<= 8` (фактически 3).

Почему это НЕ код: каждая из трёх половин — законная команда
(`0xAAAAAA` → `слиа '25252'(М12)`, `0x555555` → `вчп '72525'(М5)`,
`0xDB6DB6` → `по '66666'(М15)`), поэтому `valid% = 100` и forced-листинг
даёт 2048 «инструкций». Решают **байтовый паттерн** и отсутствие
какой-либо структуры: flow = 2, CALL = 0, только 3 мнемоники.
См. `docs/SEMANTIC/Z0167.md`, `Z0567.md`, `REGISTERS.md §3`
(псевдо-М5/М12). Оригинальный листинг этих зон тоже не содержит
`конд` (0 строк) — ещё одно подтверждение, что «нет `конд`» не равнозначно
«есть код».

## 5. Честные оговорки

1. **Декодируемость не доказывает исполнение.** 97–100% половин дают имя
   из `OPS` почти в каждой зоне, включая fill и чистые таблицы. Forced-листинг
   всегда содержит около 2000 «команд» — это свойство методики, а не
   доказательство кода. Решают байтовые паттерны и независимые свидетельства:
   пары CALL/RET, GOST-штампы, CROSSREF, следы исполнения в ОП.
2. **Байтовый паттерн важнее мнемоники.** `AA/55` и нули decode как
   `слиа/вчп/по` и `зп`, но это данные. Таблицы с одним повторяющимся
   словом (0174/0175/0556/0574/0575/0577) тоже попали в class DATA,
   хотя их forced-листинг полон «инструкций».
3. **Класс CODE — это «был ошибочно помечен как данные», а не приговор
   о семантике.** Внутри CODE-зон есть вкрапления таблиц и констант
   (например, пулы масок 0055); в MIXED-зонах (0171–0173, 0172, 0572, 0573)
   код соседствует с ГОСТ-текстами.
4. **Артефакты forced-симтаба.** Метки `A#####`/`D#####`,
   `* next insn used as data`, `пам` и `конк` — следствие принудительной
   достижимости и подавленной правой половины, а не реальные ячейки
   двойного назначения (`ASM-CODE-RECOVERY.md §5`).
5. **Границы зон.** Листинг каждой зоны строится отдельно (6144 байт),
   склейка не размечает границы; адреса восьмеричные при `-a0`.
6. **Колонка «doc fix?» — эвристика** по тексту §1 семантического документа
   с исключением документов, где правка уже внесена (признак
   «принудительн…» / «как W_CODE»). Она требует ручной проверки;
   `docs/SEMANTIC/*` этим инструментом не изменяются.

## 6. Воспроизведение

```bash
cd /tmp/.private/azizz/re-bemsh
python3 tools/force_code_scan.py --all                    # таблица + 49 листингов
python3 tools/force_code_scan.py --all --markdown          # таблица в Markdown
python3 tools/force_code_scan.py --zone 0146 --no-listings # одна зона, без записи
sha256sum -c manifest.sha256                              # эталон не тронут
```

Симтаб создаётся во временном каталоге и удаляется; образы `gold/`
открываются только на чтение. Разрешённые пути записи:
`tools/force_code_scan.py`, `docs/FORCED-CODE-SCAN.md`,
`dis-forced/Z*.asm`. Листинги записаны для всех зон классов CODE и MIXED
(49 файлов); для FILL/DATA/ALREADY-CODE метрики посчитаны, но файлы
не создаются, чтобы не выдавать данные за код.
