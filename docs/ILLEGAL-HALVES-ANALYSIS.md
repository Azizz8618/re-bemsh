## 1. МЕТОДИКА

1. Слово читается из `gold/MBE-Z0137-L1.bin` как 6 байт
   big-endian (`int.from_bytes`), адрес = индекс слова в
   восьмеричной записи. Эталон не менялся.
2. 24-битная половина разбирается по полям
   (`REG-INSTRUCTION.md:14-30`, `siprod_asm.py:100-117`):
   `reg` = биты 23-20, DMS = 21, структура = 19,
   EXP = 18, КОП = 17-12, адрес = 11-0.
3. Таблицы сравнения: `disbesm6.c:45-128`,
   `siprod_asm.py:41-80`, `optab.c:61`,
   `simh/BESM6/besm6_cpu.c:1485`.
4. Проверка KOI-7 (read-only):
   `besmtool view 2348 --start=0137 --length=1`
   `--encoding=k` → строка
   `0137.0060: ЗПM``CЧM``CЛ``BЧ``BЧOБ``BЧAБ``CЧ``И`.
5. Сканер: `python3 tools/illegal_halves_scan.py`

## 2. ПОЧЕМУ `siprod_asm.decode()` ДАЁТ `None`

`lookup()` (`siprod_asm.py:92-97`) ищет
`half & mask == code` в списке `OPS` (`siprod_asm.py:41-80`)
и при промахе
возвращает `(None, 0, 0, "illegal")`.

Код 047 (`0x027000`) в `OPS` отсутствует. В исходнике
эталонного дизассемблера он **есть, но закомментирован**:

    disbesm6.c:83   /*  { "Э46", 0x026000, ..., BASIC },
    disbesm6.c:84      { "Э47", 0x027000, ..., BASIC },*/
    (цитата исходника; КОП 047 = x47, priv, не ЭК)

Другие таблицы код знают:

- `optab.c:61`: `{"x47", priv, 0, F_PRIV}, /* 047 */`;
- `besm6_cpu.c:1485`: `case 047: /* э47, x47 */`,
  привилегированная команда `M[Aex&17] += Aex`
  (ст. 1487-1491).

**Вывод.** `None` означает только «нет мнемоники в таблице
декодера». Это не доказательство того, что слово не
команда, и не признак EXP-адреса. КОП 047 (x47) -
подлинная привилегированная команда (PRIV), а НЕ
пользовательский экстракод; в наших словах она не
исполняется: слова являются данными (см. §4).

## 4. ВЕРДИКТЫ ПО ЧЕТЫРЁМ СЛОВАМ

### 4.1. `2067711510002003` (0061, строка 503)

Левая половина : подлинная команда Э67 (`disbesm6.c:100`,
`0x037000`, `OPCODE_ADDREX`). Но слово входит в KOI-7
таблицу мнемоник и в `dis/MBE-Z0137-L1.asm:63` напечатано
`конд`. Отчёт `B-KOND-DECODE-1.md:73` помечает его
«пропуск: L: only-right (авто-мода)»;
`Z0137-KOND-FULL-SWEEP.md:67` : «КОНД (left ADDREX), НЕТ».

**Вердикт: DATA** (KOI-7 «СЧМ» + атрибуты `20 04 03`).
EXP = 0, значит `'7115'` : не EXP-адрес.
Представление: **оставить `КОНД В'...'` как есть**, байты
`43 7e 4d 20 04 03` сохраняются. Разбиение на
`Э67 '7115'(М4)` / `ЗП '2003'(М2)` даёт те же биты, но
авто-мода слева делает его небезопасным по правилу
`EXTRACT-74-66-DECODE-FIX.md:62-70`; пересборка сдвигает
код. Подтверждено 4 копиями: 0141:1614, 0142:1742,
0143:1223, B2 0540:0467.

### 4.2. `2047704010010005` (0063, строка 506)

**Вердикт: DATA** (KOI-7 «ВЧ» + атрибуты `20 10 05`).
	reg=4, EXP=0, КОП=047, младшие 12 бит = 7040.
`'7040'` : не EXP-адрес и не аргумент x47 (КОП 047): это три
KOI-7-байта `42 7e 20`, где `0x20` : дополняющий пробел
до 4 знаков. В `MBE2-Z0540.be:1001` слово уже помечено
«левая illegal, ЗПМ»; в `dis-forced/Z0540.asm:634`
напечатано `конк в'20477040'` (старшая половина).

### 4.3. `2047711730410006` (0064, строка 507)

**Вердикт: DATA** (KOI-7 «ВЧОБ» + атрибуты `10 06`).
Байты `42 7e 4f 62 10 06`: `4f` = KOI-7 «О», `62` = «Б»
в правой половине. EXP = 0; `'7117'` : не EXP-адрес.
Оставлено `КОНД` в `MBE2-Z0540.be:1002`.

### 4.4. `2047710130410007` (0065, строка 508)

**Вердикт: DATA** (KOI-7 «ВЧАБ» + атрибуты `10 07`).
Байты `42 7e 41 62 10 07`: `41` = KOI-7 «А», `62` = «Б».
EXP = 0; `'7101'` : не EXP-адрес. Оставлено `КОНД` в
`MBE2-Z0540.be:1003`.

Все четыре слова : **НЕ EXP-ADDRESS**: бит 18 сброшен, а
префикс `7` в `70xx` принадлежит байтам текста KOI-7.

## 5. ЧТО ТАКОЕ ШАБЛОН `2047 70xx`

Сканер `tools/illegal_halves_scan.py` находит 1277 слов с
`name=None` слева; группа `2047xxxx` содержит 35 слов.
Все 35 имеют `KOI7 in {ВЧ, ВЧОБ, ВЧАБ}` и `EXP=0`
(тест `test_group_2047_is_all_koi7`).

Разбор префикса:

- `2047` = reg 4, КОП 047, EXP=0 (старшие 12 бит слова);
- `70xx` = байты KOI-7 `42 7e 20` (ВЧ + пробел),
  `42 7e 4f` (ВЧО) или `42 7e 41` (ВЧА), плюс
  атрибутный байт правой половины (`0x62` = «Б»).

Это НЕ экстракод с расширенным адресом и НЕ «неизвестная
операция». Код 047 (x47) реален только в таблицах ЦП
(`optab.c:61`, `besm6_cpu.c:1485`), а здесь он :
совпадение битов текста KOI-7 с битами команды.
Группа `2067xxxx` в scanner по умолчанию отсутствует:
Э67 есть в `OPS`, поэтому `name != None`; её видно
режимом `--all` (тест `test_all_mode_includes_e67`).

## 6. ДВЕ УЖЕ РАЗБИТЫЕ СТРОКИ (0062, строки 504-505)

`Э66 '6040'(М4)` / `ЗПМ '4'(М2)` : разбиение слова
`2066604010010004`.

Побайтовая проверка (`test_split_lines_are_byte_identical`):

    Э66 '6040'(М4) -> 24 бита 0o20666040 = 43 6c 20
    ЗПМ '4'(М2)    -> 24 бита 0o10010004 = 20 10 04
    конкатенация   = 43 6c 20 20 10 04 = gold 0137:0062

**Байты точны.** Обе половины кодируются так же, как в
эталоне; реальная пересборка зоны в этой задаче
не выполнялась. Но по
`Z0137.md:141` это KOI-7 «СЛ» + атрибуты `10 04`, то
есть **ДАННЫЕ**. Следовательно:

- как гипотеза о мнемониках строки **неверны**
  (семантически ложное чтение);
- как побайтовая реконструкция они **нейтральны**
  (с оговоркой про авто-моду: Э66 слева сдвига не
  вызывает по `EXTRACT-74-66-DECODE-FIX.md:62-70`);
- в `MBE2-Z0540.be:1000` то же слово оставлено
  `КОНД ... , Э66/ЗПМ: неподдерж.` : согласованный выбор.
