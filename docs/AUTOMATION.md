# Автоматизация аннотирования и аналитических сводок

Документ описывает инструмент `tools/annotate_zone.py`, его тесты и цели
`Makefile`, добавленные по итогам разовых работ (см. `docs/ROADMAP.md`, §4).

---

## 1. Инвариант (главное)

**Аннотация меняет только комментарии.** Числовые поля, мнемоники, метки,
адреса, BOM и переводы строк сохраняются побайтово. Разрешается лишь:

1. вставить строки шапки, начинающиеся с `*` (длина строки ≤ 59 колонок);
2. добавить в конец строки комментарий после запятой — разделитель ` , `
   (пробел, запятая, пробел), длина самого комментария ≤ 55 символов.

Это прямое follow-up правила `AGENTS.md` §0: «разрешено только добавлять
комментарии после запятой». Скрипт перед записью **сам проверяет**
инвариант: снимает шапку и комментарии и сравнивает результат с исходником;
при любом расхождении файл не пишется и будет код возврата 2.

Исходный листинг `disbesm6` не содержит запятых, поэтому разделитель ` ,`
однозначен. Строки `* next insn used as data` являются частью листинга и
сохраняются: при снятии шапки удаляются только строки `*` **до первой строки
с TAB** (первой инструкции), то есть только вставленная шапка. Это работает
как для шапки в начале файла, так и для шапки после метаданных
`File:/Type:/Code:/Address:` (как в существующих `bemsh/annotated-*.asm`).

## 2. CLI `tools/annotate_zone.py`

```bash
python3 tools/annotate_zone.py \
  --input dis/MBE-Z0147-L1.asm \
  --output bemsh/annotated-MBE-Z0147-L1.asm \
  [--header FILE] [--comment-file FILE] [--force]
```

| Ключ | Назначение |
|---|---|
| `--input FILE` | исходный `.asm` листинг `disbesm6` (обязателен) |
| `--output FILE` | выходной `.asm` (обязателен) |
| `--comment-file FILE` | карта комментариев в формате `ADDRESS<TAB>COMMENT`, адрес восьмеричный (например `0`, `1234`) |
| `--header FILE` | файл строк шапки; каждая непустая строка начинается с `*`, ≤ 59 колонок, без TAB; пустые строки пропускаются |
| `--force` | разрешить перезапись существующего `--output` |
| `--verify-only` | не писать файл, а снять шапку/комментарии и сравнить с `--input` |

Комментарий приклеивается к строке, чей адрес (первые 5 колонок листинга,
правый выравниватель) совпал с ключом карты. Строки без адреса (вторая половина
слова) не комментируются. Строки карты, начинающиеся с `#` или `;`, и пустые
строки игнорируются; при повторе адреса действует последняя запись.

Пример карты (`bemsh/comments-0147.tab`, табуляция между полями):

```
0	НАЧАЛО ТРАНСЛЯТОРА
1	УИА: БАЗА TAB5, ГИПОТЕЗА
6	ЦЕЛЬ ВЕТВЛЕНИЯ
```

### Коды возврата

| Код | Значение |
|---|---|
| 0 | успех (в т.ч. `0 differences` в режиме проверки) |
| 1 | ошибка использования/Ввода-Вывода: нет входного файла, нет `--comment-file`, OUTPUT уже существует без `--force`, `--input == --output`, нет файла при `--verify-only` |
| 2 | ошибка проверки: комментарий > 55, строка шапки > 59 или без `*`, TAB в шапке, запись с невосьмеричным адресом, изменение содержимого, расхождения при `--verify-only` |

### Режим проверки (ключевой инвариант)

```bash
python3 tools/annotate_zone.py --verify-only \
  --input dis/MBE-Z0147-L1.asm \
  --output bemsh/annotated-MBE-Z0147-L1.asm
```

Печатает `0 differences` (код 0) либо список расхождений с номерами строк и
прошлым/нынешним содержимым (код 2). Проверено на всех четырёх существующих
образцах `bemsh/annotated-MBE-Z{0137,0147,0154,0170}-L1.asm`: везде
`0 differences`.

## 3. Тесты

```bash
python3 -m unittest tools/tests/test_annotate_zone.py -v
```

`tools/tests/test_annotate_zone.py` — 6 тестов `unittest` (все на синтетическом
трёхстрочном листинге с BOM и LF, через реальный CLI):

1. `test_roundtrip` — аннотирование + `--verify-only` → `0 differences`,
   BOM и переводы строк на месте;
2. `test_comment_length_rejected` — комментарий из 56 символов → код 2;
3. `test_numeric_mutation_detected` — правка числового поля `4567 → 4560`
   в аннотированном файле → код 2 и список расхождений;
4. `test_refuse_overwrite` — отказ перезаписать файл без `--force` (код 1,
   содержимое нетронуто), с `--force` → код 0;
5. `test_header_length_rejected` — строка шапки из 60 колонок → код 2;
6. `test_usage_error_code` — отсутствие `--input` → код 1 (не 2).

Результат: `Ran 6 tests … OK`.

## 4. Цели Makefile

| Цель | Что делает |
|---|---|
| `make annotate` | для каждой карты `bemsh/comments-<зона>.tab` пересобирает `bemsh/annotated-MBE-Z<зона>-L1.asm` (шапка — `bemsh/header-<зона>.txt`, если есть). Если карт нет — печатает подсказку и выходит с 0, ничего не меняя. |
| `make procedures` | grep-сводка границ процедур из `analysis/procedures*.md` (заголовки разделов, адреса `A#####`, возвраты `пб (Мn)`, пометки `ГИПОТЕЗА`). |
| `make variables` | валидация `sym/MBE.named.validated.tab` дизассемблером на зоне `0137₈`: `disbesm6 -a10000 -e10000 -n… gold/MBE-Z0137-L1.bin` → `dis/MBE-Z0137-validated-named.asm` + число найденных имён. |

Проверить команды без выполнения:

```bash
make -n annotate procedures variables
```

Существующие цели `stage0 inventory dis xref verify versions check clean`
не изменены.

## 5. Порядок работы с новой зоной

1. Сгенерировать карту: строки `ADDRESS<TAB>COMMENT` (≤ 55 симв.) в
   `bemsh/comments-<зона>.tab`; при необходимости — `bemsh/header-<зона>.txt`.
2. `make annotate` (или прямой вызов CLI из §2).
3. `python3 tools/annotate_zone.py --verify-only --input dis/... --output bemsh/...`
   — обязательно `0 differences`.
4. Только после этого фиксировать результат в `docs/ANNOT-<зона>.md`.

Эталонные образы томов не изменяются (см. `AGENTS.md`, правило 1):
скрипт читает только `.asm`/`.tab` и пишет только указанный `--output`.
