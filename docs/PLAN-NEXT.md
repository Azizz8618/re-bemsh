## Фаза A — Масштабирование реконструкции `.be` на все зоны

**Цель:** для каждой из 69 зон получить `.be`, собираемый настоящим
МАКРО-БЕМШ 06/78 и дающий **0 байтовых отличий** от `gold/`.

### A1. Автоматический конвертер `disbesm6 → BEMSH`

- Создать `tools/dis2be.py`.
- Вход: `dis/MBE-Z<зона>-L1.asm`, таблица `OPS` из
  `~/Yandex.Disk/re-siprod/tools/siprod_asm.py`, `sym/MBE.named.validated.tab`.
- Выход: `bemsh/MBE-Z<зона>-L1.be`.
- Правила (проверены на зоне 0137):
  - команда БЭСМ = два 24-битных полуслова → две строки `.be`
    (`ЗП / ЗП '70000'`, `ЗП / СБР`, …);
  - данные → `КОНД В'<16 восьмеричных цифр>'` (**только восьмеричные!**);
  - нулевые слова → `ПАМ 1` или `КОНД В'0'` (что даёт тот же word);
  - адрес 0 не печатается (`ЗП`, а не `ЗП 0`);
  - `В'...'` — восьмеричная константа; 16-ричные цифры дают `ЧУЖОЙ СИМВОЛ`.
- Проверка на зоне 0137: конвертер обязан воспроизвести существующий
  `bemsh/MBE-Z0137.be` **побайтово** (эталон регрессии).

### A2. Универсальный скрипт сборки

- Обобщить `tools/rebuild-0137.sh` → `tools/rebuild-zone.sh <ZONE> [B|ASM|MBE2]`.
- Сохранить guard: отказ работать, если `BESM6_PATH` указывает на настоящий
  каталог образов (`/usr/local/share`, `~/.besm6`, `.../EC5061`).
- Копировать 2048/2053/2099/2248 в `/tmp/.private/azizz/rebuild-all/`.
- Сравнение через листинг `0-0` (запись `1-1` добавляет relocation-слова).

### A3. Итерация по проблемным зонам

Ожидаемые трудности и обходы:

| Проблема | Где | Обход |
|---|---|---|
| relocation-слова в начале зон | 0137, 0140–0143, 0540–0543 | кодировать как `КОНД`, не как команды |
| граница код/данные после `пб (М3)` | 0147, 0547 | восстанавливать по `analysis/procedures-RESOLVED.md` |
| таблицы ошибок 1024×`слиа/вчп` | 0146/0160/0163/0164/0167 | `КОНД` + проверка, что disbesm6 ошибочно читает их как код |

| макрорасширенный код | 0170, 0165 |оставить как `КОНД`, отметить в отчёте |

## Фаза B — Управляемые эксперименты с таблицей макроопределений

Текущий `docs/MACRO-TABLE-FORMAT.md` — гипотеза (`[TAG|VAL]`), подтверждения
нет. Вместо догадок — эксперимент с настоящим транслятором.

1. Подготовить 3 контролируемых набора макроопределений в синтаксисе
   `re-dispak/macros.be`:
   - B1: один макрос `∧М ПРЕ ∧А / УИА ∧А / МЕND`;
   - B2: два макроса с разным числом ∧-параметров;
   - B3: макрос с `GВLА`, `SЕТА`, `АIF`, `.МЕТКА` (цикл 48→0).
2. Прогнать каждый через `dispak` (`*BEMSH`, `ВВД…КВЧ…ТРН`, `0-0`/`1-1`)
   на **копиях** образов; извлечь объектный модуль.
3. Сравнить три результата побайтово: меняющиеся поля = поля записи таблицы;
   неизменяющиеся = заголовок/служебные слова.
4. Зафиксировать **экспериментально подтверждённый** формат в
   `docs/MACRO-TABLE-FORMAT-VERIFIED.md` с тремя наборами входных данных как
   доказательством.

**Критерий успеха:** формат записи подтверждён ≥3 независимыми вариантами
входа; гипотеза `[TAG|VAL]` либо доказана, либо опровергнута.

## Фаза C — Связать память и зоны диска (динамическая трассировка)

`docs/DYNAMIC-TRACE.md` снял 735 270 инструкций, но адреса 15-битные
(память), а не зоны диска. Нужно снять это ограничение.

1. В `dispak -b` (debugger) использовать `breakpoint <octal>` на адресах,
    которые мы теперь знаем из `.be` зоны 0137 (например, первые команды
    `0..4`), и `trace N` вокруг них.
2. Найти в исходниках `dispak`/`monitor80-re` механизм загрузки оверлеев
   (`LOADANGO`, `GIVTRAN*`, `LOADLIS*`, `TTABLE*`) и таблицу соответствия
   «зона диска → адрес памяти». Ключ: `*PAGE* C 02000`, `PLBEG E 04007`,
   `МОN*ITOR 04000` из `*EXECUTE` (это адреса памяти).
3. Построить `analysis/MEMORY-MAP.md`: зона диска | адрес загрузки | размер |
   процедуры.
4. ПОДТВЕРЖДЕНО 22.11: 0154 и 0170 исполняются по `02000₈`
   (оверлей page 01), переход `01314: uj 2000`; см.
   `analysis/PASSES-CODE-LOCATION.md`.

**Критерий успеха:** либо карта «зона → память» с подтверждёнными
	breakpoint'ами, либо документированный отрицательный результат
	с указанием причины.
