## 0. КОРОТКИЙ ОТВЕТ

Формула гипотезы оператора **подтверждена на уровне исходника**:

```
адрес вызова = (метка во внешнем модуле) -
               (начальная метка внешнего модуля)
```

Прямое свидетельство (SL:486-488, 465):

```
Э60Д ВНЕШН Э60Д.        ← начало внешнего модуля
ПЕРЕК ВНЕШН Э60Д.ПЕРЕК  ← метка внутри модуля
ПОЛЕ ВНЕШН Э60Д.ПОЛЕ
       ПВ ПЕРЕК-Э60Д(13)
       ЗП ПОЛЕ-Э60Д+19(I)
```

Это **смещение D внутри внешнего модуля**, а не адрес
памяти. В объектном модуле D лежит в младших разрядах
адресного поля, а номер внешнего символа X — в старших;
бит 21 (или 0o4000 в 12-битном поле) помечает адрес как
перемещаемый (SP:427-428; MM:22-24; MO:75-76).
Загрузчик подставляет `значение = база(X) + D` (LD:22-26).

Для листинга МВЕ60 частный случай D=0, поэтому видны
только порядковые номера связей 1, 2, 3 (L:375-377) —
это не опровергает формулу, а лишь её вырожденный случай.

## 1. СИНТАКСИС И СЕМАНТИКА

### 1.1 Объявления ВНЕШ / ВНЕШН

`macros.be:1-6`: макрос `ВНЕШ` разворачивается в
`∧А(1) ВНЕШН ∧М..∧А(N'∧А)`, то есть в последовательность
`ВНЕШН` — по одному внешнему символу на элемент списка.
`macros.be:8-13`: `ВХОД` аналогично разворачивается в `ВХОДН`.

`lk:212-222`: глобальное имя внешнего символа строится
как `владелец.символ`; директива `ВНЕШ` должна указывать
**владельца** (модуль с подпрограммой или общий блок),
а не ссылающийся модуль. Примеры из LK:218-221:

```
ADRSEK ВНЕШ ADR,LYG,...   (неверно)
ADR    ВНЕШ ADR           (верно)
```

`SL:486`: форма `Э60Д ВНЕШН Э60Д.` — владелец с точкой на
конце есть **начальная метка модуля**; `SL:487-488` — метки
внутри него. `LK:244-245`: `RASPI ВНЕШ RASPS` — ссылка на
оверлей объявляется с базовым модулем.

`LK:261-264`: ссылка модуля на самого себя (`SKZONA+1024`)
внешним символом не объявляется; она разрешается как
«база модуля + смещение». Прямая формула из LK:264.

### 1.2 Атрибут СА, `*МЕТ*`, `*EXECUTE`

Сводка листинга L:366:
`ВНЕШН=00003` — ровно три внешние ссылки.
`*МЕТ*` (L:368-377) помечает их суффиксом `СА`:
`PRINT8 00001СА` (L:376), `CM400 00002СА` (L:377),
`PAGE 00003СА` (L:375). Суффикс `В` у `МВЕ60 00001В`
(L:371) — вход модуля, не внешняя связь.

`docs/MACRO-COMMANDS.md:108-110`, `PL:180-181`,
`MACRO-BEMSH-ARCHITECTURE.md:343-344`: внешний символ
помечается `СА`, загрузчик подставляет адрес из
`*EXECUTE` (L:383, 385-390):

| Символ | Номер | Адрес | file:line |
|---|---|---|---|
| PRINT8 | 1 | 01205 | L:376, 386 |
| *CM400* | 2 | 01243 | L:377, 388 |
| *PAGE* | 3 | 02000 | L:375, 389 |
| MBE60 | вход | 01000 | L:371, 385 |
| MON*ITOR | — | 04000 | L:390 |

`EP:295-297`: `*EXECUTE` даёт адреса **памяти**, не адреса
зон диска. `EP:301-303`: `PRINT80 E 01205` — эквивалент,
не четвёртая связь (`ВНЕШН=3`).

`docs/USER-PROGRAM-EXTERNAL-CALLS.md:49-52`: пары
`000000 55320ВА`, `000000 42001СА` в правой колонке
L:375-377 имеют неясный смысл; в расчёт не включены.

### 1.3 Колонка `+N` листинга

Заголовок L:28: `ОШИБКИ НПК СВОБ ПЕРЕМ АДРЕС КОМАНДА...`.
Проверка позиций (L:87, 92, 276): `+` стоит в колонке 13,
число `0002`/`0003` — в колонке 15 (`СВОБ`), адрес слова —
в колонке 26 (`АДРЕС`), команда — в колонке 32.

```
L:87  + 0002  00012  00 22 0000  ... МОДА СМ400
L:92  + 0003         16 24 0000  ... УИА РАGЕ(М16)
L:276 + 0003  00146  00 22 0000  ... МОДА РАGЕ
```

Число `+N` **совпадает с номером внешнего символа** из
`*МЕТ*`: 0002 = CM400, 0003 = PAGE. Поле адреса команды
при этом равно `0000`, то есть D=0 (ссылка на начало
внешнего модуля/блока). Формальное название колонки
(`СВОБ` или `ПЕРЕМ`) по выравниванию заголовка однозначно
не установлено; корреляция чисел прямая.

### 1.4 Формула кодировки

Схема, подтверждённая несколькими независимыми источниками:

1. Исходник: `ПВ МЕТКА-НАЧАЛО_МОДУЛЯ(Мn)` (SL:465) или
   `ВНЕШН владелец.метка` + ссылка на символ (S:28, 56-57).
2. Ассемблер вычисляет `D = метка - начало_модуля`
   (SL:1424 в `pchkz.be`: `СТАТ = СТАТЗ-ПЧКЗ`, где
   `СТАТЗ = ПЧКЗ+4`, значит D=4).
3. В команде выставляется бит перемещаемости; старшие
   разряды адресного поля несут номер символа X, младшие
   — смещение D (SP:427-428; MM:22-24; MO:75-76:
   «бит 14 адресного поля 0o4000 + номер идентификатора
   в младших битах»).
4. Загрузчик: `значение = база(X) + D` (LD:22-26,
   `C=0: X — номер символа СВОЕГО модуля, значение =
   символ X + D`; LK:264 «база модуля + смещение»;
   SP:432 «ссылка вида символ + смещение»).

Итоговая формула слова CALL:

```
CALL_word = бит_перемещаемости | X | D
память после загрузки = база(X) + D
D = адрес_метки_во_внешнем_модуле -
    адрес_начальной_метки_внешнего_модуля
```

## 2. ОБЪЕКТНЫЙ МОДУЛЬ И ЗОННЫЙ ДАМП

**Однословная ссылка** (`МОДА СМ400`, `УИА РАGЕ(М16)`):
в объектном модуле — одна команда с битом 21 и номером
символа/смещением в адресном поле. В листинге это
`+0002`/`+0003` при поле адреса `0000` (L:87, 92, 276).
Загрузчик записывает **абсолютный адрес** в поле адреса
команды: 01243 и 02000 (L:388-389; MC:108-110).

**Двухсловная ссылка** (`CALL PRINT8`): макрос
(`S:12-16`, `L:29-33`) разворачивается в:

```
∧L ПВО ∧T.(М15)   ← команда, адрес возврата в М15
   ПАМ 0          ← зарезервированное адресное слово
```

`PL:168-186`, `MACRO-COMMANDS.md:104-113`,
`MACRO-BEMSH-ARCHITECTURE.md:333-346`.
В объектном модуле (DT:446-447):

```
00531531 74001   13, VJM, PRINT8
 -  0022 00000
```

Первое слово содержит ссылку на символ PRINT8 (номер 1),
второе (`ПАМ 0`) — адресное слово, заполняемое загрузчиком
(PL:174). Это и есть двухсловная внешняя ссылка.

**Зонный дамп**: зоны транслятора (0055-0060, 0137-0177,
0540-0577) — уже слинкованный код. В них внешние адреса
заменены Absolute-адресами ОП; логические адреса листинга
`*МЕТ*`/`*EXECUTE` **не являются физическими якорями**
(AGENTS.md §3; `docs/SIPROD/01-obzor.red:23`;
`docs/SIPROD/05-kak-chitat.red:44-46`). В объектах
библиотеки (не в зонах транслятора) relocation хранится
в разделе `sym`: `(0o4000+X)<<24 | C<<12 | D` (LD:19-30).

## 3. КОНКРЕТНЫЕ ПРИМЕРЫ

| Пример | Значение | Источник |
|---|---|---|
| `PRINT8 00001СА` | внешний символ №1, D=0 | L:376 |
| `CM400 00002СА` | внешний символ №2, D=0 | L:377 |
| `PAGE 00003СА` | внешний символ №3, D=0 | L:375 |
| `PRINT8 01205` | подстановка загрузчика | L:386 |
| `MON*ITOR 04000` | системный символ, не связь модуля | L:390; EP:128-129 |
| `02000₈ = зона 0154` | база зоны и `*PAGE*`; совпадение адресов не значит общий код | `docs/SIPROD/03-konveyer.red:44-46`; EP:142-144 |
| `+ 0002 ... МОДА СМ400` | relocation, X=2, D=0 | L:87 |
| `+ 0003 ... УИА РАGЕ` | relocation, X=3, D=0 | L:92, 276 |
| `ПВ ПЕРЕК-Э60Д(13)` | D = метка - начало внешнего модуля | SL:465 |
| `ЭКВИВ (СТАТ,СТАТЗ-ПЧКЗ)` | D=4 внутри своего модуля | pchkz.be:1423-1424 |
| `01205-01000 = 00205` | PRINT8 сразу после МВЕ60; с ней совпала ДЛИНА ПРОГ | USER-PROGRAM-EXTERNAL-CALLS.md:138,147 |

Важно:_numbers_ `00001/00002/00003` — это **номера связей**,
а не разности адресов (USER-PROGRAM-EXTERNAL-CALLS.md:150-160).
Но D=0 для них; формула работает, давая 0 в младших битах.

## 4. ПРАВИЛО РЕШЕНИЯ ДЛЯ ЧИСЛОВОГО ОПЕРАНДА

Дано число `N` (например `10`, `11`, `137`) при `ПВ/ПБ/УИА`:

1. **Локальный адрес** — если `N < 0100₈` и соседняя
   метка/ячейка найдена в той же зоне при `-a0 -e0`.
   `disbesm6` печатает такие значения **десятичными**:
   `17→021₈`, `28→034₈`, `53→065₈` (EP:31-35;
   DISBESM6-GUIDE.md:44-46). Требуется: дизассембль
   зоны, sym-таблица, совпадение с `A#####`/`D#####`.
2. **Смещение во внешнем модуле** — если в команде
   выставлен бит 21 (0o4000 в 12-битном поле), старшие
   биты несут номер символа, младшие — D, и в исходнике
   есть `ВНЕШН владелец.метка` или выражение
   `метка-начало` (SP:427-428; MM:22-24; SL:486-488,465).
   Требуется: бит поля, `+N` в листинге, `*МЕТ*`, `*EXECUTE`.
3. **Абсолютный адрес памяти** — если значение >= 01000₈
   совпадает с `*EXECUTE` или картой загрузки. Такие
   адреса 0o2013…0o50000 не помещаются в 12-битное поле
   второй структуры, поэтому требуют первой структуры с
   регистром (`УИА X(М13)`, не `УИ X`) — LK:299-303.
   Требуется: `*EXECUTE`, MEMORY-MAP, формат команды.
4. **Простая константа / immediate** — экстракоды Э50-Э77
   (IMMEX: константа, не адрес — MM:28-31); отрицательное
   смещение печатается как `>= 077700` (DISBESM6-GUIDE.md:46);
   `СДА 64+N` — база 64 + десятичная дельта.

Порядок проверки: (2) → (3) → (1) → (4). Сначала ищем
бит relocate и номер символа, затем абсолют по `*EXECUTE`,
затем локальную метку, затем константу.

## 5. ЧЕСТНАЯ НЕОПРЕДЕЛЁННОСТЬ

**Документировано прямо:**
- синтаксис `ВНЕШН` и `ВНЕШ` (MB:1-13; SL:483-488);
- бит 21 = перемещаемый адрес, старшие биты = номер
  символа, младшие = смещение (SP:427-428; MM:22-24);
- формула загрузчика `символ X + D` (LD:22-26);
- `ПВ ПЕРЕК-Э60Д(13)` в исходнике (SL:465);
- `+0002`/`+0003` и `СА`-номера в листинге (L:87, 92,
  276, 375-377);
- два слова CALL и подстановка адреса (DT:446-447; PL:174).

**Выведено (логически, без прямого текста):**
- что `D` в SL:465 есть именно «метка - начало модуля»
  (вывод из объявлений SL:486-488 и вида выражения);
- что число в колонке 15 листинга — номер внешнего
  символа (корреляция 0002=CM400, 0003=PAGE);
- что `ПАМ 0` — адресное слово, заполняемое загрузчиком
  (PL:174; в DT:447 оно напечатано как `00000`).

**Не установлено:**
- смысл пар `55320ВА` / `42001СА` (L:375-377);
- формальное название колонки `+N` (СВОБ или ПЕРЕМ);
- точная битовая раскладка X и D внутри 12/15-битного
  адресного поля без дизассемблирования тела АРАПа;
- машинное слово `ПВО PRINT8` в листинге не напечатано
  (макрос, L:169, 193); доступна только DTRAN-форма DT:446.
