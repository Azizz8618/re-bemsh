## 1. ПОСТАНОВКА ПРОБЛЕМЫ

Ранее зоны 0055–0060₈ классифицировались как «таблицы/забелы»
с 1–8 код-словами и 816–1014 строками `конд` [Z0055 §1–2; Z0056 §1–2;
Z0057 §1–2; Z0060 §1–2]. Это **ошибка статического анализа**.
Побайтовое декодирование каждой 24-битной половины по таблице
`siprod_asm.OPS` даёт 99.17–99.90% известных мнемоник из 2036 половин
на зону (слова 6..1023: 1018 слов × 2). Следовательно, массив
`конд` — это **исполняемый код**, который `disbesm6` не смог
достигнуть при трассировке.

## 2. МЕТОДИКА И ТОЧНЫЕ КОМАНДЫ

### 2.1 Таблица символов

Симтаб перекрывает все слова зоны, начиная с 6 (decimal) и до 1543
(decimal); в формате `-n` адреса **восьмеричные**, поэтому decimal
1543 записывается как `03007₈`. Всего 1538 строк вида `%o 2 -`:

```bash
python3 - <<'EOF'
with open('/tmp/asm-all.tab','w') as f:
    for a in range(6, 1544):      # decimal 6..1543
        f.write('%o 2 -\n' % a)   # 00006 .. 03007 (octal)
EOF
# => 00006 2 - / 00007 2 - / ... / 03006 2 - / 03007 2 -
```

Тип `2` = `W_CODE` (создаёт точку входа), имя `-` = только пометить
тип [GUIDE §1; AGENTS §3]. Симтаб хранится вне репозитория, чтобы не
изменять чужие файлы.

### 2.2 Прогон

```bash
cd /tmp/.private/azizz/re-bemsh
for z in 0055 0056 0057 0060; do
  disbesm6 -a0 -e0 -n/tmp/asm-all.tab \
    gold/ASM-Z$z-L1.bin > dis/ASM-Z$z-full.asm
done
```

`-e0` обязателен; `-a0` сохраняет адреса листинга; BOM и ANSI в выводе
отсутствуют (ESC = 0 во всех четырёх файлах), дополнительной очистки
не требуется.

### 2.3 Верификация (цитаты)

| зона | строк всего | `конд` (до → после) | строк с мнемоникой | код >1300? |
|---|---|---|---|---|
| 0055 | 2170 | 816 → **4**  | 1995 | да |
| 0056 | 2128 | 973 → **4**  | 1946 | да |
| 0057 | 2156 | 1014 → **0** | 1990 | да |
| 0060 | 2062 | 873 → **0**  | 1951 | да |

Условие задания (`конд` < 10, строк кода > 1300) выполнено во всех
четырёх зонах. Для 0055 ключевое свидетельство сообщало «1357 строк
кода и 4 `конд`»; число `конд` воспроизведено точно (4), а расхождение
в числе строк объясняется методикой подсчёта: здесь считаются **все**
строки с именем мнемоники из `OPS`, включая строки с метками `D#####`
и артефактами `* next insn used as data`. Если исключить метки
`D#####`/`A#####`, получается 1265 строк — того же порядка.

Дополнительные счётчики recovered-листингов:

| зона | `конк` (illegal) | `пам` | `* next insn used as data` | A-меток |
|---|---|---|---|---|
| 0055 | 13 | 1 | 147 | 107 |
| 0056 | 17 | 1 | 150 | 49  |
| 0057 | 2  | 0 | 155 | 33  |
| 0060 | 10 | 0 | 92  | 38  |

Числа `конк` совпадают с числом «неопознанных» половин в проверке
`OPS` (13/17/2/10) — то есть расхождения дизассемблера нет, это
зарезервированные коды [XCHECK §3–4].

### 2.4 Независимая проверка `OPS`

```bash
python3 - <<'EOF'
import sys
sys.path.insert(0,'/home/azizz/Yandex.Disk/re-siprod/tools')
from siprod_asm import lookup
for z in ('0055','0056','0057','0060'):
    b = open('gold/ASM-Z%s-L1.bin' % z,'rb').read()
    w = [int.from_bytes(b[i:i+6],'big') for i in range(0,len(b),6)]
    h = [x for word in w[6:] for x in (word>>24, word&0xffffff)]
    n = sum(lookup(x)[0] is not None for x in h)
    print(z, len(h), n, round(100*n/len(h),2))
EOF
```

Результат: `0055 2036 2023 99.36`, `0056 2036 2019 99.17`,
`0057 2036 2034 99.90`, `0060 2036 2026 99.51`.

### 3.2 Точки входа и границы процедур

`START` = слово 0 во всех зонах. Метки `A#####` расставлены
`disbesm6` по достижимым целям ветвлений; подмножество, куда идут
**CALL (`пв`)**, — вероятные точки входа подпрограмм (адреса указаны как
смещения при `-a0`, физическая привязка не доказана):

| зона | A-меток | CALL-внутри зоны (A-метки) |
|---|---|---|
| 0055 | 107 | A00220, A00221, A00232, A00276, A00300, A00301, A00302, A00321, A00322, A00343, A00366, A00402 |
| 0056 | 49  | A00220, A00221, A00232, A00301, A00302, A00320, A00321, A00322, A00333, A00533, A00561, A00637, A00662 |
| 0057 | 33  | A00220, A00221, A00301, A00533, A00561, A00637, A00641, A00662 |
| 0060 | 38  | A00220, A00221, A00301, A00533, A00637, A00641, A00661, A00662 |

Повторяющиеся во всех зонах входы `A00220`, `A00221`, `A00301`,
а также `A00533`, `A00637`, `A00662` (3 зоны) и `A00641` (2 зоны),
указывают на **общий набор сервисных подпрограмм ИТМ**,
адресуемых по одним и тем же логическим смещениям. Идентичность
смещений при `-a0` не доказывает физическую общность ячеек.

## 5. ПОЧЕМУ `disbesm6` НЕ СПРАВИЛСЯ

1. В 0055/0056 слово 0 — `выпр '70707'(М17)` (IRET,
   `OPCODE_IRET`). По `analyze_insn()` [disbesm6.c:750–758] IRET
   выставляет `W_NORIGHT` и **не создаёт преемника**: трасса
   обрывается сразу, остальные слова помечаются как данные.
   В 0057 трасса доходит до слова 4 (`сч START; пб '4012'`),
   в 0060 — до короткого блока слов 0..7 с выходами `пб '6017'`
   и `пб (М1)` в слове 20; дальше анализ достижимости тоже останавливается.
2. В 0055 слово 5 — `пам 1` (один нулевой word между «шапкой» и
   массивом), а слово 6 — `пб (М3); зп '6770'`. `analyze_jump()`
   [disbesm6.c:581–590] создаёт точку входа только при
   `regvals[M3] != -1`; регистр M3 из кода не вычислен, значит
   преемника нет, `W_NORIGHT` подавляет правую половину, и весь
   хвост слов 6..1777 остаётся `W_DATA` → `конд`
   [GUIDE §3.2; Z0055 §1]. Аналогично в остальных зонах: первая же
   косвенная передача обрывает достижимость.
3. Статический анализ не знает содержимого регистров и не видит
   самомодификации; `мод` помечает цель как `W_DATA`, `уи`
   обнуляет `regval` [GUIDE §3.3]. Поэтому даже `-R3=<адрес>`
   лечит только локальный переход, а не весь массив.
4. Лечение — принудительная достижимость через `-n` с типом `2`
   на все адреса слов. После этого 99%+ половин получают имена
   из `OPS`, а `конд` падает с 816–1014 до 0–4.

### Артефакты принудительного симтаба

`* next insn used as data` (92–155 на зону) печатается, когда
ячейка имеет одновременно `W_CODE|W_DATA` [disbesm6.c:830–831].
При принудительном `W_CODE` на все слова любая ссылка `зп/нтж/мод`
с известным регистром добавляет `W_DATA` — отсюда метки `D#####`
на код-строках и `* next insn used as data`. **Это не реальные
ячейки двойного назначения**, а следствие методики; в настоящей
программе часть из них — данные (таблицы/константы), часть — код.
Точно так же `пам` и `конк` в восстановленном листинге — не
доказательство «забела», а подавленная правая половина и
зарезервированные опкоды соответственно.

## 6. ИСПРАВЛЕНИЕ ПРЕЖНЕЙ КЛАССИФИКАЦИИ

Ранние выводы [Z0055–Z0060 §1–2, §6–7]: «1 код-слово + таблицы/
забелы», «992–1014 чисел — экстракоды/адреса ИТМ», «CALL и A-меток
нет» — **неверны** и основаны на усечённой трассе `disbesm6`.
Правильная интерпретация:

- Зоны 0055–0060₈ — **исполняемые модули** программы
  `ТРАНСЛЯТОР С А/К И Т М` (автокод ИТМ), каталог `0000.0204`,
  дата `.75` [PLAN:18; FINAL-REPORT:19], **другой транслятор**,
  не МАКРО-БЕМШ (зоны 0137–0177₈) и не B2 (0540–0577₈).
- В каждой зоне ~1950–2000 декодированных инструкций, 33–107
  точек входа, 36–82 CALL, до 35 переходов на общую цель 3762₈.
- Фрагменты GOST-текста в 0056.0436–0453 («ОШИБКА В ОБРАЩЕНИИ…»)
  и одиночные GOST-«буквы» в 0055.0253–0261 — **константы внутри
  исполняемого модуля**, а не «весь модуль — текст/данные».
- Заголовки `.be` «ТРАНСЛЯТОР С М/К БЕМШ ВЕР.06/78» в `bemsh/`
  остаются ошибочными [Z0055 §1; Z0056 §1]; это не повод
  переименовывать зоны в БЕМШ.

## 7. ОГОВОРКИ И ВОСПРОИЗВЕДЕНИЕ

1. Файлы `dis/ASM-Z00zz-full.asm` получены **только** командой
   `-a0 -e0 -n<симтаб>`; байты `gold/` не менялись. Сравнение с
   эталоном — побайтовое, расхождений нет.
2. Листинги содержат метки `A#####`/`D#####` и `* next insn used as
   data`, сгенерированные принудительным симтабом. Это не
   авторские имена; использовать их как физические адреса
   запрещено [AGENTS §3].
3. Логические адреса внешних целей (`70707₈`, `3604₈`, `3762₈`,
   …) не привязаны к физическим ячейкам тома без карты памяти ИТМ.
4. Точная природа подпрограмм (`3604`, `5041`, `377x`, `56xx`)
   остаётся гипотезой до появления исходников/листингов
   `ТРАНСЛЯТОР С А/К И Т М`.
5. Воспроизведение: §2.1–2.4 выше; аннотация комментариев в
   `bemsh/*.be` не требует (листинги — побочный продукт).
