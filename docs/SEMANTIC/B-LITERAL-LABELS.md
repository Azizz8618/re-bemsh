# B-зоны (0137–0177₈): применение глобальной таблицы литерал → метка

Пакетная обработка всех 33 зон БЕМШ 06/78 по `docs/LITERAL-LABELS.md`
и `sym/ALL_LABELS.tab`. Изменены **только** `bemsh/MBE-Z*.be` (33 файла).

## 1. Методика

1. Для каждой зоны: `python3 tools/literal_labels.py --apply-zone <Z> --mode B`.
2. Обязательная побайтовая проверка: `bash tools/rebuild-zone.sh <Z> B`
   → `RESULT: PASS`, `WORDS: всего=1024 совпало=1024 различий=0`,
   `✓ Файлы идентичны`.
3. Счёт «литералов» — кавычные восьмеричные операнды в кодовой части строки
   (до первой запятой, вне строк `*`), которые сканер `tools/literal_labels.py`
   относит к `ADDRESS`/`AMBIGUOUS` (строки `ЭКВ` исключены). Это и есть
   кандидаты на переименование. Счёт «до» и «после» сделан одним и тем же
   сканером/классификатором, что и в инструменте; «до» зафиксирован до всяких
   правок, «после» — после `--apply-zone`.
4. Метка вводится строкой `МЕТКА ЭКВ 'NNNN'`, которая не порождает слово,
   поэтому 48-битные слова и байты эталона не меняются.
5. Зона 0137 обработана пилотным прогоном до общего батча (батч — 0140–0177);
   в таблицу ниже вписаны её реальные числа до обработки.

## 3. Отказы

Отказов нет. Ни одна зона не дала `RESULT: FAIL`, `ОПЕРАЦИИ НЕТ` или
расхождения байтов; откат из `.bak` не потребовался (0 повторных прогонов).
Все 33 проверки прошли с первой попытки.

## 4. Константы, оставленные без меток

Классификатор намеренно **не** трогал операнды класса `CONSTANT`:
экстракоды (`Э50 '105'`, `Э52 …` и др.; кроме `Э70`/`Э74`, продвинутых
в `ADDRESS`), маски (`СДА`, `СЛПА`, `ВЧПА`), immediate-операнды (`РЖА`, `РЖ`),
номера регистров, слова данных (`КОНД`), 48-битные слова `В'…'`, текст
`П'…'`/`Х'…'`, шахмальную заливку (`'25252'`/`'72525'`,
`docs/LITERAL-LABELS.md` §5.3) и все уже существующие определения `ЭКВ`.

После обработки в 33 зонах осталось **10 713** кавычных операндов класса
`CONSTANT` плюс **7 335** строк `ЭКВ` (7 285 добавленных и 50 уже
существовавших: 3 в 0137 и 47 в 0147). Адресных литералов
(`ADDRESS`/`AMBIGUOUS`) не осталось ни в одной зоне (0 по всем 33).

Зоны-«заполнители» B: **0146, 0160, 0163, 0164, 0167** — по 2046
`CONSTANT`-операндов в каждой (в основном данные/заливка). Адресных
литералов в них почти нет (по 2 на зону): это `ПО '66666'(М15)` в слове 1777
(строки 2061/2062), признанная классификатором целью перехода и получившая
метку `CON666`. Константы в метки **не форсировались**: применено ровно то,
что классификатор счёл адресом; сама заливка `'66666'` в качестве константы
и шахматная заливка `'25252'`/`'72525'` сохранены без меток.

Короткие/частичные зоны с малым числом адресных литералов: 0156 (1),
0174 (15), 0175 (3), 0177 (4) — обработаны без принудительных правок.
В 0147 до обработки уже было 47 определений `ЭКВ`; добавлено ещё 126.

## 5. Оговорки

1. Метки — компактные аннотации для чтения листинга, **не** ground truth
   (`docs/LITERAL-LABELS.md` §0, `docs/LABEL-MAP.md` §0). Роли из
   `GLOBAL.tab`/`SEMANTIC` — гипотезы без исходника транслятора.
   Метки с confidence `ГИПОТЕЗА` (`AMBIGUOUS`) требуют ручной проверки.
2. `ЭКВ` не порождает слово; байтовая идентичность подтверждена для каждой
   зоны отдельным `rebuild-zone.sh` (1024/1024, «Файлы идентичны»).
3. Инструмент укорачивает только хвост комментария после первой запятой,
   чтобы строка не превышала 78 символов (лимит транслятора,
   `docs/RAW-RECOVERY.md`); кодовая часть не изменяется.
4. `.bak.<timestamp>`-файлы, созданные этим агентом для 33 зон B, удалены
   после успешной проверки.
5. Другие файлы (`bemsh/ASM-Z*`, `bemsh/MBE2-Z*`, `tools/`, `sym/`, `gold/`,
   `dis/`, прочие `docs/`) этим агентом не изменялись.
