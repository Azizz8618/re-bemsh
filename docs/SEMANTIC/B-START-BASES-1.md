# СТАРТ-БАЗЫ ЗОН B 0137, 0140-0146

Дата: 20.11.2026. Образ 2348. Методика — по заданию
родительской сессии. Изменены ТОЛЬКО 8 заголовков .be
и этот документ. tools/, gold/, dis/ и другие .be не
трогались. Временные файлы — /tmp/.private/azizz/.

## 1. ОБОСНОВАНИЕ БАЗЫ

analysis/RAM-SNAPSHOT-MAP.md §4 («Не найдены ни в
одном снимке») перечисляет: 0137, 0140-0146. Это
НЕРЕЗИДЕНТНЫЕ диск-оверлеи: физического адреса в ОП
у них нет. По указанию оператора для таких зон
берётся произвольная база '10000' (восьмеричная).

Смена СТАРТ меняет только базу адресов листинга и
загрузки, НЕ значения слов. Обратная сборка даёт
побайтово тот же объектный образ.

## 2. МЕТОДИКА

1. .be скопирован в /tmp (бэкап *.orig).
2. В заголовке заменено `Z<Z> СТАРТ 1` на
   `Z<Z> СТАРТ '10000'` (операнд закавычен).
3. Прогон: bash tools/vneshn_probe.sh probe <копия>
   <З> B <tag>. Проверка: ошибок 0, ДЛИНА=02000.
4. Из листинга извлечены 1024 слова и сравнены с
   gold/MBE-Z<З>-L1.bin (6144 байт = 1024 x 6 байт).
   Совпало 1024/1024 у всех 8 зон.
5. Дополнительно: пословное сравнение значений старого
   (СТАРТ 1) и нового (СТАРТ '10000') листингов —
   0 различий у всех 8 зон.

## 4. АРТЕФАКТ tools/rebuild-zone.sh

rebuild-zone.sh читает базу из СТАРТ в .be и ищет
слово i по адресу BASE+i. Но листинг МАКРО-БЕМШ
нумерует слова от 1 (у части зон — от самой базы),
поэтому после смены базы на '10000' старый экстрактор
даёт 0 совпадений. Это ОШИБКА ЭКСТРАКТОРА, а не
изменение байтов: tools/ сознательно не менялся.
Побайтовая сверка (п.2) доказала неизменность слов.

## 5. ВЫВОД

Заголовки 8 зон переведены на базу '10000' без
изменения объектных слов. Обратная сборка даёт
1024/1024 совпадающих слов с gold для каждой зоны.
