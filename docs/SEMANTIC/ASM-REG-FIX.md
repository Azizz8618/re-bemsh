# Перемаркировка подозрительных РЕГ в модулях Автокод ИТМ (0055–0060₈)

Дата: 20.11.2026. Изменены только четыре `bemsh/ASM-Z00zz.be` и этот
файл. Образы `gold/`, листинги `dis/`, `tools/`, `sym/` не трогались.

## 1. Правило отбора

РЕГ считается командой только при `Aex & 0377` из множества
`000-007, 020-033, 036-037, 0100-0137, 0200-0207, 0237`.
Остальные значения означают данные, случайно прочитанные как
opcode 002 (`simh cmd_002`). Источники: `docs/REG-INSTRUCTION.md`,
`docs/REG-OPERAND-AUDIT.md` §7 (таблица предложенных правок),
`docs/SEMANTIC/ASM-KOND-DECODE.md` (способы побайтовой замены).

## 2. Способ правки

Для каждой строки таблицы §7 в своей зоне проверено слово из
`gold/ASM-Z<зона>-L1.bin` по смещению `адрес x 6`. Все восемь слов
оказались данными целиком: шесть печатных байт (текст/таблица)
или константа `00 00 00 00 2f e8`. Поэтому две полустроки
заменены одной строкой `КОНД В'<16 восьмеричных цифр>'` с тем же
словом. Комментарий принял вид `, данные: байты ... (РЕГ)`.

Скобки `(принято за РЕГ)` не поместились: МАКРО-БЕМШ читает строку
не длиннее 72 колонок, хвост комментария разбирался как новая
строка и давал `ОПЕРАЦИИ НЕТ`. Короткое `(РЕГ)` сохраняет пометку
и проходит сборку. Слова `КОНК` не потребовались: ни одна половина
не была реальной командой.

## 4. Итоги по зонам

| Итого | 8 | 8 | 3 |

Пропуски в 0057: три строки `РЕГ , в регистр сумматор` без
числового операнда (Aex = M[0], напечатанное поле адреса 0000).
Слово `0000000000020000` не является текстом и не доказывает
«данные/другая команда», поэтому код и комментарий оставлены
без изменения. Другие «гипотетические» РЕГ вне таблицы §7
(0055: 2, 0056: 0) также не трогались.
