# БАЗЫ СТАРТ ДЛЯ ЗОН B2 (0540-0557₈)

## Причина выбора базы

Зоны 0540-0557₈ это старая редакция 12/77 транслятора
с макроассемблером БЕМШ (AGENTS.md, §0). Ни одна из них
не найдена в снимках ОП, которые покрывают исполняемый
набор 06/78, зоны 0147-0162₈. См. RESIDENT-ZONES.md §2:
все зоны 0540-0577₈ там помечены как НЕРЕЗИДЕНТные.

Это оверлеи, грузящиеся с диска на произвольный адрес.
По указанию оператора для нерезидентных зон берётся
произвольная база '10000'₈.

## Что именно изменено

В заголовке каждого модуля изменён только операнд СТАРТ:
было `Z0540   СТАРТ 1`, стало `Z0540   СТАРТ '10000'`.
Метка модуля и все остальные строки не тронуты.

Исключение, Z0547. В этом файле 64 строки ЭКВ стояли
ДО директивы СТАРТ. Опыт показал, что МАКРО-БЕМШ
игнорирует СТАРТ в таком положении: слова оставались
на базе 1, а символ Z0547 равнялся 00000. Поэтому
строка СТАРТ перенесена перед блоком ЭКВ (была 151,
стала 23). Операнд тоже заменён на '10000'. Метка
модуля Z0547 сохранена.

Важно: СТАРТ задаёт только базу адресов в листинге
транслятора, но НЕ меняет значения самих слов.

## Проверка байтовой безопасности

Транслятор запускался через tools/vneshn_probe.sh на
копии каждого .be (тот же job, что и в rebuild-zone.sh).
Ошибки трансляции = 0, ДЛИНА ПРОГ = 02000₈ во всех
16 зонах, dispak_rc = 0.

Слова извлекались из листинга с базой 10000₈:
столбец адреса [25:30], слово по адресу 10000₈+i для
i=0..1023; каждое 6-байтовое слово сверялось с

## Почему rebuild-zone.sh теперь «падает»

tools/rebuild-zone.sh (и встроенный extract в
vneshn_probe.sh) жёстко извлекает слова с базы i+1, то
есть ожидает СТАРТ 1. С новой базой '10000'₈ его
экстрактор читает не те адреса листинга и сообщает о
расхождениях (bad_words=1024). Это АРТЕФАКТ
ЭКСТРАКТОРА, а не реальное изменение байтов: при
извлечении с правильной базой 10000₈ все 1024 слова
совпадают с gold (см. таблицу выше).

Сам инструмент НЕ менялся. Для проверки этих зон
используется переизвлечение с базой 10000₈, описанное
выше.
