---

## 1. МЕТОДИКА

1. Кандидаты — строки `.be` вида `КОНД В'................'`, в комментарии
   которых есть CALL / код / переход / выход / шлюз / Э20.
2. 16 восьмеричных цифр слова делятся на две 24-битные половины:
   старшие 8 цифр = левая команда, младшие 8 = правая. Каждая половина
   разбирается `siprod_asm.decode()`: мнемоника, адрес, регистр, DMS,
   признак структуры. Регистр печатается в ВОСЬМЕРИЧНОЙ форме (`(М17)`),
   как в full-листинге `disbesm6`.
3. Строка `КОНД` (одно 48-битное слово) заменяется ДВУМЯ строками команд.
   Число слов не меняется, поэтому сборка остаётся побайтовой.
4. Подавленная `disbesm6` правая половина (`00000000`) пишется как
   голая `ЗП` — это ноль, а не `мода`.
5. Обязательная проверка после каждой зоны: `rebuild-zone.sh <Z> ASM`,
   ожидается `RESULT: PASS`, `1024/1024`, «Файлы идентичны».

## 4. ПРОПУСКИ И ПРИЧИНЫ

1. **Э20 / `конк` (0055: 555, 561, 1867; 0056: 624).** Половина с
   кодом `0200xxxx` не имеет мнемоники в `OPS`; `disbesm6` печатает её
   `конк`. Символическая запись невозможна, оставлено `КОНД`.
2. **CALL в левой половине (0056: 2567).** По правилам транслятора БЕМШ
   команды типов `call`/`addrex`/`immex`/`stop` ставятся только в правую
   половину (`dis2be.py`, `RIGHT_HALF_KINDS`). Попытка `ПВ P3705(М1)`
   вызвала авто-вставку слова `00 22 00000` (`мода`), длина программы
   выросла до `02001`, слово 1777 обнулилось. Строка возвращена в `КОНД`.
3. **Э64 в левой половине (0057: 695).** `addrex` тоже right-half-only;
   та же вставка `мода`. Оставлено `КОНД`.

Всего: кандидатов 29, применено 23, пропущено/откачено 6.
