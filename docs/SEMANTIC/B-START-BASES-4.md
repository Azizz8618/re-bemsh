# БАЗЫ СТАРТ ДЛЯ ЗОН БЕМШ 0170-0177₈ (B)

## Причина выбора базы

Зоны 0170-0177₈ не найдены ни в одном снимке RAM
(analysis/RAM-SNAPSHOT-MAP.md §4: «Не найдены ...
0170-0177 (кроме таблиц 0174/0175 как шума)»;
analysis/MEMORY-MAP.md §6: 0170 в ОП не найдена).
То есть это НЕРЕЗИДЕНТные оверлеи на диске. По указанию
оператора для нерезидентных зон берётся база '10000'₈.

## Что именно изменено

В заголовке каждого модуля изменён только операнд СТАРТ:
было `Z0170   СТАРТ 1`, стало `Z0170   СТАРТ '10000'`.
Метка модуля и все остальные строки не тронуты.
diff правки: ровно одна строка на каждый из 8 файлов.

Важно: СТАРТ задаёт только базу адресов в листинге
транслятора, но НЕ меняет значения самих слов.

## Проверка байтовой безопасности

Транслятор запускался через tools/vneshn_probe.sh на копии
каждого .be (тот же job, что и в rebuild-zone.sh).
Ошибки трансляции = 0, ДЛИНА ПРОГ = 02000₈ во всех 8 зонах,
dispak_rc = 0.

Слова извлекались из листинга с базой 10000₈:
столбец адреса [25:30], слово по адресу 10000₈+i для
i=0..1023; каждое 6-байтовое слово сверялось с
gold/MBE-Z<Z>-L1.bin.

| Зона | Операнд СТАРТ | База   | Ошибок | Совпало   |
|------|---------------|--------|--------|-----------|
| 0170 | 1 -> '10000'  | 10000₈ | 0      | 1024/1024 |
| 0171 | 1 -> '10000'  | 10000₈ | 0      | 1024/1024 |
| 0172 | 1 -> '10000'  | 10000₈ | 0      | 1024/1024 |
| 0173 | 1 -> '10000'  | 10000₈ | 0      | 1024/1024 |
| 0174 | 1 -> '10000'  | 10000₈ | 0      | 1024/1024 |
| 0175 | 1 -> '10000'  | 10000₈ | 0      | 1024/1024 |
| 0176 | 1 -> '10000'  | 10000₈ | 0      | 1024/1024 |
| 0177 | 1 -> '10000'  | 10000₈ | 0      | 1024/1024 |

Итог: 8/8 зон прошли проверку. Во всех 8 зонах 1024
из 1024 слов совпадают с эталоном побайтово, расхождений
нет (first_bad=None). Ни одно значение слова не изменилось.
Зоны 0174 (маска таблицы ошибок) и 0175 (нули) тоже
сверены на все 1024 слова, расхождений нет.

## Почему rebuild-zone.sh теперь «падает»

tools/rebuild-zone.sh (и встроенный extract в
vneshn_probe.sh) жёстко извлекает слова с базы i+1, то
есть ожидает СТАРТ 1. С новой базой '10000'₈ его экстрактор
читает не те адреса листинга и сообщает о расхождениях
(bad_words=1024, byte_safe=false). Это АРТЕФАКТ
ЭКСТРАКТОРА, а не реальное изменение байтов: при
извлечении с правильной базой 10000₈ все 1024 слова
совпадают с gold (см. таблицу выше).

Сам инструмент НЕ менялся. Для проверки этих зон
используется переизвлечение с базой 10000₈, описанное выше.
