# ЗОНА 0546₈ — шахматный fill, НЕ таблица ошибок

Основа: `gold/MBE2-Z0546-L1.bin`, `dis/MBE2-Z0546-L1.asm`,
`docs/SEMANTIC/Z0146.md`; образ 2348.
B2-аналог зоны 0146₈ — БАЙТОВО ИДЕНТИЧЕН (`cmp`, 0
  различий).
Адреса восьмеричные; 1024 слова × 6 байт = 6144 байт.

## 1. НАЗНАЧЕНИЕ МОДУЛЯ

Роль: зона НЕ содержит ни текста, ни исполняемого кода,
ни таблицы ошибок. Все 1024 слова заняты чередующимся
шахматным шаблоном AA/55; последнее слово — иная фаза.

EVIDENCE:
- `cmp gold/MBE2-Z0546-L1.bin gold/MBE-Z0146-L1.bin` —
  тождество
  [V:88: diff=0, s=0, class I];
- distinct word = 3 (512× AA, 511× 55, 1× DB6DB6) —
  проверено
  по байтам дампа [Z0146 §2];
- `besmtool search` текстов в зоне НЕ находит [Z0146 §1];
- XR:99: КМ=0, ДМ=0, BR=2, CALL=0 — переходов нет (BR=2 дают
  START и последнее «по») [XR:99; Z0146 §4].

_confidence_: ПОДТВЕРЖДЕНО (байты, cmp, 3 distinct, 0
  текстов).

## 3. ЗНАЧЕНИЯ КОНСТАНТ

`besmtool view 2348 --start=0546 --length=1
  --encoding=g,k,t,i`
(только чтение). oct→bytes→decoded:

```
адр    oct                bytes             
  decoded(disbesm6)
0000   5252525252525252   aa aa aa aa aa aa  слиа
  '25252'(М12)
0001   2525252525252525   55 55 55 55 55 55  вчп '72525'(М5)
1777   6666666666666666   db 6d b6 db 6d b6  по '66666'(М15)
```
Байтовая причина (НЕ инструкции, а данные) [Z0146 §3]:
- 0xAA = 0b10101010 = 0o252; половина 0xAAAAAA = 0o02525252;
  `reg = word>>20 = 0o12` → М12; `& 0x0f8000 = 0x0a8000`
  → opcode «слиа»; аргумент 0o25252.
- 0x55 = 0b01010101 = 0o525; половина 0x555555 = 0o05252525;
  `reg = 0o5` → М5; `& 0x0bf000 = 0x015000` → «вчп»;
  аргумент 0o2525+0o70000 = 0o72525.
- 0xDB 0x6D 0xB6 = повтор «110»; половина 0xDB6DB6:
  `reg = 0o15` → М15; `& 0x0f8000 = 0x0b0000` → «по»;
  аргумент 0o66666.

GOST/KOI7/TEXT/ITM-колонки view для всех трёх слов — мусор
(`≡≡≡≡≡≡`, `UUUUUU`, `JJJJJJJJ`) → диагностика кодировки:
  это
не текст [TC §3]. Вывод: М5/М12/М15 здесь — ПСЕВДО-РЕГИСТРЫ,
артефакт совпадения шаблона с opcode [REG §1.3, §3].

## 4. ПЕРЕМЕННЫЕ И ЯЧЕЙКИ

```
ER_TAB_WORD = 0o25252 / 0o72525 — слово-заполнитель,
  НЕ переменная и не EQU регистра [REG §3; COMMENTING §2.5].
Входящих ссылок на данные зоны НЕТ: индексация отсутствует
  [Z0146 §4; XR:99]. Штампов других зон на 0546 нет.
```
`0o66666` CROSSREF называет «RETM15» (20 вхождений) — то же
слово-заполнитель в 10 зонах, не вызовы [Z0146 §4].

## 5. РЕГИСТРЫ

```
М5   псевдо: 511× «вчп '72525'(М5)» — данные, не регистр
     [REG §1.3; Z0146 §3] ПОДТВЕРЖДЕНО (шум)
М12  псевдо: 512× «слиа '25252'(М12)» — данные, не регистр
     [REG §3; Z0146 §3] ПОДТВЕРЖДЕНО (шум)
М15  псевдо: последнее слово «по '66666'(М15)» [Z0146 §3]
     ПОДТВЕРЖДЕНО (артефакт)
```
Реально работающих регистров в зоне НЕТ: все `(Мn)` — поле
команды, совпавшее с битами шаблона [REG §4].

## 6. ПОСЛЕДОВАТЕЛЬНОСТЬ ВЫПОЛНЕНИЯ

Исполняемой последовательности НЕТ.
- ВХОД: нет. ВЫХОД: нет (BR=2 — START и последнее «по», не
  CALL).
- Почему данные: (1) все слова — `конд`-шаблон одной из 3
  форм; (2) 0 CALL, 0 меток кода [XR:99]; (3) `disbesm6`
  печатает массовые «слиа/вчп», но это не исполняемый код, а
    биты
  AA/55, совпавшие с opcode [Z0146 §3].

## 7. НЕИЗВЕСТНОЕ

1. Почему последнее слово 0xDB6DB6, а не AA/55 — неизвестно.
   ГИПОТЕЗА: тестовый шаблон резервной зоны; 0xDB6DB6 —
   вариант фазы того же шаблона (период 3 бита вместо 2).
2. Текстов, дат, номеров ошибок в зоне нет — искать нечего.
3. B↔B2: отличий НЕТ (class I) — зона не участвует в
   правке 12/77 [V:88]; это сильный контраст с 0547 (class
     C).
