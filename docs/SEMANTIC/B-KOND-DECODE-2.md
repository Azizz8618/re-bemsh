## 1. МЕТОДИКА

1. Слово `КОНД В'<16 восьм. цифр>'` - это одно 48-битное слово.
   Старшие 8 цифр = левая 24-битная команда, младшие 8 = правая.
2. Обе половины разбираются `siprod_asm.decode()` (таблица `OPS`
   из `/home/azizz/Yandex.Disk/re-siprod/tools`). Результат:
   мнемоника, регистр (восьмеричный), адрес, DMS/EXP/структура.
3. Если обе половины дают именованную мнемонику и записываются
   в МАКРО-БЕМШ 06/78 без изменения байтов, строка `КОНД`
   заменяется ДВУМЯ командными строками. Число слов не меняется.
4. Операнд: существующая `ЭКВ`-метка с тем же значением, иначе
   новая компактная метка `Pxxx` (цели ПБ/ПВ/ПИО/ПИНО) или
   `Cxxx` (ячейки данных), либо числовой литерал `'xxx'` для
   команд 2-й структуры. Имена новых меток ≤6 символов.
5. Комментарий - только после запятой, ≤55 символов, строка ≤60
   колонок, перенос через `*`. Разделитель `↑` в тексте не нужен.
6. Границы код/данные взяты из `dis-forced/Z<зона>.asm` и
   `docs/SEMANTIC/Z<зона>.md`: плотность командных строк в окне
   ±16 слов ≥8 или (для 0155/0156) документированный диапазон
   кода. Зоны-таблицы и fill не трогаются.
7. Обязательная проверка после КАЖДОЙ зоны:
   `bash tools/rebuild-zone.sh <Z> B` → `RESULT: PASS`,
   `1024/1024`, «Файлы идентичны (2000 слов)». Перед каждым
   изменением создавался `.bak` (равило AGENTS.md §0.5).

## 4. НОВЫЕ МЕТКИ

Добавлено 192 `ЭКВ`-метки. Имена: `P<восьм>` для целей переходов
и вызовов (например `P76036 ЭКВ '76036'`), `C<восьм>` для ячеек
данных (например `C6272 ЭКВ '6272'`). Все имена ≤6 символов,
`ЭКВ` не порождает слово. Там, где была метка с тем же значением
(`MB6601`, `BR7602`, `CA...` и др.), она использовалась повторно.
