# ЗОНА 0567₈ — шахматный fill B2 (копия 0167₈)

Дата: 20.11.2026. Образ 2348 (read-only, besm6).
B2 = старшая копия 0540–0577₈ (ВАР.12/77).
Адреса восьмеричные. Зона = 1024 слова (6144 байт).

## 1. НАЗНАЧЕНИЕ МОДУЛЯ

Роль: резервная зона, заполненная шахматным тестовым
шаблоном AA/55. Ни текста, ни кода, ни таблиц ошибок.

EVIDENCE:
- `cmp gold/MBE2-Z0567-L1.bin gold/MBE-Z0167-L1.bin` →
  байтово идентичны; distinct word = 3.
- `besmtool dump 2348 --start=0567 --length=1` даёт 6144
  байт, чередование aa/55; `besmtool search` текстов
  не находит.
- CROSSREF.md §3: Z0567 КМ=0, ДМ=0, BR=2, CALL=0 —
  переходов нет (BR=2 дают START и последнее «по»).
- versions.md §5: 0167↔0567 diff=0, s=0, класс I.
- `besmtool dump --start=0537` → 6144 нулевых байт:
  B2 начинается с 0540, зона 0537 пуста.

Confidence: ПОДТВЕРЖДЕНО (байты и cmp). Само назначение
«резерв/fill» — ГИПОТЕЗА (смысл шаблона неизвестен).

## 5. РЕГИСТРЫ

М5/М12 здесь — АРТЕФАКТ, а не реальные регистры:
disbesm6 читает 0xAA/0x55 как opcode+поле (REGISTERS.md
§1.3, §3; docs/SEMANTIC/Z0167.md §3):

  0xAA = 0o252 → половина 0xAAAAAA = 0o02525252:
    reg = word>>20 = 0o12 → М12; «слиа '25252'(М12)»;
  0x55 = 0o525 → половина 0x555555 = 0o05252525:
    reg = 0o5 → М5; «вчп '72525'(М5)»;
  0xDB6DB6 → reg = 0o15 → М15; «по '66666'(М15)».

То же слово 0o66666 VARIABLES-VALIDATION.md называет
RETM15 (20 вхождений в 10 зонах) — заполнитель, не вызов.
ПОДТВЕРЖДЕНО (байты, формулы); реальная работа М1–М17
в зоне отсутствует.

## 6. ПОСЛЕДОВАТЕЛЬНОСТЬ ВЫПОЛНЕНИЯ

Исполняемой последовательности НЕТ.

  0000–1777: 1024 слова данных. Линейная развёртка
    disbesm6 даёт «слиа/вчп … (М12)/(М5)», но это
    НЕ код: забелы `пам`=0, `конд`=0,CALL=0.
  Вход: нет. Выход: нет. Процедур и `пб (Мn)` нет.
  Evidence: CROSSREF.md §3 (Z0567 0/0/2/0);
    Z0167.md §4; `dis/MBE2-Z0567-L1.asm` строки 8–12.

## 7. НЕИЗВЕСТНОЕ

1. Почему последнее слово 0xDB6DB6, а не AA/55 —

2. Смысл выбора «шахматки» для резервной зоны.
