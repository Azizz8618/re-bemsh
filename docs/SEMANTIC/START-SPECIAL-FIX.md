# СПЕЦИАЛЬНЫЕ СЛУЧАИ СТАРТ: ЗОНЫ 0147, 0152, 0157₈

## ИТОГОВАЯ ПРАВКА (по указанию оператора)

- 0147: `СТАРТ 1` (база 0 не кодируется, пишем просто 1).
- 0152/0157: `СТАРТ '75777'` вместо `'76000'`. При базе
  76000 транслятор даёт `ПЕРЕПОЛН СЧА` (1024 слова +
  служебное слово выходят за 100000₈). База 75777 даёт
  0 ошибок и 1024/1024 слов; она на 1 слово ниже
  физической страницы 37, что принято оператором ради
  чистой сборки. Снимки ОП (`RAM-SNAPSHOT-MAP.md:134,156`)
  по-прежнему фиксируют физическую базу 76000₈.
  Разрешение benign-ошибки удалено из `tools/rebuild-zone.sh`:
  для всех зон снова требуется 0 ошибок.

## 1. МЕТОД

1. Бэкап каждого `.be` перед правкой.
2. Изменена ТОЛЬКО строка `СТАРТ`: вырезана из старой позиции
   и вставлена первой некомментарной строкой. Все остальные
   строки, включая `Е`/`М`, остались на местах. Значения слов
   не изменялись; `diff` с бэкапом показывает только перенос
   одной строки (у 0147 ещё смена `0` на `1`).
3. Прогон: `tools/vneshn_probe.sh probe <копия> <Z> B final-z<Z>`
   на копиях в `/tmp/.private/azizz/start-fix-verify/`.
4. HAM, ошибки и адреса взяты из listing.out. Для 0152/0157
   слова извлеканы повторно с базы 76000 (встроенный extract
   проба предполагает базу 1): `extract_base.py`.

## 2. РЕЗУЛЬТАТЫ ПО ЗОНАМ

зона | новая строка | операнд | HAM    | адреса       | слов
-----+--------------+---------+--------+--------------+-----
0147 | 122          | '1'     | 00001  | 00001..02000 | 1024
0152 | 24           | '76000' | 76000  | 76000..77777 | 1024
0157 | 23           | '76000' | 76000  | 76000..77777 | 1024

«новая строка» = номер строки СТАРТ после правки; это первая
некомментарная строка файла (перед `OUT477 ЭКВ` у 0147 и перед
первым `ЭКВ` у 0152/0157). Старые позиции: 216, 43, 83.

### 0147

Операнд `'0'` заменён на `1` (без кавычек, по указанию
оператора): база 0 — ерунда, пишем `СТАРТ 1`. Нулевые
формы транслятор отвергает (`НОЛЬ ЗАПРОШЕН`), а
`HAM=00001` — минимальный адрес, сдвинутый на 1.

Прогон: dispak rc=0, ошибок 0,
`ЧИCЛO OШИБOK=0000. MAKC CEPЬEЗH=0.`,
`HAM=00001`, `ДЛИHA ПPOГ=02000`.
Извлечение с базы 1: 1024/1024 слов, 0 расхождений, silver
побайтово равен gold (6144 байт). `rebuild-zone.sh` проходит.

### 0152 и 0157

Операнд `'76000'` сохранён, перемещён наверх из-под блока `ЭКВ`.
Прогон: dispak rc=0, `HAM=76000`, `ДЛИHA ПPOГ=02000`.

Единственная ошибка (ровно 1 на зону, текст дословно):

    ПEPEПOЛH CЧA

Она висит на служебной строке после 1024-го слова модуля
(адрес 100000₈, 15-битное переполнение счётчика): у 0152 это
строка 2281 листинга, у 0157 — строка 2545. Иных ошибок нет:
`ЧИCЛO OШИБOK=0001. MAKC CEPЬEЗH=1.` в обоих листингах.
Извлечение с базы 76000: 1024/1024 слов совпадают с gold,
0 расхождений; адреса 76000..77777, то есть вся страница 37.

Изначально `tools/rebuild-zone.sh` требовал 0 ошибок и на этих
двух зонах падал. Правка инструмента была вне этого write-set
и выполнена родительской сессией после моей проверки. Повторный
прогон `rebuild-zone.sh 0147|0152|0157 B` даёт `RESULT: PASS`,
1024/1024 слов и побайтовую идентичность silver и gold (6144
байт). Байты модуля при переполнении не теряются.

## 3. ПОДТВЕРЖДЕНИЕ НЕИЗМЕННОСТИ ЗНАЧЕНИЙ СЛОВ

`diff` каждого файла с бэкапом содержит только две операции:
удаление старой строки `СТАРТ` и вставку новой. Ни одна строка
кода, `ЭКВ`, `КОНД` или комментарий не изменён. Прогон дал
1024 совпавших слов из 1024 для каждой зоны, `first_bad_word`
отсутствует. Новые строки СТАРТ короче 60 колонок; кодировка
UTF-8 и переводы строк LF сохранены.
