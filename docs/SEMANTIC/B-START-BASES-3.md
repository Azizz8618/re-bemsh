`dispak` шли на копиях под
`/tmp/.private/azizz/vneshn-probe/`.

## Причина выбора базы

Базы взяты из `analysis/RAM-SNAPSHOT-MAP.md` §4:

- 0147 — резидентна, страница 00, адрес 00000₈;
- 0161, 0162 — резидентны, адреса 24000₈ и
  26000₈ (AMBIG);
- 0160, 0163-0167 — не найдены в снимках, база
  '10000'₈ по правилу для нерезидентных зон
  (как в ASM-START-BASES.md).

СТАРТ задаёт только базу адресов в листинге
транслятора, НО НЕ меняет значения самих слов.

## Опыт со СТАРТ '0' для зоны 0147

Транслятор ПРИНЯЛ `СТАРТ '0'`: ошибок 0, ДЛИНА ПРОГ
02000₈, отказа нет. Но печать адресов в листинге
однозначна (1-based): первый адрес — 00001₈, дальше
00002..02000₈, то есть так же, как при `СТАРТ 1`.
Номинальная база 00000₈ в листинге не появляется.

Поэтому извлечение слов для 0147 идёт с базы B=1,
а не B=0:

- B=0: совпало 185/1024 (смещение на 1 слово);
- B=1: совпало 1024/1024, расхождений нет.

Это свойство печатного адреса, а НЕ изменение значений
слов: при B=1 все 1024 слова байтово равны эталону.
Возврата к '10000' НЕ сделано: 0147 резидентна на
странице 00, и база '10000'₈ неверно указывала бы
другой адрес загрузки. Правило '10000' относится
только к нерезидентным зонам.

## Почему rebuild-zone.sh «падает»

tools/rebuild-zone.sh (и встроенный extract в
vneshn_probe.sh) жёстко извлекает слова с базы i+1,
то есть ожидает СТАРТ 1. С новой базой его экстрактор
читает не те адреса листинга и сообщает о
расхождениях. Это АРТЕФАКТ ЭКСТРАКТОРА, а не реальное
изменение байтов: при извлечении с правильной базой
(таблица выше) все 1024 слова равны gold.

Сам инструмент НЕ менялся. Для проверки этих зон
применяется переизвлечение с базой из таблицы:
столбец адреса [25:30], слово по адресу B+i для
i=0..1023, сверка с gold/MBE-Z<Z>-L1.bin.
