## 1. Задача и метод

Добавить в реконструированные `.be` **осмысленные** метки и ссылки
на источники там, где они доказаны документами, не изменив ни одного
машинного слова. Источники, прочитанные до правок:

- `docs/COMMENTING-STANDARD.md` (роль + WHY + `file:line`, ≤55 симв.);
- `docs/LABELS-BE.md` ( формат `ЭКВ`, инвариант 1024/1024 );
- `docs/PROCEDURES-B.md` (каталог процедур B, §4 и §8 );
- `docs/SEMANTIC/Z0170-KOND-FULL.md` (53 дескриптора = ДАННЫЕ);
- `docs/CALL-OUT-OF-MODULE.md` (§4 роль/компакт, §6 приложение);
- `AGENTS.md` §0 (комментарии после запятой, ≤60 кол., ↑ не `^`).

Метод: скан `.be` на `ПБ/ПВ/ПИО/ПИНО` и цели возврата, сопоставление
адресов с каталогом процедур и с приложением CALL-OUT, затем запись
метки `ЭКВ` и `*`шапки с ролью, входами/выходами и ссылкой.

### 1.1 Формы меток (все ≤6 символов, UPPERCASE)

| Форма | Назначение | Пример |
|---|---|---|
| `Pnnnn` | цель `ПВ/ПБ/ПИО/ПИНО`, то есть вход процедуры | `P1522`, `P1636` |
| `Cnnnn` | ячейка/данные процедуры | `C1205`, `C0010` |
| `XnnnnB` | внешний адрес с ИМЕНОВАННОЙ целью из CALL-OUT §4 | `X4130B`, `X7417B` |

Суффикс `B` у `X` взят из компактной метки CALL-OUT §4. Запись идёт
по образцу `0147`: строка `* <роль>; <источник>` над короткой
строкой `ИМЯ ЭКВ 'значение'`. Это удерживает длину строки ≤60 кол.

### 1.2 Почему не подставлялись метки в операнды

Байтовая безопасность важнее красоты листинга. Опыт
`Z0170-KOND-FULL.md` §2.1 показал: замена 43 числовых операндов
на `Pxxxx` дала 6 расхождений (половины `ПИО (М11)` теряли регистр
из-за выравнивания). Поэтому добавляются **только** определения
`ЭКВ` (слова не порождают) и `*`строки (ребилд их отбрасывает).
Все числовые поля, мнемоники, `(Мn)` и операнды оставлены как есть.

## 3. Примеры

### 3.1 Метка внешней цели (0170)

    * MEM_P02_Z0155, 38 вх.; CALL-OUT:77, Z0170.1147+
    X4130B ЭКВ '4130'

Роль `MEM_P02_Z0155` и компакт `X4130B` взяты из CALL-OUT §4, строка 77;
38 входов и адреса `Z0170.1147+` даны в §4/§6 того же документа.

### 3.2 Шапка процедуры (0176)

    * --- ПРОЦЕДУРА P1354 (0176:1354) ---
    * РОЛЬ: настройка адресации М14 для справки.
    * ВХ: ПВ из 0176:0033(М1); ВЫХ: RET@1362.

Единственная в B-зонах PROCEDURES-B процедура со статусом

## 4. Особые случаи, где метки не навязывались

1. **0170, 53 дескриптора (0003–0067).** Оставлены «как есть»
   строками `КОНД В'2710…'` с честным комментарием `ДАННЫЕ дескриптор`.
   Добавленный xref явно говорит, что 53 `пв '2070'(М5)` из
   CALL-OUT:1573 суть тег ДАННЫЕ, а не вызовы (KOND §2, §2.1).
   Метка `X070B` переименована комментарием в «тег 53 дескр.».

2. **0174.** Одна внешняя цель `40100` (CALL-OUT:115,
   UNKNOWN_ABSOLUTE_ADDRESS).CALL-процедур нет, помечена шапка зоны.

3. **0175.** CALL-OUT не дал ни одной цели, PROCEDURES-B §8
   относит зону к «без процедур». Добавлена только честная шапка
   «забел нулей, метки не навязываем». Ни одного `ЭКВ` не введено.

4. **0172.** Процедур нет, но есть 3 именованные цели ZONE_PAGE
   зоны 0154. Добавлены только `X`-метки и шапка зоны.

## 5. Оговорки (при дефиците данных не домысливаем)

- Эталонного исходника транслятора на диске нет. Статус `ПОДТВЕРЖДЕНО`
  имеет только `P1354` (CALL+RET+текст по PROC-B:1287). Все остальные
  метки, включая роли `X` из CALL-OUT §4, суть ГИПОТЕЗА.
- Для 0170 есть противоречие источников: PROCEDURES-B:1160/1171
  даёт 2 CALL-процедуры по принудительному листингу, а
  `Z0170-KOND-FULL.md` §4 фиксирует `CALL=0` по базовому листингу.
  Обе шапки 0170 честно помечают это как ГИПОТЕЗА и указывают,
  что RET нет. Ни одна сторона не «исправлена» молча.
- `(Mn)` в листинге есть поле команды, а не доказанное значение
  (REGISTERS.md §4). Метки не утверждают значений регистров.
- Роли `MEM_Pxx_Z0yyy` суть гипотезы CALL-OUT §4, а не имена
  процедур из исходника.
