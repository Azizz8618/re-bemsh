## 1. ЗАДАЧА И РЕЗУЛЬТАТ

Требовалось вставить в уже реконструированные `.be` зон B 0150-0157
осмысленные метки и кросс-ссылки по правилам `COMMENTING-STANDARD.md`,
`LABELS-BE.md`, байтово безопасно:

- `Pxxx` — входы процедур ПБ/ПВ/ПИО/ПИНО, подтверждённые каталогом
  `docs/PROCEDURES-B.md` §4;
- `Cxxx` — ячейки (уже присутствуют в файлах от прохода КОНД,
  новых не потребовалось);
- `Xxxx` — внешние адреса с именем цели из
  `docs/CALL-OUT-OF-MODULE.md` §4/§6;
- человекочитаемые `*`шапки «роль + входы/выходы + источники xref»;
- комментарии только после запятой, ≤55 символов, строки ≤60 колонок,
  без тавтологий.

Итог: **7 зон**, **4 новые P-метки**, **21 новая X-метка**,
**14 существующих меток снабжены xref-комментариями**, **7 шапок**.
Все 7 сборок: `RESULT: PASS`, `1024/1024`, различий 0.
Ни одно машинное слово не изменилось (проверено побайтово).

## 2. МЕТОД

1. Сканируются операнды CALL/return (`пв`, `пб`, `пио`, `пино`,
   `пио36`) в `docs/CALL-OUT-OF-MODULE.md` §6; для зон 0150-0157
   извлечены все ссылки и сопоставлены с именованными целями §4
   (`MEM_*`, `EXT_CALL_*`, компактная метка `XnnnnB`).
2. Входы процедур взяты из `docs/PROCEDURES-B.md` §4 (только
   `BRANCH`/`CALL`, ложные цели `—` не метились). Для
   каждого входа записаны вызывающие (`ВХ=…`) и выход (`RET`/`ДАН`).
3. Роль зоны взята из `docs/SEMANTIC/INDEX.md:22-29`, роль регистра —
   из `docs/REGISTERS.md` §3. Метки `P`/`C` уже созданные проходом
   КОНД (`B-KOND-FULL-SWEEP-2.md`) не дублировались: новые `P` даны
   только входам, у которых не было метки с тем же значением.
4. Новые `ЭКВ` вставлены после `М`, сразу за последней существующей
   `ЭКВ` строкой (как в `LABELS-BE.md` §4); `ЭКВ` не порождает слово.
5. Перед каждым файлом создан `.bak.<timestamp>` (AGENTS.md §0.5).
   После КАЖДОЙ зоны выполнялся `bash tools/rebuild-zone.sh <Z> B`;
   при отказе была бы выполнена реактивация из `.bak` (отказов не было).
6. Инвариант проверен программно: множество строк кода (без `*` и
   `ЭКВ`) до и после правки совпадает посерийно для каждой зоны.

## 6. ОГРАНИЧЕНИЯ И ИСТОЧНИКИ

- Роли процедур — ГИПОТЕЗА (`PROCEDURES-B.md` §1: исходника
  транслятора на диске нет, статический анализ не знает значений
  регистров). `ПОДТВЕРЖДЕНО` только там, где есть CALL+RET пара
  и текстовый якорь; здесь все роли помечены как гипотезы.
- Метки `Xxxx` дают имя цели по `CALL-OUT-OF-MODULE.md` §4, но не
  доказывают, что внешний адрес — точка входа; это гипотеза по
  странице памяти (`MEMORY-MAP.md` §5).
- `P0000` — метка нулевого слова зоны (адрес `СТАРТ 1`), не артефакт
  `MBEENTRY` (`FINAL-REPORT.md` §5).
- Источники: `docs/COMMENTING-STANDARD.md`, `docs/LABELS-BE.md`,
  `docs/PROCEDURES-B.md` §4, `docs/CALL-OUT-OF-MODULE.md` §4/§6,
  `docs/SEMANTIC/INDEX.md:22-29`, `docs/SEMANTIC/B-KOND-FULL-SWEEP-2.md`,
  `docs/REGISTERS.md` §3, `gold/MBE-Z<зона>-L1.bin`,
  `bemsh/MBE-Z<зона>.be`, `tools/rebuild-zone.sh`.
