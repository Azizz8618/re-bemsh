## 2. МЕТОД

1. Для каждой зоны перечислены все строки `КОНД В'<16 восьм. цифр>'`.
   Индекс слова сверен с `gold/ASM-Z<зона>-L1.bin`: 203/203 совпали.
2. Обе 24-битные половины разобраны `siprod_asm.decode()`
   (`/home/azizz/Yandex.Disk/re-siprod/tools/siprod_asm.py:100-117`):
   мнемоника, `kind`, регистр (в восьмеричной записи, включая DMS),
   адрес, DMS, EXP, КОП.
3. Для половин с `name=None` разобраны поля по `disbesm6.c:40-128` и
   `simh/besm6_cpu.c`: КОП, структура, бит 18 (EXP); проверено, есть ли
   код в закомментированных строках (`КОП2 020` c:87,
   `КОП2 021` c:88, `УВВ (КОП 032)` c:71, `Э46` c:83,
   `x47 (КОП 047)` c:84) и в dispatch симулятора.
4. Половина признана **символически представимой**, если:
   - `name != None` и мнемоника есть в таблице МАКРО-БЕМШ 06/78
     (исключены `ПИО36`, `Э66`, `Э74`, `Э72` - их транслятор не знает);
   - `exp == 0` (адрес с EXP 5-значной формой `7abcd` не воспроизводится,
     см. `ASM-KOND-FULL-SWEEP.md` §3);
   - `kind` не из `{call, addrex, immex, stop}` в **ЛЕВОЙ** позиции
     (иначе транслятор вставляет `мода` и сдвигает код);
   - для `reg1` адрес укладывается в поле `М0..М37₈`;
   для `imm64` используется форма `64+N` (N - десятичная дельта);
   - адресные поля не выходят за 12 бит (2-я структура) или 15 бит
     (1-я структура).
5. Замена: `КОНК В'<непредставимая половина>'` + символическая команда
   для другой половины. `КОНК` передаёт ровно 24 бита (доказано
   `Z0137-KOND-EXTRA.md` §4 и настоящими пересборками). Число слов не
   изменяется.
6. Проверка после каждой зоны: `bash tools/rebuild-zone.sh <Z> ASM`.

## 5. ВЕРДИКТЫ И ДОКАЗАТЕЛЬСТВА

1. **UNRESOLVED (5 слов)**: левая/правая половина имеет КОП 00 или 01
   в 1-й структуре (`КОП2 020`/`КОП2 021`, системные коды,
   `disbesm6.c:87-88`, закомментированы), КОП 46 (`Э46`, c:83)
   или КОП 32 (`УВВ`, c:71). Коды есть в
   dispatch и/или закомментированы в disbesm6, но **нет мнемоники в
   таблице транслятора 06/78**. По аналогии с
   `docs/ILLEGAL-HALVES-ANALYSIS.md` §2-5 (KOI-7 таблица мнемоник в
   зоне 0137) это могут быть ДАННЫЕ; для зон АСМ ИТМ такое совпадение
   **НЕ доказано** (ГИПОТЕЗА). Байты сохранены побайтово.
2. **EXP-ADDRESS (14 слов)**: бит 18 установлен, адресное поле имеет
   префикс `0o700000`; 5-значная форма `7abcd` транслятором 06/78 не
   воспроизводится, поэтомуword оставлен `КОНД`. ГИПОТЕЗА: это
   расширенные адреса экстракодов; альтернатива - текст/данные, как в
   зоне 0137.
3. **EXP? / нет мн (4 слова)**: обе причины одновременно; обе половины
   непредставимы, вердикт неоднозначен.
4. **COMMAND: мнемоники нет в 06/78 (4 слова)**: `ПИО36`, `Э66`, `Э74`.
   Коды есть в `disbesm6.c:99,105,121` и `OPS`, но транслятор их не
   принимает (доказано ошибкой `OПEPAЦИИ HET` при пробной записи).
5. **COMMAND: авто-мода слева (1 слово)**: левая половина `addrex`/
   `immex` вызвала бы вставку `мода`; вторая половина одновременно
   непредставима, поэтому добавление `КОНК` не даёт выигрыша.
6. **DATA/COMMAND: поле reg1 (5 слов)**: `счи` с адресом > `0o37`
   теряет старшие биты при символической записи `М<n>`; побайтовая
   сверка это подтвердила ещё в `ASM-KOND-FULL-SWEEP.md` §3.

Итог: вердикты 1-3 - ГИПОТЕЗЫ (нет KOI-7/листингового доказательства
для зон АСМ); вердикты 4-6 - факты, подтверждённые пересборкой.
Ни одно слово не «исправлено» по содержимому - только комментарий.
