## 1. Класс ошибок 1: `ЗП` с пустым операндом = нулевое слово

Механический шаблон предыдущего прохода («мнёмокод + роль операнда»,
`docs/SEMANTIC/B-HUMAN-COMMENTS.md`) породил комментарий `, записать` на строках
вида `ЗП , …` — хотя операнда нет, а само слово нулевое.

Доказательство из листинга сборки (`/tmp/.private/azizz/rebuild-all/0147/
listing.out:200-201`, то же в 0175:26-28):

```
         001  00001  00 000 0000  ...  ЗП   , ЗАПИСАТЬ   -> ЗАБЕЛ
                ...  00 000 0000  ...  ЗП   , ЗАПИСАТЬ   -> ЗАБЕЛ
```

Opcode `000` + адрес `0000` + модификатор `0` = `00 000 0000`, т.е. **забел**.
Действие «записать» придумано: писать некуда и нечего.

**Исправление:** комментарий заменён только на `, нулевое слово (забел)`.

```
БЫЛО:          ЗП             , записать
СТАЛО:         ЗП             , нулевое слово (забел)
```

Всего **9 541** строка в 29 зонах (зоны 0146/0160/0163/0164/0167/0156 —
без таких строк).

### Важное уточнение (ложное срабатывание, НЕ менялось)

Пустой операнд **не всегда** означает нулевое слово. Листинг 0147:

```
   00012  00 22 00000  ...  МОДА , НАСТРОИТЬ АДРЕСАЦИЮ   (op=022 — команда)
   00015  00 010 0000  ...  СЧ   , СЧИТАТЬ               (op=010 — команда)
```

`МОДА`, `СЧ`, `СЧИ`, `ПБ`, `ПО`, `ВЧАБ` и др. с пустым операндом собираются
в **настоящие команды** с ненулевым opcode; их комментарии — дословный
перевод мнёмокода и **не** являются галлюцинацией. Они **сохранены**.
Проверено по листингам 0147 и 0146. Аналогично сохранены уже корректные
`, забел` / `, забел буфера вывода` (2220+59 строк в КОНД‑данных) и
`, служебное слово` (честная метка нерасшифрованных данных).

## 2. Класс ошибок 2: противоречие «комментарий ↔ операнд»

Сканер извлекал из комментария упомянутые регистры `(?<![A-ZА-Я0-9])Мn`
и имена‑метки из `ЭКВ`, затем проверял их наличие в операнде.

* После отсева ложных срабатываний (голый операнд `М16` допустим;
  `AM15` — метка, а не `М15`) найдено **0 настоящих противоречий**.
* Примеры ложных: `СЧИ М16 , счёт индекса М16`, `ЗП AM15 , записать AM15`.
* Ни одна строка по этому классу не изменена.

## 3. Класс ошибок 3: повторяющиеся контекстно-свободные комментарии

Единственный подлинный случайpattern‑mapping — `,填充 AA/55` в пяти
зонах‑Fill (0146, 0160, 0163, 0164, 0167), по 2046 строк в каждой.
Один и тот же комментарий ставился и на `'25252'(М12)` (= `AA`), и на
`'72525'(М5)` (= `55`) — без привязки к операнду.

**Исправление:** комментарий сделан контекстно-зависимым:

```
БЫЛО:  СЛИА '25252'(М12),填充 AA/55     -> assembly 12 25 25252 / 0xAAAAAA
СТАЛО: СЛИА '25252'(М12),填充 AA
БЫЛО:  ВЧП  '72525'(М5),填充 AA/55      -> assembly 05 125 2525 / 0x555555
СТАЛО: ВЧП  '72525'(М5),填充 55
```

Всего **10 230** строк (5 120 `AA` + 5 110 `55`). Остальные частые
комментарии (`служебное слово`, `настроить адресацию`, role‑specific
`вызвать CA… через М16` и т.п.) либо честно описывают роль операнда,
либо являются допустимым признаком нерасшифрованных данных — сохранены.
