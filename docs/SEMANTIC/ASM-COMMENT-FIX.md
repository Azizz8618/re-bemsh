# ИСПРАВЛЕНИЕ ГАЛЛЮЦИНИРОВАННЫХ КОММЕНТАРИЕВ В ASM-МОДУЛЯХ (0055–0060₈)

Дата: 20.11.2026. Изменены **только комментарии после запятой**
в четырёх `.be`-файлах АСМ ИТМ. Код, числа, метки, ЭКВ, ` tools/`,
` dis/`, ` gold/` не тронуты (пословная сверка с копиями до правки:
CODE diffs = 0 во всех четырёх зонах).

## 1. ЧТО БЫЛО НЕПРАВИЛЬНО

Предыдущая правка (commit `841a4be`) заменила механические комментарии
вида `,слово 32, прав. часть` на «человеческие» фразы. Для команд с
**пустым полем операнда** были придуманы адреса/регистры, которых в
операнде нет:

```
        ЗП             , записать по адресу из УИА
```

Нижележащее **полуслово** сборки — `00 000 0000` (нулевое слово,
забел): ни адреса, ни `(Мn)`, ни `УиА` в команде нет. Фраза
«записать по адресу из УИА» — галлюцинация, повторённая из
предыдущей строки `УИА -3(М5)` (характерный пример: строки 0055:595 → 596).

Тот же дефект найден у `СЧ` (полуслово `00 010 0000`, адрес 0 —
не `УИА`) и у `ПБ` (полуслово `00 30 00000`).

## 2. ПРАВИЛО ЗАМЕНЫ

Выбрана **последовательная, но осмысленная** схема (обе фразы
разрешены формулировкой задачи; см. §5.2 `COMMENT-AUDIT.md` — пустой
операнд ≠ всегда нулевое слово):

|Мнемоника / полуслово|Старый комментарий|Новый комментарий|
|---|---|---|
| `ЗП` → `00 000 0000` (истинный забел) | `записать по адресу из УИА` | `нулевое слово (забел)` |
| `СЧ` → `00 010 0000` (адрес 0) | `взять по адресу из УИА` | `пустое слово` |
| `ПБ` → `00 30 00000` (адрес 0) | `перейти по адресу из сумматора` | `пустое слово` |

Замена только после первой запятой; выравнивание и пробелы до запятой
сохранены. Все новые строки ≤46 колонок (лимит 55/60 соблюдён).

## 6. ПРОВЕРЕННЫЕ ЛОЖНЫЕ СРАБАТЫВАНИЯ (НЕ ПРАВИЛИСЬ)

1. **`ПВ X(Мn) … , возврат в М15`** — 147 строк (27/47/38/35).
   `COMMENT-AUDIT.md` §5.3 помечает их как CONTRADICTION, но это
   **законное role-утверждение**: `docs/DISBESM6-GUIDE.md` §5 —
   `пв | 0c8000 | CALL | arg2 + (Мn); возврат в M15`;
   `docs/PROCEDURES-ASM.md` §1.2 — «`пв` заносит адрес возврата
   в М15 [GUIDE §5]». `(Мn)` индексирует **цель** перехода, а не
   регистр возврата. Менять нельзя — это создало бы новую ошибку.
2. **КОНД-декодировки в 0060** (`код: пб (М1), CALL`, `код: нтж
   D00721`, `код: зп D00777`) — проверены `disbesm6`: слово
   `0700000000000000` → `01 30 00000 пб (М1)`. Декодировки верны.
3. **«экстракод Э70/Э64/…»** — ложное срабатывание: `Э70` — это
   сама мнемоника, а не отсутствующий в операнде регистр.
4. **Безадресные команды с корректным описанием**
   (`СЧМР , считать модификатор`, `СБР , сбросить сумматор`,
   `СЛ , сложить с сумматором`, `ЗПМ , записать в сумматор
   с модификацией`, `РЖА`, `СЧРЖ`, `РЕГ`, `ЧЕД`, …) — их полуслова
   ненулевые (`00 031 0000`, `00 020 0000`, …), описание соответствует
   мнемонике; по `COMMENT-AUDIT.md` §5.2 это легитимная безадресная
   форма. Не трогались.
5. **Повторяющиеся комментарии >20** после правки: `служебное слово`
   (51/110/48/103) — уже нейтральная точная фраза для КОНД
   неизвестной роли; `взять FLG720 в сумматор`, `перейти на JMP762`,
   `И с AM3500`, `взять AM6767 в сумматор` — совпадают с операндом
   и воспринимаются как осмысленные повторы опросов флагов.
   Замена не требовалась.
