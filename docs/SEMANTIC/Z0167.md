# ЗОНА 0167₈ — шахматный fill, НЕ таблица ошибок

Дата: 19.11.2026. Образ 2348.
Образ: read-only /usr/local/share/besm6/2348.
B2-аналог: зона 0567₈ — байтово идентична (проверено cmp).

## 1. НАЗНАЧЕНИЕ

Зона 0167 НЕ содержит ни текста, ни таблицы
ошибок. Все 1024 слова
(6144 байт) заняты чередующимся шахматным шаблоном:

  слова 0000,0002,…,1776  (512 шт) = AA AA AA AA AA AA
  слова 0001,0003,…,1775  (511 шт) = 55 55 55 55 55 55
  слово 1777 (последнее, 1 шт)     = DB 6D B6 DB 6D B6

Доказательство: `cmp` gold/MBE-Z0167-L1.bin с
`besmtool dump 2348 --start=0167 --length=1` — идентичны;
distinct word = 3; `besmtool search` текстов не находит.
Ранее зона называлась «1024 слов слиа/вчп — таблица ошибок»:
это описание дизассемблера, а не содержание (см. §3).

## 2. СТРУКТУРА

Записей нет. Однородный массив из 1024
48-битных слов, шаг 1 слово.
Границы: слово 0000 — первое, слово 1777 — последнее.
Терминатора нет; слово 1777 отличается от шаблона AA/55.
Повтор в каждом слове: левая и правая половины равны.

Примеры (адрес: hex, обе половины):

  0167.0000: aaaaaaaaaaaa  L=0xAAAAAA R=0xAAAAAA
  0167.0001: 555555555555  L=0x555555 R=0x555555
  0167.1776: aaaaaaaaaaaa  L=0xAAAAAA R=0xAAAAAA
  0167.1777: db6db6db6db6  L=0xDB6DB6 R=0xDB6DB6

## 3. РАСШИФРОВКА КОНСТАНТ

Дизассемблер читает шаблон как код (`disbesm6.c`: вчп ст.66,
слиа ст.114, REG2/STR1 — st.402–428, prreg — st.321):

  зона.слово | hex           | пол. | decoded (disbesm6)
  -----------+---------------+------+-------------------
  0167.0000  | aaaaaaaaaaaa  | L,R  | слиа '25252'(М12)
  0167.0001  | 555555555555  | L,R  | вчп '72525'(М5)
  0167.1777  | db6db6db6db6  | L,R  | по '66666'(М15)

Байтовая причина (НЕ инструкции, а данные):

  0xAA = 0b10101010 = 0o252. Половина 0xAAAAAA = 0o02525252.
    reg = word>>20 = 0o12 → М12;
    word & 0x0f8000 = 0x0a8000 → opcode «слиа»;
    word & 0o77777 = 0o25252 → аргумент '25252'.
  0x55 = 0b01010101 = 0o525. Половина 0x555555 = 0o05252525.
    reg = 0o5 → М5; word & 0x0bf000 = 0x015000 → «вчп»;
    аргумент 0o2525+0o70000 = 0o72525.
  0xDB 0x6D 0xB6 = повтор «110»; половина 0xDB6DB6:
    reg = 0o15 → М15; & 0x0f8000 = 0x0b0000 → «по»; 0o66666.

Вывод: М5/М12 здесь — «псевдо-регистры»
(docs/REGISTERS.md §1.3, §3): артефакт
совпадения шаблона с opcode/регистр.
Уверенность: ВЫСОКАЯ (байты и формулы проверены).

## 4. ИСПОЛЬЗОВАНИЕ

analysis/CROSSREF.md §3: Z0167 КМ=0, ДМ=0, BR=2, CALL=0 —
переходов нет (BR=2 дают START и последнее «по»).
Входящих ссылок на данные зоны нет: индексация отсутствует.
analysis/VARIABLES-VALIDATION.md называет
0o66666 «RETM15» (20 вхождений) — то же
слово-заполнитель в 10 зонах, не вызовы.
Штампов других зон на 0167 нет.

## 5. НЕИЗВЕСТНОЕ

Почему последнее слово 0xDB6DB6, а не
0xAA/0x55 — неизвестно.
ГИПОТЕЗА: тестовый шаблон заполнения
резервной зоны; 0xDB6DB6 — вариант фазы
того же шаблона (период 3 бита вместо 2).
Текстов, дат, номеров ошибок в зоне нет — искать нечего.
