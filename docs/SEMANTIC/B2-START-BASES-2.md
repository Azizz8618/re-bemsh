# БАЗЫ СТАРТ ДЛЯ ЗОН B2 0560-0577₈ (MBE2, 12/77)

## Причина выбора базы

Зоны 0560-0577₈ (копия 12/77, MBE2) не найдены ни в
одном снимке RAM: analysis/RESIDENT-ZONES.md §таблица
строк 104-119 для 0560, 0563-0567, 0570-0577 указывает
`НЕТ / копия 12/77`. То есть это НЕРЕЗИДЕНТные оверлеи
на диске, которые том 2048 в ОП не грузит. По указанию
оператора для нерезидентных зон берётся база '10000'₈.

## Что именно изменено

В заголовке каждого модуля изменён только операнд
СТАРТ: было `Z<Z>   СТАРТ 1`, стало
`Z<Z>   СТАРТ '10000'`. Метка модуля (Z0560, Z0561,
...) и все остальные строки не тронуты. diff правки:
ровно одна строка на каждый из 16 файлов.

Важно: СТАРТ задаёт только базу адресов в листинге
транслятора, но НЕ меняет значения самих слов. Это
подтверждено отдельной сверкой (см. ниже).

## Проверка байтовой безопасности

Транслятор запускался через tools/vneshn_probe.sh на
копии каждого .be (тот же job, что и в rebuild-zone.sh,
режим MBE2, эталон gold/MBE2-Z<Z>-L1.bin).
Ошибки трансляции = 0, ДЛИНА ПРОГ = 02000₈, dispak_rc = 0
во всех 16 зонах.

Слова извлекались из листинга с базой 10000₈:
столбец адреса [25:30], слово по адресу 10000₈+i для
i=0..1023; каждое 6-байтовое слово сверялось с эталоном.

## Значения слов не изменились

Для каждой зоны дополнительно извлекались слова из
исходного листинга с базой 1 (СТАРТ 1) и из листинга с
базой 10000₈ (СТАРТ '10000'). Последовательности из 1024
значений побайтово совпадают: 1024/1024 в каждой зоне.
То есть смена базы СТАРТ сдвинула только адреса в
листинге, не изменив ни одного значения слова.

## Почему rebuild-zone.sh теперь «падает»

tools/rebuild-zone.sh (и встроенный extract в
vneshn_probe.sh) жёстко извлекает слова с базы i+1, то
есть ожидает СТАРТ 1. С новой базой '10000'₈ его
экстрактор читает не те адреса листинга и сообщает о
расхождениях (bad_words=1024, byte_safe=false). Это
АРТЕФАКТ ЭКСТРАКТОРА, а не реальное изменение байтов: при
извлечении с правильной базой 10000₈ все 1024 слова
совпадают с gold (см. таблицу выше).

Сам инструмент НЕ менялся. Для проверки этих зон
используется переизвлечение с базой 10000₈, описанное
выше.
