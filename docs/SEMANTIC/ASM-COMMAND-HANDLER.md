# ОБРАБОТЧИК КОМАНД АВТОКОДА ИТМ: МАШИННЫЙ ЛИСТИНГ

Дата: 20.11.2026. Объект: `ТРАНСЛЯТОР С А/К И Т М`, каталог `0000.0204`,
том 2348, зоны `0055–0060₈`, дата `.75`. Образ читался только для чтения.

Условные пометы: **ПОДТВЕРЖДЕНО** — байты/адреса/счётчики проверены;
**ГИПОТЕЗА** — смысловая привязка без исходника. Исходника автокода ИТМ
на диске нет (`docs/PROCEDURES-ASM.md:13`), поэтому все «роли» процедур
остаются гипотезами.

---

## 1. Что лежит на диске

Четыре зоны содержат **машинный код БЭСМ-6** (1024 слова каждая).
При принудительной разметке всех адресов как `W_CODE` в зоне `0055`
2023 из 2036 половин (99,4%) разбираются в именованные команды
(`docs/SEMANTIC/Z0055.md:28-40`). Это исполняемый образ, не исходник:
любая программа, хранимая как загружаемый модуль, есть машинный код
независимо от языка, на котором её писали.

В зонах **нет** таблицы, цепочки сравнений или обработчика,
индексированного кодами Приложения 3 (`3000…3045₈`, `322…337₈`).
Проверены все 4096 слов на 12- и 24-битных смещениях: положительный
результат отсутствует. Единичные совпадения — адреса обычных команд.

## 3. Найденный обработчик команд

### 3.1 Стартовый шлюз (зона `0057`, слова `0000–0004`)

**ПОДТВЕРЖДЕНО** (`dis/ASM-Z0057-L1.asm:8-16`, `full:8-21`,
`bemsh/ASM-Z0057.be:703-711`, `docs/SEMANTIC/Z0057.md:191-218`):

```
0000  0010405717103604   сч  '4057'      ; аргумент в сумматоре
                          пв  '3604'(М3)  ; CALL внешней цели 3604
0001  0010000000000172   сч  START       ; обнулить сумматор
                          зп  D00172      ; ячейка-команда (ГИПОТЕЗА)
0002  0010017302604012   сч  D00173      ; прочитать слово-команду
                          по  '4012'      ; условный выход зоны
0003  0064362700000000   Э64 '3627'      ; системный экстракод
                          зп  START       ; сброс
0004  0010000003004012   сч  START       ; -
                          пб  '4012'      ; безусловный выход зоны
```

`пв` со индексом М3 по соглашению БЭСМ-6 запоминает возврат в М15
(`docs/DISBESM6-GUIDE.md:114`). В зоне `0057` нет ни одного `пб (М15)`:
возврат неявный. Повтор того же идиома — слова 0410, 1237, 1252,
1266, 1304 (`full:642-643,1481-1482,1502-1503,1525-1526,1553-1554`).

### 3.3 Альтернативный обработчик `5451`

**ПОДТВЕРЖДЕНО**: шесть пар с другой целью (`full:119-120,243-244,
885-886,945-946,1340-1341,1390-1391`; `docs/SEMANTIC/ASM-CODE-RECOVERY.md:221`):

```
0045  0010411403005451   сч  '4114'   ; код вне basic-диапазона
                          пб  '5451'   ; альтернативный обработчик
```

Коды: `4114, 4133, 4603, 4643, 5131, 5162`. Пропуск `4114` в основной
таблице и отдельный переход подтверждают наличие второго класса
обработки. Смысл класса (ошибка/спецкоманда) — ГИПОТЕЗА.

### 3.6 Отрицательный результат по Э-кодам

В зоне `0056`, слова `1003–1034₈`, есть переходы на адреса, численно
равные Э-кодам (`bemsh/ASM-Z0056.be:1638-1695`):

```
1003  по  '3017'   ; 3017 = АУ
1004  по  '3037'   ; 3037 = РА
1016  пб  '3005'   ; 3005 = АВ
1034  уиа '3014'(М3); 3014 = ИЗ
```

Это `ПО`/`ПЕ`/`УИА`, а не сравнение кода команды. **ГИПОТЕЗА (средняя)**:
область `3000₈+опкод` — entries обработчиков, но сами обработчики
вне данных четырёх зон. Прямого пути «прочитан оператор → выделен
опкод → вызван обработчик → выдано слово» в корпусе нет.

## 4. Итог: где обработчик команд

**ПОДТВЕРЖДЕНО:** в зонах `0055–0060` нет обработчика, индексированного
кодами Приложения 3. Найденный механизм — это **таблица косвенных
вызовов**: 34 (плюс 6 альтернативных) пары `сч КОНСТАНТА / пб 3762`.
Аргумент передаётся в сумматоре, переход — `пб` (без связи), настоящий
декодер находится по адресу `3762₈` вне этих зон и в корпусе отсутствует.

Поэтому «переписать транслятор на машинных командах» в буквальном
смысле невозможно: писать не с чего и нечего переводить. Единственное,
что можно сделать достоверно, — зафиксировать машинный код и его
комментарии, что и сделано в `bemsh/ASM-Z00{55,56,57,60}.be` и в
настоящем документе. Реконструкция алгоритма целиком потребует либо
исходника (автокод-операторов или символческого машинного листинга
с авторскими метками), либо статьи Чайковского/Назарова о реализации.

**ГИПОТЕЗА (низкая уверенность):** плотная таблица из 22 consecutive
стендов и «default»-ветка на `5451` похожи на сгенерированную
`case`-таблицу; самоизменяющиеся ячейки `D00172/D00173` и `мод …; пб 0`
похожи на ручной ассемблер. Стиль не доказывает язык реализации.
