## 1. ПОЛНЫЙ ПЕРЕЧЕНЬ СВИДЕТЕЛЬСТВ

### 1.1 Объявления ВНЕШ / ВНЕШН

| file:line | Дословно |
|---|---|
| S:28 | `PRINT8 extrd PRINT8` |
| L:45 | `РRINТ8 ЕХТRD РRINТ8` |
| L:366 | `ВНЕШН=00003` |
| MC:36 | `ВНЕШ` → таблица внешних связей `ВНЕШН=N` |

`extrd` / `ЕХТRD` = объявление внешнего символа
(S:28, L:45).
`ВНЕШН=00003` (L:366) — ровно три внешние ссылки.

### 1.2 Символы с суффиксом СА в `*МЕТ*`

Блок `*МЕТ*`: L:368 (заголовок), L:369–377 (таблица).

| file:line | Фрагмент строки | Суффикс |
|---|---|---|
| L:371 | `МВЕ60 00001В` | `В` (вход), не СА |
| L:375 | `РАGЕ 00003СА` | СА |
| L:376 | `РRINТ8 00001СА` | СА |
| L:377 | `СМ400 00002СА` | СА |

Три СА-символа = три `ВНЕШН`. Логические номера:
PRINT8 = `00001`, CM400 = `00002`, PAGE = `00003`.

Дополнительно в правой колонке L:375–377 стоят пары
`000000 55320ВА` (L:375), `000000 42001СА` (L:376),
`000000 55320ВА` (L:377). Их смысл не установлен;
в расчёт ниже НЕ включены (дефицит данных).

MC:108–110: внешний символ помечается `СА` и подставляется
загрузчиком; `PRINT8 → 01205`. Это прямое подтверждение
роли `СА`: метка внешней связи, а не адрес.

### 1.3 Колонка «СВОБ ПЕРЕМ» (`+N`)

Заголовок: L:28, L:100, L:171, L:242, L:313
(`ОШИБКИ НПК СВОБ ПЕРЕМ АДРЕС ...`).

| file:line | Значение | Строка |
|---|---|---|
| L:87 | `+ 0002` | `МОДА СМ400` |
| L:92 | `+ 0003` | `УИА РАGЕ(М16)` |
| L:276 | `+ 0003` | `МОДА РАGЕ` |

Это значения в колонке «свободные параметры» листинга,
не адреса и не операнды CALL. Ни одного `ПЕРЕМ +N` как
директивы в исходнике (S:1–301) нет.

### 1.4 `*EXECUTE` (L:383, L:385–390)

| file:line | Символ | Адрес ОП | Флаг |
|---|---|---|---|
| L:385 | `МВЕ60` | `01000` | — |
| L:386 | `РRINТ8` | `01205` | — |
| L:387 | `РRINТ80` | `01205` | `E` |
| L:388 | `*СМ400*` | `01243` | `C` |
| L:389 | `*РАGЕ*` | `02000` | `C` |
| L:390 | `МОN*IТОR` | `04000` | — |

`PRINT80 E 01205` (L:387) — эквивалент PRINT8, не 4-я
внешняя ссылка (ср. `ВНЕШН=3`, L:366; EP:301–303).

### 1.5 Вызовы внешних процедур (CALL / ПВ / ПВО)

Макрос определенён в S:12–16 и L:29–33:

| file:line | Дословно |
|---|---|
| S:13 / L:30 | `∧L САLL ∧Т` |
| S:14 / L:31 | `∧L ПВО ∧Т.(М15)` |
| S:15 / L:32 | `ПАМ 0` |

MC:108–109: `CALL ∧T` разворачивается в `ПВО ∧T.(М15)`
плюс `ПАМ 0`; адрес возврата в М15.

Вызовы PRINT8 (внешний):

| file:line | Строка | ИСХ N |
|---|---|---|
| L:169 / S:129 | `САLL РRINТ8` | 0118 |
| L:193 / S:150 | `САLL РRINТ8` | 0139 |

Обе строки САLL напечатаны без машинного слова (макрос),
поэтому числовой операнд `ПВО` в листинге не виден.

Остальные `ПВ` идут на ВНУТРЕННИЕ метки этого же модуля:
`ПВ RD16(М14)` L:106,112,126,135,155,175;
`ПВ VТ60(М15)` L:199 (VT60 определена внутри: L:300).
К внешним процедурам они отношения не имеют.
`ПВО` как отдельная строка развёртки в листинге не
показан: только в определении макроса (L:31).

## 2. АРИФМЕТИКА В ВОСЬМЕРИЧНОЙ СИСТЕМЕ

Дано (из §1):

| Величина | Значение | file:line |
|---|---|---|
| PRINT8, логич. номер | `00001` | L:376 |
| CM400, логич. номер | `00002` | L:377 |
| PAGE, логич. номер | `00003` | L:375 |
| PRINT8, память | `01205` | L:386 |
| CM400, память | `01243` | L:388 |
| PAGE, память | `02000` | L:389 |
| MBE60, вход в память | `01000` | L:385 |
| ДЛИНА ПРОГ | `00205` | L:366 |

Разности:

| Выражение | Результат |
|---|---|
| `01205 - 01000` | `00205` |
| `01243 - 01205` | `00036` |
| `02000 - 01243` | `00535` |
| `02000 - 01000` | `01000` |
| `01243 - 01000` | `00243` |
| `01205 - 01205` | `00000` |

Ключевые факты:

1. `01205 - 01000 = 00205 = ДЛИНА ПРОГ` (L:366).
   PRINT8 загружен сразу после МВЕ60. Это единственная
   «чистая» разность, совпадающая с полем листинга.
2. Ни одна из разностей не даёт `00001`, `00002` или
   `00003`. Логические номера внешних символов НЕ равны
   никакой разности «адрес - начало модуля».
3. `02000 - 01000 = 01000` — граница страницы
   (1024 слова = `2000`(8)), а не номер external-а.

ГИПОТЕЗА: числа `00001/00002/00003` — порядковые номера
внешних ссылок, присвоенные по порядку появления в
исходнике: PRINT8 (S:28), CM400 (S:56), PAGE (S:57).
Порядок совпадает с номерами. Прямой документации
способа присвоения в доступных исходниках нет.

## 3. СРАВНЕНИЕ С НАШИМИ ЗОННЫМИ ДАМПАМИ

| Адрес | Что в МВЕ60 | Что в реконструкции | file:line |
|---|---|---|---|
| `01000` | вход МВЕ60 | точка входа | L:385; EP:92 |
| `02000` | `*PAGE*` | база зоны `0154` | L:389; EP:235 |

MM/EP:229–247: зона `0154` загружена по `02000`,
подтверждено breakpoint `02000` → первая команда зоны.
S:57: `РАGЕ ОЛПАМ 1024` — выделение 1024 слов
(одной страницы) под буфер PAGE.

Почему `02000` — и `*PAGE*`, и адрес загрузки зоны
`0154`, НЕ означаёт общий код:

1. `02000`(8) = 1024(10) = начало 2-й страницы ОП.
   Это структурная граница, а не имя программы.
2. EP:131–144 прямо предостерегает: совпадение
   адресов не означает совпадение программ. МВЕ60 —
   тест ДКС, зона `0154` — материал транслятора.
3. Штампы транслятора (`0147.1315`, `0154.0751`) —
   якоря ДРУГОЙ программы (AGENTS.md §3); слова
   листинга МВЕ60 с ними не сверяются.

ГИПОТЕЗА: `02000` унаследовано от схемы страничной
адресации ДКС, где PAGE — буфер на одну страницу;
поэтому совпадение с базой зоны `0154` закономерно,
но не является указанием на общий код.

## 4. ОКОНЧАТЕЛЬНЫЙ ОТВЕТ

Гипотеза «операнд вызова = метка во внешнем модуле
минус начало внешнего модуля» — ОПРОВЕРГНУТА для
листинга МВЕ60 имеющимися данными:

1. Три внешних символа несут логические номера
   1, 2, 3 (L:375–377), равные `ВНЕШН=3` (L:366).
   Это порядковые индексы связей, не разности адресов.
2. Ни одна разность адресов из §2 не равна 1, 2 или 3.
3. `СА` означает метку внешней связи, подставляемую
   загрузчиком (MC:108–110): PRINT8 → `01205`.
   Механизм — подстановка адреса, а не вычитание
   начала модуля из метки.

ОГРАНИЧЕНИЕ: машинное слово `ПВО` для CALL в
листинге не напечатано (макрос, L:169, L:193).
Поэтому прямое чтение битового операнда вызова
невозможно; вывод опирается на `*МЕТ*` и `*EXECUTE`.

ГИПОТЕЗА (не доказано): в объектном модуле CALL
хранит именно порядковый номер внешней связи,
который загрузчик заменяет на адрес из `*EXECUTE`.
