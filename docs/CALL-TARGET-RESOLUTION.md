# РАЗРЕШЕНИЕ ВНЕШНИХ CALL-ЦЕЛЕЙ PROGRAM 2 (ЗОНЫ 0137–0177₈)

Дата: 20.11.2026. Эталонные образы, `gold/`, `dis/`,
`dis-forced/`, `sym/`, `bemsh/` — только чтение.
Записан только этот файл.

Задача: разрешить СМЫСЛ самых частых целей передач
управления вне дискового модуля (зоны B 0137–0177₈).
Полный каталог всех 1746 ссылок ведётся другим агентом;
здесь — только топ-цели.

**Уточнение по заданию (второе указание):** в класс
«передач с возвратом» включены **только** `ПБ`, `ПВ`, `ПИО`,
`ПИНО` (включая `пио36`) с числовым операндом. Мнемоники
`ПО`, `ПЕ`, `ЦИКЛ`, `ВЫПР` из классификации целей исключены
и могут оставаться только как контекст. Настоящая версия
документа пересчитана по этому правилу.

## 1. МЕТОДИКА (ПЕРЕСМОТРЕННАЯ)

1. Скан 49 файлов `dis-forced/Z*.asm` зон B (0137–0177₈).
   Разрешены мнемоники `пио36|пио|пино|пб|пв` только с
   кавычным числовым операндом ≥ `02000₈` (адреса `0…1777₈`
   в листинге `-a0` внутризональные). Косвенные `(Мn)` без
   числа не учитываются.
   Итог: **4145** ссылок, **1447** различных целей.
2. `пио36` — самостоятельная мнемоника disbesm6; по
   `DISASM-CROSSCHECK.md:6` это имя опкода `0x0f0000`
   (в другом адаптере — `втбрз`), поэтому оно учтено как
   вариант `ПИО` по прямому указанию оператора.
3. Для каждой цели: счётчик, зоны-источники, мнемоника,
   регистр `(Мn)` и 5 строк контекста.
4. Различение КОД/ДАННЫЕ: каждая цель сверялась с
   не forced-листингом `dis/MBE-Z*-L1.asm` и каталогами
   `SEMANTIC/Z*.md`. Если там слово — `конд`/`пам` или
   оно входит в описанную таблицу, «передача» из
   forced-листинга есть **артефакт данных**:половина
   слова, совпадающая с кодом `пв/пб/пио36`.
   Автоматический тест «конд ⇒ данные» здесь
   **неприменим**: он ошибочно помечает и настоящий код,
   который трасса не дошла (`Z0140.md:65-67` — код
   `мода; пв '34562'` в base-листинге тоже `конд`).
5. Привязка цели: страница ОП = `адрес / 02000₈`
   (`MEMORY-MAP.md:3,47-58,100-117`). Карта покрывает
   12 зон из 33; прочие адресы остаются непривязанными.
6. Имена: `sym/GLOBAL.tab`, `sym/ALL_LABELS.tab`,
   `docs/ENTRY-POINTS.md`, `docs/LITERAL-LABELS.md`,
   `docs/SEMANTIC/Z*.md`, `docs/PROCEDURES-B.md`,
   `analysis/GLOBAL-XREF.md`, `docs/TEXT-CONSTANTS-ALL.md`.
7. **Ключевой словарь имён:** `re-dispak/svsmott.txt` —
   именной листинг модуля `МОТТ` (`НАМ=76000`,
   076000–077777₈, `S:2412`), то есть страница 37 =
   зона 0157 по `MEMORY-MAP.md:112`. В нём есть `*МЕТ*`

Разница с числом 1746 в задании: здесь 4145 — потому что
добавлены `ПБ/ПИО/ПИНО` и снят фильтр дедупликации между

## 2. МЕХАНИЗМ «ПЕРЕДАЧ С ВОЗВРАТОМ»

По указанию оператора рассматриваются четыре мнемоники:

| Мнемоника | Что делает здесь | evidence |
|---|---|---|
| `ПВ X(Мn)` | CALL, link в `(Мn)` | `ARCH:416` |
| `ПБ X(Мn)` | переход, возврат по `(Мn)` | `Z0142:209` |
| `ПИО X(Мn)` | передача с индексом | `FZ171:1014` |
| `ПИНО X(Mn)` | то же, вариант | `FZ55:1261` |

`пио36` — разновидность `ПИО` (опкод `0x0f0000`,
`DISC:6`) и учитывается наравне с ней.

1. Канонический макрос `CALL ∧T` разворачивается в
   `ПВО ∧T.(М15)` + `ПАМ 0`: адрес возврата в **М15**,
   возврат — `ПБ (М15)` (`ARCH:439`,
   `PROGRAM2-LOGIC:641-647`). Это уровень сгенерированной
   программы, а не самого транслятора.
2. Во внутреннем коде транслятора устойчива пара
   `мода START; пв 'NNNNN'(М16)`; `мода` настраивает
   регистр модификации адреса (в dispak `MODREG=020₈`),
   а `пв X(М16)` — CALL со ссылкой на **М16**; возврат —
   `пб (М16)` (`Z0140.md:26,65-67`, `Z0142.md:26,76-78`).
   Так вызываются общие подпрограммы загрузчика и МОТТ.
3. В зонах 0137–0141 вторая пара:
   `пв 'NNNNN'(М4)` + `пб 'NNNNN'(М4)` — короткие вызовы
   через **М4** (`FZ140:1297-1300`, `FZ137:218-219`).
4. `М5`, `М7`, `М6`, `М2` в топ-целях — индексы,
   а не link-регистры.

Итог: М16 = link общих библиотек/загрузчика; М4 = link
парных loader-вызовов; М15 = link кода, переносимого
макросом `CALL`.

## 4. ЧТО ИМЕННО РАЗРЕШЕНО

### 4.1 Лидер 07417₈ = УППСЛУ, сервис ТЕРМ (PROVEN)

По прямому указанию оператора адрес признан не
«повторяющимся шаблоном», а абсолютным адресом БЭСМ-6.
`0o7417 = 3855₁₀`. При пересчёте исправлена ошибка
 предшествующей версии: `07417₈` — четырёхзначное число,
 оно лежит на странице **03** (база `06000₈`), смещение
 `01417₈`, а не на странице 36. `074000₈` (пять цифр) —
 другой адрес, границей здесь не является.

**Разрешение:** это именованная точка входа `УППСЛУ`
модуля `ТЕРМ` мониторной системы:

```
TTAB:124   07417 0 УППСЛУ
TERM:342   07417 06 036 0140  0383 0313
           УППСЛУ СДА 64+32(М6)
TERM:816   ... УППСЛУ 07417   (таблица *МЕТ*)
TERM:312   00 30 07417  ПБ УППСЛУ  (реальный вход)
```

Смысл по шапке и справочнику модуля:

```
TERM:17-18  "МОДУЛЬ ТЕРМ ПОДГОТОВКА МАССИВА ДЛЯ ВЫДАЧИ
             НА ТЕРМИНАЛ (ТЕЛЕТАЙП, ВИДЕОТОН, КОНСУЛ)"
TERM:330-334 "*** ПЕРЕВОД ИЗ КОДА УПП В КОД ТЕРМИНАЛА ***"
             "ИСПОЛЬЗУЕТ ТАБКОД С УЧЁТОМ СДВИГА М6"
             "М6 ОПРЕДЕЛЯЕТ, КАКОЙ БАЙТ ИЗ СЛОВА
              ТАБКОД БУДЕТ ИСПОЛЬЗОВАН"
TREF:89    УППСЛУ 313-330: сдвиг M6*8 (64+32(M6)),
           П377, vton1 если 0 (ВТ-340);
           консул (М14+8, СГ) -> ттайп4
```

То есть `07417₈` — **резидентный сервис монитора/ДИСПАК**:
перекодировка символа из кода УПП в код терминала с
выбором байта таблицы `ТАБКОД` по М6 (тип терминала).

Исходные инструкции по соседним адресам (`TERM:338-347`):

```
07415 УППКУ  МОД 42(М7); СЧ ТАБКОД
07416 УППКУ2 СЛИА 1(М5); УИА ОЧСИМВ(М17)
07417 УППСЛУ СДА 64+32(М6); И П377
07420        ПИО VТОN1(М6); УИИ М14(М6)
07421        СЛИА 8(М14); ПИНО СГ(М14)
```

Что проверялось дополнительно (отрицательные результаты):

* `simh/BESM6/besm6_mmu.c:125-175` — встроенные
  hardwired-программы 5–10 лежат по `0176/0376/0036`,
  но 07417 в них нет: это не β-ROM/hardwired-точка.
* `besm6_cpu.c:1036` — `PC < 02000 || PC >= 04000`
  treats 07417 as supervisor-память, то есть код ОС,
  а не пользовательская страница.
* `monitor80-re/docs/СПРАВОЧНИК_КОМАНДЫ.md` — явного
  вхождения `07417` нет; модуль ТЕРМ в перечне
  permanent-библиотеки не поименован (`§4.1, §5.1`).
* `besmtool list 2053/2099` — модуля `ТЕРМ` в каталоге
  этих томов не найдено; образ ТЕРМ взят из листингов
  `re-dispak/term.lst` и `term.be`, не из дампа.
* `sym/GLOBAL.tab` не содержит `07417`;
  `analysis/GLOBAL-XREF.md:73` даёт ему
  `MEM_7417_UNKNOWN` (ГИПОТЕЗА) — это_static-оценка
  без внешнего символьного листинга, теперь снята.

Механические 205 входов (`пио36:202`, `пб:2`, `пио:1`)
подтверждают, что PROGRAM 2 активно обращается к этому
адресу. Часть входов лежит в словах, которые base-
листинг помечает `конд` (`NZ166:580`); это означает
лишь, что адрес 07417 используется и как константа
ссылки в link-ячейках, а не то, что самый адрес
«не существует». Идентичность адреса доказана именным
листингом, что и требуется.

### 4.5 CALL-цели загрузчика 0137–0143 (ГИПОТЕЗА)

`34562`, `34417`, `34366`, `43434`, `14342`, `34526`,
`34524`, `36562`, `34661`, `36515`, `41744`, `44631`,
`41441` — устойчивые пары `мода START; пв '…'(М16)` в
8–18 код-словах загрузочных зон. Каталоги называют их
«общая подпрограмма загрузчика» (`Z0140.md:65-67`,
`Z0142.md:56-57`, `Z0141.md:50-51`).

Ранняя формулировка «физические страницы 016/017/020/
022 картой ОП не привязаны, значит адреса не в модуле»
**отозвана как ошибочная**. Карта ОП ищет совпадение с
байтами дисковых зон; зоны загрузчика 0137–0143 при
загрузке модифицируются (load-time relocation) и поэтому
в снимке не опознаются (`Z0140.md`: «загрузчик вытеснен
до съёма трассы»). Отсутствие совпадения НЕ означает,
что страница не принадлежит задаче. Адреса вида
`34526(М4)` / `51670(М4)` — 15-разрядные адреса в поле
самой задачи-транслятора с индексом М4, а не внешние
константы. Паспорт тома 2048 отсутствует
(`Z0140.md:178-180`); «MONITOR» или «другая зона» здесь
по-прежнему **не утверждается**.

## 5. СТРУКТУРНЫЙ ВЫВОД (ПЕРЕСМОТРЕННЫЙ)

1. После перехода к четырём мнемоникам лидером стал
   `07417` (205) — **абсолютный адрес именованного
   сервиса `УППСЛУ` модуля `ТЕРМ`** (перекодировка
   из кода УПП в код терминала), PROVEN по
   `term.be.tab:124` и `term.lst:342,816`. Вторая и
   третья позиции — `77316` (link-ячейка на MON
   `ДЛЯСВЯ`) и `34562` (CALL загрузчика). Первые два
   места топ-таблицы, таким образом, занимают именно
   мониторные сервисы, а не внутренние процедуры.
2. PROGRAM 2 вызывает **и монитор, и свои другие зоны**:
   - MON/СВС: `07417` → `ТЕРМ:УППСЛУ`, 077xxx → модуль
     МОТТ (0157), плюс шлюз `70000`;
   - внутренние: `02070`/`03162`/`03173` → 0154,
     `027525/027521` → 0162, `075653`/`074020` → 0153,
     page 02 → 0155 (гипотеза оверлея).
   `07417₈` не является адресом зоны 0153: он лежит на
   странице 03 со смещением `01417₈` (§4.1).
   Наиболее чётко доказаны мониторные адреса — для них
   есть именные листинги.
3. Ведущий механизм внутренних вызовов — не канонический
   `CALL` макроса (`М15`), а `мода START; пв '…'(М16)`
   с возвратом `пб (М16)`. М4 — link коротких
   loader-пар; М15 — link сгенерированного кода.
4. Профиль источников согласуется с трёхпроходной
   схемой (`PROGRAM2-LOGIC.md` §1), но не доказывает её:
   редактор/диспетчеры (0154/0155/0157) несут link-ячейки
   в МОТТ; макромашина/компилятор (0170/0165/0166) несут
   page-02 и `пио36`-шаблоны; loader (0137–0143) адресует
   страницы 016–024 **в поле самой задачи** (индекс М4)
   и уходит в `77430`; это не внешние модули.

## 6. ЧЕСТНЫЕ ОГОВОРКИ

1. Пользовательское правило «ПБ/ПВ/ПИО/ПИНО = передачи с
   возвратом» принято как рабочее определение. В таблице
   мнемоник репозитория (`ARCH:414-417`) `пб` описан как
   JUMP, а `пио/пино` — как BRANCH; это расхождение
   терминологии не меняет механического фильтра.
2. `svsmott.txt` и `base.txt` — внешние листинги из
   `re-dispak`, не эталон тома 2348. Имена надёжны как
   соответствие внутри листинга, но побайтовая сверка со
   зоной 0157 не проводилась.
3. Карта ОП снята в двух точках; оверлеи не исключены
   (`MEMORY-MAP.md:161-172`). Для page 02, 16, 17, 20, 22,
   24 зона не доказана; это значит лишь, что байты снимка
   не совпали с диском, а НЕ то, что страница вне задачи.
4. `refs` учитывают дубли 49 forced-файлов; это не число
   машинных обращений (`XREF-INTERMODULE.md:261`).
5. Никакая роль не приписана по сходству с `*EXECUTE`
   теста МВЕ60 (`01000`, `01205`, `04000`) — см.
   `ENTRY-POINTS.md:131-144`.
