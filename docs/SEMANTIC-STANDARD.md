# СТАНДАРТ СЕМАНТИЧЕСКОЙ АННОТАЦИИ ЗОН МАКРО-БЕМШ

Версия 1.0 / 19.11.2026. Образ 2348.
Зоны 0137-0177 (B, ВЕР.06/78) и 0540-0577 (B2, ВАР.12/77).

Цель: чтобы читатель ПОНИМАЛ смысл каждой команды, константы
и ячейки, а не видел пересказ листинга. Статус вывода —
ПОДТВЕРЖДЕНО или ГИПОТЕЗА (AGENTS.md: не домысливать).

## 1. Обязательная структура документа зоны (7 разделов)

1. НАЗНАЧЕНИЕ МОДУЛЯ — роль + EVIDENCE (штампы, адреса
   вызовов, декодированные строки) + confidence.
   Если роль неизвестна — прямо написать «неизвестно».
2. КАРТА ПАМЯТИ — диапазоны адресов → код / текст /
   таблицы ошибок / ячейки данных / забелы (зона.слово).
3. ЗНАЧЕНИЯ КОНСТАНТ — таблица:
   адрес | значение (oct/bytes) | что это | decoding
   (GOST/KOI7/TEXT/ITM) | evidence | confidence.
   Декодируются ВСЕ нетривиальные слова, включая штамп.
4. ПЕРЕМЕННЫЕ И ЯЧЕЙКИ — таблица:
   адрес/имя | роль | кто пишет | кто читает | evidence |
   confidence (по CROSSREF.md и VARIABLES-документам).
5. РЕГИСТРЫ — какие М1-М17 здесь работают, что хранят,
   evidence (REGISTERS.md), confidence.
6. ПОСЛЕДОВАТЕЛЬНОСТЬ ВЫПОЛНЕНИЯ — базовые блоки /
   процедуры по порядку: start-end, ЧТО ДЕЛАЕТ (смысл,
   а не «пб — переход»), входы, выходы, evidence:line.
   Каждая характерная команда объясняется в контексте.
   Для слов данных — почему это данные и что они значат.
7. НЕИЗВЕСТНОЕ — явный список нерасшифрованных слов
   и неопределённых ролей.

## 2. Правила

1. Запрещены тавтологии: «переход — это переход»,
   «константа — это константа», «ячейка — данные».
   Всегда отвечай на вопрос ЗАЧЕМ / ЧТО ЭТО ЗНАЧИТ.
2. Любое утверждение требует evidence: file:line,
   результат besmtool view/search или шаблон вызовов.
   Нет доказательства — пиши ГИПОТЕЗА / НЕИЗВЕСТНО.
3. Объясняй ПОЧЕМУ: `пб (М15)` — возврат, т.к. М15 хранит
   адрес возврата CALL (REG:§3M15); `уиа '14000'(М1)` —
   загрузка базы TAB5 в индекс М1 (VAR §5).
4. Текст декодируй во всех 4 кодировках:
   `besmtool view 2348 --start=<зона> --length=1 \
     --encoding=g,k,t,i` (только чтение). GOST-штамп
   читается в GOST, KOI-7-таблица — в KOI-7; мусор в
   остальных колонках — диагностика кодировки (TC §3).
5. `п'...'` не доказывает текст (TC §2): рядом должны
   быть ≥3 осмысленных слова + попадание besmtool search.
6. oct → bytes → глифы раскрывай явно. Пример:
   `1202745403626040`₈ → `28 2f 2c 0f 2c 20` →
   GOST `ИПМ МА` (штамп 0147.1315).
7. `(Мn)` в листинге — поле команды, не доказанное
   значение: disbesm6 не отслеживает регистры (REG §4).
   Роль М15/M16/M13 — ПОДТВЕРЖДЕНО, остальные —
   ГИПОТЕЗА до трассировки с `-R<N>=<адрес>`.
8. Отличай код от данных: обрыв трассы `пб (М3)`,
   забелы `пам`, `конд`, `конк` (illegal opcode) —
   данные, а не процедуры (PROC-RESOLVED §4).
9. Не путай логические адреса листинга МВЕ60
   (01000, 04000) с физическими зонами — 0 совпадений
   (CROSSREF §6). Физические якоря — только штампы.
10. Моноширина, строка ≤60 кол., комментарий ≤55,
    перенос со `*`, `↑` вместо `^`. Ни один байт
    эталона не меняется; только read-only инструменты.

## 3. Примеры: ПЛОХО / ХОРОШО

ПЛОХО:
```
пб (М15) — переход по М15.
0147.1315 — константа, текст.
D00717 — счётчик.
```
ПОЧЕМУ ПЛОХО: тавтология, нет decoding, нет evidence,
нет «кто пишет / кто читает», не объяснён М15.

ХОРОШО:
```
пб (М15) — возврат из CALL: М15 = адрес возврата,
  записанный парой пв A00477(М15);
  [dis/MBE-Z0147-L1.asm:655; REG:§3M15; ПОДТВЕРЖДЕНО].
0147.1315 — штамп версии: 1202745403626040₈ =
  28 2f 2c 0f 2c 20 → GOST «ИПМ МА», продолжение
  1316-1320 «КРО-БЕМШ ВЕР.06/78»; KOI7/TEXT/ITM —
  мусор (признак GOST); [TC:149, view; ПОДТВЕРЖДЕНО].
D00717 — счётчик вывода: пишут зп (0147:500),
  читают сч (0147:32); ВХ=31; [CROSSREF:146; ГИПОТЕЗА].
```
ПОЧЕМУ ХОРОШО: смысл + механизм + decoding + адрес
источника + статус.

## 4. Контрольный список проверки (10 пунктов)

1. Все 7 разделов на месте, заголовки совпадают с §1.
2. У каждой роли есть evidence в форме file:line.
3. Нет тавтологий; каждое «ячейка/команда» объяснено.
4. Все нетривиальные константы декодированы в GOST/
   KOI7/TEXT/ITM; указан read-only вызов view.
5. oct→bytes→глифы раскрыты для штампа версии.
6. Для ячеек есть «кто пишет / кто читает» и ВХ-счётчик.
7. Регистры сверены с REG:§2; `(Мn)` не выдан за значение.
8. Для процедур есть start-end, входы, выходы, смысл,
   исправленные границы (PROC-RESOLVED).
9. Гипотезы помечены; нерасшифрованные слова — в §7.
10. Строки ≤60 кол., ↑ не ^, эталон и .be не тронуты.
